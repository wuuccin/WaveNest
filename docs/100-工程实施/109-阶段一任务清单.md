## 2 各人具体

### 2.1 卢肄文：接单判断主链接线

做法：

1. 下单时执行接单判断链，按分流结果分四路处理，分别是受理并调度、延后、拒单、转人工。
2. 新增接单输入装配器，从预测快照、机巢查询与配置组装判定输入。配置策略为空时，判定输入的构造器直接抛非法参数异常，策略取值来源是这项任务的硬前置。
3. 订单受理服务在下单前完成装配，订单控制器按结果返回是否受理、原因码与等待原因。

分流口径：受理则发布订单提交事件；延后则置为已受理待唤醒，带等待原因并注册唤醒；拒单则返回未受理与原因码；信息不完整则转人工。

判据：航段外延后或拒单，不进调度；重复单、超载、白名单外拒单；闸门熔断延后；正常单照常调度。

评审修复项：

| 修复位置 | 改成什么 |
|---|---|
| 订单受理服务的船号处理 | 船号只归一化一次，校验与落库用同一个值 |
| 订单受理服务的优先级处理 | 取优先级枚举，落库写枚举名，不写原始请求串 |
| 接单判断链的载重余量守卫 | 加有限性检查，非有限值一律拒单 |
| 接单判断链的点列判定 | 空点列一并计入预计到达时间跳过条件，不进服务航段闸门 |
| 接单判断链的闸门顺序 | 数据有效性闸提到时效闸之前，含船为空、AIS 过期、连接器不健康 |
| 接单判断链的未进段判定 | 未进段改判延后再评，不判服务区外永久拒单 |
| 接单判断链的船号校验 | 船号限 ASCII 数字，请求船号先归一再比对 |
| 预测服务的版本写入 | 按船号串行化取版本、建快照、发布三步，或改用合并操作只接受更高版本，消除低版本覆盖高版本 |

### 2.5 杨添爻：候选链

两条危险方向先说，共同特点是不报错，系统照常运行并静默给出看起来没问题的结论。

非有限值判非法：可行性判定里全是大于与小于比较，而 NaN 参与任何比较恒返回假。最不利风为 NaN 时风况闸失效，距离为 NaN 时剩余电量为 NaN 且电量闸失效，两道闸同时失效，全部候选静默判为可行。修法是在可行性判定入口与候选服务入口做双层守卫，非有限或负数直接抛异常。选择抛而不是返回空列表，是因为空列表会被读成没有可用候选，把上游传坏数这件事埋掉。

未登记抗风不再按最宽松处理：原回落值取气象熔断阈值 12.0，那是已登记机型里抗风最高的一档，结果是台账漏填一行的机型反而比填了的更能飞，等于用数据缺失换豁免。改为取本批候选集已登记机型抗风最小值与预警阈值 8.0 的较小者，候选集里没有登记值就退回 8.0，只会更严或持平。取候选集而非全表，是因为未登记的机器混在一批强机型里时，不该因为表里别处有个弱机型就被压到那个值。

| 修复位置 | 改成什么 |
|---|---|
| 候选服务的输入校验 | 任务距离与最不利风在入口拒绝非有限值与负值，不再让 NaN 静默判为可行 |
| 候选选择器的查询过滤 | 候选查询加健康状态过滤，只取健康机 |
| 候选选择器的机型匹配 | 支持机型串拆分后去空格并滤空，机型匹配不再被前导空格挡住 |
| 无人机上下文适配器 | 机巢坐标缺失时返回空，不回落原巢再查；当前巢与原巢相同时不重复查同一行 |
| 候选选择器的缺字段处理 | 缺经度、纬度或货物重量时快速失败并记日志，不填零造出零坐标取货点 |
| 候选可行性规划器的未登记抗风 | 回落改保守值，取已登记机型抗风上限的最小值或预警阈值，原因里保留未登记按保守口径判 |
| 候选可行性规划器的机型串 | 拆分后去空格并滤空，未登记统一为空列表语义 |
| 会面帧投影器的距离字段 | 改用有限性判断，NaN 与正负无穷一并转空 |

自验：算法模块 232 条与调度模块 176 条合计 408 条全绿，零失败，并强制重跑非缓存。新增 14 条用例，均带旧口径必红的正反对照，含 NaN 风况与 NaN 距离的正向用例、正常输入仍照常判定的反向用例，以及未登记机型在十一米每秒风速下必须淘汰的用例。`wl-app` 有 8 条失败，换回 `develop` 原版同样失败，确认是既有基线问题，与本次无关。

## 5 注意点

1. 包边界防冲突：吴可欣负责飞行状态包与预测包；罗才辉负责编排包与会面求解包；卢肄文负责订单包与预测服务；张睿哲负责队列包与气象包；杨添爻负责候选包、可行性包与会面帧包；彭紫情负责记录包；宋冰鑫负责告警包。
2. 唯一跨包交叉：罗才辉的航迹摘要事件走任务日志记录器，该记录器在记录包内由彭紫情修改。罗才辉若需改其签名或新增参数，先与彭紫情对齐再改，两边默认都只在自己包里改。
3. 跨模块调用方向：`backend/README.md` 规定 M2 到 M3 只调会面门面，M3 不反向依赖 M2。航迹接入走会面门面的生成航迹方法，会面重算走会面门面的重算方法，M2 侧不出现航迹生成器的直接调用。
4. 计划航迹无持久化载体：任务日志只有日志标识、订单号、操作类型、起止状态与时刻，无航迹字段；飞行点表的注释是只记实际飞行点，由 M4 的遥测监听器写实测点。航迹接入默认只做广播前端加任务日志摘要事件；是否新增计划航迹表涉及改灌库脚本与 `37-M6-数据库` 的表口径，属范围扩大项，由组长裁定，罗才辉不自行改表。
5. 危险方向三条优先做：陈旧实体回写冲掉已派发、NaN 让全部候选判可行、未登记抗风反而最宽松。
6. 阈值不许硬编：接近半径、末段兜底时限等阈值取配置项；配置键名上游未指定的，由吴可欣在合并请求描述中写明键名与取值。
7. 改表即超范围：若必须新增列才能建立周期隔离，同样属改表项，由组长裁定；退而求其次按评审建议，边界建不起来时记警告。
8. 灌库脚本不动：`deploy/sql` 下既有脚本当日不改、不重灌。
9. 构建与拉取：构建只用 Wrapper，不跑本机直接调用的 gradle；拉代码用完整路径的 `git.exe`，不用 PATH 里的便携版。
10. 分支：个人分支向 `develop` 提合并请求，合并后清理本人分支。
11. 当日不碰：对外文书一律不排期、不预写，含答辩口径、答辩演示内容、演示剧本、申报材料与答辩用录屏，等项目全部定稿、全部功能完成之后再做。
