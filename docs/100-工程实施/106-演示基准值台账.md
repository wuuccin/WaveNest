## 3 仿真船基准

演示的阶段为单实例的运行，起始的状态是确定的值，不是随机的值。

| 项的名称 | 当前的取值 | 定稿的取值 | 状态的说明 | 依据的出处 |
|---|---|---|---|---|
| 起点的位置 | `115.8611 / 28.6660`，沿程 2.40 km | 同左的取值 | 已定 | 2026-10-29 的拍板选 B，缘由见本节的约束注 |
| 初始的航向 | `31.2°` | 同左的取值 | 已定 | 南昌到八一航段的走向；原值 `6.7°` 是起点到北巢的方位角，会把船开上岸 |
| 航速的取值 | 8.0 节，合 4.12 m/s | 同左的取值 | 已定 | 场景的口径 |
| 位置的噪声 | `0.00005` 度，约 5 m 的量级，逐拍叠加的扰动 | 同左的取值 | 已定 | 只叠加扰动，不改变起点确定的性质 |
| MMSI 与船的名称 | `123456789` 与 `SIM-SHIP-01` | 同左的取值 | 已定 | 演示的单船 |
| 起点的运行时复位 | `POST /sim/ship/reset` 的端点 | 同左的取值 | 已定 | 起点取最后一次复位的时刻 |

起点定稿二点四零公里的缘由是演示要能看见候选择优的过程。船从南端出发，先由近的 NEST-01 承接，随船北移越过两巢的等距切换点之后切换或比对到 NEST-02。起点须落在切换点以南的一段，才留得出可观测的择优窗口。

- 为什么不是现状的二点六九公里：二点六九距切换点仅零点零五公里，约四十八米，NEST-01 的优势期约十二秒，复位、下单、派单之后基本已过切换点，择优来不及看。
- 为什么是二点四零公里：北移的零点二九公里落在南昌与八一之间的开阔江面，距切换点零点三四公里，约三百三十八米，NEST-01 的优势期约八十二秒，足够看清先 NEST-01 后切换的过程。该点仍在预测校验框之内，框的南界为 28.660，起点距之尚余约 666 m；在服务区的包围盒之内；两巢均不超过五公里；一千八百秒的预测尾巴在框内。因此不触发重定框，也不触发重灌。代价仅为图上放样的坐标回填与两行默认值的修改。

多船的说明：数据模型支持多船，船舶轨迹表按 MMSI 建索引，演示的阶段不启用多船。

### 7.4 环境重灌注意事项

- 初始化脚本挂在容器初始化目录，只在空数据卷时执行一次，只执行 `up -d` 不生效。
- 统一做法仍是删卷重建，重建会清掉库里的订单与日志，动手前先看有没有要留的数据。
- `006_alert_position.sql` 是独立幂等脚本，删卷重建时会自动执行；已在运行的库需手工执行该文件。
- 灌库坐标若还是武汉老坐标，预计到达时间会算出二十四小时并把订单全判为时间不可行，须刷成 `003` 定稿的南昌坐标。

**复跑命令**：compose 默认端口下为 `./gradlew build --no-build-cache --rerun-tasks`（MySQL 3306／Redis 6379／RabbitMQ 5672，零环境变量）。`3306` 被其他 MySQL 实例、`6379` 被其他 Redis 实例占用时，改用 `MYSQL_PORT=3307 REDIS_PORT=6380` 加同一条命令；被测代码路径一致，但**不声称两种口径等价**，实测记录见[《2026-11-06 卢肄文 预测专业化收尾》](../50-过程记录/2026-11-06-卢肄文-预测专业化收尾.md)第 7.2 节。

**端口冲突的两种表现**：MySQL 被占时报 `Access denied for user 'root'@'localhost'`，一跑就红，容易发现；Redis 被占时**不报任何错**——Windows 上精确 IP 绑定优先于 `0.0.0.0` 通配绑定，容器照常启动、`docker ps` 全绿，连接却静默落到原生 Redis 上。排查 Redis 侧问题前先 `netstat -ano | findstr ":6379"` 看监听方是不是 `redis-server` 而非 `com.docker.backend`。

**旧值作废说明**：上表「旧值」列的 97.74%、0.910、`c = 0.638` 出自「两顶点直线航道 ＋ `SpeedLimitLookup.unbounded()`」的 240 轮，不与生产装配同构（生产已配置 `0,2000,4.5;2000,4000,4.5;4000,5778.9,2.5` 分段限速）。按[《114 11-06任务清单》](../110-工程实施/114-11-06任务清单.md)第 7 节注意点第 3 条「受影响的实验结论」，原值保留并在此注明口径，不得再作为验收结论引用。

**一处必须先说清的陷阱**：把跑批起点放在 `[5000, 6000]` m 时，船已在航道末段，预测时域内先到终点饱和，生产限速与不限速两种 lookup 的最后一点都停在 6000.00 m，两批数值会连小数位完全相同。限速批次因此把起点改到 `[1000, 3000]` m 并配一组同起点的「限速窗口基线」对照组，差值才成为 −190.7 m。数值细节见[《78 阶段二仿真验收报告》](../50-过程记录/78-阶段二仿真验收报告.md)第 8.2.1 节。
