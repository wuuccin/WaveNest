## 3 共享文件与落点归属

七个人今天同时改同一个仓库，后端是多模块工程，真正的撞车点不在「同一个模块」，而在「同一个包、同一个文件」。这一节只回答一件事：**每块代码今天归谁独占**。

两条铁律：

**一、契约文件只能一个人动——吴可欣。** 三个帧被多处构造，谁改谁都要动全部构造点，分开改必冲突。

**二、分界划到包，不划到模块。** `wl-m2-dispatch` 今天三个人动三个包（`plan/`、`queue/`、`prediction/`），`wl-m4-monitor` 两个人动两个包（`alert`＋`detect`、`query`）——包不重叠就能同时改，包重叠必须一个人做完。

| 模块内的位置 | 谁动 | 分界 |
|---|---|---|
| `wl-contract` 三个帧、告警消息对象 | 吴可欣 | 别人不动 |
| `wl-app/push` 实时出口投影 | 吴可欣 | 别人不动 |
| `wl-m2-dispatch/plan` 编排器会面帧 | 吴可欣 | 不动 `queue/`、`prediction/` |
| `wl-m2-dispatch/queue` 队列侧会面帧 | 张睿哲 | 不动 `plan/`、`prediction/` |
| `wl-m2-dispatch/prediction` 预测链路与校验区间 | 卢肄文 | 不动 `plan/`、`queue/` |
| `wl-m3-rendezvous/solver` 会面点求解 | 罗才辉 | 别人不动 |
| `wl-m4-monitor/alert`、`detect` 告警组装与发送 | 宋冰鑫 | 不动 `query/` |
| `wl-m4-monitor/query` 回放投影 | 彭紫情（只改构造参数，一行） | 不动告警，不改回放逻辑 |
| `wl-m1-collector` 三个仿真器 | 杨添爻 | 别人不动 |
| `deploy/sql` | 张睿哲 | 别人不动 |
| `frontend` | 彭紫情 | 别人不动 |

**宋冰鑫的落点**：告警帧本身在 `wl-app/push` 由吴可欣构造，`AlertEventMessage` 在 `wl-contract` 由吴可欣扩字段——宋冰鑫只负责在 `alert/`、`detect/` 把位置与订单号**填进**这两个现成对象，不改它们的定义。这也正是他排在序号 2 的原因。

## 4 每人的具体做法、判据与边界

### 4.1 吴可欣 —— T1-1 三帧扩字段（最先做）

三帧现有字段与要补的东西：

| 帧 | 现有字段 | 要补 |
|---|---|---|
| 告警帧 | 告警类型、级别、目标、文案 | **位置（经纬度）、订单号、事件号** |
| 无人机状态帧 | 机号、经纬度、电量、阶段、时刻 | **航向、在飞订单号** |
| 会面点帧 | 订单号、会面经纬度、是否锁定 | **候选数、逐条淘汰原因、预计到达时刻** |

告警消息对象（消息队列里的那一个）现为九字段，**补经纬度**，其余不动。

- **做法**：三帧各加字段，**每个新字段都配一个保留旧参数的兼容构造器**——四处构造点分散在三个模块，直接改签名会当场编译不过，配了兼容构造器才能一处一处改完。字段类型与新值来源逐一对应，不新造同义类型。
- **判据**：全模块编译通过；契约守卫测试全绿（主题清单条数不变）；三个帧的 record 上能读到全部新字段。
- **边界**：**不动主题常量、不动消息转换器、不加新帧类型、不动告警类型与级别的枚举**。主题清单被守卫测试逐项钉死，加一条必红；转换器是全项目唯一 Jackson 转换器，新 record 自动映射，无需注册。
- 合入后立刻在群里发一句「契约已扩，可填值」，别让人等。

### 4.2 吴可欣 —— T1-2 实时出口投影填真值

- **做法**：实时出口的三处帧构造点改调新构造器并填真值；告警帧的位置从告警目标的当前状态取，取不到就留空——**不许造假坐标**。
- **判据**：订阅端收到的帧里新字段非空且取值正确。**编译通过不算完成。**
- **边界**：不改投影的订阅与转发逻辑，不改帧类型。

### 4.3 吴可欣 —— 编排器会面帧

- **做法**：编排器派单成功时发出的会面帧改调新构造器，候选数与淘汰原因取候选链已产出的结果（上轮已做好透出方法）。
- **判据**：派单成功时帧里候选数与淘汰原因都有值。
- **边界**：不改编排器的决策流程。

### 4.4 宋冰鑫 —— T1-3 告警发送侧补位置

- **做法**：告警记录与发布时，把告警目标的当前位置与所属订单号一并带上。
- **判据**：**偏航、失联两类各实测一次**，帧里位置非空。失联场景的坐标要格外确认——机已失联，位置只能取最后一次上报值，取不到就留空并写明"最后已知位置缺失"，不要用默认点。
- **边界**：不碰检测判据、不新增告警类型、不改路由键、不动组装层。

### 4.5 杨添爻 —— T1-4 仿真坐标与气象网格切南昌段

- **做法**：船、无人机、气象三处的**代码默认值**切到南昌段；无人机数量与张睿哲的机队规模对齐。
  - 船：起点在朝阳端，初航向朝上游（八一方向）。
  - 无人机：巡航中心设在航段内，半径缩到不越出江面。
  - 气象：网格原点随航段一起挪，**这条最容易漏**——只切船不切网格，风落在原来的地方，抗风淘汰无从触发。
- **判据**：**自己起 M1 看帧**，船位在航段一带；气象网格四点与航段同区；四架无人机都有遥测帧。看完在群里说一句"仿真已在南昌段发帧"，卢肄文的序号 3 才能开。
- **边界**：不改采集与清洗逻辑。**`application-m1-sim.yml` 这个文件从未被加载过**（激活的 profile 名与文件名不匹配），改它无效——今天只改代码默认值，不动 profile 机制；若发现该文件与实际值不一致，在群里说一声，别自己顺手改名。

### 4.6 张睿哲 —— T1-5 灌库四类

- **做法**：
  1. 两个机巢坐标改到航段两端（按总计划第五节已定的建议值）；
  2. 机队重配为四架，两巢各有可用机、抗风两档、载重三档，编号与仿真器口径一致（否则会出现"没有遥测的幽灵机"）；
  3. 三座桥梁入空域限制表——**`scope` 字段是自由文本，没有格式约束，先定一种可解析的写法再灌**，定完在群里说一句，后面谁都按这个格式写；
  4. 熔断阈值上调到高于最高机型抗风上限。
- **判据**：**先在自己机器上重灌一遍确认改动真生效**。灌库只有一个动作：`deploy/sql` 是数据库容器的初始化脚本，只在空数据卷时执行，卷已存在时 `up -d` 不会重跑；三份脚本又都是纯 INSERT、零 `DELETE`，手工重跑单个文件会主键冲突。所以只能 `docker compose down -v && docker compose up -d` 删卷重建——它会清掉本机库里的订单与日志，**动手前看一眼有没有要留的**。重灌后查库确认——机巢在航段两端；两巢各有可用机且抗风有档差；三桥有记录且 `scope` 能解析；熔断阈值大于最高抗风上限；**中文状态词不乱码**（乱码会让候选链一个无人机都查不到）。灌通后群里说一句，罗才辉的序号 3 才能开。
- **边界**：不改表结构（初始化脚本不动）；机巢的支持机型字段要跟兵配同步改，否则台账上会出现"只支持某机型却停着另一机型"的矛盾。
- **他人的前提不在你这**：罗才辉要验会面点，得在**他自己机器上**也重灌一次（每人连本机库，卷不共享）。你只需保证 SQL 灌通、格式定死、群里通知。

### 4.7 张睿哲 —— T1-6 队列侧会面帧

- **做法**：队列侧发出的会面帧改调新构造器，填候选数与淘汰原因。
- **判据**：入队等待的订单，其会面帧带得出为什么是这几架候选。
- **边界**：不动编排器（那处归组长）。

### 4.8 罗才辉 —— T1-7 会面点随新机巢重算

- **序号**：3，等张睿哲 T1-5 灌通并在群里通知。
- **前置**：**你自己机器上也要重灌一次**——每人连本机库，卷不共享，别人灌通不等于你库里有新坐标。只执行 `up` 不生效，必须先删卷再起（具体命令见 §4.6 张睿哲一节的判据）。
- **做法**：机巢坐标落库后，验证会面点确实随新机巢重算，而不是仍在旧位置。
- **判据**：
  1. 会面点落在航段经纬度范围内，**不落在岸上或江心洲上**；
  2. 从两巢各算一次，会面点到两巢的距离有明显差异（体现候选比较）；
  3. 若某处断言把旧坐标钉死了，一并改掉。
- **边界**：不改会面点求解算法本身。

### 4.9 卢肄文 —— T1-8 预测链路与校验区间

- **序号**：3，等仿真在南昌段真的发出帧。**下面的两步都是你自己一个人在同一天做，不拆成两个序号**——但顺序不能反：先跑通，再收窄。
- **做法**：
  1. **先跑通**——确认预测链路在航段上能正常出帧，此步只验不改；
  2. **再收窄**——把预测的地理校验区间从「原仿真域与航段取并集」收窄到航段；收窄走配置项，不改判定逻辑（该配置项现为空，走的是并集默认值）。
     宁可等，也不抢：先收窄、后切坐标的后果是每帧被自己的校验拦下、静默回落匀速版，看起来像「切了等于没切」。
- **判据**：对上两步各一条——
  1. 跑通：主故事预测帧在航段上正常出帧；
  2. 收窄：主故事预测帧**不被拦**；同时故意喂一个航段外的坐标（例如原仿真点），**必须被拦下**——这条是证明校验网真在工作的唯一办法。
- **边界**：不改校验的判定逻辑与阈值；不改预测引擎。

### 4.10 彭紫情 —— T1-9 底图与坐标系

  2. 初始视野锁到航段，不再用现在的默认中心点；

- **判据**：影像可见、三座桥肉眼可辨；船、机巢压在真实江面上**无偏移**。偏移是这一步唯一要盯的东西——转换错了，后面所有图层都白画。
