## 2 顺序与纪律

### 2.1 顺序

序号 1 的七人并行，各人文件不重叠。交界处先对齐再动手：

- 吴可欣与卢肄文：误差样本由吴可欣在引擎内计算残差并暴露按船号取样本的出口，卢肄文在服务层消费。
- 张睿哲与杨添爻：看台接口的字段名、分页参数与错误码由张睿哲在合并请求描述里先定。
- 卢肄文的预测帧补船号是看台的前提，优先合入。
- 吴可欣与宋冰鑫：投放回执推进脱离返航，状态名与流转顺序由吴可欣在合并请求描述里先定。
- 罗才辉与彭紫情：罗才辉写航迹摘要事件需改任务日志记录器签名时，先与彭紫情对齐。
- 卢肄文与彭紫情：幂等守卫加在派发触发器一侧，卢肄文不动该文件。
- 张睿哲与罗才辉：重调度服务调用派单队列的条件更新入口，由张睿哲在派单队列一侧定。
- 彭紫情与罗才辉：罗才辉完成起飞时刻改名为会面时刻之后，彭紫情再引用该字段。

序号 2 的前提是阶段二的真航道中心线、前提监测与回流校准三项已合入 `develop`。序号 3 的前提是序号 1 与序号 2 全部合入 `develop`。

灌库、起服务与跑测试属各自作者自验，不占任务序号。

### 2.2 通用纪律

- 阈值取配置或脚本参数，不硬编；键名与取值写进合并请求描述。
- 改表须组长确认，涉及误差样本表、中心线表与计划航迹表。`deploy/sql` 只在空数据卷执行一次，新增脚本后须删卷重建才建表。
- M2 到 M3 只调会面门面，M2 侧不出现航迹生成器的静态调用。
- 合并请求的基线必须是 `develop`，不是 `main`。构建只用仓库 Wrapper。
- 坐标口径：NEST-01 为 `115.8480/28.6420`，NEST-02 为 `115.8670/28.6980`，船起点为 `115.8611/28.6660`；三座桥为 `115.852/28.646`、`115.859/28.663`、`115.879/28.692`。机巢库若仍是 `114.305/30.605` 的老值，预计到达时间会全判为时间不可行。
- 验证产物不进仓库，含脚本、实验数据与截图，只把数字写进合并请求描述。

## 3 各人具体

### 3.1 吴可欣：投放信号、真航道中心线、前提监测引擎侧与预测专业化收口

独占范围：`wl-contract` 的主题名与投放回执记录、投放回执消费端、精算预测引擎及其配置与档位类、中心线新增类与数据文件。

#### 3.1.1 投放成功信号

做法：

1. 在契约模块的主题名里新增 `data.uav.delivery` 并加入主题集合，同时新增投放回执记录，字段为任务标识、订单标识、无人机标识、时刻与结果。
2. M1 仿真按需发布该主题，真实环境由飞控或投放装置上报。
3. M2 消费回执：结果为成功则推进脱离返航，结果为失败则走返航复核。
4. 回执去重键取任务标识、无人机标识与时刻三者。
5. 超时兜底新增系统参数键 `deliveryReceiptTimeoutSec`，不复用交接时长下界 `tHandoverMinSec`。键名与取值写进合并请求描述。

判据：收到回执即脱离返航，不等超时；无回执按超时判失败；重复回执不重复推进。

#### 3.1.2 真航道中心线

做法：

1. 补中心线顶点。现有权威锚点只有朝阳、南昌、八一三点，五点七八公里的航段上三点过稀，按每点不超过五百米加密到十二点以上。
2. 精算引擎建立几何的输入从本船实测轨迹窗改为中心线顶点，实测轨迹只作投影输入。几何类已有投影、取点与取走向三个方法，几何算法不新写。
3. 数据落点二选一，并在合并请求描述里写明：新建中心线表，或写入装配配置的预测中心线键。选建表须经组长确认。

判据：同一条 AIS 序列同一时刻，参考线对中心线垂距不超过走廊半宽；预测点列对中心线垂距不超过三百米。

#### 3.1.3 前提监测引擎侧

做法：

1. 船舶状态持有前提监测器实例，参考线建立时锁定参考走向。
2. 每拍以观测对象调用监测方法，取结论状态码写入快照的前提字段。该字段已存在，不改契约模块与推送帧。纵向速度取 AIS 对地航速，无航速时用相邻观测点位移除以间隔估算。
3. 评估结果要求重锚时，按既有重锚路径重建参考线。
4. 向卢肄文提供误差样本出口：在观测应用处按实测点与预测点之差计算纵向与横向残差，暴露按船号取样本的方法，供服务层喂校准器。

判据：船掉头、进锚地或大幅偏航时，前提状态不再恒为有效，并输出对应原因码。

#### 3.1.4 预测专业化收口

做法：按 `80-A组算法方案` §3.2 的退化清单逐条核对，真航道中心线、前提监测与回流校准覆盖的部分不重复做，其余补齐，重点是分段限速，当前引擎只有单一航速参数。核对结果写进合并请求描述。

判据：退化项逐条有实现，或写明不做的理由；分段限速在多区段航线上给出实际生效的速度序列。

### 3.2 卢肄文：回流校准

独占范围：预测服务与快照、轨迹快照适配器、预测校验、预测更新事件、重算请求与重算接口及其日志实现、两个校准器、新增灌库脚本。

做法：

1. 新建误差样本表脚本，字段含船号、预测版本、预测时域、纵向误差、横向误差、航向误差与样本时刻，字段口径写进合并请求描述；改表须经组长确认。
2. 校准器接线：样本取吴可欣暴露的残差出口。残差校准器累加纵向与横向残差及两个方向的标准差，结果带样本数、平均误差与校准系数，快照的校准系数取该值。偏差校准器累加样本，建议值按时间桶与速度桶返回，并回写系统参数。
3. 硬约束：残差校准器要求样本数不少于二百，置信宽度不超过零点一五；样本不足或置信宽度超限时校准结果不可用。
4. 校准系数、偏差值与标准化残差序列写入快照，字段已存在，只填值，经预测帧透出。

判据：跑一批 AIS 后误差样本表有行；系统参数的标定参数被更新；快照的校准系数非空。

| 修复位置 | 改成什么 |
|---|---|
| 预测快照的帧转换 | 帧转换带上船号，这是看台按船聚合的前提 |

| 会面帧投影器的候选列表 | 候选列表加空值守卫 |
| 候选服务的生成路径 | 生成并判定不再绕过本类生成方法 |

### 3.5 彭紫情：蒙特卡洛、动态会面验证与派发触发器

独占范围：派发触发器、任务日志记录器、监控控制器与查询服务、监控聚合器、验证脚本与对比实验测试类。

#### 3.5.1 蒙特卡洛样本量

做法：把闭环精度测试的四十轮加到能给出可信区间的量级，并使用多个随机种子，输出点估计与置信区间。样本量须满足残差校准器的采信门槛，即样本不少于二百、置信宽度不超过零点一五。种子策略写进合并请求描述，数据不进仓库。

判据：给出轮数、种子数、指标点估计与置信区间，并说明是否满足校准器采信门槛。

#### 3.5.2 动态会面验证

做法：

1. 构造扰动场景：船速阶跃、航向跳变不小于二十度、AIS 丢帧、风况突变四类，每类轻中重三档，共十二组。
2. 同场景跑两遍，一遍用动态会面求解，一遍用固定会面点，对比会面误差、船等待时间与无人机能耗。
3. 落点：在调度模块新建对比测试类，端到端走本模块派发链。会面求解器的测试与会面重算测试只读参考，不改会面模块生产代码；确需改会面模块测试文件，先告知罗才辉。
4. 会面参数取值口径与罗才辉的航迹接入一致。

判据：十二组动态与静态对比表齐备，每组三列指标与差值，并写明动态会面在哪些档位失效。

#### 3.5.3 评审修复项

| 修复位置 | 改成什么 |
|---|---|
| 派发触发器的异常重抛 | 重抛与失败仅记日志、不阻断下单响应的契约对齐 |
| 派发触发器的数值构造 | 构造十进制数前拦 NaN 与正负无穷 |
| 派发触发器的时区 | 统一用固定东八区常量 |

### 3.6 宋冰鑫：迫停他巢、是否已交付区分与迫降野外订单状态

独占范围：返航服务与输入装配器、返航决策事件、占位槽服务、告警驱动调度器、气象解除唤醒器。

做法：

1. 迫停他巢：占位槽服务补尝试占位方法，先判容量与时隙冲突再写入，占位单向不可逆，冲突判定与插入一并改条件插入。返航服务的三个下游接实：准入通过则锁占位槽，不通过则顺延次优候选，仍不行则降级迫降野外；返航航迹经会面门面生成并精算电量；返航指令下发并按监控模块的口径编码。
2. 是否已交付区分：返航服务按货物在机分流。货物不在机的已交付情形只处理无人机，不动订单；货物在机的未交付情形走货物回收与订单失败。
3. 迫降野外订单状态：判定为迫降野外且货物在机时，订单状态写为失败，写任务日志并标记待人工回收；缺迫降点标识时沿用现有警告语义，不由本组代出迫降点。

判据：空机迫降时订单保持已完成；有货迫降时订单为失败，且可被人工回收流程拾取；迫停他巢时占位记录、返航航迹与返航指令各一条。

| 修复位置 | 改成什么 |
|---|---|
| 返航服务的三级判定 | 改用带候选台账的重载，不再用三参版本 |
| 占位槽服务的参数校验 | 起止时刻、对象类型与对象标识补参数与区间校验 |
| 占位槽服务的冲突插入 | 先查冲突再插入改为条件插入 |
| 返航服务的决策完整性 | 缺目标标识时返回不完整结论，不落执行 |
| 占位槽服务的释放 | 未知或已释放的占位标识不再静默成功 |
| 占位槽服务的冲突判定 | 补时间维度 |
| 返航输入装配器的电量 | 非低电量告警，尤其失联，不再复用电池值 |
| 返航输入装配器的风向 | 风向非有限值走校验 |
| 返航输入装配器的判空 | 订单与消息解引用前判空 |
| 返航决策事件的构造器 | 构造器强制不变量 |
| 返航输入装配器的裕度取值 | 电量保留比例只取一次 |
| 返航输入装配器的位置构造 | 位置构造改具名 |
| 返航决策事件的占位标志 | 是否需要占位由判定级别派生 |
| 告警驱动调度器的反序列化 | 反序列化失败也走单条坏消息不中断队列 |
| 告警驱动调度器的兜底捕获 | 兜底捕获带上异常对象 |
| 告警驱动调度器的注入与查机 | 飞行阶段推进器改为必填注入，空分支删除或加注释；复核只用消息里的机号查无人机，而返航处理下一行才取订单机号，告警只带订单号不带机号时查不到无人机，一并修正 |
| 气象解除唤醒器的积压查询 | 积压查询加分页与排序 |
| 返航服务的注释 | 注释与待他巢台账的现实对齐 |
| 占位槽服务的标识 | 占位标识改完整全局唯一标识或加前缀 |
| 气象解除唤醒器的轮询间隔 | 轮询间隔钳制为正数 |
| 告警驱动调度器的操作类型 | 操作类型走枚举映射 |

### 3.7 罗才辉：航迹接入与编排、会面求解、构建配置

独占范围：调度编排器、会面协调器、订单回退命令、构建脚本、航迹新增类。

做法：

1. 调度编排器求得会面方案后装配任务航迹命令，字段含组合、航线、机巢经纬度、会面点、交接终点、返航目标、巡航高度、三段速度、起飞时刻与每段航点数。
2. 新增任务航迹装配器，负责机巢坐标、会面点、交接终点、返航目标即原巢、巡航高度、速度与起飞时刻。
3. 三段航迹经会面门面生成，去程为机巢到会面点，末段为会面点到交接终点，返程为交接终点到原巢。M2 侧不直接调航迹生成器静态方法。
4. 航迹广播前端，任务日志记一条摘要事件，操作类型写进合并请求描述。计划航迹的持久化载体由组长裁定，因为任务日志没有航迹字段，飞行点表只记实际飞行点。
5. 起飞时刻等于会面时刻减去去程时长。会面方案里的起飞时刻字段实际装的是会面时刻，先改名为会面时刻，任务航迹命令的起飞时刻另按去程时长计算。

判据：派发后可查三段航迹，前端按段着色；派发完成的订单状态仍为已派发。

| 修复位置 | 改成什么 |
|---|---|
| 调度编排器的会面点回写 | 改前重读最新实体，或改用只更新会面点两列的定点更新 |
| 调度编排器的订单查询 | 查询结果判空，抛与派单队列一致的订单不存在异常 |
| 会面协调器的气象调用 | 外部调用兜住运行时异常，回落系统参数的静态风况并记警告 |
| 会面协调器的风况构造 | 构造风况前对风速与风向做有限性与范围净化，风向归一到正负三百六十度 |
| 会面协调器的时刻字段 | 起飞时刻更名为会面时刻，命名遗留写进参数说明 |
| 订单回退命令的构造器 | 补全跨字段不变式 |
| 构建脚本的公开签名 | 公开签名不暴露会面模块类型，改走契约或门面 |
| 构建脚本的依赖集合 | 公共依赖集合收敛 |
| 调度编排器的状态断言 | 精确断言已受理待唤醒，其它状态直接抛异常 |
| 调度编排器的候选选择器字段 | 删除多余字段与构造参数，含赋值 |
| 会面协调器的时区 | 时区改用固定常量 |
| 订单回退命令的构造方式 | 七参位置构造改具名或构造器模式 |
