## 5 注意点

| 注意点的名称 | 判据与处置的说明 |
| --- | --- |
| 指标的性质 | [106-演示基准值台账](../100-工程实施/106-演示基准值台账.md) 第 7.5 节的 96.01%／99.05% 与 `c = 0.874` 与本批次的四项指标同为仿真内闭环的自洽性指标，不是外部有效性的证据；一律标 `simulation_closed_loop` 的档，对外写「仿真内闭环的指标」，禁写「实测的覆盖率」与「赣江的实测」；分级与分栏见接口约定第 13 节 |
| 设计的假设 | 接口约定第 13 节列出的自造值一律标 `design_assumption` 的档，其中末段的 2.5 m/s 限速不得写成赣江桥区的实际限速；中心线 v3 的十三点标 `measured` 的档，与自造的值分开标注 |
| 真实数据的用途 | 只取统计的量做独立的校核：航速的分位、报位间隔的分布、横向摆动的量级与风速的幅度；禁逐点的拟合、禁拿真实的数据回写 `sys_param` 的键、禁把带噪的 AIS 观测当 `truth.csv` 的真值；真实的 AIS 无真值且内河的报位间隔不均，固定的 1 Hz 与零均值的高斯噪声属理想化的处理，指标的报告写明 |
| 赣江真实依据的边界 | 影像的河心十三点是可追溯的真实几何；海事局的限速通告与南昌桥区的水域范围只作量级的参照，江豚的活动区与朝阳至八一航段的重叠关系未核实不作取值的依据；FVessel、MarineCadastre 与长江的 AIS 论文均非赣江，不得写成「赣江的实测」；政务执法的平台非公开的数据集，不得列为数据的来源；可用与禁用的来源见接口约定第 13 节 |
| 未补齐项与场景的口径 | [73-赣江场景说明](../50-过程记录/73-赣江场景说明.md) 第 7 节的三桥的净空、桥墩的开口、机巢的坐标与坐标的基准仍为「待核实／待配置」的状态，未补齐之前不得声称已验证桥梁净空的路径规划或真实机巢选址下的可达性；`005_ship_ais_track.sql` 的脚本只补表的结构无 INSERT 的数据，仓库内无真实的历史 AIS 数据；该说明允许仿真或半合成的数据生成，本批次的合法性不缺、须补来源的标注与证据的分级 |
| 参数来源的标注 | 每个的 `scenario.yaml` 与 `manifest.json` 必须带 `param_sources` 并覆盖接口约定第 13 节的全部参数；未标注的一律按 `design_assumption` 的档计并由 `validate_scenario.py` 报 FAIL 的结果 |
| 排期的安排 | 按组长 2026-11-09 的裁定，六段的同时开工、段间无先后、不设 reviewer、不设汇合的复跑，2026-11-10 由吴可欣统一验收；《76-任务分配顺序规范》的本身不改 |
| 组长的角色 | 吴可欣的两天只调系统，1× 的实时 30 min 全程属调系统的自验，不占任务号、不产 `testdata/mock/` 的交付物、不提 PR、不列入文件的独占；其指标的结果只作为 2026-11-10 的验收依据；六名的组员各产出一套的模拟数据 |
| 模块间的交互 | 六段只通过接口约定第 5 节与第 6 节的文件产物交互：`run_scenarios.py` 的脚本读 `truth.csv` 的文件、写 `metrics.json` 与 `manifest.json` 的文件，不 import 他人未完成的实现类；实现的方不得就地改契约的取值 |
| 基线与 develop 的分支 | 所有 PR 的 base 写 `baseline/v3-1109`，不写 commit 的 SHA；数据的分支不合 develop 的分支 |
| 灌库的方式 | `016_centerline_v3.sql` 与 `004_seed_airspace.sql` 的脚本均为 `INSERT ... ON DUPLICATE KEY UPDATE` 的幂等脚本，已有的数据卷可直接手工执行；禁止 `docker compose down -v` 的命令；各组员各自使用自己的数据卷，不得操作组长正在使用的数据库 |
| 真值的口径 | 真值一律按限速积分的口径；`normal` 的家族按接口约定第 2 节的三段值，超速的家族用独立的 `speed_profile`；不得用 4.12 的恒定值当真值；`err_along_m` 与 `err_cross_m` 的误差对无噪的真值算 |
| 945 s 包络的边界 | 30 min 的全程必然跨过该边界；按接口约定第 7 节的分段统计并标注 `bbox_fallback_samples`，不改 `prediction.bbox` 与 `horizonSec` 的取值 |
| τ 的覆盖 | 调系统自验的 30 min 覆盖全网格；200 seeds 的 20 min 子段只统计 τ ≤ 1200 的样本，不得补造 τ = 1800 的样本 |
| 生产的时基 | 不改生产的 `clock`、不压 `tick-millis` 的取值；离线的跑批走接口约定第 10 节的夹具；只有测试的缝不足时才提「最小 Clock 注入、默认 System」的单独 PR 并单独批准 |
| `sys_param` 的回写 | 离线夹具的第三参传 `null` 的值；发现校准建议的键即为夹具装配的错误 |
| 复跑的去重 | 同 seed 加同 `pred_version` 的取值会撞 `uk_pes_pair` 与 `consumedUpToTs` 的唯一键与水位；2026-11-10 的复跑之前先清表或换 `pred_version`／`sample_ts` 的新值，README 写明；不得把「行数的不增」判为实现缺陷 |
| 文件的独占 | 同一的文件只有一个 owner：罗才辉的 `testdata/mock/truth/`、卢肄文的离线夹具测试类、彭紫情的 `testdata/mock/metrics.py`、宋冰鑫的 `testdata/mock/run_scenarios.py`、杨添爻的 `testdata/mock/scenarios/` 与 `testdata/mock/replay/`、张睿哲的 `testdata/mock/validate_scenario.py`；`.gitignore` 由发清单之前一次性加入，其余的人不得修改；吴可欣不设交付的目录 |
| 非代码的文件 | `scenario.yaml`、`manifest.json`、指标的报告与 `sample/` 的目录属非代码的文件，2026-11-10 由吴可欣逐文件的点批之后合入；全量的产物只写 `testdata/mock/_generated/` 不进 PR 的范围 |
| 演示与验收的分离 | 一套的 replay 只做演示，不写进验收的台账；不得把演示的数据当验收的数据 |
| 文档的自检 | 个人区的文档纯 LF；`docs/` 的文档纯 CRLF；表格的列数一致；禁用指向性的简写；禁用盘符的绝对路径、用户名、个人的目录名与以个人环境为主语的结论；交付之前跑环境专属信息的扫描零命中 |
