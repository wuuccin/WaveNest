- 真值一律按限速积分的口径生成；`normal` 家族的取值按 4.5／4.5／2.5 的三段值走，超速的家族使用独立的 `speed_profile`，不得用 4.12 的恒定值当真值。
- 要覆盖桥并做会面闭环的验证，用 30 min 的全称、s = 0 的起点；只做预测误差的核对、不要求到桥的验证，用 20 min 的子段、s = 1000 的起点与约 5333.3 m 的终点。
- 不得修改 `prediction.bbox` 与 `horizonSec` 的取值；945 s 之后的预测包络的回退按第 7 节的分段统计口径处理。

## 5 run_scenarios.py 的接口签名

```text
python run_scenarios.py --scenario <path> --mode <live|offline> --seed <int> --out <dir>
```

该脚本的职责只有两项：编排 run 的流程、汇总指标的数值；它不生成 CSV 的全量数据集，不是每人一份的生成器。脚本的产物是 `<out>/manifest.json`、`<out>/truth.csv`、`<out>/metrics.json` 与 `<out>/sample/` 的四类文件。全量的产物写 `testdata/mock/_generated/<family>-<seed>/` 的目录，不进 PR 的范围。六段之间只通过第 5 节与第 6 节定义的文件产物交互：`run_scenarios.py` 的脚本读 `truth.csv` 的文件、写 `metrics.json` 与 `manifest.json` 的文件，不 import 他人未完成的实现类。

metrics.json 的字段如下。

| 字段 | 单位 | 定义 |
|---|---|---|
| `nrmse_along` | 无量纲 | `sqrt(mean((err_along_m / sigma_along_m)^2))` 的纵向归一化均方根误差 |
| `nrmse_cross` | 无量纲 | `sqrt(mean((err_cross_m / sigma_cross_m)^2))` 的横向归一化均方根误差 |
| `coverage_2sigma_along` | 比例 | `\|err_along_m\| <= 2 * sigma_along_m` 的样本占比 |
| `coverage_2sigma_cross` | 比例 | `\|err_cross_m\| <= 2 * sigma_cross_m` 的样本占比 |
| `nees` | 无量纲 | `mean(err_along_m^2 / sigma_along_m^2 + err_cross_m^2 / sigma_cross_m^2)` 的归一化估计误差平方均值 |
| `meet_error_m` | m | 预测的会面点与无噪真值的会面点之间的大地距离 |
| `tau_grid_sec` | s 数组 | 本次实际配对的 τ 网格的取值 |
| `bbox_fallback_samples` | 行 | 945 s 之后进入包络回退段的样本行数 |
| `rows_pred_error_sample` | 行 | 本次 run 的落库行数 |
| `evidence_class` | 无量纲 | `simulation_closed_loop`／`externally_anchored` 的两值，本批次固定前者的取值，见第 13 节 |
| `by_evidence_class` | 对象 | 按 `evidence_class` 的分栏统计的四项指标，两栏不得合并出 NEES 或 2σ 的覆盖 |

本批次不设指标的阈值，只要求以上的四项指标可计算且非空；阈值的数值随测随补进 [106-演示基准值台账](../100-工程实施/106-演示基准值台账.md) 的台账。

## 6 真值轨迹 truth.csv

```text
ts_ms,s_m,lon,lat,sog_ms,cog_deg
```

该文件由限速积分的口径生成，是无噪的真值轨迹，`lon` 与 `lat` 的取值为 WGS-84 的度。`err_along_m` 与 `err_cross_m` 的误差一律对这张表的真值算，不对带噪的 AIS 观测算。带噪的观测只作为 `PrecisePredictionEngine.predict(AisMessage)` 的输入。

本节的表格给出正常预测段与包络回退段的统计口径。

| 段 | 范围 | 统计的口径 |
|---|---|---|

## 8 WS 与状态的契约

| 项 | 取值 |
|---|---|
| 统一的信封 | `WsEnvelope` 的类，字段为 `type` 与 `data`；不写 `payload` 的字段，顶层不写 `ts` 的字段 |
| 帧的类型 | `WsFrameType` 的六类固定值：`ship_traj`／`drone_state`／`rendezvous`／`alarm`／`order_state`／`plan_track` |
| 订单的状态 | 中文的 `OrderStatus.getValue()` 的取值，终态为 `FINISHED` 的中文「已完成」，不写 `COMPLETED` 的英文值 |
| 等待的原因 | `WaitReason.WAIT_CARGO` 的取值不进 `orderTimeline` 的列表 |
| `expected` 的字段 | 状态的序列一律用中文的状态词 |
| `ws_frames` 的用途 | 只做前端的回放，不承担算法的验收 |

## 9 复跑与去重的规则

| 约束 | 规则 |
|---|---|
| 唯一的键 | `uk_pes_pair (ship_mmsi, pred_version, tau_sec, sample_ts)` 的四字段组合 |
| 水位的限制 | `PredictionCalibrationService` 的 `consumedUpToTs` 的取值，同 seed 的复跑会撞唯一键或水位，`inserted = 0` 的结果 |
| 2026-11-10 的复跑之前 | 先清 `pred_error_sample` 中该 run 的行，或换 `pred_version`／`sample_ts` 的新值 |
| README 的内容 | 必须写明清表的 SQL 或换号的命令、固定的 seed、`baseline_commit` 与 `tick_millis` 的取值 |
| 禁止的判断 | 不得把「复跑后的行数不增」的现象判为实现缺陷 |

## 10 离线夹具的约束

| 项 | 约束 |
|---|---|
| 生产时钟的处理 | 不改生产的 `clock`，不压 `tick-millis` 的取值；`PredictionService.clock` 保持 `System::currentTimeMillis` 的实现 |
| 离线路径的写法 | 直接构造 `AisMessage(mmsi, shipName, lon, lat, sog, cog, ts)` 的对象喂 `PrecisePredictionEngine.predict(AisMessage)` 的方法，再取 `residualSamplesOf(mmsi)` 的结果 |
| 落库装配的写法 | `PredictionCalibrationService.forTesting(source, sampleMapper, null)` 的调用；第三参传 `null` 的值跳过 `sys_param` 的回写，依据是 `PredictionCalibrationService:528` 与 `:552` 的空值守卫 |
| 包路径的约定 | 夹具类放 `com.waterlogistics.dispatch.prediction` 的包（`forTesting` 的方法为包级的可见性） |
| 数据隔离的写法 | MMSI 用 `T` 前缀加 seed 的写法；`finally` 的块里清理本 run 写入的行 |
| 时间推进的写法 | 用 `calibrateIfDue(mmsi, virtualNowMs)` 的方法显式传虚拟的时刻，或调用 `calibrate(mmsi)` 的方法不节流；不经过 `CollectionScheduler` 与 `@Scheduled` 的调度 |
| 测试缝不足时的处理 | 才提「最小 Clock 注入、默认 System」的单独 PR 并单独批准；本批次的默认不需要 |

## 12 失败的判据与处置

| 现象 | 判据 | 处置 |
|---|---|---|
| `pred_error_sample` 的 0 行 | Live E2E 结束时 `SELECT COUNT(*)` = 0 的结果 | 先核第 10 节的离线路径与夹具的装配，再核 `ResidualSampleSource` 的装配；不得直接改生产的 `clock` |
| 包络的回退 | `bbox_fallback_samples` > 0 的数值 | 按第 7 节的分段统计口径统计，不改 Bbox 与 `horizonSec` 的取值 |
| 全部被唯一键挡 | `duplicated` > 0 且 `inserted` = 0 的结果 | 按第 9 节的规则清表或换 `pred_version` 的新值 |
| `sys_param` 的被回写 | 出现校准建议的键 | 夹具的第三参改传 `null` 的值 |
| 真值的越界 | `truth.csv` 的 `s_m` > 6003.3510 的数值 | 按第 2 节的限速积分重算，禁止用 4.12 的恒定值 |
| 时基的不一致 | 离线的 `sample_ts` 与虚拟的 `ts` 不同步的现象 | 用第 10 节的夹具，不压 `tick-millis` 的取值 |

## 13 数据来源与效度的标注

| 项 | 取值 |
|---|---|
| `param_sources` 的结构 | `map<string,string>` 的类型，键为参数的名称，值为来源的档位 |
| 来源的三值 | `measured`（实测或影像放样可追溯的值）／`standard`（公开的规章、规范或已发表统计的值）／`design_assumption`（为自证功能或演示的设定值） |
| 必须标注的参数 | `sog_ms`、`speed_limits_ms`、`speed_profile`、`noise_deg`、`sigmaEM`、`tauESec`、`alphaAlongMs`、风突变的幅度、`tick_millis`、`path_start_m`、中心线的十三点 |
| 未标注的处置 | 一律按 `design_assumption` 的档位计，`validate_scenario.py` 的脚本报 FAIL 的结果 |
| `evidence_class` 的取值 | `simulation_closed_loop`（仿真内闭环的自洽性指标，本批次的固定值）／`externally_anchored`（外部锚定的验证集指标） |
| 指标报告的分栏 | 按 `evidence_class` 的取值分「外部锚定族／设计假设族」的两栏；两栏不得合并出一个 2σ 的覆盖或 NEES 的数值 |

必须标 `design_assumption` 的参数，出处见下表的说明，不得改标。

| 参数 | 当前的值 | 出处 |
|---|---|---|
| `speed_limits_ms` 的末段限速 | 2.5 m/s | `application.yml` 的注释「只有这样才能自证限速确实生效」；不得写成赣江桥区的实际限速 |
| `noise_deg` 的取值 | 0.00005 度 | `SimAisConnector` 的 `@Value` 的默认值，无 AIS 误差模型的出处 |
| `sigmaEM` 的取值 | 15 m | `deploy/sql/002_sys_param.sql` 的头注「初始建议值（登记口径）」 |
| `tauESec` 的取值 | 120 s | `deploy/sql/002_sys_param.sql` 的头注「初始建议值（登记口径）」 |
| `alphaAlongMs` 的取值 | 0.10 | `deploy/sql/002_sys_param.sql` 的头注「初始建议值（登记口径）」 |
| 风突变的幅度 | 六家族的自定值 | `deploy/sql/002_sys_param.sql` 的头注「尚无上游风况分布可依」 |

本节的规则如下。

- `sog_ms` 的 4.12 m/s（8 节）同为 `SimAisConnector` 的设定默认值，标 `design_assumption` 的档位；旧的注释称「实测的 sog」属内部的沿用口径，不得据此写成赣江的实测航速。
- 中心线 v3 的十三点标 `measured` 的档位：`deploy/sql/016_centerline_v3.sql` 的头注为 2026-11-09 的天地图影像河心重取（WGS-84 的坐标），全长为 6003.3510 m；影像的放样可追溯，与上面的六项自造值分开标注。
- [106-演示基准值台账](../100-工程实施/106-演示基准值台账.md) 的第 7.5 节的 2σ 覆盖 96.01%／99.05% 与标定因子的 `c = 0.874` 同为仿真内闭环的值；本批次的四项指标一律标 `simulation_closed_loop` 的档位。对外统一写「仿真内闭环的指标」，禁写「实测的覆盖率」与「赣江的实测」。
- 真实的 AIS 只取统计量做独立的校核：航速的分位、报位间隔的分布、横向摆动的量级、风速的幅度。禁止逐点的拟合、禁止拿真实的数据回写 `sys_param` 的键、禁止把带噪的 AIS 观测当 `truth.csv` 的真值。真实的 AIS 只有带噪的观测、无真值；内河的 AIS 普遍缺报、报位的间隔不均匀、航速不服从特定的分布，本批次的固定 1 Hz 与零均值的高斯噪声属理想化的处理，须在指标的报告写明。
- 可借用的公开统计来源：FVessel（长江的武汉段，视频与 AIS 的数据，需机构的邮箱申请）、MarineCadastre（美国的 2009 至 2017 年的历史 AIS，1 分钟的间隔）、国内的长江 AIS 航速与轨迹预处理的论文。三者的来源均非赣江，只能借统计的特征，不得写成「赣江的实测」。南昌市的船舶动态安全监管平台为政务执法的系统、非公开的数据集，不得列为数据的来源。
- 赣江规章的量级：中华人民共和国海事局的《关于赣江南昌段江豚活动区限制航速及禁止锚泊的航行通告》规定船速小于 15 km/h、交会小于 10 km/h；南昌的桥区水域为桥上游的 400 m 与下游的 200 m，18 座的桥含朝阳、南昌、八一，桥区内的禁止淌航、掉头、横越、追越与并列的航行。江豚活动区的范围与朝阳至八一航段的重叠关系未核实，只作量级的参照，不作取值的依据。
- [73-赣江场景说明](../50-过程记录/73-赣江场景说明.md) 的第 7 节的三桥桥下净空的高度、桥墩开口的位置与宽度、两岸机巢的坐标、坐标的基准仍为「待核实／待配置」的状态；未补齐之前不得声称已验证桥梁净空的路径规划或真实机巢选址下的可达性。`deploy/sql/005_ship_ais_track.sql` 的脚本只补表的结构、无 INSERT 的数据，仓库内无真实的历史 AIS 数据。
- [73-赣江场景说明](../50-过程记录/73-赣江场景说明.md) 允许「场景中的船舶、无人机、货物、天气和任务的时间均可采用仿真或半合成的数据生成」，并写明「不代表系统已经完成真实水面的运营」；本批次按半合成的口径执行，每个的产物必须带 `param_sources` 与 `evidence_class` 的标注。
