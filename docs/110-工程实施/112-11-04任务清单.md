## 7 注意点

1. 阈值取配置或脚本参数，不硬编；键名与取值写进 PR 描述。
2. `007` 已建表，复核不改结构；确需改表时走组长批准。
3. 每条任务合并前 PR 的 base 是 `develop`；合并后由验收人复核 `git show --name-only` 无文档夹带。
4. 现场验证需要 MySQL、RabbitMQ、Redis、Mosquitto 四件套，起库步骤见 `41-运行环境说明`。
5. 构建只用 Wrapper，复跑命令固定为 `./gradlew build`。
6. 验证产物不进仓库，脚本、实验数据与截图都不入库，只把数字写进 PR 描述或台账。
7. `m2` 到 `m3` 只调 `RendezvousFacade`，M2 侧不出现 `TrackGenerator` 静态调用。
8. 评审余力项清单未随任务文件进入仓库，本次以《Open CodeReview Result》全量导出与 `develop` 代码逐条核对；清单若另有新版，由张睿哲按包补做。
9. `predAlongSpeedBiasMs` 在 G1 裁定前引擎不读该键；裁定后由卢肄文补读取点闭环。
