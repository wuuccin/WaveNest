# 10 月 30 日告警位置落库 006 记录 张睿哲

## 一 任务

补齐 `alert` 表的 `lon`、`lat`、`current_value`、`threshold_value` 四列，使告警触发时的目标位置与检测阈值随 `alert` 行一并持久化。此前这四个字段仅随 `alert.event` 消息携带，服务重启后历史告警位置丢失。

## 二 交付物

四件一起交。

### 2.1 `deploy/sql/006_alert_position.sql`

该文件为新增件，是幂等 ALTER 脚本，仿照 003 的 IF 与 PREPARE/EXECUTE 模式，为 `alert` 表追加四列：

```sql
ALTER TABLE `alert` ADD COLUMN `lon` DOUBLE NULL ...
ALTER TABLE `alert` ADD COLUMN `lat` DOUBLE NULL ...
ALTER TABLE `alert` ADD COLUMN `current_value` DOUBLE NULL ...
ALTER TABLE `alert` ADD COLUMN `threshold_value` DOUBLE NULL ...
```

新列与 `37-M6-数据库` §5.12 现有八列并存，不删不改。四列全可空：失联告警的 `current_value` 恒为 null；没有最后已知位置时 `lon` 与 `lat` 为 null。

### 2.2 `AlertEntity.java`

该文件新增四个 `Double` 字段，分别是 `lon`、`lat`、`currentValue`、`thresholdValue`。MyBatis-Plus 按驼峰转下划线规则映射到 `lon`、`lat`、`current_value`、`threshold_value`。

### 2.3 `AlertRecorder.java`

`persist()` 的 insert 分支补四个 set：

```java
entity.setLon(event.lon());
entity.setLat(event.lat());
entity.setCurrentValue(event.currentValue());
entity.setThresholdValue(event.thresholdValue());
```

位置取自 `lastKnownPosition()`。失联场景取最后一次真实上报值，补插帧不参与；取不到位置时留空，不造假坐标。类 javadoc 同步更新，原「alert 表无此三列，不写入」改为「四列由 006 扩列补入，RAISED 时一并写入；唯 `duration` 不落库」。

### 2.4 `AlertRecorderTest.java`

原用例「首次触发落库 insert、级别变化 update，且仅八列口径」更名为「落库十二列口径」，并补四字段断言：

```java
assertNull(row.getLon());   // 无 FlightRecordStore 时位置留空
assertNull(row.getLat());
assertEquals(15.0, row.getCurrentValue());
assertEquals(20.0, row.getThresholdValue());
```

新增用例「位置与检测值随首次触发一并落库」。该用例同时接 `MapperRecorder` 验落库、接 `FlightRecordStore` 验非空坐标，断言 `lon=115.88`、`lat=28.68`、`currentValue=15.0`、`thresholdValue=20.0` 全部写入实体。
