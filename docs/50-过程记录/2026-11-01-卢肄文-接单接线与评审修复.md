# 11 月 1 日接单接线与评审修复记录 卢肄文

## 一 任务

阶段一第一天的两件事：接单判断主链接线，以及名下八项评审修复。分支为 `feat/luyiwen-1101-admission`，基线是 `develop`。

## 二 接单判断主链接线

下单现在会跑完整判定链并分四路处理：

- 受理：直接进调度主链。
- 延后：建已受理待唤醒单，按进入时刻减唤醒余量与数据重评点定时唤醒，闸门解除唤醒也走同一个重调度出口。
- 拒单：带原因码，含重复单、时间不可行、超载等，前端可直接提示。
- 转人工：信息不完整时转人工处理。

空间闸门修了一个语义问题：投影垂足会被夹进折线，只看弧长的话船在段内永远为真。现在按双条件判定，弧长落在区间内，且横向垂距不超过走廊半宽五十米。

航段折线、白名单、容差全部进了装配配置，键前缀为 `wavenest.m2.admission`，要调不用改代码。

## 三 评审修复

订单包七项与预测服务的版本并发一项，内容如下。

| 修复位置 | 改成什么 |
|---|---|
| 订单受理服务的船号 | 归一化一次，校验与落库用同一个值 |
| 订单受理服务的优先级 | 取优先级枚举，落库写枚举名 |
| 接单判断链的载重余量 | 加有限性检查，NaN 与正负无穷一律拒单 |
| 接单判断链的点列 | 空点列一并计入预计到达时间跳过条件 |
| 接单判断链的闸门顺序 | 数据有效性闸提到时效闸之前 |
| 接单判断链的未进段判定 | 未进段改判延后再评，不判永久拒单 |
| 接单判断链的船号校验 | 限 ASCII 数字，请求船号先归一再比对 |
| 预测服务的版本写入 | 版本号取值、建快照、登记三步按船号串行化，低版本不再覆盖高版本，带并发回归测试 |

重复单判定的数据源从进程内登记改成查订单表的非终止态订单。原做法在重启后会丢，且与落库状态漂移，还会把事务测试的用例间状态串起来。

## 四 两条要知会的事项

- 罗才辉的 F1 测试改了一处：判重键是同船、同货类、重量差不超过零点五千克，每笔新单现在轮换白名单货类错开。不能用重量错开，因为 M30T 载重上界六千克，NEST-02 不允许 M400，重量一超六千克，同用例第二笔单就无候选，实测踩过。断言语义没有改动。
