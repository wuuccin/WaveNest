## 三 首次复验发现的缺陷

### 3.1 现象

连续下三单，三单全部派给同一架 `UAV-03`，组合号都是 `CMB-001`。三单状态下发后，`drone` 表的 `status` 仍为「空闲」。这违反「多单并发」的前提，同一架机不可能同时执行三个任务。

| 订单 | 无人机 | 组合 | 会面点 |
|---|---|---|---|
| ORD-1793374905461-1 | UAV-03 | CMB-001 | 115.8789395 / 28.6918445 |
| ORD-1793374910744-2 | UAV-03 | CMB-001 | 115.8774640 / 28.6897111 |
| ORD-1793374916272-3 | UAV-03 | CMB-001 | 115.8762774 / 28.6879903 |

### 3.2 根因

`TaskQueueService` 的 Spring 装配构造器标注 `@Autowired`，但其内部调用五参构造器时把 `droneMapper` 传成了 `null`：

```java
@Autowired
public TaskQueueService(..., ApplicationEventPublisher eventPublisher) {
    this(orderTaskMapper, taskLogMapper, dispatchGateService, null, eventPublisher);
}
```

`markDronePreoccupied` 的第一行就是 `if (droneMapper == null || droneId == null) return;`，所以派单时从未把无人机置为「已预占」。`CandidateSelector` 按 `status = 空闲` 取候选，下一单仍能看到同一架机，于是连续命中同一架。

### 3.3 修法

把 Spring 装配构造器改为五参并注入 `DroneMapper`，保留三参与四参构造器供既有单测使用：

```java
@Autowired
public TaskQueueService(OrderTaskMapper orderTaskMapper, TaskLogMapper taskLogMapper,
        DispatchGateService dispatchGateService, DroneMapper droneMapper,
        ApplicationEventPublisher eventPublisher) {
    this.orderTaskMapper = orderTaskMapper;
    this.taskLogMapper = taskLogMapper;
    this.dispatchGateService = dispatchGateService;
    this.droneMapper = droneMapper;
    this.eventPublisher = eventPublisher;
}
```

文件为 `backend/wl-m2-dispatch/.../queue/TaskQueueService.java`。改动只影响装配路径，状态机口径与单测用的 mock 路径未变。

- **会面点不互相覆盖**：三单会面点互不相同，沿航段依次分布，两两相距约 0.4 km。
- **交接不错配**：三单的「进入末段交接」时刻与各自 `meet_time` 分秒不差，分别为 23:52:22、23:53:08、23:52:58；「交接完成」时刻均为会面时刻加 120 s。三单分属三架不同无人机。
- **无偏航误报循环**：全程 `alert` 表 0 条，`drone` 表在飞行结束后全部回到「空闲」。
- **三架同时在飞**：`UAV-01`、`UAV-03`、`UAV-04` 分别承担一单，`UAV-02` 空闲待命。派单后 `drone.status` 依次为「执行任务中」「已预占」「已预占」，说明预占链路已生效。

## 五 会面点目视核对

### 5.1 垂距计算

以航段折线朝阳 `115.852/28.646`、南昌 `115.859/28.663`、八一 `115.879/28.692` 为基准，按 28.68° 纬度做局部米制投影，计算三个会面点到折线的垂距与沿程比例：

| 订单 | 垂距 | 所在段 | 沿程比例 |
|---|---|---|---|
| ORD-1793375271148-1 | 2.97 m | 南昌至八一 | 0.6067 |
| ORD-1793375279798-2 | 2.93 m | 南昌至八一 | 0.5358 |
| ORD-1793375284165-3 | 3.01 m | 南昌至八一 | 0.4847 |

三点垂距均为 3 m 左右，落在航道中心线附近，沿程比例在 0.48 到 0.61 之间，位于南昌大桥至八一大桥的中段江面。

### 5.2 底图目视

前端未配置 `VITE_TIANDITU_KEY`，页面显示「卫星底图待配置」。为完成目视判据，用 Playwright 驱动 Edge 加载 OpenStreetMap 底图，叠加航段折线、两巢与三个会面点后截图核对。

截图显示三个会面点均落在赣江主航道水面，位于航段蓝线东侧附近，未压岸线，也未落在老官洲、裘家洲两处江心洲上。目视结论为不压岸、不压江心洲。OpenStreetMap 与天地图坐标系存在轻微差异，最终演示前仍建议配好天地图 key 后在项目页面复核一次。
