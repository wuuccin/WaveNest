## 3 优先级与分组

按可在同一阶段一起修分成四组，从上到下即修复顺序，组内按依赖与优先级排列。

### 3.1 阶段一：主链接通与闭环

目标是把已写好但没接的逻辑接上，让主链真正跑通，路径为接单、航迹、末段、返航。

| 问题 | 修复要点 |
|---|---|
| 接单判断未接线 | 接上接单判断链，覆盖航段、货况、白名单、重复单、时间窗 |
| 航迹生成未接入 | 派发后生成并下发去程、末段、返程三段航迹 |
| 飞行阶段与订单状态一致性 | 明确单一事实源或双向同步 |
| 迫降野外订单状态 | 平台写入失败状态并触发人工回收 |
| 迫停他巢链路 | 占位准入、锁定、航迹、指令 |
| 是否已交付区分 | 按货物在机与否分流订单状态与货物处置 |
| 末段切入 | 由时间近似改为会面点邻域位置判定 |
| 投放信号 | 新增投放确认消息，取遥测字段或事件消息 |
| 六a 纠偏接会面点 | 接 `RendezvousFacade.recompute` |

### 3.2 阶段二：预测专业化

目标是把预测从退化实现变成带航道约束的预测，并补齐验证。

| 问题 | 修复要点 |
|---|---|
| 真航道中心线 | 建中心线与拓扑台账，精算参考线改读真中心线 |
| 预测专业化 | 补齐退化项，含前提监测、标定、分段限速 |
| 前提监测 | 接入 `PremiseMonitor`，透出 `premise` |
| 回流校准 | 接校准器并建误差样本表 |
| 验证样本量 | 加大蒙特卡洛轮数，报告置信区间 |
| 验收报告 | 汇总仿真验收的设置、指标与结论 |
| 动态会面验证 | 扰动场景下动态与静态对比及量化收益 |
| 预测看台 | 先做后端观测面，界面部分待界面分析后并入 |

### 3.3 阶段三：调度细化

目标是补齐订单与资源维度的细节，这些项不影响主链跑通，但影响调度质量。

| 问题 | 修复要点 |
|---|---|
