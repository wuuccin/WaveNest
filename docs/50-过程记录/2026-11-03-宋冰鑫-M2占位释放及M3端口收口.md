# 2026-11-03 宋冰鑫 M2占位释放及M3端口收口记录

## 一 任务与结论

本次承担阶段一 M2 占位释放与 M3 返航航迹端口收口两项任务。两项任务均已完成，代码推送到分支 `feat/sbx-1103-m2-m3`，PR 以 `develop` 为 base 建立，验收人为张睿哲与罗才辉。

## 二 M2 占位释放

- `occupancy_slot` 表新增 `order_id` 列，迁移脚本为 `deploy/sql/009_occupancy_slot_order_id.sql`。加列方案已经获得组长批准。
- `OccupancySlotService.tryReserve` 增加 `orderId` 参数，占位成功时把关联订单写入占位行；`occupy` 调用传入空值。
- `OccupancySlotService` 新增 `releaseByOrder`，按订单号查询有效的迫停占位并逐条释放。单条释放失败只记日志，不回滚订单状态。
- `FlightPhaseAdvancer` 在订单推进到「已完成」终态时调用释放，该调用位于事务之外。
- `HomecomingService` 在第三级迫降把订单置为「失败」成功之后调用释放，作为防御性兜底。

## 三 M3 返航航迹端口收口

- `wl-m2-dispatch` 新增返航专用端口 `HomecomingTrackPort`，方法为 `generateTrack`。该端口是函数式接口，与既有的 `RendezvousPort` 使用同一模式。
- `HomecomingService` 的构造器与字段改为注入 `HomecomingTrackPort`，返航航迹调用点改走端口，主源码不再引用 `rendezvous.facade`。
- `wl-app` 的 `RendezvousWiring` 新增 `homecomingTrackPort` 装配，实现为 `facade::generateTrack`，返航航迹仍然由门面生成。
- `wl-m2-dispatch` 对 `wl-m3-rendezvous` 的编译期依赖保留，符合 `77` 第 4 节端口归属的结论。

## 四 数据库迁移

> [!IMPORTANT]
> 本次改动包含迁移 `009_occupancy_slot_order_id.sql`。PR 合入 `develop` 后，每个人都需要在本地执行一次，否则 `wl-app` 相关测试会报 `Unknown column 'order_id'`。

执行命令：

```powershell
Get-Content -Raw deploy/sql/009_occupancy_slot_order_id.sql | docker exec -i wavenest-mysql sh -c 'mysql -u root -p"$MYSQL_ROOT_PASSWORD" wavenest'
```
