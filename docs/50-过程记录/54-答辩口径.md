## 1 讲什么、不讲什么

| 级别 | 内容 | 核心说法 |
|---|---|---|
| ★★★ 主打 | 第 3 步可达性前置剪枝（与第 2 步的预测驱动合为一句卖点） | 别人默认所有单都能派，我们先证明这一单到底能不能派 |
| ★★ 支撑一 | 第 2、6 步：航道约束下的轨迹预测 ＋ 飞行中滚动纠偏 | 多数时候准，且不准时能及时发现并纠正 |
| ★★ 支撑二 | 仿真验证框架 ＋ 数据回流闭环 | 无实物条件下的有效性证明，系统越用越准 |
| ★ 配套亮点 | 剪枝漏斗顺序（货物 → 机型 → 机巢 → 实例）；会面点是组合级产物；起飞时刻两级估算并回填；航迹级冲突二查优先错峰；实时追踪为横切线且末段切换控制目标；末段相对静止交接建模；兜底状态机 | 体现流程想透了，但不作为主卖点 |
| 不标星 | 第 1 步订单接入、第 5 步航线规划、第 8 步返航与回收 | 标配模块，讲多了会稀释主打 |

**讲的时候只讲有星的。**

## 2 主讲顺序与一句话兜底

主讲三步：第 2、3 步（预测驱动与可达性剪枝，★★★）→ 第 6 步（滚动纠偏，★★）→ 数据闭环与仿真（★★）。其余步骤带过即可。

一句话兜住全场：

> 「在船进入服务航段之前，就用轨迹预测算出会面点，并在派单前证明这一单追得上、送得到、回得来；追不上或回不来的组合，在派单前就被剪掉。」

## 3 高频追问标准答案

| # | 追问 | 标准答案 |
|---|---|---|
| 1 | 船突然掉头了怎么办？ | 这不是纠偏能解决的，我们判定为意图变更，回到可达性判断重新走一遍。能说出「回上游重走」而不是「继续微调」，说明清楚预测的边界，比硬撑「我们预测很准」更可信 |
| 2 | 会面点是怎么算出来的？ | 不是先算一个全局会面点再去挑机——求会面点需要速度和起飞点，这两者只有具体到「哪架机、从哪个巢」才确定。所以会面点是每个候选组合自己算出来的，属于剪枝的产物之一，不是剪枝的输入 |
| 3 | 多机多单怎么分？ | 先预测、再剪枝淘汰、后择优；中选后占住机、巢位、会面窗口、归巢时隙，冲突顺延次优；起飞时刻在航迹精算后回填，航迹级冲突优先错峰 |
| 4 | 会面交接时还追踪吗？ | 全程都在追踪，交接时更在追。追踪是横切线不是步骤；变的只是控制目标——去程段追「船未来会到哪」，末段追「我与船此刻相对怎样」。进入会面点邻域后不再重算会面点，改为保持相对静止并完成交接 |
| 5 | 中途出问题，能换一架机接着送吗？ | 不能，而且这正体现了想清楚了。货物是有限对象，离巢后就绑在那一架机上，此时派任何别的机都拿不到货。正确处置是让原机带货返航或迫停 → 货物落巢回收 → 订单重入队重派。能主动说出「换机的前提是货物先回到系统」比回答「支持中途换机」更有说服力 |
| 6 | 派单时就算过电量，返航为什么还要再算？ | 两次性质不同：派单时是预测（按预计风况与航线估），返航前是事实（按实际剩余电量与实时风况复核）；复核不过则申请应急迫停，需按占用时间窗判定准入，无位可借才转应急迫降点 |
| 7 | 装货不要时间吗？ | 装机耗时在首版显式取 0，理由已写进设计：该耗时相对飞行时长与船舶等待时间量级很短；偏乐观造成的偏差由去程段持续纠偏吸收；若实测表明不可忽略，它会作为一个可配置参数重新引入 |
| 8 | 并发是怎么控的？ | 不用「来一单派一单」的流式派发，而是建立全局资源占用台账，并在批处理窗口内做订单与资源的全局匹配——这避免了先到先得的贪心次优；高优先级订单走快速通道保证时效。对飞行中的重规划请求做分级流量治理：安全相关告警不可丢弃并优先处理，常规纠偏可合并、可延后，超出处理能力的直接降级为维持原航迹。因为**过时的决策比不做决策更危险**，这保证系统在任何负载下都能维持基本的监控与兜底能力。（可补一句「类似网约车派单的攒批匹配」） |
| 9 | 机位判断与别家有什么不同？ | 多数方案的机位判断是静态计数——「还有没有空位」；本项目做到时间窗维度——「借出去的这段时间里，会不会把原驻机挤掉」。它与第 5 步精算后的占位复校是同一套思想：**占位是时隙，不是布尔** |
| 10 | 系统加了多少锁？ | 应讲「统一台账」。真正的设计是「登记哪些资源、占用多久、何时释放」，锁只是保护台账的工具；只讲加锁会显得停留在工程细节层面 |

## 4 讲法与实现顺序可以不同

对抗风与剪枝顺序，对外讲法与本机实现刻意不同，这是设计过的，不是不一致：

| 场景 | 采用的顺序 | 说明 |
|---|---|---|
| 代码实现、算法设计 | 机型 → 机巢 → 实例 | 剪枝效率最优，符合「静态先剪、动态后剪」原则 |
| 流程图、答辩表述 | 机巢 → 机型 → 哪架 | 更符合听众直觉：听起来是「从哪片区域调机 → 调什么型号 → 派哪一架」 |

被追问「你怎么知道这个巢够得着」时，答「因为机型先过了载重与全域条件关」。机巢从来不是独立的一关：它要么在展开时被机型过滤掉，要么在组合级与机型一起被判断。

## 5 话术纪律

1. **对外表述按 `02-术语表` §6 的去算法化映射**，算法名词只在被追问技术细节时展开。
2. **禁用**「改派」「接力」「由下游接手」，统一说「货物回收后重派」。
3. 不承诺本期范围外的能力：接力交接（空中换机）、货物转运、多级改投、空中排队等待、下游同品库存补送。
4. 讲「时间窗占位」而不是笼统的「占位」；讲「统一台账」而不是「加锁」。
5. 不把讲法写回设计文档：星级、卖点、讲法只存在于本文与 `55-演示剧本`。
