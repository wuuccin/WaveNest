## 一、坐标系与参考折线

### 1.1 为什么必须先投影

算法层自己不按经纬度算误差。`WaterwayGeometry` 把二维经纬度压成**沿航道一维坐标** `(s, e)`：

- `s` = 沿折线的累计弧长，m，从折线首点起算；
- `e` = 横向偏移，m，**沿前进方向右侧为正、左侧为负**（`WaterwayGeometry` §`e` 的符号约定）。

沿航道一维卡尔曼在 `s` 上做、横向 OU 在 `e` 上做（`80` §3.2.5／§3.2.6）。所以预测误差也必须在
`s`／`e` 上分解，否则「沿程慢了多少」和「横向偏了多少」会被一个欧氏距离混成一个数，答辩时说不清
误差来自哪一层。

### 1.2 参考折线取哪一条（定稿，不随帧变）

用**固定**折线，不用每帧预测器自建的那条参考线。理由：预测器的参考线是它从 AIS 窗口自建的，
拿它当尺子量自己的误差属于自证；固定折线才是外部基准。

| 顶点 | 经度 | 纬度 | 说明 |
|---|---|---|---|
| V1 朝阳洲 | 115.852 | 28.646 | 服务航段西南端 |
| V2 南昌站 | 115.859 | 28.663 | 折点 |
| V3 八一大桥 | 115.879 | 28.692 | 服务航段东北端 |

与 `SimCoordinatesNanchangSegmentTest.CORRIDOR_LON/LAT` 同值（《73-赣江场景说明》§3.1）。

**复算校验（口径自洽性的证明，任何人可重跑）**：

```
段1 朝阳洲→南昌站  2012.2 m   方位角 19.865°
段2 南昌站→八一大桥 3773.3 m   方位角 31.179°
全线合计            5785.5 m
定稿船起点 115.8611/28.6660 投影 → s = 2404.1 m，|e| = 2.59 m
```

`s = 2404 m` 与 `application.yml` 注释、《73》写的「沿程 2.40 km」吻合（差 4 m，来自平面近似）。
这一条对得上，说明折线顶点、投影公式、平面近似三者与代码同源；对不上则整张报告的数都不可信。

### 1.3 投影专用延长段

预测时域 1800 s × 8 节 ⇒ 末点比船头远 7.41 km，必然越过 V3（全线仅 5.79 km）。若不在 V3 之后
补线，`t` 会被夹到 1，`s` 饱和、`e` 沿延长方向乱涨，大 τ 层的数全部作废。

**口径**：在 V3 之后沿段2方位角（31.179°）**延长 15 km**，仅供投影使用。延长段不是航道，
报告中不出现、也不用于任何「船在航道上」的结论。

### 1.4 平面近似

1° 纬度 = 111320 m，1° 经度 = 111320 · cos(28.666°)，与 `WaterwayGeometry`／
`ConstantVelocityPredictor.METERS_PER_DEG_LAT` 同源。航段跨度 5.8 km，该近似误差远小于其他环节。

## 二、四个基本偏差量

| 量 | 定义 | 单位 | 角色 |
|---|---|---|---|
| **沿程偏差** `Δs` | `s_pred − s_true` | m（报告换算 km） | 主分解项之一；带符号，反映预测「快了／慢了多少」 |
| **横向偏差** `Δe` | `e_pred − e_true` | m | 主分解项之二；带符号，反映「偏左／偏右多少」 |
| **点位偏差** `ρ` | `√(Δs² + Δe²)` | m | 单一汇总数，只用于对外一句话结论 |
| **预测点垂距** `\|e_pred\|` | 预测点到折线的最近距离 | m | 清单原文「点到航段折线垂距」的字面口径 |

**关于第 4 项要说清的一点**：清单写的是「横向偏差（点到航段折线垂距，m）」，字面就是 `|e_pred|`。
但这条线本身有固有偏差——定稿起点离折线 2.59 m，`|e_pred|` 里恒含这 2.59 m，量不出「预测偏了多少」。
故：**报告同时给 `|e_pred|` 与 `Δe`，主判据用 `Δe`**（扣掉航段固有偏差），`|e_pred|` 作对照。

## 三、指标公式

### 3.1 绝对值类（清单点名要的 MAE／RMSE／最大偏差）

对某一层样本 `{x_1 … x_N}`（`x` 取 `Δs`／`Δe`／`ρ`）：

```
MAE  = (1/N) · Σ |x_i|
RMSE = sqrt( (1/N) · Σ x_i² )
最大偏差 = max |x_i|
P95  = |x| 的 95 分位（样本少时一并报，避免最大值被单点野值主导）
```

### 3.2 归一化类（`80` §4.2 的**主判据**，验收以它为准）

```
n_along(τ) = RMSE_along(τ) / mean[ σ_along(τ) ]
n_cross(τ) = RMSE_cross(τ) / mean[ σ_cross(τ) ]
```

`σ` 取帧内 `points[k].sigmaAlong` / `sigmaCross`（模型自报的 1σ），**不是**样本标准差。
目标区间 **[0.6, 1.2]**：

- `> 1.2` 判**过于乐观**（模型低估自己的误差，必须调大 `α` 或带宽）；
- `< 0.6` 判**过于保守**（浪费可行集，可收紧）。

**为什么归一化是主判据而不是绝对米数**：绝对米数依赖 `α`、`q` 这些参数猜值（`80` 附录 B），
改参数就变，比不出「模型诚不诚实」；归一化把参数消掉，只剩「你报的带宽和你实际的误差对不对得上」。
`80` §4.2 的绝对量级（10 min 约 100 m、30 min 约 300 m）**只作人工核对的参考线，不作通过与否依据**。

### 3.3 带覆盖率（2σ，名义 95%）

```
覆盖 = # { |Δs| ≤ 2σ_along 且 |Δe| ≤ 2σ_cross } / N
```

目标区间 **[90%, 99%]**。`>99%` 说明带过宽（保守浪费），`<90%` 说明带过窄（危险）。
与 `80` §4.2 第 4 条一致。

### 3.4 有效期命中率

`τ ≤ validitySec` 的样本中，`|Δs| ≤ σ_along` 且 `|Δe| ≤ σ_cross` 的比例，目标 **≥ 95%**。
`validitySec` 的算法是 `min{τ : σ_along > lTolM 或 σ_cross > wTolM}`，本仓 `lTolM=180 m`、
`wTolM=40 m`（`PredictionConfig` 默认值），实测多数帧落在 840 s——即 σ_cross 先触到 40 m。

## 四、样本量口径（这一条最容易出错，单列一节）

### 4.1 样本单元

**一跳 = 一个（帧 i，步 k）对**，对应目标时刻 `t_target = t0_i + 60·k`。

纳入条件：`60·k ≤ validitySec_i`（超有效期的点是低置信外推，`80` §3.2.8 明示不算可信输入）。

### 4.2 两个 N，必须分开报

| 记号 | 含义 | 算法 |
|---|---|---|
| `N_跳` | 参与了误差统计的（帧, 步）对数 | `Σ_i (k_max(i) + 1)` |
| `N_独立` | 被真值覆盖的**不同目标时刻**数 | 去重后的 `t_target` 个数 |

**为什么要分开**：帧是 1 Hz、每帧覆盖 14 步（0…840 s），所以同一个时刻会被约 14 帧预测覆盖。
2014 帧 × 14 步 ≈ 2.8 万跳，但实际独立的时刻只有约 2000 个。两者差一个数量级。

**规则**：

- `MAE / RMSE / 最大偏差` 按 `N_跳` 报——它回答的是「这套系统每发一次预测，误差多大」；
- **置信区间按 `N_独立` 算**，用按时刻分块的 bootstrap（块长 = 60 s）。
  若拿 `N_跳` 算区间，区间会假性收窄约 `√14 ≈ 3.7` 倍，等于用重叠样本骗自己。
- 报告里两个数都写。只写一个的，视为口径不合格。

### 4.3 分层

- **按 τ 分层**：60 / 120 / … / 840 s。误差随时域增长是指标的本质，混在一起报一个数没有意义。
- **按遍次分层**：三遍各自一组，再给合计。**不得**把两次运行拼成一个 N 还当作一次统计。
- 每一层都带自己的 `N_跳` 与 `N_独立`。

## 五、真值与时间对齐

### 5.1 真值表

`ship_ais`（`37` §5.10）：`ship_mmsi / ts / lon / lat / sog / cog`，M1 落库
（`ShipAisIngestListener`，`005_ship_ais_track.sql` 保障表存在）。
落地口径：`ts` 由 Unix 毫秒转 `Asia/Shanghai` 的 `DATETIME`，`sog` 由节转 m/s。

采样率 1 Hz（`wavenest.sim.tick-millis=1000`）。

### 5.2 对齐规则

```
目标时刻 t_target = t0 + 60k（毫秒）
取 ship_ais 中 |ts − t_target| ≤ 500 ms 的最近一条
无满足条件的记录 ⇒ 该跳丢弃，计入「未配对」
```

**为什么用最近邻、不用线性插值**：插值会平滑真值，系统性低估偏差；最近邻是保守选择，
宁可比真值差一点，也不给自己刷数。

**必须写进报告的系统不确定度**：`ship_ais.ts` 是 `DATETIME`，秒精度。四舍五入后对齐残差
≤ 0.5 s，8 节（4.115 m/s）对应沿程 ≤ **2.06 m**。这一项不从数据里扣，明写在报告里，
让读者知道 `Δs` 的 MAE 里天然含约 2 m 的对齐噪声。

### 5.3 配对前提（红线）

帧与 `ship_ais` 必须来自**同一次跑批、同一台机器、同一时钟**。跨机器的数据不能配对——
时间戳都对不上，算出来的不是偏差是巧合。

## 六、剔除规则

编号固定，报告里逐条给「剔了多少跳、为什么」。

| # | 规则 | 判别方式 | 理由 |
|---|---|---|---|
| **R1** | 前提失效帧 | `premise ≠ VALID` | 模型自己声明前提不成立，其输出不该被计分 |
| **R2** | 超有效期 | `60k > validitySec` | `80` §3.2.8：有效期外是低置信外推 |
| **R3** | 跨重启缺口 | `t0` 与 `t_target` 之间存在帧间隔 > 5 s，或后端重启时刻落在区间内 | 重启前后是两个 JVM 实例，状态不连续 |
| **R4** | 复位后重收敛窗口 | 见 6.1 | 船位被复位但预测侧状态未复位，产出的是幻影位置 |
| **R5** | 越框回落帧 | `courseDeg` 由 31.18° 切到 31.20°（精算版→匀速版信号） | 整帧已回落兜底算法，不是同一个预测器的输出 |
| **R6** | 无真值 | 五.2 未配对 | — |

### 6.1 R4 的可执行判据

不能靠肉眼。用帧内隐含速度判：

```
v_k = ( s(point_{k+1}) − s(point_k) ) / 60          # 帧内第 k 段的隐含沿程速度
标称 v ≈ 4.115 m/s（8 节）
若 v_0 < 0 或 |v_0 − 标称| > 1.0 m/s，且连续 ≥ 3 帧 ⇒ 判为异常窗口
异常窗口自起判帧起，到 |v_0 − 标称| 回到 ≤ 0.5 m/s 且符号为正为止
```

10-30 这批帧上，该判据命中**两段**，都在 `POST /sim/ship/reset` 之后（详见序号 2 报告 §四）。
这两段不是「误差大」，是**船位被复位而预测侧沿程状态（`s`、`v`）没有一起复位**，
产出的是物理上不存在的轨迹——计进偏差统计会把 MAE 抬成没有意义的数。

> 这条同时是个缺陷线索：`premise` 全程 `VALID`，说明前提失效闸门**没有**识别出
> 一次 3 km 量级的位姿跳变。归谁修需组长确认（预测侧状态复位／闸门口径）。

## 七、统计方法与交付形态

### 7.1 计算顺序

1. 读帧文件，按 `t0` 升序排，按 `version` 回退切段（每次回退＝一次后端重启）。
2. 逐帧逐 `k` 生成跳，过 R1／R2／R5。
3. 查 `ship_ais` 配对，过 R6。
4. 过 R3（缺口）、R4（异常窗口）。
5. 按 τ 分层、按遍次分层，算三.1 的三个绝对量 + 三.2 的归一化 + 三.3 覆盖率。
6. 按 `N_独立` 做块 bootstrap（2000 次，块长 60 s），给 MAE／RMSE 的 95% 区间。

### 7.2 报告必含字段

- `N_跳`、`N_独立`、真值表名与跑批时间窗口
- 对齐容差与由此引入的系统不确定度
- R1–R6 各自剔除的跳数
- 每个 τ 层的 `MAE_along / RMSE_along / max_along / MAE_cross / RMSE_cross / max_cross`
- 归一化 `n_along(τ)`、`n_cross(τ)` 与是否落在 [0.6, 1.2]
- 2σ 带覆盖率与是否落在 [90%, 99%]

### 7.3 三条红线

1. **样本不足就写不足**，不许拿单次演示结果冒充统计结果。
2. **不许拿 `N_跳` 当独立样本**报置信区间。
3. **不许跨跑批、跨机器拼样本**。拼不出来就如实说「本批只有一次有效跑批」。
