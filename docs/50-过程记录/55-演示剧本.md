## 1 演示目标

让评委在不手动操作的前提下，看完整条主流程，并让主讲人的讲解与画面对得上。**演示的不是界面，是流程。**

三件事必须在画面上看得见：

1. 会面点是**动态**算出来的，不是固定坐标；
2. 风速突变时系统**回上游重走**，进入在飞安全复核，而不是硬撑预测；
3. 中途不能换机，处置链条是**回收后重派**。

---

## 2 主演示脚本（一键演示）

建议做一个「一键演示」入口，自动按脚本推进一个完整任务：

```
下单
 → 预测并画出会面点（虚线轨迹 ＋ 置信椭圆 ＋ 十字准星）
 → 无人机起飞（去程段着色）
 → 飞行中风速突变（气象超限告警 → 在飞安全复核）
 → 原机放弃本次会面并返航
 → 货物回收、订单重新入队
 → 重新派机完成交接（末段交接中 → 返航中 → 完成）
```

要点：

1. 第 4 段是整个演示的**高光桥段**，必须在画面上清晰可见：气象标尺指针跃升、告警实体红色闪烁、事件流追加一条；任务状态从「去程中」转「返航中」作为可选旁证，不作为通过条件（通过条件见 §2.1）。
2. 第 6 段要让人看到「订单重入队」这一步——这是本项目与「支持中途换机」说法的分水岭。
3. 全程无需评委操作，讲解按段穿插。

### 2.1 实时一键演示的三段通过条件

实时一键演示分三段推进。第三段以气象超限事件与无人机返航状态作为通过条件，不以订单状态的跳变作为通过条件。演示台提供仿真复位按钮，使八项动作都有入口。实时通道允许的来源为本机与内网网段，不放开任意来源。

### 2.2 收口加演（风况回落、熔断解除、重派交接）

一键演示的收口三段在气象超限处置后接续，顺序与前端 `demo.js` 的第五至第七段逐一对应：

| 顺序 | 画面 | 后端确认 | 手段与时机 |
|---|---|---|---|
| 风况回落 | 气象标尺指针回落到预警线以下 | 风速帧低于 8.0 m/s | 清偏置 `DELETE /sim/weather/bias`，自产风回到基准 5.0 m/s（低于预警 8.0、远低于熔断 14.0） |
| 熔断解除 | 派单闸门由「熔断中」回「正常」 | 闸门状态帧为正常 | 解除样本数 × 采样周期加 15 s 余量；等待窗口 25 s，上限 30 s（见 `53` 第 27 项） |
| 重派交接 | 新机接手，订单逐段走到「已完成」 | 订单由「待调度」经「已派发／去程中」「末段交接中」至「已完成」，且执飞机号不同于原机 | 新机由调度重新派发，不由原机中途换机 |

三段按序推进，任何一段未获后端确认即停在该段并提示超时，不跳段、不以画面猜测替代确认。

### 2.3 异常情形与兜底

若现场实测发现清偏置后自产风在 25 s 窗口内抖动跨过 8.0 m/s，退化为重注 `?wind=4&persist=true`，不另造第三种回落手段（见 `53` 第 27 项裁定原文）。清偏置仍作为首选，兜底只在实测抖动跨线时启用。

### 2.4 末屏说明

末屏展示风速突变主线的闭环：落点在风况回落与订单重派交接，即原机返航回收后，风况回落、闸门解除，订单重新入队并由新机完成交接。在飞安全复核结论（继续／调整／终止三值）由复核结论展示位呈现，本节只引用该展示位，不重复定义字段。

## 3 大屏讲解配套

| 画面元素 | 讲解要点 |
|---|---|
| 船舶图层 | 预测轨迹用**虚线**，不确定性用半透明置信椭圆；讲解强调「在船进入服务航段之前就已经开始预测」 |
| 会面点图层 | **十字准星**随预测刷新而移动，锁定后高亮；讲解强调「会面点是组合级产物，不是先算好的全局点」 |
| 无人机图层 | 规划航迹实线并按去程、末段交接、返程、兜底盘旋分段着色；讲解强调「末段追踪的控制目标变了」 |
| 告警图层 | 触发兜底事件的实体闪烁红色并与事件流联动；讲解强调「检测归监控、决策归调度」 |
| 统计面板 | 「传统方案与本方案」能耗对比柱状图；轨迹预测误差曲线（对应数据回流的 ★★ 卖点） |
| 实时状态面板 | 机巢与无人机的实时状态同屏；讲解强调「检测归监控、决策归调度」 |
| 气象标尺 | 三条线同屏可见；注入风速后指针与状态随之变化；讲解强调预警 8.0 与熔断 14.0 的取值来自 `sys_param`，前端在后端没有查询端点时以契约常量兜底 |
| 无人机异常注入 | 偏航的注入需要存在在飞的派发，也就是有订单、有航段，没有航段时检测器收不到投影；低电量的注入没有前提，注入即出；偏航的方向按航段的走向选择，南北向取 90 或 270，东西向取 0 或 180 |
| 禁飞多边形图层 | 收到合法几何时绘制，无数据时不报错；讲解时不得声称已经接入真实禁飞区台账 |
| 订单队列与候选卡 | 订单按状态与优先级筛选，两项都有「全部」；候选卡逐条显示原因句、占位与错峰结果 |
| 状态线 | 订单状态时间线走完「待调度 → 已派发 → 去程中 → 末段交接中 → 返航中 → 已完成」，异常时只显示异常终止，迫停与迫降的落点单列展示（见 23 §5.4） |

## 4 时间轴回放（备用桥段）

底部时间轴可拖动，回放任意一段历史任务。回放接口按订单号选择任务，并把读取范围限制在飞行时间窗之内，支持无人机状态、订单状态、告警、规划航迹与船舶预测五类帧。旧客户端遇到未知帧类型可以跳过。答辩时可拖回去重放：

> 风速突变 → 在飞安全复核 → 原机放弃会面 → 返航迫停并回收货物 → 订单重入队

用途：主链路出问题时的兜底，以及回答「刚才那段能再放一遍吗」这类追问。

## 5 现场兜底准备

演示失败比设计缺陷更容易致命，四项兜底必须提前做（细则见 `36-可视化` §7）：

| 兜底项 | 内容 |
|---|---|
| 公网与局域网双部署 | 正式部署给公网网址；同时部署到现场一台笔记本或 mini 主机，走局域网，断外网也能跑 |
| 离线底图 | 提前把沿江作业区瓦片下成离线包，现场无外网时切本地瓦片，否则大屏一片空白 |
| 数据回放兜底 | 准备一套录制好的仿真任务数据，实时链路出问题时切「回放模式」，照样走完从下单到交接的全过程 |
| 字段对齐 | 开工前先开一次接口对齐会，把数据对象与消息格式定死，避免联调现场改字段 |
