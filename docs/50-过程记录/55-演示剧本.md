## 1 演示目标

让评委在不手动操作的前提下，看完整条主流程，并让主讲人的讲解与画面对得上。**演示的不是界面，是流程。**

三件事必须在画面上看得见：

1. 会面点是**动态**算出来的，不是固定坐标；
2. 船意图变更时系统**回上游重走**，而不是硬撑预测；
3. 中途不能换机，处置链条是**回收后重派**。

---

## 2 主演示脚本（一键演示）

建议做一个「一键演示」入口，自动按脚本推进一个完整任务：

```
下单
 → 预测并画出会面点（虚线轨迹 ＋ 置信椭圆 ＋ 十字准星）
 → 无人机起飞（去程段着色）
 → 飞行中船突然变向（触发 6b 意图变更）
 → 原机放弃本次会面并返航
 → 货物回收、订单重新入队
 → 重新派机完成交接（末段交接中 → 返航中 → 完成）
```

要点：

1. 第 4 段是整个演示的**高光桥段**，必须在画面上清晰可见：船位轨迹突变的瞬间、告警实体红色闪烁、事件流追加一条、任务状态从「去程中」跳转。
2. 第 6 段要让人看到「订单重入队」这一步——这是本项目与「支持中途换机」说法的分水岭。
3. 全程无需评委操作，讲解按段穿插。

## 3 大屏讲解配套

| 画面元素 | 讲解要点 |
|---|---|
| 船舶图层 | 预测轨迹用**虚线**，不确定性用半透明置信椭圆；讲解强调「在船进入服务航段之前就已经开始预测」 |
| 会面点图层 | **十字准星**随预测刷新而移动，锁定后高亮；讲解强调「会面点是组合级产物，不是先算好的全局点」 |
| 无人机图层 | 规划航迹实线并按去程、末段交接、返程、兜底盘旋分段着色；讲解强调「末段追踪的控制目标变了」 |
| 告警图层 | 触发兜底事件的实体闪烁红色并与事件流联动；讲解强调「检测归监控、决策归调度」 |
| 统计面板 | 「传统方案与本方案」能耗对比柱状图；轨迹预测误差曲线（对应数据回流的 ★★ 卖点） |
| 状态线 | 订单状态时间线走完「待调度 → 已派发 → 去程中 → 末段交接中 → 返航中 → 已完成」，异常时只显示异常终止，迫停与迫降的落点单列展示（见 23 §5.4） |

## 4 时间轴回放（备用桥段）

底部时间轴可拖动，回放任意一段历史任务。答辩时可拖回去重放：

> 船突然变向 → 识别 6b → 原机放弃会面 → 返航迫停并回收货物 → 订单重入队

用途：主链路出问题时的兜底，以及回答「刚才那段能再放一遍吗」这类追问。

---

## 5 现场兜底准备

演示失败比设计缺陷更容易致命，四项兜底必须提前做（细则见 `36-可视化` §7）：

| 兜底项 | 内容 |
|---|---|
| 公网与局域网双部署 | 正式部署给公网网址；同时部署到现场一台笔记本或 mini 主机，走局域网，断外网也能跑 |
| 离线底图 | 提前把沿江作业区瓦片下成离线包，现场无外网时切本地瓦片，否则大屏一片空白 |
| 数据回放兜底 | 准备一套录制好的仿真任务数据，实时链路出问题时切「回放模式」，照样走完从下单到交接的全过程 |
| 字段对齐 | 开工前先开一次接口对齐会，把数据对象与消息格式定死，避免联调现场改字段 |
