## 1 本次的任务

本次的实现依据 11 月 12 日的任务清单中宋冰鑫负责的编排器的四处遗留与单 run 的范围。代码从 `baseline/v3-1109` 的分支建立个人的分支，只修改 `testdata/mock/run_scenarios.py` 的一个文件，未改动其他人的文件独占的内容，也未重做已合入基线的场景、指标与校验器。

## 2 已实现的内容

本段实现四项内容，逐项的说明如下。

第一，批量的入口。入口按《1112-功能做实批次｜接口约定》的第 6.2 节的 `run_batch` 的签名实现，命令行的参数新增 seed 的区间与统一的时基；seed 的单点与区间同时给出时报错退出，避免两种的口径混用。

第二，时基的统一。时基统一为场景的 `t0_ms` 的取值。编排器拒绝夹具旧的硬编码的值，并把同一的数值以环境变量的形式传给夹具，指标的计算使用同一的口径，避免样本的时间落在 run 的范围之外。

第三，会面点的两点。会面点原先的单一的占位坐标已删除。真值的会面点取真值轨迹的末点，预测的会面点由末段的残差在航向的坐标系上偏移得到，两者相同时报错退出。

第四，真值的读取。编排器现在读取真值轨迹的文件，校验表头之后解析真值的点，离线的模式按 T 的前缀加 seed 查库，产出 `manifest.json`、`metrics.json`、`truth.csv` 与 `sample/` 的四件产物。

## 3 顺带修掉的三个阻塞

本段顺带修掉三个阻塞的问题，各自的说明如下。

第一，真值的表头缺少 `cog_deg` 的列。《1109 模拟数据的接口约定》的第 6 节规定的是六列，代码此前只认五列，真值的文件按契约产出时会直接报错。

第二，编排器此前没有传入 `FIXTURE_KEEP_SAMPLES` 的变量。夹具默认在 `finally` 的块里删除本 run 写入的行，编排器随后读不到数据，指标无法计算。

第三，Gradle 的输出解码此前没有容错。Windows 上的输出混入非 UTF-8 的字节时，编排器抛出解码的异常，把真正的测试结果盖住。

## 4 验证的结果

单 run 使用契约口径的临时真值文件真实跑通，落库五行的数据，`manifest.json` 的行数与库内的行数一致，四件的产物齐全。契约的校验器对场景、manifest、manifest 的一致性、metrics、真值表头五项复验全部通过，零失败的结果。

`truth.csv` 的缺文件报错已消除，会面点的占位已删除。本段的验证为单 run 的离线跑批，不代表 200 个的 run 的全量跑批，也不代表真实的服务的联跑。

## 5 团队的接入点

本段有两个团队的接入点，说明如下。

第一，罗才辉的真值轨迹需要六列的表头，最后一列是 `cog_deg`。编排器此前只认五列，本次已按《1109 模拟数据的接口约定》的第 6 节修正，按契约产出的文件即可直接读取。

第二，卢肄文的夹具需要接收 `FIXTURE_T0_MS` 与 `FIXTURE_KEEP_SAMPLES` 的两个环境变量。前者的变量保证时基与场景同源，后者的变量保证行在编排器读回之前不被清理。编排器已在每次的 run 时传入这两个的变量。

## 6 口径与边界的说明

本节的说明补齐编排器的口径与边界，供后续的跑批与验收的核对。

批量的入口与单 run 的入口并存：单 run 的入口使用 `--seed` 的参数，批量的入口使用 `--seed-from` 与 `--seed-to` 的参数；两者的参数同时给出时报错退出，避免同一个的 run 被重复的定义。统一的时基为 `1794268800000` 的取值，等价于 2026-11-10 的零点；该值与场景的 `t0_ms` 同源，也与夹具的默认值同源，三处的口径一致。

会面点的两点为真值的会面点与预测的会面点。真值的会面点取真值轨迹的末点，代表无噪的真实的到达的位置；预测的会面点由末段的残差在航向的坐标系上偏移得到，代表预测的模型给出的到达的位置。两者的值相同时报错退出，避免把同一的占位当作两个的独立的证据。

产物的目录为 `<out>` 的根目录，四件的产物分别为 `manifest.json`、`metrics.json`、`truth.csv` 与 `sample/` 的目录。批量的汇总按 seed 的区间逐个 run 的执行，每个的 run 的产物落在各自的子目录，汇总的 `manifest.json` 记录每个的 run 的 `seed`、`out_dir` 与 `row_count` 的三项，`total_rows` 的值为全部 run 的行数之和。

本段的边界为单 run 的离线验证。200 个的 run 的全量跑批、跨机器的环境的复现、真实的服务的联跑均不在本段的范围；这些项由序号 3 的汇合复跑承担。

本段的口径与基线的口径保持一致的来源为接口的约定与基线之上的实现：批量的签名、时基的取值、会面点的两点的定义、产物的字段均取自接口的约定；实现的代码不改契约的取值，遇冲突时改实现的代码而不改契约的正文。

## 7 测试与风险的说明

本节的说明补齐本次验证的边界与后续的风险，供汇合复跑的核对。

本次的单 run 验证覆盖四项的内容：批量的入口的参数解析、统一的时基的传递、会面点的两点的生成、四件的产物的落盘。参数解析的验证覆盖 seed 的单点、seed 的区间与两者的冲突；时基的传递的验证覆盖场景的 `t0_ms`、夹具的 `FIXTURE_T0_MS` 与指标的口径的三处的一致性；会面点的验证覆盖真值的末点与预测的偏移的两点的生成与两者的相等的报错；产物的验证覆盖 `manifest.json` 的字段、`metrics.json` 的指标、`truth.csv` 的表头与 `sample/` 的目录的齐全。

风险有三项。第一，200 个的 run 的全量跑批未执行，行数的总量与 `total_rows` 的一致性只在单 run 的范围验证，批量的汇总的逻辑待全量的跑批确认。第二，真值的六列表头依赖罗才辉的产出，六份的 `scenario.yaml` 的 `param_sources` 的缺项依赖杨添爻的补齐，两项的外部依赖未闭环之前，复验的结论可能变化。第三，Windows 的编码的问题只在灌库的环节修正，编排器的输出的解码已有容错，但其他的脚本的编码未逐一的检查。

以上三项的风险在本记录中显式登记，避免在汇合复跑时把外部的依赖当作本段的缺陷。
