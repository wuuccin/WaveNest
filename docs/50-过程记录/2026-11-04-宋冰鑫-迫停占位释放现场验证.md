# 2026-11-04 宋冰鑫 迫停占位释放现场验证记录

## 一 任务与判据

任务清单要求构造一笔触发迫停占位的订单，走 `OccupancySlotService.releaseByOrder`，只做现场验证，不加逻辑。判据是订单到终态后，`occupancy_slot` 对应行的 `status` 由「有效」转「已释放」。释放终态与调用点的约定见 `77` 第 3 节占位释放：终态含已完成、失败、已拒绝、异常终止四态，调用点为 `FlightPhaseAdvancer` 与 `HomecomingService` 两处。

## 二 环境与方法

- 基线为 `origin/develop` 的 `e97dbc7`，本地构建 `wl-app-0.1.0.jar`，`sim` profile，端口 8080。
- 中间件为本机 Docker Compose 四件套，MySQL 中 `occupancy_slot` 已含 `order_id` 列，验证前表内无「有效」行。
- 仿真船 MMSI `123456789` 沿南昌航段行驶。经 `POST /api/orders` 下单，载重 5.0 千克，类型为医疗物资。
- 迫停触发走生产告警链路：向 `wavenest.data` 交换机以 `alert.event` 路由键发布低电量告警，由 `AlertDrivenDispatcher` 消费、`HomecomingInputAssembler` 组装、`HomecomingService.reviewAndDecide` 判定。
- 第一笔告警电量 30%，位置取 `115.8485, 28.6425`，贴近 `NEST-01`、远离原巢 `NEST-02`，使第一级不可回、第二级 `NEST-01` 可达。
- 第二笔告警电量 5%，位置取 `115.8575, 28.6700`，取两巢之间，使候选全部不可达，降级第三级迫降野外，订单到「失败」终态。
