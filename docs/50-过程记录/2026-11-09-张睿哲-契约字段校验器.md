张睿哲按执行计划第 3 节的序号 1 与第 4 节的本人行，实现 `testdata/mock/validate_scenario.py`，对六段产物输出逐项 PASS／FAIL。校验覆盖如下。

| 契约章节 | 校验对象 | 校验点 |
| --- | --- | --- |
| 第 3 节，十四个字段 | `scenario.yaml` | 字段齐全与类型；`family` 六族；`mode`／`path_start_m`／`duration_sec` 的 live 0 加 1800、offline 1000 加 1200 对应；`speed_limits_ms` 段格式与 `normal` 家族三段值；`tick_millis` 固定 1000；`truth_source` 相对路径；`mmsi` 的 T 加 seed／123456789；`pred_version` 正整数 |
| 第 4 节，十四个字段 | `manifest.json` | 十四项齐全；`tick_millis`、`speed_profile` 与 `evidence_class` 取值；`rows` 与 `bytes` 非负整数；`sha256` 六十四位小写十六进制；`command` 与 `baseline_commit` 非空；与 `metrics.json` 的 `rows`、`evidence_class` 一致性复核 |
| 第 5 节，十一个指标 | `metrics.json` | 十一字段齐全；六项核心指标非空且为有限数；覆盖率落在 0 至 1；`tau_grid_sec` 非空正整数数组且 offline 只统计 τ ≤ 1200；`by_evidence_class` 两栏齐全、不得并入单一 NEES |
| 第 6 节 | `truth.csv` | 表头 `ts_ms,s_m,lon,lat,sog_ms,cog_deg`；`s_m` ≤ 6003.3510；`ts_ms` 与 `s_m` 单调；经纬度范围；`sog` 非负 |
| 第 8 节，四行契约 | replay 帧 JSON | 统一信封 `type` 与 `data`、不写 `payload`、顶层不写 `ts`；帧型六类；订单状态用中文十二态、出现 `COMPLETED` 即 FAIL；`orderTimeline` 不得混入 `WAIT_CARGO`；`expected` 用中文状态词 |
| 第 13 节 | `param_sources` | 十一项「必须标注的参数」全覆盖；来源档只取三值；六项固定标注（`sog_ms`／`noise_deg`／`sigmaEM`／`tauESec`／`alphaAlongMs`／风突变幅度）必须为 `design_assumption`、中心线十三点必须为 `measured`；未标注一律 FAIL |

实现只依赖标准库：环境无 PyYAML 时按契约第 3 节的扁平 `key: value` 布局自带回退解析，六名组员机器不必预装第三方包。校验器只读，不改被检产物。
