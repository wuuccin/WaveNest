## 2 环境修复

第一次全量构建在 `wl-app` 阶段失败，22 个用例没有通过。失败原因不是代码，而是虚拟机里的中间件状态：

第一，RabbitMQ 里有一条旧的 `wavenest.m2.data-weather` 队列，创建时没有 `x-dead-letter-exchange` 参数。当前代码要求该队列带 `wavenest.dlx` 与路由键，重建时报 `PRECONDITION_FAILED`，监听器启动失败，连带 22 个 `@SpringBootTest` 用例无法加载上下文。

第二，MySQL 的 `wavenest` 库缺 `centerline_point` 表。`T29FlightPointIntegrationTest` 能通过，但依赖中心线台账的用例会报 `Table 'wavenest.centerline_point' doesn't exist`。

经确认后做了两项环境修复：

1. 删除旧的 `wavenest.m2.data-weather` 队列与它的 DLQ。队列里有 8 条旧消息、没有消费者，删除后由应用按新参数重建。
2. 执行 `deploy/sql/016_centerline_v3.sql` 与 `deploy/sql/017_plan_track.sql`。前者建 `centerline_point` 并灌入 v3 的 13 行，后者建 `plan_track` 空表。两个脚本都是 `CREATE TABLE IF NOT EXISTS`，没有清空既有数据。

## 7 文档卫生的两处发现

### 7.1 118 号任务清单末尾多一个空行

`git diff --check aeaddec a57579a` 报出一处：

```text
docs/100-工程实施/124-11-12任务清单.md:157: new blank line at EOF.
```

该文件是 PR #175 新增的文件，末尾有两个连续的 CRLF，构成一个多余的空行。它不影响构建与测试，但违反项目对 `git diff --check` 零输出的要求，也说明 3-2 的「git diff --check 零输出」是在提交前的工作树口径上取得的，没有覆盖提交范围。

3-1 是只读复核，本次不改该文件。建议另开一个小提交，删掉末尾多余的空行。

### 7.2 当前工作区有 51 份文档为纯 LF

当前工作区 176 份 Markdown 中有 51 份是纯 LF。这些文件在索引里是 LF，`.gitattributes` 要求工作区检出为 CRLF，但当前工作区的实际字节是 LF。这是检出状态的问题，不是 PR #175 新增内容的问题。若要满足 26 条中「docs 纯 CRLF」的现场口径，需要重新检出或按文件逐个转换。

3-1 是只读复核，本次不改这些文件。建议在提交文档修正时一并处理，或在新的干净克隆里复核。

### 7.3 历史记录中有一处虚拟机 IP

`git grep` 扫到 `2026-10-30-罗才辉-多单并发.md` 第 9 行有 `<vm-host>`。这是历史记录里的环境信息，不是 PR #175 引入的。按「历史叙述不改写」的原则，本次不判不通过，只登记为环境专属信息的残留。
