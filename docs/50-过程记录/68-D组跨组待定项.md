## 3 自定项决定全文（D-10／D-11／D-12）

决定人：张睿哲（D 组 择优与占位并发）｜日期：2026-10-02｜依据：《D 组-跨组待定项》中保留的三项本组自定内容；宏观层裁决（D-1～D-9）已落地，不在本文范围。

### 3.1 D-10 绕行后再次触发电量重验的判据

**决定**：

1. **不新设阈值，与 C 组功能 4 第二关（回得来）同口径**：绕行后电量重验直接复用第二关的安全余量判据，参数键名与 C 组共用同一个，避免两套电量标准。
2. **绕行必然触发一次重验，无例外**：绕行改变航程与能耗，不允许沿用绕行前的电量结论。
3. **判据**：

```text
用绕行航迹的精算能耗重算返航剩余电量：
  SOC_ret' = SOC_now − E_remain_to_meet − E_handover − E_detour_return
判定：
  SOC_ret' ≥ soc_safe_margin   → 通过，继续回写占位
  SOC_ret' < soc_safe_margin   → 按候选失败处理：
                                 释放本候选占位 → 回候选列表取下一名
                                 （措辞为「回退换候选」，不涉及换机概念）
```

4. **键名归属**：`soc_safe_margin` 进 `sys_param` 总表，由本组与 C 组会签确认同一键名、同一口径。
5. **边界**：本判据只回答「绕行后还回不回得来」；不重新选择归巢目标（归巢目标维持回原巢，校验回原巢不成立时按候选失败处理，依据宏观裁决 D-2）。

**验证**：

- 场景：绕行航迹能耗显著增大、临界余量附近绕行、多次绕行逐次重验。
- 指标：绕行后重验触发率（应为 100%）、重验拦截率、绕行方案误放行数（目标 0）。

### 3.2 D-11 不动点迭代震荡时的阻尼机制

**决定**：

1. **先识别、后阻尼**：在起飞时刻不动点迭代中监控相邻步增量 `Δ_i = t^(i+1) − t^(i)`：符号交替（`Δ_i · Δ_{i−1} < 0`，时刻在解两侧来回跳）；或停滞不下降（在震荡检测窗口内连续多步 `|Δ|` 未按预期减小）。命中任一条即判定为震荡。
2. **阻尼方法——松弛迭代**：判定震荡后启用松弛因子 α，更新式由全量修正改为阻尼修正：

```text
原始修正：t^(i+1) = t_raw^(i+1)
阻尼修正：t^(i+1) = t^(i) + α · ( t_raw^(i+1) − t^(i) )
```

3. **α 调整策略**：每次触发震荡，α 按衰减系数向下折减（从无阻尼状态逐次减小），但不低于下限；α 恢复原值的时机为「连续若干步单调收敛」。衰减系数、初值、下限、恢复所需连续收敛步数均为参数，进 `sys_param`，首版不写死。
4. **出口不变**：达到最大迭代次数仍不满足收敛容差／会面点收敛距离 → 该候选失败，回候选列表下一名。阻尼只改善收敛性，不放宽收敛标准，不改变候选淘汰语义。
5. 收敛判据维持：时刻差 ≤ 收敛容差，且会面点位移 ≤ 会面点收敛距离（两项同时成立）。

**参数名目**：

| 参数键名 | 含义 |
|---|---|
| damping_alpha_init | 松弛因子初值（无阻尼状态） |
| damping_alpha_min | 松弛因子下限 |
| damping_decay | 每次触发震荡的折减系数 |
| damping_recover_steps | 单调收敛多少步后恢复 α |
| oscillation_detect_window | 停滞判定的检测窗口（步数） |

**验证**：

- 仿真构造已知震荡场景（风况／会面点几何使全量迭代交替跳变），观察：启用阻尼后收敛率、平均迭代次数、α 折减与恢复行为、阻尼后仍不收敛的淘汰正确性。
- 阻尼机制在仿真验证前默认**先按本机制实现但保持可关闭**（开关亦进参数表），验证通过后转为常态启用。

### 3.3 D-12 加锁粒度（nestId 行锁 vs 占位明细行锁）

**决定**：

1. **正确性前提**：无论哪种粒度，正确性都由「事务内重叠检测 ＋ 写入 ＋ 二次校验」与幂等约束保证，锁粒度只影响并发性能，不改变正确性结论。
2. **默认采用占位明细行锁（高并发度方案）**：

```text
事务内按本次键控资源（droneId / nestId / shipMMSI）
  对该 key 下「有效」占位明细行 SELECT … FOR UPDATE
  → 重叠检测 → 写入 / 回写 → COMMIT
```

   理由：常态下不同资源、不同时间窗的事务大多不触及同一批明细行，明细锁让它们并发通过，吞吐高。

3. **热点升级为资源行锁（串行化兜底）**：当某个 key（如同巢、同船）在统计窗口内的事务回滚率超过升级阈值，判定该 key 为热点，对该 key 的资源父行加锁（nestId／shipMMSI 维度行锁），使该 key 的占位短期串行化；回滚率回落到恢复阈值以下再退回明细行锁。
4. **固定加锁顺序防死锁**：一个事务涉及多个 key 时，一律按 key 的固定序（如类型序 ＋ Id 序）申请锁；事务保持短小，禁止事务内等待外部精算结果（精算在事务外完成，事务只做检测／写入／回写）。
5. **最终取值以压测为准**：升级阈值、恢复阈值、统计窗口进 `sys_param`；压测前默认全部走明细行锁，热点升级是压测后可启用的机制，不提前对所有 key 粗化锁。

**参数名目**：

| 参数键名 | 含义 |
|---|---|
| lock_escalation_rate | 触发资源行锁的事务回滚率阈值 |
| lock_recover_rate | 退回明细行锁的回滚率阈值 |
| lock_stat_window | 回滚率统计窗口 |

**压测验证**：

- 两级并发压测：常态并发（多巢／多船分散）与热点并发（单巢、单船集中下单）。
- 指标：事务吞吐、回滚率、死锁数（目标 0）、事务 P99 耗时、热点升级／恢复触发正确性。
- 压测结论回填本文与 `sys_param` 总表；若明细行锁在常态压测已不满足吞吐，再评估是否调整默认粒度。
