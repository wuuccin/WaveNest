# 11 月 1 日队列与气象闸门评审修复记录 张睿哲

## 一 任务

阶段一第一天，修队列包五项与气象闸门相关三项。核心目标是消除无条件整行更新带来的并发覆盖风险，并把气象熔断触发器的本地标记与闸门实际状态对齐。

## 二 队列包五项

| 修复位置 | 改成什么 |
|---|---|
| 派单队列的状态流转 | 状态流转与派单、回退的字段回填全部改为条件更新，更新语句带订单号与原状态条件，校验影响行数等于一，否则抛状态冲突异常，不再用陈旧实体整行覆盖并发写入 |
| 派单队列的回退白名单 | 黑名单改为白名单，只允许已派发、派发中、待派发、已受理待唤醒四种状态回退，飞行中与终态一律拒绝；起止状态相同时短路返回，不重复写日志发事件 |
| 派单队列的占位 | 占位改条件更新，只从空闲转入已预占，影响行数不等于一时抛异常，防止同一架机被并发派给两单 |
| 派单队列的回落版本 | 用原子长整型记录已发布最大版本；日志分支取最大值，回落分支在其上自增且不回退；订单进终态时移除回落版本键，防止映射无限增长 |
| 派单队列的无人机行查询 | 占位查不到行直接抛异常；释放查不到行时记警告提示复核，不再静默吞掉 |

## 三 气象闸门三项

| 修复位置 | 改成什么 |
|---|---|
| 气象闸门触发器的本地标记对账 | 每次评估先读闸门摘要，确认自动来源是否实际登记；本地标记为真但闸门无自动来源且风仍临界时重新熔断；反向场景下 Bean 重建后闸门残留自动来源时，低于阈值的样本照常计入去抖清除 |
| 气象闸门触发器的阈值边界 | 风大于临界改为风不小于临界，达到即熔断，与运维口径一致 |
| 气象闸门触发器的标记更新时机 | 熔断与清除都先调闸门服务，成功返回后再改本地标记，避免调用抛异常时标记悬空 |

## 四 联动修改的测试

- 气象闸门测试的未超阈值用例改为达到阈值即熔断的语义，并新增闸门被外部复位后下一次评估重新熔断的用例，固定对账行为。
- 实时事件测试在 `wl-app` 模块，两处模拟的订单任务映射补上条件更新返回一行的桩，适配条件更新的行数校验。此项属跨包联动，仅测试桩改动。
- 冒烟测试、重调度服务测试与气象接入监听测试逐一排查，真实数据库时点的子状态均在白名单内，无需改动。

## 七 影响面

状态流转改为条件更新后，并发写入不再互相覆盖，同一架机不会被并发派给两单。回退操作只接受处于待调度与已受理状态且回到待调度状态的订单，飞行中与终态订单不能回退。气象熔断在达到阈值时立即触发，本地标记与闸门状态每次评估都对账，人工复位闸门后不会因标记悬空而漏熔断。
