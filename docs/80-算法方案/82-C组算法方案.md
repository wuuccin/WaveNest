### 3 算法设计

**核心思路**：先按静态能力预筛、再展开受限笛卡尔积，避免"全量机型×机巢×实例"组合爆炸；静态约束离线预计算并缓存，动态状态在每次展开时实时判定；实例"空闲"作为展开前的硬前置条件做早剪枝。

**候选组合展开方式（步骤）**

1. **机型筛选（静态）**：依据任务载荷、时间窗松紧、抗风要求，对照机型能力包线，过滤出候选机型集 `M`。
2. **机巢筛选（静态 + 半动态）**：过滤"可驻留机型 ∈ M"且"地理上处于可达半径内"的机巢，得候选机巢集 `N`。
3. **实例筛选（动态）**：在 `N` 内，过滤出当前状态为"空闲"的无人机实例，得候选实例集 `U`。
4. **组合展开**：对 `(m∈M, n∈N_m, u∈U_n)` 做受限笛卡尔积，生成候选组合列表。

**静态剪枝与动态剪枝的分工**

- **静态剪枝（离线 / 低频缓存）**：机型能力包线、机巢–机型兼容、机巢地理可达半径、任务–机型硬性约束（载荷 / 抗风 / 续航）。不随运行时状态变化，预计算后缓存复用。
- **动态剪枝（运行时实时判定）**：实例当前状态（空闲 / 占用 / 故障 / 充电中等既定状态）、机巢实时占用、当前风况是否超出机型抗风等级。随调度时刻变化，每次展开实时判定。

**实例是否空闲在展开阶段就过滤掉**：**是**。采用"先筛实例空闲、再展开组合"的早剪枝策略——把"实例空闲"作为展开前置硬条件，而非展开后再剔除。这样避免生成大量以"忙"实例为成员的候选，直接压低下游计算量。是否纳入"充电中但预计在任务窗口前可就绪"的实例，列为待定项（见第 5 节）。

**参数与阈值（只列名目与含义，不写死取值）**

| 参数名 | 含义 |
|---|---|
| `payload_match` | 机型最大载荷 ≥ 任务载荷 的匹配判据 |
| `windclass_match` | 机型抗风等级 ≥ 任务区最不利风级 的匹配判据 |
| `range_match` | 机型最大续航 ≥ 任务粗估航程 × 安全系数 的匹配判据 |
| `R_nest` | 机巢地理可达半径：机巢到任务端点的可达距离阈值（直线 / 规划航迹，待定） |
| `idle_whitelist` | 进入候选的实例状态白名单，默认仅"空闲"；可配置是否含"充电中且预计可调度" |
| `cap_combo` | 单任务最大候选组合数上限；超出时按距离 / 优先级截断 |
| `TTL_static` | 机型 / 机巢静态约束缓存的失效刷新周期 |

#### 候选展开与排序策略（本组自定项 C-9）

> C-9 属本功能内部策略，不涉宏观裁决。本节仅定义 **展开与排序口径**，最终择优仍归 **D 组·候选方案综合择优**，本组不越位定案。

**两种展开模式**

| 模式 | 触发时机 | 实例可用集 `U` 的范围 |
|---|---|---|
| **全量展开**（派单） | 新任务派单 | 全部满足静态约束的机巢内"空闲"实例 |
| **受限展开**（重派 / 批次窗口内换候选） | 货物尚未装机、仍在批次窗口内 | **限定为货物所在机巢的可用实例**（依跨组裁决 C-3 的货物位置输入） |

- 两类模式**共用同一条展开流水线**（机型→机巢→实例→受限笛卡尔积），仅 `U` 的取值域不同。
- **红线①约束**：仅在"批次窗口内、货物尚未装机"时允许换候选 / 换组合；**起飞后不换机、不改派、不改变执行主体**。受限展开的适用前提由 D 组在批次窗口内判定，本功能只按传入的窗口状态择模式。

**排序（供 D 组择优前的粗略定序）**

本组排序**只做定序、不打终分**，输出带排序键的候选列表交由 D 组功能 5 终评。排序键结构：

```
rank_key = (hard_ok, -slack_time, -energy_margin_ratio, -payload_ratio, priority_bias)
```

| 分量 | 含义 | 方向 |
|---|---|---|
| `hard_ok` | 两关是否均通过（通过优先） | 降序 |
| `slack_time` | 时间余量 = 最迟起飞时刻 − 当前时刻 | 降序（余量大的靠前） |
| `energy_margin_ratio` | 电量余量比 = (`E_avail` − `E_total`) / `E_avail` | 降序（更宽裕的靠前） |
| `payload_ratio` | 载荷利用率 = 任务载荷 / 机型最大载荷 | 升序（不过度占用大机型） |
| `priority_bias` | 任务优先级偏置 | 与 D 组功能 5 口径一致 |

- **与 D 组功能 5 的衔接契约**：本组排序键**必须可由 D 组复算**（各分量均为显式可导出量），D 组可在其综合择优中覆盖 / 加权；本组不引入 D 组无法复算的隐含偏好，避免"两张皮"。
- **截断口径**：候选数超 `cap_combo` 时按上述排序键**自前向后保留**，保证被截断者严格劣于保留者（单调性），使截断不改变相对优劣。

### 3 算法设计

**核心思路**：两关顺序执行，**先"追得上"后"回得来"**，任一关不过即剪枝，不再进入下一关，降低计算量。两关均依赖上游：第一关依赖 **B 组·会面点求解**，第二关依赖**航迹能耗与电量整环验算**。

**重触发口径（跨组接口）**：飞行中若 E 组功能 17（去程段追踪与纠偏）的 6a 分支**重算会面点**，则以新会面点 / 会面窗对该在飞候选**重新触发本功能判断（复判）**——第一关以新会面点 / 会面窗复判时间可行性；第二关因去程 / 回程航迹长度随会面点变化，需重算整环能耗。复判仍按"回原巢"口径，输出格式与原因码不变；派单阶段的批量判断与飞行中的单候选复判**共用同一套两关判据**。

> **跨组裁决 C-1（结论流向）**：飞行中复判**只更新可行性结论、不直接驱动动作**，结论作为**事实**回给 **E 组功能 9**：追得上 → 由 9 判「继续／调整」；追不上或回不来 → 由 9 判「终止」并进功能 10 归巢。
> **跨组裁决 C-2（红线）**：复判**不触发换机／改派、不改变执行主体**（《项目红线》红线①）。

#### 第一关｜追得上（依赖会面点）

- **判定目标**：无人机从机巢 `n` 出发，能否在会面时刻窗 `[t_arr_min, t_arr_max]` 内到达会面点 `P`。
- **步骤**：
  1. 取 B 组·会面点求解给出的会面点 `P` 与到达时间窗，结合机型速度包线，估算去程飞行时间 `t_fly_out`（含风修正）。
  2. 反推**最迟起飞时刻** `t_launch_max = t_arr_max − t_fly_out − launch_buffer`。
  3. 判定：`t_launch_max ≥ 当前时刻` ⇒ **追得上**；否则 **追不上**。
  4. 若即便立即起飞也晚于 `t_arr_max`（会面窗本身不可达），标记 `追不上-会面窗不可达`。
- **依赖说明**：本关只做**时间可行性**，不重算会面点；派单阶段的会面点与会面窗由 B 组·会面点求解先产出，飞行中的会面点更新由 E 组功能 17（6a 分支）推送并触发复判（见"重触发口径"）。
- **中间量性质（跨组裁决 C-5）**：`t_launch_max` **仅作第一关判据的中间量，不定实际起飞时刻**；实际起飞时刻仍由 B 组功能 14 反推、D 组功能 7 定案，三方不得各算各的。

#### 第二关｜回得来（依赖航迹能耗与电量整环验算）

- **判定目标**：对"去程（机巢→会面点）+ 会面停留 + 回程（会面点→机巢）"整环做能耗与电量验算，确保落回**原机巢**时电量 ≥ 安全余量。**派单阶段只判"回原巢"，不判备降落点。**
- **步骤**：
  1. 去程能耗 `E_out` = 机型能耗模型 × 去程航迹长度 × 最不利风修正。
  2. 回程能耗 `E_back` = 机型能耗模型 × 回程航迹长度 × 最不利风修正（回程常逆风，更耗能）。
  3. 会面停留能耗 `E_hold` = 悬停 / 盘旋功耗 × 预计停留时长（含会面窗等待上限）。
  4. 整环需电 `E_total = E_out + E_hold + E_back`。
  5. 可用电量 `E_avail = 当前电量 − soc_margin`。
  6. 判定：`E_total ≤ E_avail` ⇒ **回得来**；否则 **回不来**（该候选直接不通过，不落任何巢）。

#### 最不利风况的取值方式

- 采用**沿整环逐段取该段最不利风分量（逆风分量最大）**的方式，而非全程取单一最大风。逐段取对能耗最不利的风方向与量级，使能耗估算**偏保守但不至于过度悲观**。
- 风值来源：实时 / 短期预报风场在对应时空网格的取值，可叠加配置的安全系数 `wind_safety`。
- **不取**"历史极端风"（过于保守、误杀可行组合），也**不取**"无风基准"（过于乐观、漏杀不可行组合）。

**参数与阈值（只列名目与含义，不写死取值）**

| 参数名 | 含义 |
|---|---|
| `hold_max` | 会面点盘旋等待的最长时长上限 |
| `launch_buffer` | 反推最迟起飞时刻时的安全缓冲 |
| `soc_margin` | 落巢时须保留的最低电量（比例 / 绝对值） |
| `wind_seg` | 最不利风分段粒度（与风场网格分辨率匹配，待定） |
| `wind_safety` | 风况安全系数，叠加于分段最不利风取值 |
| `cruise_power` | 巡航功耗（机型能耗模型条目） |
| `hover_power` | 悬停 / 盘旋功耗 |
| `wind_factor` | 风速 → 功耗修正系数 |
| `reason_code` | 不通过原因码枚举：`追不上` / `回不来` / `其他` |

#### 参数标定方案（本组自定项 C-8）

> C-8 属标定工作，不涉宏观裁决。**本组只给标定方法、初值建议区间与敏感性方向，最终取值随全项目 `sys_param` 总表统一固化**，避免各组各写死一套值。

| 参数 | 物理含义 | 标定方法 | 初值建议区间 | 敏感性 / 权衡 |
|---|---|---|---|---|
| `launch_buffer` | 反推最迟起飞时刻的安全缓冲 | 以起飞前检查（自检 / 挂载确认 / 停机位离场）实测耗时分布，取 **P95 分位** | 与起飞前流程时长同量级（分钟级） | 过大 → 误杀可行候选、推高误杀率；过小 → 赶不上会面窗 |
| `soc_margin` | 落回原巢时的最低保留电量 | 机型**降落电量离散度** + 安全冗余，取「典型落地余量 + k×σ」；须与 **G 组·低电量预警** 阈值保持「预警线下穿预留」关系 | 高于 G 组预警线一个安全间隔 | 过大 → 候选普遍回不来（剪枝召回虚高、误杀升）；过小 → 挤占返航安全裕度 |
| `hold_max` | 会面点盘旋等待时长上限 | 取会面窗宽度上界 + 盘旋安全上限；与 B 组·会面点求解的会面窗定义一致 | 不超会面窗上限 | 与 `E_hold` 正相关，过大直接吃掉 `E_avail` |
| `wind_seg` | 最不利风分段粒度 | 取**风场网格分辨率**的整数倍（避免过采样/欠采样）；与气象数据源对齐 | = 风场网格粒度或其 2 倍 | 过细 → 计算量升；过粗 → 最不利风低估、漏杀 |
| `wind_safety` | 风况安全系数 | 以**历史误杀率**为约束反向标定：在可接受误杀率下取最小系数（见 §4 敏感性曲线） | 略大于 1 | 关键权衡参数：↑则误杀↑、漏杀↓ |
| `cap_combo` | 单任务候选数上限 | 以 D 组择优耗时预算为约束，找「候选规模—择优时延」拐点 | 与 D 组性能预算联调 | 过小 → 漏掉更优组合；过大 → 拖慢择优 |
| `R_nest` | 机巢地理可达半径 | 取机型续航换算的**最大可飞半径 × 折减系数**；口径（直线 / 规划航迹）须与 **B 组·可飞航迹生成** 对齐 | 续航半径的保守折减 | 直线口径偏乐观（易漏杀），航迹口径更准但依赖 B 组 |
| `TTL_static` | 静态约束缓存刷新周期 | 依据机型 / 机巢配置变更频率设定；异常变更走**主动失效**兜底 | 分钟~小时级 | 过大 → 用陈旧约束；过小 → 缓存收益下降 |

**标定流程（统一口径）**

1. **合成网格扫描** → 定位各阈值的安全边界与拐点；
2. **历史回放标定** → 用 A 组船舶轨迹 + B 组会面点回放，测误杀 / 漏放；
3. **`sys_param` 固化** → 将确定值登记入全项目参数总表，本组正文只留名目与含义；
4. **回归监控** → 上线后以 `wind_safety`、`soc_margin` 为主监控项，偏离计划即回调。

**与外部口径的一致性约束（防冲突）**

- `soc_margin` 与 **G 组·低电量预警** 阈值必须满足「预警线下穿预留」：预警线 > 落地预留线，避免"已触发预警却仍在派单"的逻辑打架。
- `wind_seg` / `wind_safety` 与**气象数据源**网格粒度对齐，不另立一套风场刻画。
- `launch_buffer` 与 **B 组功能 14（起飞时刻回填）/ D 组功能 7（航线确认与起飞时刻确定）** 的起飞前时长口径一致；本组 `t_launch_max` 仅中间量（跨组裁决 C-5），不与之争定实际起飞时刻。

### 4 验证方式

| 维度 | 内容 |
|---|---|
| 数据 / 场景 | ① **合成网格扫描**：可控变量（会面窗宽度、风况、初始电量、机巢距离）做参数网格，验证两关在各边界下的通过 / 剪枝行为正确；② **轨迹回放**：用 A 组·船舶状态估计与轨迹预测管理的船舶轨迹 + B 组·会面点求解的会面点回放若干历史任务，统计剪枝结果；③ **重触发复判场景**：模拟飞行中会面点重算（E 组功能 17 触发），验证复判链路正确触发且口径一致 |
| 指标 | 两关判据**准确率**（与精算仿真对比的误杀率 / 漏放率）；**剪枝召回**（真实不可行组合被剪掉的比例）；**误杀率**（可行组合被错杀比例，过严的最不利风会推高此项）；单候选判断时延；`wind_safety` 敏感性（其对误杀 / 漏放的影响曲线） |

### 5 待定项

- **口径澄清（原"跨机巢备降"表述有歧义，已按项目口径更正，非开放问题）**：派单阶段只判"回原巢"，判"回不来" = 该候选**不通过、不进入择优**；飞行中返航落点决策（原巢 / 借他巢 / 迫降）属 **E 组功能 10（返航复核与归巢资源判定）**，不在本功能范围。
- **阈值标定（本组自定项 C-8，已给出标定方案，见 §3「参数标定方案」）**：`launch_buffer`、`soc_margin`、`hold_max`、`wind_seg`、`wind_safety`、`cap_combo`、`R_nest`、`TTL_static` 的取值随全项目 `sys_param` 总表固化；本组已给方法、初值区间与敏感性方向。**遗留待补**：与 G 组低电量预警线、气象数据源的具体数值对齐。
- B 组·会面点求解输出的"会面窗"若带不确定性（来自船舶轨迹不确定度），本关如何吸收？取窗上限做保守判，还是传递概率？需与 **B 组·会面点求解** 对齐接口。
- 最不利风分段粒度 `wind_seg` 与风场网格分辨率如何匹配？需与气象数据源对齐。
- 电量安全余量 `soc_margin` 是否随任务关键级 / 夜间 / 海况动态调整？需与 **G 组·低电量预警** 口径一致。
- 各组功能编号对照表：建议在总报告统一附一张"各组功能编号对照表"；本方案中他组功能暂以"组名 + 功能名"指代（E 组已按其报告既定编号功能 9 / 10 / 17 引用）。
- 算法方法出处：功能 3 / 4 为工程规则推导，未引用外部文献；若项目要求每个功能附算法文献出处，需补充确认（当前按"规则合理即可"口径执行）。
