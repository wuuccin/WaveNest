## 1 研究范围

| 序号 | 功能名 | 所属模块 | 回答什么问题（一句话） |

| 5 | 候选方案综合择优 | 模块二 调度引擎 | 一批可行候选方案中，按什么代价准则、以什么流程排出选用顺序？ |
| 6 | 资源占用与并发冲突管理 | 模块二 调度引擎 | 机、起飞时段、会面窗口、归巢时隙四类资源怎样占用，并发冲突如何检测与顺延？ |
| 7 | 航线确认与起飞时刻确定 | 模块二 调度引擎 | 精算航迹后怎样反推起飞时刻、消解航迹冲突，并在回写占位后完成二次校验？ |
| 8 | 任务队列与状态管理 | 模块二 调度引擎 | 多订单按什么节奏、什么顺序进入调度，等待与限流如何管理？ |

本文遵循三条总纪律：

1. **先可行、后择优**：功能 5 只在已通过「追得上、回得来」两关的候选内比较，任何时间/能耗优势都不能召回安全不可行方案。
2. **优先级不跨层**：订单优先级只在订单与订单之间（功能 8）起作用，不参与同一订单候选之间（功能 5）的比较。
3. **先占先得、绝不抢占**：已确认占位不被后来订单移动；后来者只顺延自己，顺延触顶则换候选或等待。

## 2 共享约定（四功能公共部分）

### 2.1 术语与状态词（沿用既定口径，不另造）

- 订单状态、无人机状态、货物状态枚举，一律沿用 `23-状态机定义` 的枚举定义（原稿引用的《数据库与缓存模块-功能细化》已归档，枚举权威处为 `23`）；本文只引用，不重画状态机。
- 订单状态关键词：待调度 / 已受理待唤醒 / 调度中 / 执行中 / 返航中 / 已完成 / 已拒绝 / 失败 / 异常终止（货物灭失）。
- 无人机状态关键词：空闲 / 已预占 / 执行中 / 返航中 / 迫停 / 迫降 / 故障 / 维护 / 失联。
- 货物状态关键词：未就绪 / 已就绪 / 已装机 / 已交付 / 已回收 / 灭失。
- 占位状态关键词：**有效 / 已释放 / 已过期**。
- 归巢目标默认**原驻巢**；默认回原巢时不占容量、不落容量锁，仅占用归巢时隙；他巢占用只在应急迫停获批时发生（属功能 10，不在本文范围）。

### 2.2 候选方案对象的表示

功能 4 输出的每一个可行候选组合，是功能 5 的比较单元，统一表示为：

```text
候选方案 C = {
  机型,
  出发机巢 nestId（= 默认归巢目标）,
  具体无人机 droneId,
  粗估会面点 P_meet（经纬度，绑定本组合）,
  粗估会面时间窗 [t_meet^lo, t_meet^hi),
  理论（粗估）飞行时长 τ_coarse、粗估能耗 E_coarse,
  预计返航剩余电量 SOC_ret,
  任务风险标记 R（风/空域/预测不确定性）
}
```

- 会面点是**组合级产物**：不存在对所有无人机相同的全局会面点。
- 粗估量来自功能 4（直线近似 + 风况修正），精算量来自模块三的可飞航迹；两者是两笔账，不得混用。

### 2.3 时隙统一模型

- 一切时间占用统一表示为**连续半开时间窗** `[t₁, t₂)`，长度 `d = t₂ − t₁`，与模块六 `occupancy_slot` 台账「[t₁, t₁+d]」口径对应（末端开闭约定在落库时统一）。
- **安全缓冲并入区间后再判重叠**：不同资源的缓冲参数不同（见 2.4），占用区间 = 业务区间向两侧扩展缓冲。
- 半开区间重叠判据（参考 Interval Tree 与主流日历组件的排他结束约定）：

```text
区间 A、B 冲突  ⇔  A.t₁ < B.t₂  且  B.t₁ < A.t₂
```

- **占位链**：一个候选方案的起飞时段、会面窗口、归巢时隙不是独立资源——起飞时刻一旦平移，三者连锁平移，任何检测与回写都以链为单位整体进行；机占用覆盖全任务区间。
- 占位分两个阶段：**暂定占位**（粗估时刻，带 TTL）→ **确认占位**（精算回写并二次校验通过）。

### 2.4 四类资源与键控方式

| 资源 | 键控（按谁互斥） | 区间含义 | 缓冲/间隔参数名目 |
|---|---|---|---|
| 机占用 | `droneId` | 从预占到落巢的全任务区间，独占 | 占位有效期 T_hold（软占位存活） |
| 起飞时段 | `nestId` | 该巢起降坪/作业通道的起飞占用窗 | 起飞安全缓冲；同向起飞间隔、反向（起降交叉）间隔 |
| 会面窗口 | `shipMMSI` | 目标船接收交接的时间窗 | 会面交接缓冲 |
| 归巢时隙 | `nestId` | 该巢返航降落占用窗 | 降落安全缓冲；同向/反向间隔 |

关键约定：

1. **起飞与归巢共用同一条巢位作业通道**：同一 `nestId` 下，起飞时段与归巢时隙放在同一张区间表中互相检测，同向、反向间隔分别参数化。
2. **同一艘船同一时刻只能接收一架机**：会面窗口按 `shipMMSI` 互斥，交接缓冲计入。
3. 默认回原巢时，归巢时隙只表达"何时占用作业通道"，**不表达容量竞争**。

### 2.5 上游数据输入总表（表示方式与粒度）

| 数据 | 从哪来 | 表示方式与粒度 |
|---|---|---|
| 订单 | 订单接入与校验（功能 1）/ `order_task` | orderId、船 MMSI、货物重量/类型、期望送达时间、订单优先级（订单级）、订单状态；粒度：单订单 |
| 船舶预测轨迹 | 功能 2（按需精算预测） | 带不确定性带的时间序列航迹点 + 有效期 + 前提可信状态 + **预测版本号**；同一轮调度所有候选共用同一版本 |
| 常驻预测快照 | 功能 2（常驻预测） | 全量在航船舶短期轨迹快照，粒度可粗于精算；用于等待唤醒与驶入判定 |

| 参数 | `sys_param`（模块六） | 阈值/权重/间隔/窗口/容量集中管理，本文只引用键名 |

### 2.6 统一边界（四功能共同不做的事）

- 不做船舶轨迹预测与航迹计算本身：只调用模块二功能 2、模块三的结果。
- 不做气象红线、服务航段、货物就绪的受理判定：那是功能 1/12 的职责。
- 不做飞行中重新调度、返航迫停准入：属功能 9/10。
- 派单阶段不做计划性改投他巢。
- 本文不给出任何参数的具体取值，只列名目与含义。

## 3 功能 5 候选方案综合择优

### 3.1 输入与输出

- **输入**：功能 4 输出的可行候选集合（2.2）；同一版本船舶预测；当前活跃占位概览（用于繁忙度统计）；权重与归一参数（`sys_param`）。
- **输出给谁**：排好顺序的候选方案列表 → 功能 6（取首位做占位）；暂定最优方案及其选择理由；落选原因（供功能 11 记录）。
- **边界（不做什么）**：不召回可行性判断已淘汰的方案；不接受订单优先级作为打分输入；不直接生成航迹与起飞时刻。

### 3.2 算法设计

#### 3.2.1 做法选择：多目标加权代价函数

在可行候选内，对五个代价维度评分、归一、加权求和，取综合代价最小者：

```text
Score(C) = Σ_k  w_k · n_k(C)        （w_k 为权重，n_k 为归一化后的该维代价）
选定方案 = argmin Score(C)
```

**为什么选它（而不是拍卖式分配）**：

1. 主流程已把多对多问题**串行化**——功能 8 先决定订单进入调度的顺序，进入调度的单个订单再展开自己的候选集合并逐个占位/回退。拍卖机制要解决的"多订单同时对多资源竞价"的组合爆炸在本架构中不存在。
2. 加权代价的每一维、每一权重都可解释、可复盘，契合功能 11 的决策依据保存与答辩展示要求；拍卖的价格迭代过程对调度员不直观。
3. 与「优先级只在订单间起作用」的定稿天然一致：本层全部候选同属一个订单，评分只含候选间取值不同的量。

**拍卖式机制保留为对比项与未来选项**（见 3.2.5），当架构演进为多订单全局联合分配时可重新评估。

#### 3.2.2 五个代价维度

| 维度 | 取值 | 方向 | 含义 |
|---|---|---|---|
| 时间 | 预计完成时间（或粗估会面时刻） | 越小越好 | 送达早晚 |
| 能耗 | 粗估往返能耗 | 越小越好 | 运行成本与电池占用 |
| 余电 | 返航剩余电量 SOC_ret | 越多越好 | 安全裕度 |
| 风险 | 任务风险（沿途/会面风况、空域、预测不确定性） | 越低越好 | 执行不确定性 |
| 繁忙度 | 候选机/巢当前与近期占用率 | 越低越好 | 负载分散 |

#### 3.2.3 归一化与计分规则

1. **时间、能耗两维：候选集内 min-max 归一**：

```text
n_k(C) = ( x_k(C) − min_k ) / ( max_k − min_k )      （越小越好的维度）
```

   本评分只服务单订单候选排序，不跨批次比较，因此候选集归一不损失可用性，且在候选数量很少（通常 2–5 个）时区分度最好。当某维所有候选取值相同（max = min），该维归一值统一记为 0（不产生区分）。

2. **余电、风险两维：固定阈值效用，不做候选集归一**。防止"全体候选电量都偏低/风险都偏高"时矮子里拔将军——效用函数以安全阈值（如余电安全余量阈值、风险分级阈值）为基准刻画，参数化配置。
3. **计分放大为整数**：归一值统一乘以计分放大系数后取整，加权求和得到整数综合分，避免浮点排序争议（企业级约束求解器的通行做法）。
4. **繁忙度不占固定权重，仅作并列决胜项**：繁忙度是全局态，给固定权重会使同一方案在不同批次分数漂移。决胜顺序：

```text
综合分小者优先 → 并列时繁忙度低者优先 → 再并列时余电高者优先
```

5. 权重 w_k、各阈值、放大系数均为 `sys_param` 参数，不写死。

#### 3.2.4 粗估择优与精算回填的两级关系

```text
第 1 级（粗估）：以功能 4 的粗估量对全部可行候选打分排序
第 2 级（精算）：仅取粗排前 K 个候选提交模块三精算
                 得到精算时长/能耗/路径风险后，按同一代价函数重排
                 → 第 1 名进入功能 6 占位
前 K 个全部占位失败 / 二次校验失败：
                 释放本批临时占位，展开下一批 K 个粗排候选，重复上述过程
```

- **K 为配置参数**：精算要生成真实可飞航迹，是全流程最贵的计算，不全量精算。
- 若精算值与粗估值偏差超过**精算偏差阈值**，说明功能 4 的电量判断建立在错误时长上，退回重验电量（沿用模块三已定口径），不带着失真估计继续占位。

#### 3.2.5 与拍卖式分配的对比（论证不选）

| 对比项 | 加权代价函数（选用） | 拍卖式（Bertsekas / CBAA / CNP） |
|---|---|---|
| 适用结构 | 单订单内多候选、订单串行处理 | 多任务多智能体同时竞价的全局分配 |
| 可解释性 | 维度、权重逐项可解释 | 价格迭代、共识轮次不直观 |
| 与本流程契合 | 与队列排序、先占先得直接衔接 | 需另建竞价/共识协议，与占位串行模型重叠 |
| 主要风险 | 权重依赖标定 | 通信轮次、价格震荡、与时间窗占位耦合复杂 |
| 未来适用条件 | —— | 若改为多订单联合分配、机群规模显著增大，可作为功能 8 之后的全局优化层重新评估 |

### 3.3 验证方式

- **场景**：①多候选时间/能耗/余电排序结果与人工直觉一致；②全体候选余电偏低时固定阈值效用不产生"最优"错觉；③粗排前 K 截断后精算重排发生名次翻转的比例；④精算偏差超阈退回重验的触发正确性。
- **指标**：择优结果与全量精算"理想排序"的排序一致率、前 K 截断造成的最优解错失率、精算调用次数（算力开销代理指标）、综合分对权重扰动的稳定性。
- **对照**：加权代价 vs 拍卖式分配在同一场景下的方案质量与计算开销（拍卖仅在仿真对照中实现）。

### 3.4 待定项

- 五维权重的标定方法（专家赋权 / 历史数据客观赋权如熵权、CRITIC）未定。
- 风险维度的量化合成口径（风、空域、预测不确定性如何合并为一个风险效用）待定。
- K 的取值需用场景数据在"精算开销—错失率"曲线上标定。

## 4 功能 6 资源占用与并发冲突管理

### 4.1 输入与输出

- **输入**：功能 5 排序后的候选方案（按顺序逐个尝试）；`occupancy_slot` 台账与缓存活跃占位集；间隔/缓冲参数；占位有效期 T_hold；订单送达时限与最大顺延时长。
- **输出给谁**：占用成功 → 方案进入功能 7；冲突不可消解 → 切换下一候选；当前候选全部失败 → 订单进等待队列（功能 8）或拒单/转人工；占用与释放记录 → 功能 11。
- **边界（不做什么）**：不移动、不撤销他人已确认占位；不做巢位容量分配（默认回原巢）；不做航迹本身的冲突判定（功能 7 的航迹级二查）。

### 4.2 算法设计

#### 4.2.1 占用对象与键控

按 2.4 表执行：机（`droneId` 全任务独占）、起飞时段与归巢时隙（`nestId`，起降同表互检，同向/反向间隔）、会面窗口（`shipMMSI`，含交接缓冲）。占用前先把各自安全缓冲并入区间。

默认回原巢不占容量、不落容量锁；仅应急迫停获批时才占用他巢时隙（功能 10）。

#### 4.2.2 冲突检测

```text
对候选占位区间 X（键控资源为 key）：
  取出该 key 下全部「有效」占位 → 按 2.3 半开区间判据逐一比对
  任一重叠即冲突
```

- 实现结构：缓存维护按 key 组织的活跃占位集做快速预检（可参照区间树的按区间重叠查询结构）；数据库事务做最终仲裁（见 4.2.6）。
- 检测以**占位链**为单位：机占用、起飞、会面、归巢四个区间在各自键控空间内全部无重叠，才算该候选通过。

#### 4.2.3 顺延策略（贪心，只动自己）

```text
当占位链中某区间冲突：
  以顺延步长 Δ_shift 为单位，将整条占位链向后平移
  逐位检查，找第一个使四类区间对各自键控均无重叠的位置（最早可行位）
约束（双上限，任一触顶即该候选失败）：
  ① 累计顺延 ≤ 最大顺延时长
  ② 顺延后预计完成时刻 ≤ 订单送达时限
候选失败 → 释放本次临时占位 → 尝试候选列表下一名
全部候选失败 → 进等待队列（等运力）/ 拒单 / 转人工
```

纪律：

1. **一次贪心底移找最早可行位**，不做反复来回微调，避免时刻震荡。
2. 只平移本订单的占位链，绝不修改他人已确认占位（与不抢占总则一致）。
3. 平移后会面窗口、归巢时隙随之改变，必须整体重检——这也是功能 7 精算后必须回写占位的原因。

#### 4.2.4 软占位生命周期与 T_hold

```text
创建暂定占位（粗估时刻，状态=有效，记录到期时刻 = now + T_hold）
  → 在 T_hold 内完成精算回写：同事务"续租"并转确认占位
  → T_hold 内未完成：超时巡检自动释放（状态=已过期）
取消 / 调度失败 / 异常终止：立即释放（状态=已释放）
```

- T_hold 参数化；超时巡检周期另设参数。
- **幂等**：同一 orderId 只允许一组有效占位，禁止同一订单生成多个有效任务；占位轮次号与 orderId 共同构成幂等键。

#### 4.2.5 释放与一致性

- 任务取消、调度失败、占用超时：及时释放全部相关占位，无人机回「空闲」。
- 任务异常终止（含货物灭失）：**同事务**释放全部占位；无人机灭失时状态转故障/失联，不回空闲。
- 货物落巢回收完成后，由调度引擎写入订单重新入队（事件驱动进入批次队列，见功能 8），不走特殊通道。
- 资源占用与任务状态始终一致：占位存在 ⇔ 订单处于调度中及以后状态。

#### 4.2.6 MySQL 下的原子占用

系统数据库采用 MySQL。MySQL 不具备 PostgreSQL 基于范围类型的 GiST 排他约束，区间重叠无法用唯一索引表达，因此：

```text
BEGIN;
  -- 对本次涉及的键控资源/占位行加锁（SELECT … FOR UPDATE，按 nestId / shipMMSI / droneId 维度）
  -- 事务内：读入该 key 下全部有效占位 → 重叠检测
  -- 无冲突：写入占位行（occupancy_slot）
  -- 精算回写场景：更新时刻并在同一事务内完成二次校验
COMMIT;  -- 冲突则 ROLLBACK，按顺延/换候选处置
```

- `occupancy_slot` 建立支撑查询的索引：（对象类型、关联对象 Id、状态）及时间字段索引。
- 缓存（Redis）活跃占位集只做**快速预检**以降低事务冲突，不承担正确性：预检通过仍以数据库事务仲裁为准；预检失败不影响数据正确。
- 应用层幂等键（orderId + 占位轮次）防止并发重试产生重复占位。
- 该落法与模块六「占位原子占用，事务保证占位与时刻一致」的既定口径一致。

### 4.3 验证方式

- **场景**：同巢多机同时段抢起飞、同船两单抢会面、起飞与返航在同巢交叉、顺延触及送达时限、占位 T_hold 超时、取消/异常终止后的释放、并发重试重复占位。
- **指标**：时隙冲突逃逸数（已确认占位中仍存在重叠的数量，**目标恒为 0**）、顺延触发率与平均/最大顺延时长、候选切换次数、占位获取事务冲突/回滚率、超时释放及时率、占位与状态不一致条数（目标 0）。

### 4.4 待定项

- 加锁粒度（按 nestId 行锁 vs 占位明细行锁）在高并发下的性能表现待压测验证。
- T_hold 与精算耗时分布的匹配关系需实测标定，过短会误释放、过长会占住运力。
- 缓存预检与数据库仲裁不一致的极端时序（预检后、事务前他单提交）完全依赖事务回滚重试，重试策略参数待定。

## 5 功能 7 航线确认与起飞时刻确定

### 5.1 输入与输出

- **输入**：功能 6 暂定占位成功的候选方案；模块三精算能力（可飞航迹、精算时长、精算能耗、路径风险、航迹冲突二查）；会面时间窗；收敛容差、最大迭代次数、错峰间隔与重试上限等参数。
- **输出给谁**：完整派单方案（机、巢、实际航线、起飞时间、会面点与窗口、完成时间）→ 创建正式任务并交功能 8 状态管理；回写后的确认占位 → `occupancy_slot`；退回/失败原因 → 功能 11。
- **边界（不做什么）**：不自行计算航迹（提交模块三）；不带着已知冲突或失真电量生成任务；精算导致方案不可行时退回候选选择，不勉强派机。

### 5.2 算法设计

#### 5.2.1 起飞时刻反推的循环依赖

基本关系为：

```text
t_takeoff = t_meet − τ_fine（精算去程时长）
```

但起飞时刻一旦后移（顺延/错峰），船舶在新时刻起的可会面位置改变 → 会面点要以新的求解起点重解 → 航迹重算 → τ_fine 再变。该循环用**迭代不动点**处理：

```text
初值：t_takeoff^(0) 取当前可用时刻（功能 4/6 的粗估结果）
循环 i = 0,1,2,…：
  ① 以 t_takeoff^(i) 为求解起点，重解本组合会面点，得 t_meet^(i)
  ② 提交模块三生成可飞航迹，得精算时长 τ_fine^(i)
  ③ 反推 t_takeoff^(i+1) = t_meet^(i) − τ_fine^(i)
  ④ 收敛判据：
       |t_takeoff^(i+1) − t_takeoff^(i)| ≤ 收敛容差
       且会面点位移 ≤ 会面点收敛距离
  满足 → 收敛，进入冲突二查
达到最大迭代次数仍不收敛 → 该候选失败，回功能 6 换候选
```

- 参数名目：**收敛容差、会面点收敛距离、最大迭代次数**。
- 不选择"只反推一次"：顺延/错峰可能把起飞时刻推出较远，一次反推的残差未必落在模块三去程纠偏阈值内；迭代逻辑简单，且"不收敛"本身是有效的淘汰信号。

#### 5.2.2 航迹级冲突二查与错峰

```text
对精算航迹补做航迹级空域冲突二查（模块三）：
  无冲突 → 进入回写
  有冲突 → 处置优先级：
    第一步 错峰：以后飞者为对象，以时间安全间隔 Δ_sep 为基准、
            按顺延步长 Δ_shift 递增平移起飞时刻，
            每平移一次重新走 5.2.1 不动点迭代并重查冲突；
            受最大顺延时长、送达时限、错峰重试次数上限三重约束
    第二步 绕行：错峰达到上限仍冲突 → 请求模块三规划绕行航迹
    第三步 回退换候选（仅派单阶段、起飞前）：绕行仍不消除冲突 → 该候选失败，
            回功能 6 取候选列表下一名，全套流程重走
```

- 错峰改变起飞时刻，必然连锁平移会面窗口与归巢时隙——旧占位作废，按下条回写。

#### 5.2.3 回写占位与二次校验（同一事务）

```text
精算/错峰/绕行确定新时刻后，在同一数据库事务内：
  ① 更新机占用、起飞时段、会面窗口、归巢时隙四类占位（旧窗→新窗）
  ② 二次校验（全部通过才允许提交）：
     a. 机占用对 droneId 无重叠
     b. 起飞时段、归巢时隙对 nestId 无重叠（含起降互相错峰、同向/反向间隔）
     c. 会面窗口对 shipMMSI 无重叠（含交接缓冲）
     d. 按精算能耗复算返航剩余电量 ≥ 安全余量阈值
  ③ 占位续租（重置 T_hold），暂定占位 → 确认占位
COMMIT
```

- **校验范围是四类占位全集，不是只检被改动项**：其他订单可能在本单精算期间已提交新占位。
- 二次校验失败处置顺序与航迹冲突一致：本轮重新错峰（重试次数上限参数化）→ 绕行 → 换候选；连续失败则订单回等待队列并记录原因。
- 纪律：**不允许"带着已知冲突占位"生成任务**。

#### 5.2.4 精算偏差与完整派单

- 精算时长/能耗与粗估差异超过精算偏差阈值：重新检查电量、会面窗口、归巢目标；电量不再满足则按候选失败处理（与 3.2.4 衔接）。
- 所有条件通过后生成正式任务，派单方案内容：具体无人机、出发机巢与归巢目标（默认原巢）、实际飞行航线、起飞时间、会面位置与窗口、预计任务完成时间。

### 5.3 验证方式

- **场景**：顺延较远时不动点迭代收敛、迭代不收敛候选淘汰、双机航迹时空接近触发错峰、错峰连锁平移占位链、绕行后冲突消除、精算期间他单提交占位导致二次校验失败、精算偏差超阈重验电量。
- **指标**：不动点平均迭代次数、不收敛发生率、错峰一次成功率、错峰→绕行→换机的处置分布、二次校验拦截到的冲突数（应 > 0 且全部被拦截，逃逸 = 0）、确认时刻到起飞时刻的余量。

### 5.4 待定项

- 不动点迭代是否存在震荡（非单调收敛）情形，是否需要引入松弛/阻尼系数，待场景验证。
- Δ_sep 与功能 6 各缓冲参数的口径关系（同一间隔还是分别定义）需统一。
- 绕行航迹本身改变能耗，绕行后是否再次触发电量重验的判据阈值待定。

## 6 功能 8 任务队列与状态管理

### 6.1 输入与输出

- **输入**：已受理订单（功能 1）；各等待原因订单；资源释放/货物就绪/唤醒事件；功能 12 闸门状态；批次窗口、排序权重、限流上限等参数。
- **输出给谁**：每批次按序进入调度的订单 → 功能 5；订单/无人机当前状态与占用状态 → 模块五展示、功能 11 记录；下一个待调度订单。
- **边界（不做什么）**：不决定单订单选哪套资源（功能 5 的职责）；不直接改派货物；被限流订单不拒单、只留队。

### 6.2 算法设计

#### 6.2.1 批次触发模型（周期窗口 + 事件触发）

```text
周期触发：每隔批处理窗口长度，关闭一个批次并按序释放进入调度
事件触发：加急单到达 / 资源释放 / 等待订单唤醒，可提前组织批次
节流约束：两次触发间隔 ≥ 最小触发间隔；单批订单数 ≤ 单批最大订单数
闸门联动：气象熔断 / 人工冻结期间，批次触发整体挂起（订单保持受理态，非拒单）；
          在飞任务不受影响
```

纯周期牺牲加急时效、纯事件在需求暴增时失控，混合模型两者兼顾。

#### 6.2.2 订单排序键（动态）

批次内按排序键从大到小进入调度：

```text
Key(O) = w₁·S_priority(O) + w₂·S_deadline(O) + w₃·S_aging(O)
```

| 分量 | 含义 | 口径 |
|---|---|---|
| S_priority 优先级分 | 订单优先级直接映射 | 订单级属性，只在此层出现 |
| S_deadline 时限紧迫度 | 期望送达时间与预计完成耗时的余量，余量越小分越高 | EDF（最早截止期优先）思想 |
| S_aging 老化分 | 等待时长 × 老化系数 | 等待越久分越高 |

- 权重 w₁/w₂/w₃、老化系数全部参数化；排序键每次组批时动态计算。

**防饥饿（双重硬机制）**：

1. 普通单**保底位次**：队列中普通订单在满足条件时获得不低于某位次的调度保障；
2. **加急单连续插队次数上限**：超过后该批次必须放行队首等待最久的普通订单。

两者共同防止普通订单在持续加急流量下长期无法执行。

#### 6.2.3 等待子队列与唤醒

| 子队列 | 等待原因 | 唤醒方式 |
|---|---|---|
| 等船 | 船会驶入但尚未进入服务航段 | 常驻预测给出驶入时刻，按预计可派单时刻定时唤醒 |
| 等货 | 已受理但货物未备好 | 货物就绪事件唤醒 |
| 等运力 | 无可用资源 / 时隙冲突失败 | 资源释放事件唤醒 + 最长重入队时长兜底轮询 |

**唤醒纪律**：唤醒不等于立即派单——唤醒订单回到批次就绪队列，按 6.2.2 重新排序，防止"后唤醒的单直接插到队首"，也避免唤醒风暴。

#### 6.2.4 节流限流四层体系

| 层 | 控制内容 | 参数名目 | 超限处置 |
|---|---|---|---|
| 批次层 | 批处理窗口长度、单批最大订单数、最小触发间隔 | 同 6.2.1 | 留到下一批 |
| 准入层 | 全域同时在飞任务数上限（受机队规模约束） | 在飞任务总数上限 | 已受理订单留在就绪队列 |
| 资源层 | 单巢单位时间起飞架次上限；单船单位时间会面接收架次上限 | 令牌桶：桶容量、令牌生成速率（参考令牌桶模型） | 顺延到下一个可用时隙/批次，不拒单 |
| 熔断层 | 气象熔断 / 人工冻结 | 闸门状态（功能 12） | 批次挂起，解除后恢复 |

- 资源层令牌桶：按固定速率生成许可、允许一定突发桶容量，获取不到许可的订单不构成拒单，按时隙顺延或下一批处理。
- 所有上限均参数化，超限订单一律**留队不拒单**；拒单只来自业务边界与运力彻底无解。

#### 6.2.5 状态管理与幂等

- 维护订单状态流转、无人机状态流转（枚举引用模块六）：任务取消/失败/完成时同步释放或更新资源。
- 防止同一订单生成多个有效任务：以 orderId 为幂等键，已在调度中/执行中的订单不重复组批。
- 回收重派：货物回收后订单以事件方式重新进入就绪队列，按统一排序键参与排序。

### 6.3 验证方式

- **场景**：加急与普通单混合排序、加急连续插队触发防饥饿、等船/等货/等运力三类唤醒、唤醒后重排、需求暴增下批次与在飞上限限流、单巢/单船令牌桶节流、熔断挂起与解除恢复。
- **指标**：接单成功率、订单平均/最大等待时长、普通单最大等待时长（防饥饿指标）、时限满足率、批次触发频率与单批规模、在飞任务数峰值与准入拒绝（留队）次数、单巢/单船单位时间架次、限流留队订单比例。
- **对照**：老化机制开/关对普通单最大等待的影响；周期+事件混合 vs 纯事件触发在需求暴增下的稳定性。

### 6.4 待定项

- 排序键三部分权重与 EDF 紧迫度的具体函数形式（线性余量 / 阶梯 / 指数）待标定。
- 保底位次与加急插队上限两个硬机制的参数需在流量分布上平衡加急时效与公平性。
- 在飞总数上限按机队规模的何种比例设定、是否随气象/能见度动态收紧，待定。

### 8.2 指标体系

- **正确性（硬指标）**：时隙冲突逃逸数 = 0；占位与状态不一致条数 = 0；二次校验拦截后无冲突任务生成。
- **效率**：接单成功率、时限满足率、平均/最大等待时长、普通单最大等待时长。
- **资源**：顺延触发率、平均/最大顺延时长、单巢/单船单位时间架次、在飞任务数峰值、机巢与无人机利用率。
- **开销**：精算调用次数、不动点平均迭代次数、占位事务回滚率、批次触发频率。

## 9 统一待定项与风险

1. **参数标定数据缺乏**：权重、K、T_hold、各间隔与限流上限均依赖真实/仿真运行数据，当前只能给名目；首轮取值后必须经场景回归调整。
2. **风险维度量化口径未定**：风、空域、预测不确定性合成一个风险效用的方式待定，存在主观合成风险。
3. **MySQL 加锁性能**：高并发按 nestId/shipMMSI 加锁可能成为瓶颈，锁粒度与重试策略需压测；缓存预检只降冲突、不改变正确性边界。
4. **不动点震荡风险**：起飞时刻迭代若非单调收敛需引入阻尼，机制待验证。
5. **错峰连锁扩散**：多单密集时顺延可能逐级向后扩散（非抢占下的级联等待），需以最大顺延与送达时限兜底，并在验证中观察扩散深度。
6. **公平与时效的平衡**：保底位次/插队上限参数不当会损伤加急承诺，需结合实际订单优先级分布设定。
7. **缓存与库一致性**：Redis 预检与 MySQL 仲裁间的极端时序完全依赖事务回滚与重试，补偿链路需与模块六联合验证。
