## 1 第 6–7 步：去程追踪与纠偏、末段会面与交接

```mermaid
sequenceDiagram
    autonumber

    box rgb(232,245,233) 态势与预测层 · 持续在线
    participant SE as 态势估计<br/>持续在线的当前态势
    participant TP as 轨迹预测<br/>重估「船未来会到哪」
    end

    box rgb(227,242,253) 调度与监控层
    participant DP as 调度引擎 M2<br/>6b 回上游时重跑
    participant M4 as 飞行任务监控 M4<br/>接收任务方案
    end

    box rgb(255,243,224) M3 · 去程纠偏循环
    participant M3 as M3 路径规划<br/>去程纠偏循环（33）· 每收到新状态触发
    end

    participant RS as 会面求解 M3<br/>32 动态会面 · 同一机同一巢重算会面点
    participant FC as 飞控<br/>执行与回传实况

    DP ->> M4: 任务方案（机 · 巢 · 会面点 · 起飞时刻）
    M4 ->> FC: 上行指令（判定与编码后经 M1 的 MQTT 通道下发）
    Note over M4: 遥测经 M1 接入后由本模块做飞行语义级清洗，写入共享数据源（见 91-2）
    activate M3
    Note over M3: 第 6 步 · 去程段（起飞即进入）：循环体在 M3 路径规划（33 §3.5）；实时追踪横切在线，不单设生命线
    loop 每收到一次新状态（新遥测触发）
        SE -->> M3: 新态势（船位 / 航向 / 航速）
        M3 ->> TP: 重估「船未来会到哪」
        TP -->> M3: 更新后的预测 ＋ 前提有效性
        alt 偏差未超容忍阈值
            M3 ->> M3: 小幅抖动不改指令，避免空中反复横跳
        else 偏差超阈值 · 前提仍成立（6a 量变）
            M3 ->> RS: 以同一机、同一巢重算会面点
            RS -->> M3: 更新后的会面点
            M3 ->> FC: 只重算这一架机的会面点并下发新指令（减速 / 加速 / 避让 / 换道），不重新选机
        else 偏差超阈值 · 前提已失效（6b 质变）
            M3 ->> DP: 回上游上报前提已失效（航向持续偏离 / 速度持续趋零 / 进入分汊点、锚地、港区）：变的是「船怎么走」，原预测已不适用
            DP ->> TP: 重算轨迹
            TP -->> DP: 新轨迹
            DP ->> DP: 重跑第 2、3 步及之后：可达性 → 择优 → 占位
            DP ->> FC: 出口只有两个：原机继续追（重算会面点）／ 放弃本次会面（原机带货返航或迫停）
            Note over DP: 飞行中不存在换机出口；换机须待货物回收后重派，见 91-7
        end
    end
    Note over FC: 第 7 步 · 末段（进入会面点邻域即切入）：控制目标切换为「我与船此刻相对怎样」
    FC ->> FC: 保持相对速度趋近于零、相对位置稳定于甲板上方；不再重算会面点
    FC ->> FC: 四子阶段：接近 → 匹配 → 交接 → 脱离
    alt 对接失败
        FC ->> FC: 重试 ／ 悬停等待 ／ 放弃本次会面并上报 M2
    else 交接成功
        FC ->> RS: 交接完成（含伴飞与交接的时间、能耗开销）
        RS ->> DP: 交接完成确认
        DP ->> M4: 任务状态更新（M4 记录投送结果）
        Note over RS,DP: 水上交接的完成与否以 M3 本功能的判定为准，M4 的投送确认只记录结论
    end
    deactivate M3
```

## 2 兜底保障：横切在线

```mermaid
sequenceDiagram
    autonumber

    box rgb(255,243,224) 监控侧
    participant M4 as 兜底监控 M4<br/>检测与上报 · 横切在线
    end

    box rgb(227,242,253) 调度层
    participant DP as 调度引擎 M2<br/>决策
    end

    participant M3 as M3 动态会面、路径规划<br/>重算会面点 · 航迹级冲突检测
    participant FC as 飞控<br/>执行

    Note over M4,DP: 兜底不是第 9 步，而是从起飞到归巢横切在线的监控机制 —— 检测归 M4，决策归 M2
    loop 全程持续监视，触发即介入
        M4 ->> DP: 电量告急
        DP ->> FC: 提前返航 ／ 申请迫停（优先近处机巢，须判准入；无可借机位时选应急迫降点）
        M4 ->> DP: 风速突变超阈值
        DP ->> FC: 降速改航 ／ 放弃本次会面，原机带货返航或迫停
        M4 ->> DP: 船舶大幅变向或减速
        DP ->> M3: 重算会面点；若已不可达则进入第 6b 步意图变更流程
        M4 ->> DP: 船位信号丢失
        DP ->> FC: 降级为沿航道外推；超时未恢复则盘旋等待或返航
        M4 ->> DP: 通信中断
        DP ->> FC: 按最后已知指令执行 ＋ 自主返航
        M4 ->> DP: 无人机失联或灭失
        DP ->> DP: 按最后已知位置与时间外推搜寻；确认灭失则货物随之灭失，订单标记异常终止
        M3 ->> DP: 临时禁飞、空域管制突现（航迹 × 空域台账检测）
        DP ->> M3: 实时改航绕行
        M3 ->> DP: 多机航迹冲突（航迹级空域冲突二查）
        DP ->> DP: 派单时先查资源占用，航迹算出后再按航迹级查一次；优先错峰或绕行，都不行才回退换候选（仅派单阶段、起飞前；飞行中禁换机）
    end
```

## 3 说明

1. 任务下达按 `22` §5 画成 `M2 → M4`；飞控侧的上行指令由 M4 判定与编码、经 M1 的 MQTT 通道下发（M1 的收发链路见 `91-2`）。
2. 兜底一图中「`M2` 决策 → M3 执行改航或退避」按 `22` §5 与 `21` §7 画出 `M3` 这一环，不再让检测侧直接指挥飞控。
3. 6b 与末段交接确认的发起方都不是飞控：6b 由 M3 判定后上报 M2，交接完成由 M3 判定后回报 M2——依据 `22` §5 的硬约定「闭环只经 M2 闭合」与 `32` §3.5、`33` §3.5。
4. **去程纠偏循环体在 M3**：第 6 步去程段环形循环由 **M3 路径规划（33 §3.5）**承载、以「每收到一次新状态（新遥测）」为触发，**飞控（FC）不驱动该循环、不直连 TP／RS**，FC 只执行与回传实况——依据 `22` §7.2 **U-01 裁定**（2026-10-10，组长）。本图第 1 节已按此订正（循环驱动方由 FC 改为 M3）。
