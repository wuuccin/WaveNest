## 1 第 8 步：返航复核与落点判定

```mermaid
sequenceDiagram
    autonumber

    box rgb(227,242,253) 调度层
    participant DP as 调度引擎 M2<br/>归巢复核 · 落点判定
    end

    box rgb(243,229,245) 存储层
    participant DB as 存储与台账 M6<br/>迫停准入 · 占用时间窗
    end

    participant RP as 航迹规划 M3<br/>返航航迹 · 返程电量
    participant FC as 飞控<br/>返航执行

    activate FC
    Note over DP: 第 8 步 · 返航与回收：交接完成后触发（见 91-6）；归巢目标在派单时已定为原驻巢，此处为复核
    DP ->> DB: 取实际剩余电量与实时风况
    DB -->> DP: 电量与风况
    DP ->> DP: 复核：能回原巢就回原巢（回原巢无需占位）
    alt 回不去原巢
        DP ->> DB: 向近处机巢申请应急迫停，按占用时间窗判定准入
        DB -->> DP: 准入结论
        alt 无可借机位
            DP ->> DP: 选应急迫降点
        end
    end
    activate RP
    DP ->> RP: 生成返航航迹（原巢 ／ 迫停巢 ／ 迫降点）
    RP -->> DP: 返航航迹 ＋ 精算返程电量与到达时刻
    deactivate RP
    DP ->> FC: 下发落点：归巢 ／ 迫停 ／ 迫降点
    DP ->> DB: 释放占位、更新无人机与订单状态、写流转日志
    DP ->> DP: 触发货物回收与订单重入队
    deactivate FC
```

## 2 收尾：数据回流闭环与货物回收后重派闭环

```mermaid
sequenceDiagram
    autonumber

    box rgb(255,243,224) 产出侧
    participant M4 as M4 飞行任务监控
    participant M3 as M3 动态会面、路径规划
    end

    box rgb(227,242,253) 调度层
    participant DP as 调度引擎 M2<br/>回流校准 · 订单重入队
    end

    participant TP as 轨迹预测<br/>预测模型参数

    Note over M4,DP: 任务结束 · 数据回流闭环（无实物条件下唯一的有效性证明手段）
    M4 ->> DP: 数据回流：实际能耗、轨迹预测误差
    M3 ->> DP: 数据回流：实际会面偏差
    DP ->> DP: 校准：实际能耗 → 能耗模型的动态权重
    DP ->> M3: 校准：实际会面偏差 → 调度策略偏好与纠偏阈值
    DP ->> TP: 校准：轨迹预测误差 → 预测模型参数
    Note over DP: 货物回收后重派闭环：原机落巢 → 货物回收 → 订单回到待调度 → 重走第 2、3、4 步
    Note over DP: 迫降野外须人工回收后再入队；失联或灭失则订单异常终止，不构成重派
```

## 3 说明

1. 数据回流的发起方按 `22` §5 画：`M4、M3 → M2`，**机载飞控不是回流发起方**（`22` §6 原写 `FC → DP`，已按本条修正）。实际会面偏差的产出方见 `32-M3-动态会面` §3.6；实际能耗与轨迹预测误差的分项归口正文尚未写死，本图按排除法归 M4 侧——若 53 另有定论，以定论为准。
2. 第 1 节的交接完成确认同属此类：水上交接的完成与否以 M3 的判定为准，飞控只执行与回传实况（`32` §3.5），故图上是 `FC → M3 → M2` 两跳。
3. 第 8 步的复核由 M2 发起：实际剩余电量与实时风况取自 M6（`22` §5 第 8 步行），飞控只接收落点指令，不作为上报发起方。
4. 「货物回收后重派」与「数据回流」是两条不同的回路：前者回流订单本身，后者回流用于校准模型的数据（`21` §8、§9）。
