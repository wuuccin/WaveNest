## 1 六个模块与外部：每条契约一条消息

```mermaid
sequenceDiagram
    autonumber

    box rgb(245,245,245) 外部
    participant EXT as 外部数据源与监管<br/>AIS · 气象 · 水文 · 空域公告
    participant SR as 船端（船员）
    end

    box rgb(232,245,233) 常驻层
    participant M1 as M1 数据采集<br/>五路接入 · 解析 · 投递
    end

    box rgb(227,242,253) 调度与监控层
    participant M2 as M2 调度引擎<br/>唯一调度主控
    participant M3 as M3 动态会面、路径规划<br/>被调用才求解
    participant M4 as M4 飞行任务监控<br/>只检测与上报
    end

    box rgb(255,243,224) 表现与存储层
    participant M5 as M5 终端交互、可视化
    participant M6 as M6 数据库、缓存<br/>只存不判
    end

    Note over M1,M6: 常驻层：不因订单启停，开机即在线，滚动刷新
    EXT ->> M1: 五路原始数据（AIS 船位 · 遥测 · 气象 · 水文 · 航道与空域公告）
    M1 ->> M1: 连接器 → 解码器 → 发布器，格式级校验后统一信封
    M1 ->> M2: 解析后的原始态势
    M1 ->> M3: 气象、水文与空域约束
    M1 ->> M4: 无人机遥测（格式级已校验）
    M1 ->> M5: 实时船位与机位
    M1 ->> M6: 历史数据与实时最新状态
    M2 ->> M6: 状态估计结果与常驻预测快照

    Note over M2,M6: 主流程第 1–8 步：M2 是唯一调度主控，闭环只经 M2 闭合
    SR ->> M2: 订单（经 M5 下单入口）
    M2 ->> M3: 求本组合会面点 · 求可飞航迹 · 求返航航迹
    M3 -->> M2: 会面点与会面时间窗 · 航迹与精算时长能耗 · 返航航迹
    M2 ->> M6: 查资源、占位登记、二次校验、订单与任务状态、流转日志
    M6 -->> M2: 占用登记成立或冲突顺延
    M2 ->> M4: 任务方案（机 · 巢 · 会面点 · 起飞时刻 · 航迹）
    M1 ->> M4: 遥测（实时追踪，横切在线）
    M4 ->> M2: 偏航距离、飞行进度、越阈告警
    M4 ->> M5: 告警（WebSocket 与 MQ 双推）
    M4 ->> M6: 实际航迹点、告警记录
    M2 ->> M5: 订单与任务状态推送（WebSocket）

    Note over SR,M4: 横切二：兜底保障 —— 检测归 M4，决策归 M2
    M4 ->> M2: 兜底异常上报（电量告急 / 风速突变 / 信号丢失 / 通信中断 / 失联灭失）
    M3 ->> M2: 空域冲突检测上报（临时禁飞 / 空域管制突现 / 多机航迹冲突）
    M2 ->> M3: 改航或退避

    Note over SR,M6: 收尾：数据回流与订单重派是两条不同的回路
    M4 ->> M2: 数据回流：实际能耗、轨迹预测误差
    M3 ->> M2: 数据回流：实际会面偏差
    M2 ->> M3: 校准纠偏阈值与会面策略偏好
    M2 ->> M2: 校准能耗模型动态权重与预测模型参数
    M2 ->> M6: 释放占位、更新无人机与订单状态
    M2 ->> M2: 订单回到待调度，重走第 2、3、4 步（货物回收后重派）
```

3. `M5 → M2` 的下单与人工干预链路、`M4 → M5` 的推送链路见 `91-8`；M6 的读写分工见 `91-9`。
