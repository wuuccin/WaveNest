## 1 第 4–5 步：订单排序、综合择优、资源级占位、航迹精算与起飞时刻回填

```mermaid
sequenceDiagram
    autonumber

    box rgb(227,242,253) 调度层
    participant DP as 调度引擎 M2<br/>订单排序 · 择优 · 占位 · 定案<br/>回填起飞时刻
    end

    box rgb(243,229,245) 存储层
    participant DB as 存储与台账 M6<br/>占位时隙 · 二次校验
    end

    participant RP as 航迹规划 M3<br/>可飞航迹 · 精算时长与能耗
    participant M4 as 飞行任务监控 M4<br/>接收任务方案

    Note over DP: 第 4 步 · 先做订单排序：本批待派订单按订单优先级排序，逐个进入求解
    DP ->> DP: 存活组合按综合代价排序择优：能耗 ＋ 延误 ＋ 风险（此阶段用粗估航程与能耗）
    Note over DP: 订单优先级不进候选比较 —— 同一订单的所有候选取值相同，它只在订单与订单之间起作用
    loop 资源级占位：冲突则顺延次优
        DP ->> DB: 查这架机、这个巢位、这个会面窗口、这个归巢时隙是否已被本批其他订单占住
        DB -->> DP: 占用结论
        alt 已被占住
            DP ->> DP: 顺延至次优组合
        else 未被占用
            DP ->> DB: 登记占用
            DP ->> DP: 定案：机 ＋ 巢 ＋ 会面点 ＋ 归巢目标（起飞时刻留空待回填）
        end
    end
    break 全部组合皆冲突
        DP ->> DP: 出口：顺延至下一批处理窗口
    end

    Note over DP: 第 5 步 · 航线规划 → 回填起飞时刻 → 航迹级二查 → 二次校验
    DP ->> RP: 请求航迹：起点（机巢）→ 终点（会面点）
    activate RP
    RP ->> RP: 避让禁飞区、桥梁净空，预留沿江可迫降点，生成可飞航迹
    RP -->> DP: 可飞航迹 ＋ 精算飞行时长 ＋ 精确能耗
    DP ->> DP: 反推并回填起飞时刻 → 完整派单方案（哪架机 ＋ 从哪个巢 ＋ 在哪会面 ＋ 几点起飞）
    DP ->> RP: 补做航迹级空域冲突二查（两条路径是否相撞，此时才第一次可判）
    RP -->> DP: 冲突结论
    alt 航迹级空域冲突
        DP ->> RP: 处置优先级：先错峰挪起飞时刻 → 其次规划绕行 → 都不行才回退换候选（仅派单阶段、起飞前；飞行中禁换机）
    end
    deactivate RP
    DP ->> DB: 回写会面窗口与归巢时隙占位，并对机、巢位、会面窗口、归巢时隙做二次资源校验（与第 4 步占位同一事务）
    DP ->> DP: 偏差回验：精算时长与粗估偏差是否过大
    break 偏差过大且复验不过
        DP ->> DP: 退回第 3 步复验电量与「回原巢是否仍成立」→ 降级次优组合 → 仍不可行则拒单并说明理由
    end
    DP ->> M4: 任务方案（机 · 巢 · 会面点 · 起飞时刻 · 航迹 · 船舶预测轨迹）
    Note over DP: 任务随之进入 已派发；飞行执行见 91-6
```

## 2 说明

1. 第 5 步的「任务下达 `M2 → M4`」是本图与 `91-6` 的接口，`91-6` 从 M4 收到任务方案起画。
2. 占位与二次校验必须同一事务，见 `27` §4；`91-9` 从 M6 视角再看一次这两步。
