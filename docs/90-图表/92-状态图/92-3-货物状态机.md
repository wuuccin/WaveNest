## 1 一票货一个状态：6 态，两个互斥出口

```mermaid
stateDiagram-v2
    direction LR
    accTitle: 货物状态机
    accDescr: 一票货从拣选打包的未就绪，到已就绪、已装机，此后按是否送达走已交付或已回收两条互斥出口，另有随无人机灭失的灭失终态。

    state "未就绪 · 拣选、打包中" as Raw
    state "已就绪 · 备好并通过检查，满足派单前置门" as Ready
    state "已装机 · 随无人机离巢，此后绑死在该机上" as Loaded
    state "已交付 · 与船交接完成" as Delivered
    state "已回收 · 随原机落巢后被系统回收" as Recovered
    state "灭失 · 随无人机灭失" as Lost

    [*] --> Raw : 货单建立

    Raw --> Ready : M5 人工确认或仓储录入（拣选打包完成并通过检查）
    Ready --> Loaded : M2 装机确认（离巢前）
    Loaded --> Delivered : M4 与船交接完成
    Loaded --> Recovered : M2 落巢回收完成（未送达，随原机落巢）
    Delivered --> Recovered : M2 落巢回收完成
    Loaded --> Lost : M4 判定并上报（无人机灭失）
    Delivered --> Lost : M4 判定并上报（无人机灭失）

    Recovered --> Ready : 状态转为可用，构成重派唯一入口
    Lost --> [*]

    note right of Loaded
        已装机到已交付与已装机到已回收互斥：
        交接成功走前者，未送达随原机落巢回收走后者。
    end note

    note left of Recovered
        迫降在应急迫降点不构成回收——货物落在系统设施之外，
        须人工回收后再入队。
    end note
```

## 2 说明

1. 货物是**有限对象**：离巢后绑死在该机上，空中不可转移，因此只有落进机巢才谈得上回收与重派（`21` §8）。
2. 当前载体与当前位置必须持续跟踪，位置不是「记一笔」，而是重派剪枝的必要输入（`23` §6 约束 3）。
3. `灭失` 与订单 `异常终止` 联动（`23` §8）。
