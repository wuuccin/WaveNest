## 1 一架机一个状态：9 态

```mermaid
stateDiagram-v2
    direction LR
    accTitle: 无人机状态机
    accDescr: 一架机从空闲可被占位起，经已预占、执行任务中、返航中回到空闲，另有迫停、迫降、故障、维护、失联五个旁支状态。

    state "空闲 · 唯一可被 L5 占位的状态" as Idle
    state "已预占 · L5 占位成功至起飞前的窗口" as Reserved
    state "执行任务中 · 从起飞到交接完成，含去程与末段" as OnTask
    state "返航中 · 交接完成至落巢" as Returning
    state "迫停 · 临时停靠他巢，归属不变" as Parked
    state "迫降 · 落在应急迫降点" as Grounded
    state "故障 · 设备异常，须检修" as Fault
    state "维护 · 计划检修、保养" as Maintain
    state "失联 · 心跳超过判定窗口未收到" as Lost

    [*] --> Idle : 入列

    %% ===== 派单与飞行 =====
    Idle --> Reserved : M2 占位成功（L5）
    Reserved --> Idle : 占位释放（起飞前取消，或 L7 精算偏差过大降级次优）
    Reserved --> OnTask : M4 确认起飞
    OnTask --> Returning : M4 交接完成

    %% ===== 落巢与两个旁支 =====
    Returning --> Idle : 落原驻巢（M4 上报，M2 复核）
    Returning --> Parked : 他巢获准入（M4 上报，M2 复核）
    Returning --> Grounded : 野外迫降（M4 上报，M2 复核）
    Parked --> Idle : 回收，恢复后返回原巢
    Grounded --> Maintain : 人工回收
    Maintain --> Idle : 检修完成

    %% ===== 失联 =====
    OnTask --> Lost : 心跳超过判定窗口（M4）
    Returning --> Lost : 心跳超过判定窗口（M4）
    Lost --> Returning : 链路恢复，或按最后指令转自主返航
    Lost --> Grounded : 超时未恢复

    %% ===== 故障与维护 =====
    Idle --> Fault : 设备异常（M5 干预台上报）
    Idle --> Maintain : 计划检修、保养（M5 干预台上报）
    OnTask --> Fault : 设备异常（M5 干预台上报）
    Fault --> Maintain : 转检修
    Fault --> Idle : 排障完成

    note right of Idle
        展开候选时只取空闲：在飞、在充电、充电中待派一律不进候选。
        充电中可中断派出属可选项，当前未启用。
    end note

    note right of Parked
        迫停不改变归属 homeNestId，只改当前所在 currentNestId，
        恢复后仍须返回原巢。
    end note

    note left of Lost
        失联不等于灭失：持续超过灭失判定窗口才推定灭失，
        届时货物随之灭失、订单异常终止。
    end note
```

## 2 说明

1. `执行任务中` 覆盖去程与末段两段；末段四子阶段不另建状态（`23` §4、§7）。
2. **任一状态**检出设备异常或计划检修，均由人工经 M5 干预台转入 `故障` 或 `维护`（`23` §7、§8）；图中只画了代表性入口，不逐态连线。
3. 状态名以本文所示为准，旧写法（`空闲待命`、`已占位待起飞`、`链路中断` 等）已在 `23` §9 列为禁用。
