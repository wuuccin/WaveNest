## 1 模块定位与边界

M2 是系统的**唯一调度主控**。总体目标：根据订单需求、船舶未来运动情况、机巢资源和异构无人机状态，为订单选择一套当前可执行的配送方案，并在任务条件发生重大变化时及时调整。

一套完整的调度结果要回答六个问题：

1. 这个订单是否能够接收？
2. 哪些机型、机巢和具体无人机可以参与？
3. 哪些候选组合能够追上船舶并安全返回？
4. 最终选择哪架无人机、从哪个机巢起飞？
5. 在哪里会面、什么时候起飞、返回哪个机巢？
6. 执行条件变化后，应继续、调整、重新调度还是终止任务？

除订单驱动的调度外，本模块还承担**常驻层**职责：对全量在航船舶持续做状态估计与滚动预测，为接单判断与延后订单的提前唤醒提供依据。这部分工作不因订单启停，是整条流程的底座。

边界：

| 做 | 不做 |
|---|---|
| 接单判定、候选展开与剪枝、择优与占位、起飞时刻回填、飞行中重调度、返航复核、结果记录 | 不求解会面点、不生成航迹——归 M3 |
| 与常驻层的状态估计与滚动预测 | 不接入与解码无人机遥测——接入归 M1，飞行语义级清洗归 M4 |
| 决策（可行性判断、是否返航、是否迫停） | 不检测飞行异常——检测归 M4 |
| — | 不直接写库——落库归 M6 |

## 2 模块间关系

| 对接对象 | 方向 | 内容 |
|---|---|---|
| M1 数据采集 | 输入 | 原始态势（AIS、气象、水文、空域公告），供状态估计与预测 |
| M3 动态会面、路径规划 | 双向 | 出：机型速度、机巢起点、风况修正、船舶预测轨迹、水域约束；入：会面点与会面时间窗、理论飞行时长、可飞航迹、精算飞行时长、能耗、冲突结论 |
| M4 飞行任务监控 | 双向 | 出：任务方案（机、巢、会面点、起飞时刻 ＋ 航迹 ＋ 船舶预测轨迹）；入：任务状态、航迹偏差、异常告警 |
| M5 终端交互、可视化 | 双向 | 出：订单进度、候选对比、闸门状态；入：订单、人工干预指令 |
| M6 数据库、缓存 | 双向 | 读写订单、任务、无人机、占位时隙、货物、系统参数、气象、日志 |

M2 与其他模块的分工要点：

1. **闭环只经 M2 闭合**。M3 不主动发起调度，M4 不自行判可行性，任何方案变更都回到 M2 重跑。
2. **船舶状态估计与预测归 M2，无人机遥测的状态处理不归 M2**。无人机是自有设备、遥测是直报状态，不需要像 AIS 那样做估计；M2 只消费 M4 清洗后的结果。

## 3 功能分解

12 个功能块。

### 3.1 功能 1 订单接入与基本校验

**目标**：判断新订单是否满足基本受理条件，避免明显无法执行或信息不完整的订单进入调度。

**主要内容**：接收目标船舶、货物重量、货物类型、期望送达时间、订单优先级；检查信息是否完整、是否重复、取消或超时；检查货物类型是否允许运输；检查是否超过全部机型的最大载重；检查船舶身份与 AIS 状态；判断船舶是否位于**系统服务航段**，不在时取常驻预测快照判「时间窗内是否会驶入」；派单前检查**货物是否已备好**；派单前检查**运行开关**（气象熔断期间只受理不派单）；数据不足时暂缓调度，不使用过期数据派机。

**输出**：接收并进入调度；拒绝并给出原因；**等待船舶**或**等待货物**，进入等待队列并按预计可派单时刻提前唤醒；转人工。

**说明**：受理不等于立刻派得出去——没有可用运力时同样进等待队列，属资源原因，不是拒单。拒单只来自业务边界与运力彻底无解两种情形。进入调度的订单均已通过「货已备好」前置门，因此后续求解会面点时不再考虑装货等待。

### 3.2 功能 2 船舶状态估计与轨迹预测管理

**目标**：先给出目标船舶当前状态的可靠估计，再据此获得其未来运动趋势，为候选组合判断提供统一依据。

**主要内容**：

- **2.1 状态估计**（回答「此刻在哪、多快、朝哪走」）：对 AIS 报文去噪、去重、丢包外推、时间对齐；结合航道约束修正明显偏离航道的估计；它服务于预测，本身不是预测。
- **2.2 常驻预测**（回答「未来会到哪」，全量、持续）：对所有在航船舶持续滚动产生短期预测快照，不限于已下单的船；覆盖范围**外扩于系统服务航段**；粒度可粗于精算预测，用于接单判断、延后订单的提前唤醒与资源预判。
- **2.3 按需精算预测**（回答「这一单精确怎么走」，单船、按需）：为已受理订单生成带不确定性带的专用预测轨迹；获取船舶进入不同机巢服务区域的预计时间；保存不确定范围与有效时间；检查预测所依赖的前提是否仍成立；船舶持续大幅偏航、停止或进入分汊点、锚地、港区时标记为需要更新；确保同一轮调度中各候选组合使用同一版本的船舶预测。

**输出**：全量在航船舶的态势估计与常驻预测快照；目标船舶带时间信息的预测轨迹；进入各服务区域的预计时间窗口；预测有效期与可信状态；预测失效提示。

**说明**：状态估计与预测是两件事。常驻预测与按需精算预测是**同一能力的两种触发方式**，差别在广度（全量、持续 与 单船、按需），不是精度高低；两者必须是一套实现，禁止做成两套代码。轨迹预测只回答「船可能往哪里走」，不会直接产生对所有无人机都相同的会面点。

### 3.3 功能 3 候选机型、机巢和无人机生成

**目标**：用成本较低的条件先排除明显不合适的资源，生成需要动态可行性判断的候选组合。

**主要内容**：按货物重量、体积、类型筛选机型；排除载重不足、设备不匹配的机型；检查与位置无关的一票否决条件（全域硬性禁飞、气象红线）；**认证抗风等级只登记、不比较**；查询存活机型部署在哪些机巢；查询机巢内无人机的当前状态；排除正在执行任务、故障、维护、离线或状态数据过期的实例；展开为候选组合「机型 ＋ 出发机巢 ＋ 具体无人机」；记录每个被排除资源的排除原因。

**输出**：候选组合列表；被排除资源及原因。

**说明**：机巢不能被单独判断为「可达」或「不可达」，也不能简单地先选最近的巢。能否完成同时取决于机型能力、机巢位置与实例状态，必须形成组合后再判断。

### 3.4 功能 4 候选组合可行性判断

**目标**：判断每个候选组合能否完成一次完整配送任务，在派单前淘汰追不上、回不来的方案。

**4.1 判断是否追得上**：结合机巢位置、飞行能力与船舶预测轨迹判相遇条件；求解起点为**当前时刻**；按该组合沿途与会面时刻的风况修正速度与能耗，并判定**任务时段内最不利风况**是否超过机型认证上限，超限则淘汰；为每个组合分别确定会面位置与会面时间范围；无法在订单时间内相遇的组合直接淘汰。

> **简化假设（显式声明）**：选中机型后仍需把货箱装上飞机，本版把装货上架时间取为 0。理由是该时长相对飞行时长与船舶等待时间很短，且偏乐观的误差会被去程段纠偏吸收；若实测不可忽略，可作为配置参数重新引入。

**4.2 判断是否回得来**：**归巢目标默认原驻巢**（驻位本就属于该机，不产生容量竞争）；判断电量能否覆盖去程、交接、返程与安全余量；原巢回不去的组合直接淘汰；派单阶段不做「计划性改投」，落他巢降级为飞行中的应急迫停。

**4.3 关于归巢资源余量（说明，不是本关的判据）**：本版**不设**这一关。默认回原巢时每架机的驻位本就属于它自己，同批回归总数不超过驻机数，不产生竞争，无需逐单校验容量；真正需要判容量的只有应急迫停，那是飞行中的突发决策，且必须结合同批其他机的同时占用统一判断，无法在派单时用预测算准，故下沉到功能 10。判断对象收敛为**两关：追得上吗、回得来吗**。

**输出**：可行组合自带无人机与出发机巢、会面位置与会面时间范围、归巢目标、预计任务时间与能耗、预计返航剩余电量、风险情况；不可行组合给出明确淘汰原因。

### 3.5 功能 5 候选方案综合择优

**目标**：在满足安全与可行性条件的候选中，选更适合当前订单与整体资源状态的方案。

**主要内容**：比较预计完成时间、飞行距离与能耗、返航剩余电量、天气与空域与任务风险、机巢与无人机的繁忙程度；最优候选不可用时按顺序尝试次优；全部不可行时决定拒单、延后等待或转人工。

**输出**：排好序的候选列表、暂定最优方案、选择理由、其他候选未被选择的原因。

**说明**：原则是先判断能不能执行，再比较哪个方案更好；载重、电量、安全条件不满足的方案不能因速度快或成本低而被重新选中。**订单优先级不参与候选之间的比较**——同一订单的所有候选共享同一个优先级值，加分不改变排序；优先级只在订单与订单之间起作用，落点在功能 8。

### 3.6 功能 6 资源占用与并发冲突管理

**目标**：把暂定方案需要的资源提前锁定，防止多个订单同时占用同一架机、同一个起降时段或同一个会面窗口。

**主要内容**：占用选中的无人机、出发机巢的起飞时段、目标船舶的会面时间窗口、**归巢时隙**；默认回原巢时不占容量、不落锁，仅应急迫停获批才占用目标巢时隙；检查资源是否已被其他订单占用；最优方案占用失败时释放临时资源并尝试次优；任务取消、失败或占用超时后及时释放；保证资源占用与任务状态一致；后续航线精算改变起飞、会面或返航时刻时，**同步回写占位并二次校验**（与本次占位在同一事务内完成）。

**输出**：占用成功则进入航线确认；冲突则切换下一候选；无资源可用则订单进入等待；全部失败则拒绝或转人工。

**说明**：资源占用解决的是「这个方案能不能真正拿到资源」，与「这个方案理论上是否可行」不是同一个问题。细则见 `27-一致性约束` §2。

### 3.7 功能 7 航线确认与起飞时刻确定

**目标**：把初步方案转换为含实际航线与准确起飞时刻的完整派单方案，并在起飞前做最后一次可行性确认。

**主要内容**：把出发机巢、会面位置、天气与空域条件提交 M3；接收实际可飞航线、精确飞行时间、精确能耗、路径风险；据预计会面时间与精确飞行时间反推起飞时刻；检查不同无人机航迹之间是否存在冲突；冲突时优先错峰调整起飞时间，其次请求绕行；起飞、会面或返航时间变化后同步更新资源占用；精确结果与前期估计差异较大时，重新检查电量、会面窗口与归巢目标；全部通过后生成正式任务。

**输出**：完整派单方案（无人机、出发机巢与归巢目标、实际航线、起飞时间、会面位置与会面时间窗口、预计完成时间）。

**说明**：前面的会面与能耗属初步判断，这一步用实际航线确认；精确结果导致原方案不再可行时，应退回候选选择，而不是勉强派出。

### 3.8 功能 8 任务队列与状态管理

**目标**：有序管理多个订单及其执行状态，使订单、无人机、机巢资源与任务进度保持一致。

**主要内容**：把暂无资源但仍可能按时完成的订单放入等待队列；按订单优先级、送达时限与等待时间安排调度顺序；防止普通订单因持续出现加急订单而长期无法执行；维护订单与无人机的状态流转；任务取消、失败或完成时同步释放或更新资源；防止同一订单生成多个有效任务。

**输出**：等待队列、订单与任务当前状态、每架无人机的占用状态、下一个需进入调度的订单。

**说明**：任务队列负责「先处理哪个订单」，候选择优负责「这个订单选哪套资源」，两者要区分。状态集以 `23-状态机定义` 为准。

### 3.9 功能 9 飞行过程中的重新调度

**目标**：任务执行条件发生重大变化时，判断原方案能否继续，并选择继续、重新规划、重新调度或终止。

**主要内容**：持续接收会面点变化与预计到达时间；船舶正常减速、小幅偏移或 AIS 抖动时只更新任务信息，不重新选机；船舶持续掉头、进入其他航道、长时间停止时重新获取预测并检查原方案；无人机电量异常、故障、天气恶化或临时禁飞时检查当前机是否仍能完成任务；尚未起飞时可释放原资源并重新选机；**已携货起飞后，优先让当前机继续执行或安全退出**——货物是有限对象，同一时刻只能在一个载体上，换机送同一票货的前提是货物先随当前机落回机巢并被回收；进入会面点邻域后不再重算远距离会面点，转入末段伴飞与交接；重调度时保存原方案、新方案与触发原因。

**输出**：保持当前任务；用当前机调整会面方案；起飞前释放资源并重新选机；中止任务并转入返航复核或转人工；货物被回收并重新可用后创建新任务。

**说明**：重调度不是每次数据变化都重新选机。小幅变化属实时追踪与路径纠偏；只有预测前提失效或当前机不再可行时，才重新进入调度流程。

### 3.10 功能 10 返航复核与归巢资源判定

**目标**：在交接完成、进入返航之前，基于实际状态对派单时确定的归巢目标做一次复核，并确定唯一可执行的落点。

**主要内容**：接收交接完成确认并触发复核；按**实际剩余电量**与**实时风况**复核归巢目标，默认原驻巢；能回原巢则回原巢（不做容量校验、不落锁）；原巢回不去时向近处机巢申请应急迫停，取该巢驻机预计回归时刻与本机预计占用时长，判定占用时间窗是否与驻机回归冲突，不冲突则批准占位并落锁，冲突则换下一候选；无巢位可借时从应急迫降点台账按位置检索最近可用点，并由 M3 生成迫降航迹；落点确定后请求 M3 生成**返航航迹**（当前实际位置 → 选定落点）并精算返程电量与到达时刻；迫停期间持续复核占用窗口，驻机提前回归或占用超时则触发转场或转人工回收；落巢后触发货物回收与订单重新入队，迫降野外转人工回收，无人机灭失则货物灭失、订单异常终止；记录复核结果、目标变更原因与占用时隙。

**输出**：返回原驻巢；批准应急迫停并给出目标巢与占用时隙；转应急迫降点；货物回收并重新入队；订单异常终止。

**说明**：归巢目标在功能 4 基于预测确定，本功能在返航前基于事实复核，是同一问题的第二次判定；两次依据不同（预测电量与预报风况、实际剩余电量与实时风况）。迫停占用的是他巢的时隙，与功能 6 共用同一套台账；**迫停不改变归属**，恢复后须返回原巢并释放占用。准入判定细则见 `25-返航设计`。

### 3.11 功能 11 调度结果记录与展示

**目标**：保存调度过程与决策依据，使每次资源选择都能解释、查询与复盘，并为仿真实验与答辩展示提供数据。

**主要内容**：保存订单使用的船舶预测版本与环境状态；保存参与判断的机型、机巢与实例；保存每个候选组合的会面位置、可行性与淘汰原因；保存最终选择的无人机、出发机巢、起飞时间、会面窗口与归巢目标；保存资源冲突、候选切换与重调度记录；保存实际完成时间、实际能耗与会面偏差供后续模型校准；向后台提供订单进度、候选对比与异常记录。

**输出**：订单调度全过程记录；候选组合与淘汰原因展示；最终派单方案展示；重调度时间线；调度成功率、等待时间、资源利用率等统计。

### 3.12 功能 12 派单闸门与人工干预

**目标**：提供系统级运行开关与人工介入通道，使系统在恶劣气象或人工判断下可整体收紧或暂停派单，并允许调度员干预订单与在途任务。

**主要内容**：

- **派单闸门（气象熔断）**：全域气象超红线（大风、雷暴、能见度不足）时暂停新订单派单；已受理的挂着不派，解除后恢复。它管**时间维度**的暂停，与「系统服务航段」管的空间边界互补。
- 熔断可由系统自动触发，也可由终端一键触发；解除同样支持两种方式。
- 熔断**不影响已在飞的无人机**：在途任务继续按原方案执行，异常由功能 9 与功能 10 处理。
- 接收人工干预指令：暂停或恢复派单、撤回尚未起飞的订单、转人工处理、调整候选偏好。
- 只允许系统能力范围内的动作，**不允许把货物直接改派给另一架机**。
- 记录每次熔断与干预的触发人、时间、原因与影响范围。

**输出**：当前闸门状态（正常、熔断中）；被拦下并停留在等待队列的订单清单；干预执行结果与操作记录。

**说明**：熔断与接单判断是两件事——接单判断回答「这一单我们做不做」，熔断回答「此刻我们一单都不派」。因此熔断期间的订单仍属已受理，不是被拒绝。

## 4 关键设计的落点

| 判据 | 权威处 | 本章说明 |
|---|---|---|
| 两关剪枝（追得上、回得来） | `24-选机链设计` §3 | 功能 4 |

| 起飞时刻两级估算与占位二次校验 | `27-一致性约束` §2 | 功能 6、功能 7 |
| 订单优先级的作用域 | 50-决议记录 决议 4 | 功能 5、功能 8 |
| 抗风在 L1 只登记、L3 比较 | 50-决议记录 决议 7 | 功能 3、功能 4.1 |
| 归巢余量为何不设关 | 50-决议记录 决议 3 | 功能 4.3 |
| 应急迫停准入判定 | `25-返航设计` | 功能 10 |
| 状态集与流转 | `23-状态机定义` | 功能 8 |

一条贯穿全部功能的取向：**判断的层级要对齐属性的层级**。一个量只有在该层不同对象间取值不同时，才能在这一层起区分作用——风速在机型之间恒定、在组合之间才不同，所以抗风比较不下沉到 L1 而是留在 L3；优先级在候选之间恒定、在订单之间才不同，所以它不进候选打分而只决定订单顺序。

## 6 技术选型

M2 的技术选型文档尚未成文。实现阶段需满足三项硬约束，并与 M1、M4 的 Java 技术栈（Spring Boot 3.x、MySQL、MQTT 与 RabbitMQ）保持一致：

1. 需要**长期驻留**的常驻层进程（状态估计与滚动预测不因订单启停）；

3. 需要与 M3 的**同步调用**能力（会面点求解、航迹生成），并支持按组合循环调用。
