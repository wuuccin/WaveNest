## 1 模块定位与边界

M6 为整套低空物流调度系统提供统一、可追溯、低延迟的数据底座：把机巢、无人机、货物、订单、会面、占位、迫降点、气象、船舶轨迹与系统参数等实体持久化，并把高频实时状态放进缓存，对外提供一致的数据访问接口。

**本模块不承载业务决策，只保证「数据能被正确写入、被一致读取、被可靠溯源」。**

| 做 | 不做 |
|---|---|
| 落库、缓存、统一访问接口 | 不判断货物流转、不判断状态是否该变 |
| 坐标与单位归一（落库与入缓存时） | 不承接业务判据 |
| 占位时隙的原子占用与事务一致性 | 不发起仲裁——仲裁由 M2 发起，本模块保证原子性 |

## 2 模块间关系

| 对接模块 | 方向 | 内容 |
|---|---|---|
| M1 数据采集 | 入 | 结构化原始数据（船位、遥测、气象、水文、空域公告），落库并归一 |
| M2 调度引擎 | 双向 | 读写订单、任务、无人机、占位时隙、货物、系统参数 |
| M3 动态会面、路径规划 | 入 | 读取空域与航道限制台账、应急迫降点台账、气象、阈值参数 |
| M4 飞行任务监控 | 双向 | 读写任务、实际航迹点、告警 |
| M5 终端交互、可视化 | 入 | 查询订单、机队、告警、回放数据 |

**状态维护方划分**（只列最容易无人认领的一类，即货物状态）：

| 流转 | 写入方 | 触发 |
|---|---|---|
| 未就绪 → 已就绪 | 运营录入（M5 人工确认、仓储侧录入） | 拣选打包完成并通过检查，满足派单前置门 |
| 已就绪 → 已装机 | M2 调度引擎 | 装机确认（离巢前） |
| 已装机 → 已交付 | M4 飞行任务监控 | 与船交接完成 |
| 已交付 → 已回收 | M2 调度引擎 | 落巢回收完成；迫降野外的须人工回收后由 M5 确认再入队 |
| 转灭失 | M4 判定上报，M2 走订单异常终止 | 无人机灭失判定成立 |

原则：**本模块只负责存储与一致性，不判断流转**。若无人负责写「已回收」，调度引擎就无从判断能否重派，整条回收闭环会断在这里——这是该划分存在的理由。

## 3 设计约束

来自七问结论与主流程定稿，须严格落实到表结构：

1. 机巢与无人机建立**两层关系**：归属（稳定「家」）、当前所在（动态）。
2. 货物是**有限对象**，须持续跟踪其状态与所在位置。
3. 占位按**时间窗 `[t₁, t₁+d]`** 记录，不做布尔化。
4. 应急迫降点为**静态设施台账**。
5. 所有阈值、风级、判定窗口、容量均**参数化**，不硬编码。
6. 实时最新状态进缓存，历史落库。
7. 坐标与单位的**归一由本模块在落库、入缓存时统一完成**：M1 保持源原始单位与坐标系交付，本模块归一到系统基准坐标系（CGCS2000 / WGS84）与标准单位，下游一律从本模块取标准值，不各自转换。

## 4 关键设计

### 4.1 机巢与无人机的两层关系

| 关系 | 性质 | 用途 |
|---|---|---|
| 归属 `homeNestId` | 稳定，是「家」 | 默认返航目标、驻机数统计、「原巢恒有位」的依据 |
| 当前所在 `currentNestId`、当前位置类型 | 动态 | 原巢、空中、他巢临时停靠、迫降点 |

临时迫停**不改变归属**：迫停他巢后仍是原巢的驻机，恢复后须返回。若只记当前所在，该机落停他巢时其原巢的驻机数会缺失，容量校验随之失效。

容量校验须区分两个数：**驻机数**（按归属统计，静态，恒不超过容量 C）与**当前占用数**（含临时停靠，动态，按时间窗校验）。应急迫停的准入判定使用后者。

### 4.2 占位是时隙，不是布尔

占位的对象是「机、起飞时段、会面窗口、归巢时隙」，按时间窗记录。做成布尔（占了或没占）无法表达「借出这段时间里会不会把原驻机挤掉」这类判断，而时间窗维度正是本项目与静态计数方案的差别所在。

### 4.3 参数集中管理

低电量阈值、失联判定窗口 N、风级阈值（L1 红线、L3 上限）、气象熔断红线、装货常量、容量 C、迫停占用标称时长 d 等全部集中在 `sys_param`，不硬编码。理由：仿真与真机的合理取值不同；现场需要能调。

### 4.4 状态集与字段对齐

四套状态机（订单、任务、货物、无人机）的定义在 `23-状态机定义`；本模块的字段枚举一律以该文为准。其中订单与任务在任务存在期间**同事务同值**（订单状态是任务状态的投影）。

## 5 表清单

共 14 张表。标注（新增）的为相对初版五表（`nest`、`drone`、`order_task`、`ship_ais`、`task_log`）新增。

### 5.1 机巢表 `nest`

| 字段 | 说明 |
|---|---|
| `nestId`（PK） | 机巢标识 |
| 位置经纬度 | 固定地理坐标 |
| 容量 C | 同一时段可容纳无人机总数，**参数化** |

#### 5.14.1 初始建议值（登记口径，2026-09-29 新增）

**本小节不是设计口径**。它只把各算法组产出的**仿真建议初值**（实现起步用的一组可跑取值）集中登记到此一处，供实现阶段写入 `sys_param` 的初始行。最终取值以运行数据回流标定为准，现场与真机须重新标定，**不得硬编码**（`NF-8`）。

登记口径：`61` §3 要求算法方案正文只列名目与含义、不写死取值（见 `80` §3.3、`84` §2.9／§3.8／§4.8.2 的标题与口径注）。故初值只登记在本小节，不回写各算法方案；各键的含义与判据仍在各方案对应章节。
