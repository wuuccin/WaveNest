## 1 定位：返航是一个被提前决定的计划

返航在主流程中是第 8 步，但它不是送完货才临时决定的。

返航目标巢在派单时就已经初步确定，因为它已经作为**可达性剪枝**的一部分被检查过了——剪枝要求电量覆盖「去程 ＋ 交接 ＋ 返程 ＋ 安全余量」整环，不看单程。所以返航这一步做的是**复核与执行**，不是从头决策。

但它也不能完全依赖派单时的判断，因为中间隔了一整段飞行，情况会变。因此返航需要至少两次计算，见 §5。

## 2 前提设定：机巢补给能力

为避免把返航复杂化，设定以下前提。这些简化符合现实：真实机巢本就按驻扎机数设计容量。

| 设定 | 内容 | 带来的简化 |
|---|---|---|
| 停机位即充电位 | 无人机落到机巢任意位置即可充电，不区分「停机位」与「充电桩」 | 台账中少一类资源，只需维护「机巢容量」 |
| 统一充电接口 | 异构机型共用同一补给接口，不按机型区分占位大小 | 占位判断退化为「当前占用数是否小于容量」 |
| 容量可配置 | 机巢容量 C 是系统参数，不预设固定值：一巢一机、一巢多机位都可容纳。C 与驻机数的差额决定是否存在可供临时停靠的空余位 | 配合「默认回原巢」，各回各家恒有位；空余位只在应急迫停时被借用，按 §4 的准入判定 |
| 供电不构成瓶颈 | 机巢供电能力充足，电量恢复速度由无人机自身属性决定 | 无需建模充电功率曲线、电池老化 |
| 电量可恢复 | 归巢后电量能够回升，否则多轮仿真后全队趴窝 | 保证仿真可持续运行与对照组实验有效 |

**反向提醒**：机巢总数不可设得过多。若各巢覆盖范围高度重叠，「选哪个巢」会退化成随便选，多机巢协同的价值就消失了。巢的分布应保持覆盖梯度——有的船只有一两个巢够得着，有的船有多个巢可选，这样选巢才是真问题。

## 3 归巢策略：默认回原巢，应急才迫停

**主策略**：无人机完成交接后，返回自己原驻机巢。派单阶段只做这一计划；若按预测电量判断回不去原巢，则淘汰该候选组合，不在派单时安排落他巢。

**落他巢只作为一种应急手段存在**：飞行中出现电量不足、故障、天气突变等突发情况，原巢已不可达时，方可向近处机巢申请临时迫停。它不是计划内的选项。

### 3.1 为什么默认回原巢，而不是就近归巢

| | 默认回原巢（采用） | 一律就近归巢（不采用） |
|---|---|---|
| 容量约束 | 各巢机数守恒，回原位必有位，「容量配足」这条前提真正成立 | 外来机向热点巢聚集，容量配足兜不住，超员是常态风险 |
| 机队分布 | 稳定。每个巢始终保有自己那份运力，上游再来单也有机可派 | 会随时间向下游漂移，热点巢挤爆、另一端没机，服务能力受损 |
| 回程能耗 | 偏高：船把机带到下游，还要飞回原巢 | 偏低：落最近的巢 |
| 占位与落锁 | 回原巢不落锁（容量按驻机数配足，位是留着的）；只有临时迫停才需要占位 | 每次归巢都可能落进别巢，每次都要抢位 |

**取舍结论：服务能力优先于能耗。** 多飞一点电可以补，机队漂走了是服务能力受损，后者更致命。能耗的极端情况由应急迫停兜住。

配套提醒：既然派单时只计划回原巢，可达性剪枝中「回得来吗」的判据就是「**能否回到原巢**」——按预测电量覆盖「去程 ＋ 交接 ＋ 返回原巢 ＋ 安全余量」，判不过即淘汰该组合。这与「就近归巢」前提下的判据不同，那里判的是「是否存在至少一个可归巢」。前提变了，判据随之改变。

代价与后续：默认回原巢意味着运力不会随需求热点自然迁移。前瞻性布位（空闲机主动调往预测热点）列为后续工作，当前不做。

### 3.2 机巢与无人机：两个关系，缺一不可

要让「回原巢恒有位」成立，必须先分清两件事：

| 关系 | 性质 | 用途 |
|---|---|---|
| 归属 | 稳定，是「家」 | 默认返航目标、驻机数统计、「恒有位」的依据 |
| 当前所在 | 动态，随时变 | 原巢、空中、他巢临时停靠、迫降点 |

**临时迫停不改变归属**：一架机迫停他巢后仍是原巢的驻机，恢复后须返回。若只记录当前所在，它落停他巢时原巢的驻机数就会缺失，容量校验随之失效。

相应地，容量校验要区分两个数：**驻机数**（按归属统计，静态，恒不超过 C）与**当前占用数**（含临时停靠，动态，按时间窗校验）。

### 3.3 临时迫停的准入按三层判定

| 层次 | 内容 |
|---|---|
| ① 请求资格 | 确实无法返回原巢，由可达性判定给出；仅为缩短航程而申请的，不批准 |
| ② 目标巢条件 | 该巢有空余位，且在其占用期间没有归属该巢的飞机回归需求——借出的位不能让原驻机回来无处可落 |
| ③ 竞争仲裁 | 多架同时申请同一巢时按紧迫度排序（剩余裕度最小者优先），挤不下的转应急迫降点 |

三层全过才批准。未获批准的转**应急迫降点**——它是静态设施台账，预先登记、位置固定，按位置检索最近可用点，**不是每次规划时「预留」出来的**。

## 4 机巢容量：当成一个可配置参数

机巢能停几架机，不是一个需要定死的数，而是系统的一个配置参数 C。它可以是一巢一机（现实中自动机巢多为此形态），也可以是一巢多机位。方案不依赖它的具体取值，只依赖一条统一规则：**申请应急迫停时，目标巢的剩余容量必须大于零。**

需要区分的是两个量：**驻机数**（归属该巢的飞机数）与 **C**（同一时段可容纳的总数）。两者相等时没有空余位可借；C 大于驻机数的部分才可供临时停靠使用。

| 取值 | 含义 | 对迫停的影响 |
|---|---|---|
| `C ＝ 驻机数` | 位刚够自家机用，无空余 | 无位可借，应急时只能选择应急迫降点，不占用任何机巢机位 |
| `C ＞ 驻机数` | 差额可供临时停靠 | 可申请迫停，按 §3.3 三层准入判定；差额越大越容易获批 |
| `C ＝ 1` | 一巢一机，现实中最常见 | 回自己的巢恒有位；无位可借，迫停走应急迫降点 |

由此得到三条规则：

1. **回原巢**：驻位本属该机，容量按驻机数配足，位是留着的，**恒不落锁**。
2. **临时迫停**：须借目标巢的空余位，且占用期间不得与归属该巢的飞机回归需求冲突。
3. **落锁只发生在迫停**：准入批准后占位，落地后更新台账；恢复后须返回原巢并释放占位。

迫停占用的时长必须有界：从落停到恢复（换电或回收）应有预计时长，超出预计须有出口——延续占用要**重新校验后续窗口**，否则转人工回收。

**设计提醒**：本章曾写成「驻位专属绑定 ＋ 机动位」的固定结构，那是为回答「原巢的位被占了怎么办」而临时发明的机制，现实中并无此设置。正确做法是把容量当参数、用统一规则处理，不为某个取值专门设计结构。**凡是「需要新增一个机制才能回答的问题」，都应先回去质疑前提，而不是加机制。**

## 5 为什么必须算两次

返航目标巢的确定与确认不是一次计算，而是两个阶段，且两阶段处理的不是同一件事：

| | 第一次：定目标 | 第二次：复核 |
|---|---|---|
| 发生在 | 起飞前（派单时） | 返航前 |
| 依据 | **预测**：预计的能耗、风况与航程 | **事实**：实际剩余电量、实时风况、巢的实际占用 |
| 解决什么 | 默认目标＝原巢；按预测电量验「原巢回得去吗」，回不去则淘汰该候选组合，不在派单时安排落他巢 | 处理实际耗电与预估不符、原巢已不可达、途中出现禁飞等变化 |
| 结果 | 归巢目标＝原巢；未通过可行性判据的组合被淘汰 | 按原计划回原巢，或申请临时迫停（按准入判定），或转应急迫降点 |
| 是否落锁 | **不锁**：只记计划，不产生占位与释放 | 回原巢不落锁；迫停获批才占位落锁，未获批转应急迫降点 |

### 5.1 第一次为什么不锁位

两条理由：

1. **提前锁是过早占用**：派单到落地隔着几十分钟飞行，中途可能冒出禁飞、风速突变、电量偏差、需要迫停；现在锁住，等下多半要改，等于白锁，还白白挤压他机的选项。
2. **预测层不占资源**：派单时那次计算的职责是「证明这一单回得来」，属于可行性判断；占位属于执行层，要等事实确定（返航前复核）后再做——这也符合「过期决策比不决策更危险」。

而且默认回原巢之后，绝大多数单根本不需要锁——容量按驻机数配足，本机的位是留着的，回来直接落。真正需要占位的只有临时迫停这一类少数情形，锁的范围因此收得很窄。

**落锁时机**：飞行中确认原巢不可达、且迫停申请获准之后、进近之前。多机同时申请同一巢时按紧迫度排序，挤不下的转应急迫降点；落地后须更新台账。

与 §7 呼应：派单时只验「能否回原巢」，是**布尔判断**；迫停准入验「这段时间有没有位」，是**时隙判断**。两者作用于不同情形，不重复。

**为什么不能只算一次**：两次之间隔了一整段飞行。实际耗电可能与预估不符（逆风、绕行、交接超时），目标巢的占用情况可能变化，途中还可能冒出临时管制。用预测定的计划，必须用事实复核。

补充：严格说是「至少两次」。飞行途中若兜底被触发（如电量告急提前返航），还会再算一次；主线上就是上表这两次。

## 6 多机同时申请迫停：竞争怎么排

首先要定性准确：这不是「给某个巢挑两架」，而是**待迫停的多架机与它们各自可达的机巢之间的匹配问题**。单独看一个巢只能做「谁先申请给谁」，把多架机与多个巢摆在一起，才能做全局搭配。

因此与派单同理：攒一批做批处理匹配，不能先到先得。先到先得是贪心，第一架占了它最近的巢，后面的可能被逼去更远的，总和更差。

| 排序依据 | 说明 |
|---|---|
| 第一：紧迫度 | 剩余电量最少的、已触发兜底告警的优先落。这是安全维度，必须排第一 |
| 第二：就近 | 紧迫度相当时，给离该巢最近的那个，使总能耗最低 |
| 不加第三级 | 如「谁接下来有单优先」这类前瞻性排序，属于后续工作，当前不做 |

触发条件很窄：竞争只在空余位不足时发生。回原巢的机各回各家，彼此不冲突；只有多架机同时申请迫停、且看中同一个巢时才需要排队。它是**异常逻辑，不是主逻辑**。

## 7 迫停准入：从「有没有位」到「这段时间有没有位」

常规做法判断机位只看一个数：当前占用数是否小于容量。这是一个静态的布尔判断，在迫停场景下不够用——迫停占用是**有时长**的，从落停一直到恢复为止。

**核心区分：现在有位，不等于占用期间一直有位。**

可能出现这样的情形：某巢此刻确有空余位，但它的驻机正在返航途中、预计回归时刻落在这架机迫停的占用区间之内。若只看「现在有位」就批准，等驻机回来反而无处可落——**用一次迫停换来了另一次迫停**。

因此判据必须带时间维度，用三个量表示：

| 量 | 含义 |
|---|---|
| `t₁` | 迫停落停时刻 |
| `d` | 预计占用时长（落停至恢复） |
| `T_return` | 该巢驻机的预计回归时刻 |

判定：**占用区间 `[t₁, t₁+d]` 与驻机回归需求不重叠，方可批准**。存在多个空余位时逐个校验；同一时段多架申请时按紧迫度排序（见 §6）。

两个量都是估计值，因此判定不是一次性的：

1. `T_return` 会变——驻机的任务可能延误，判定时应留余量，并在该机临近回归或计划变更时复核；
2. `d` 也不确定——换电有标称时长，故障则说不准；超出预计须有出口：延续占用需重新校验后续窗口，否则转人工回收。

| 可选项 | 内容 | 当前是否实现 |
|---|---|---|
| 无退路机优先 | 可达机巢只有 1 个的机没有退路，优先保障 | 可选，不做也能跑 |
| 空余位预留 | 为应急迫停预留部分空余位 | 不做 |
| 预占与抢占 | 起飞前锁定返航位、紧急抢占已占位 | 不实现 |

## 8 与兜底层的关系

| 兜底触发 | 对返航的影响 |
|---|---|
| 电量告急 | 提前返航 → 触发返航复核：按实际电量重评落点；能回原巢就回，回不去则申请应急迫停，无位可借转应急迫降点 |
| 风速突变 | 有效航程变化，返航前的复核必须计入实时风况 |
| 临时禁飞、管制 | 原落点可能不再可达，按同一套复核流程改选落点 |
| 通信中断 | 按最后已知指令自主返航 |
| 交接未完成 | 复飞重试或改期，返航时机相应推迟 |
| 容量已满、未获批准 | 迫停申请未通过，转应急迫降点，不再占用机巢机位 |

兜底触发的每一次返航决策，实际上都是一次额外的复核计算——这正是 §5 说的「至少两次」。

---

## 9 一句话总结

返航的逻辑是：**起飞前基于预测确认回得去原巢，飞行中基于事实复核；默认回原驻巢（驻位本属该机，恒有位、不落锁），回不去才申请临时迫停，迫停须确认目标巢在这段占用时间内都腾得出空余位。**

机巢容量是可配置参数，方案不依赖它的具体取值，只依赖「空余位借出后不得挤占原驻机」这一条统一规则。
