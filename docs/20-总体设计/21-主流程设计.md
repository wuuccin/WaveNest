## 1 一句话主线

> 接单 → 预测船去哪（并监测这个预测还成不成立）→ 展开候选组合 → 逐关剪枝判谁能追上 → 择优并占住资源 → 定起飞时刻 → 边飞边纠（纠不动就回上游重来）→ 伴飞交接 → 归巢，全程追踪与兜底在线；任务结束后数据回流校准，货物未送达则随原机落地回收、订单重入队重派。

三套编号的对应关系见 `03-编号规范` §6：第 3、4、5 步对应 `24` 的 `L3`、`L4–L6`、`L7`；第 8 步对应 `25-返航设计`；并发控制对应 `26-并发控制设计`。

## 2 步骤定义

| # 步骤 | 依据什么 | 得到什么 |
|---|---|---|
| **0** 数据接入、状态估计与常驻预测（常驻层） | 船位、航向、航速、气象、空域管制、机队状态，结合航道约束处理。状态估计＝去噪、去重、丢包外推，回答「此刻在哪、多快、朝哪走」（不是预测）；常驻预测＝在其之上推「未来会到哪」，全量、滚动刷新，覆盖范围外扩于系统服务航段 | 一份统一对齐的「当前态势」＋ 所有在航船舶的常驻预测快照 |
| **1** 订单接入与接单判断 | 船号、货物属性、时效要求；船是否位于**系统服务航段**（运营范围，按航道里程算，不是直线距离，也不是机巢能力范围）。不在航段内时，取常驻预测快照判断订单时间窗内是否会驶入。具体派哪个机巢不在此判，交给第 3 步逐组合去算 | 受理并触发调度／延后触发调度（会驶入但尚未进入：入等待队列，按预计驶入时刻提前唤醒）／拒单或转人工 |
| **2** 船舶轨迹预测（含前提监测） | 船舶当前状态 ＋ 航道拓扑约束。注意前提：预测建立在「船沿既有航道行驶」之上，因此需同步监测该前提是否仍成立 | 带不确定性的未来轨迹 ＋ 进入各机巢服务范围的时刻 ＋ 前提有效性 |
| **3** 候选组合展开 ＋ 可达性前置剪枝（两关） | 先按货物 → 机型 → 机巢 → 当前可用实例展开候选组合（静态先剪、动态后剪；实例是否空闲在展开时就过掉，不占用剪枝关）。随后逐组合过关：① 追得上吗——用相对运动关系求本组合自己的会面点（会面点是组合级产物，不存在脱离飞机的全局会面点）；② 回得来吗——归巢目标默认原驻巢，验电量能否覆盖「去程 ＋ 交接 ＋ 返程 ＋ 余量」整环，原巢回不去即淘汰该组合 | 一份可行组合清单，每个组合自带：会面点 ＋ 归巢目标 ＋ 起飞时刻（待回填）；追不上、回不来的在派单前就淘汰 |
| **4** 综合择优 ＋ 资源级占位定案 | 先做一步**订单排序**：本批待派订单按订单优先级排序，逐个进入求解（这是优先级在本流程中的落点之一，另一个是延误惩罚的权重）。存活组合按综合代价排序择优（能耗 ＋ 延误 ＋ 风险，此阶段用粗估航程与能耗）。中选后做资源级占用检查：这架机、这个巢位、这个会面窗口、这个归巢时隙是否已被本批其他订单占住，冲突则顺延次优 | 定案：哪架机 ＋ 从哪个巢 ＋ 会面点 ＋ 归巢目标，并完成占位；起飞时刻为待回填字段 |
| **5** 航线规划 → 起飞时刻回填 → 航迹级冲突二查 | 起点（机巢）、终点（会面点）、水域约束（禁飞区、桥梁净空、沿江可迫降点）。此时补做航迹级空域冲突二查，撞了优先错峰挪起飞时刻或绕行，都解决不了才回退换候选（仅派单阶段、起飞前；飞行中禁换机）。错峰或绕行会改变会面与返航时刻，因此回填后**必须同步回写会面窗口与归巢时隙占位，并对机、巢位、会面窗口、归巢时隙做二次资源校验**（与第 4 步占位同一事务）；若精算与粗估偏差过大，回第 3 步复验电量与「回原巢是否仍成立」 | 一条可飞航迹 ＋ 精算飞行时长 → 反推并回填起飞时刻（起飞时刻属调度层产物，两级估算：粗估择优、精算回填） |
| **6a** 去程段追踪与常规纠偏（前提仍成立） | 小幅变化（减速、加速、避让、换道）：每收到新状态就重新估算一次，但只有偏差超过容忍阈值才下发新指令 | 修正后的会面点；小幅抖动不改指令，避免空中反复横跳。**不重新选机**，只重算这一架机的会面点 |
| **6b** 去程段追踪与意图变更（前提已失效） | 航向持续大幅偏离、速度持续趋零、位置进入分汊点、锚地、港区，任一条**持续成立**即判定 | 不再纠偏，回上游：重跑第 2、3 步及之后。出口只有两个——原机继续追（重算会面点）／放弃本次会面（原机带货返航或迫停）。**改派不在此处发生**，见 §8 |
| **7** 末段：会面与交接（控制目标切换） | 进入会面点邻域即切入。此时追踪对象从「船未来会到哪」变为「我与船此刻相对怎样」：保持相对速度趋近于零、相对位置稳定于甲板上方；四子阶段：接近 → 匹配 → 交接 → 脱离 | 交接完成确认（含伴飞与交接的时间、能耗开销）。末段内部仍有跟随误差修正，但**不再重算会面点**；对接失败则重试、悬停等待，或放弃本次会面并上报 M2 |
| **8** 返航与回收 | 归巢目标在派单时已确定为原驻巢，此处为**复核**：按实际剩余电量 ＋ 实时风况重算；能回原巢就回原巢，回不去则申请应急迫停——向近处机巢请求，须按占用时间窗判定准入，无可借机位时选应急迫降点。回原巢无需占位，迫停他巢才需占位。落点确定后调路径规划生成返航航迹并精算返程电量与到达时刻——返航航迹与去程航迹是同一项航迹能力的两次调用 | 归巢／迫停／迫降点／触发兜底；并触发货物回收与订单重入队 |

**第 1 步还有两道派单前置门**（与航段这道空间闸门并行）：

| 闸门 | 维度 | 内容 |
|---|---|---|
| 货物已备好 | 状态 | 拣选、打包、送达机巢并通过检查；未备好的订单只受理、不进调度 |
| 全域气象熔断 | 时间 | 熔断期间系统只受理不派单，已受理的挂在队列里，解除后恢复 |

因此「等待原因」有两类：**等船**（未驶入系统服务航段）与**等货**（货物未备好），二者都是受理但不派单。进调度的订单均已满足「货已备好」，故第 3 步求解会面点时无需再考虑装货等待。

## 3 预测的两级

流程写的是「第 1 步接单 → 第 2 步预测」，可第 1 步要判断「这艘船时间窗内会不会驶入服务航段」，本身就需要预测。解开它的是**常驻层**：船的预测从开机起就一直在算，与订单无关；订单来了，第 1 步只是取这艘船当前那份预测快照看一眼，并不需要「先走一遍第 2 步」。

| | 常驻预测（第 0 步） | 精算预测（第 2 步） |
|---|---|---|
| 范围 | 全部在航船舶 | 这一单指定的那一艘 |
| 触发 | 持续滚动刷新 | 接单时触发；快照过旧或缺失则现算一次 |
| 深度 | 够判断「会不会来、大概何时来」 | 完整轨迹 ＋ 不确定性带，供第 3 步求会面点 |
| 谁在用 | 第 1 步接单；第 6a 步飞行中纠偏 | 第 3 步剪枝 |
| 判错后果 | 无所谓，第 3 步还会再验证一次 | 直接错——会面点就错了 |

三条容易踩的坑：

1. **一套实现、两种触发**：常驻滚动更新 ＋ 接单时按需取用，禁止做成两套代码，否则飞行中纠偏时不知道该用哪个版本。
2. **常驻预测覆盖范围必须外扩于系统服务航段**：船尚在段外时也要有预测数据，否则第 1 步的「会不会驶入」无从判断。
3. **常驻层不是「粗略版预测」，是「永远在线的全量底座」**：它的价值在广度（全量、持续、随时可取），第 2 步的价值在深度（单船、精细、带不确定性）。

一句话：第 1 步是「查一眼」，第 2 步是「正式算」。

## 4 三段划分

| 段 | 定义 | 对应 |
|---|---|---|
| 去程段 | 从机巢起飞，到进入会面点邻域之前（飞向船的那一趟） | 第 6 步 |
| 末段 | 会面点邻域内完成伴飞与交接 | 第 7 步 |
| 返程段 | 交接完成到归巢 | 第 8 步 |

注意去程段的终点是「进入邻域」，不是「交接完成」。

## 5 追踪与交接：第 6、7 步为什么分开

实时追踪不是第 6 步独占的动作，它从起飞到归巢全程在线，与兜底同级，是**横切机制**而非流程步骤。第 6、7 步分开的依据不是「追踪停了又启动」，而是**控制目标与被控量变了**。

| | 第 6 步 去程段 | 第 7 步 末段 |
|---|---|---|
| 切入条件 | 起飞即进入 | 进入会面点邻域（末段触发） |
| 追踪什么 | 船未来会到哪（预测问题） | 我与船此刻相对怎样（控制问题） |
| 被控量 | 会面点 | 相对速度、相对位置 |
| 纠偏动作 | 重算会面点，超阈值才下发新指令；不重新选机 | 姿态跟随修正；**不再重算会面点**（两者已相遇，会面点失去意义） |
| 失败处理 | 意图变更 → 回上游重跑第 2、3 步（原机继续追／放弃本次会面） | 重试／悬停等待／放弃本次会面转兜底 |

### 5.1 6a 与 6b 是同一条链路的两个出口

它们不是两种飞行任务，也不是并列的两个模块，而是去程段内对同一个问题「船沿航道行驶这个前提还成不成立」的两种判定结果，二者**互斥**：任一时刻只可能处于其中一种。

| | 6a 常规纠偏 | 6b 意图变更 |
|---|---|---|
| 判定 | 前提仍成立，只是数值抖动 | 前提已失效，船的意图变了 |
| 性质 | 量变：减速、加速、避让、换道，预测模型还适用 | 质变：航向持续大幅偏离、速度持续趋零、进入分汊点、锚地、港区，预测模型失效 |
| 触发门槛 | 每收到新状态即重算，偏差超容忍阈值才下发指令 | 必须**持续成立**才判定，避免一次抖动就误触发——回上游重跑代价很大 |
| 处理与代价 | 只重算这一架机的会面点，不重新选机 | 重跑第 2、3 步及之后；出口为原机继续追或放弃本次会面 |

实现提示：兜底表中的「船舶大幅变向或减速」与 6b 是同一条链路，代码里复用一套判定，不要设计两套。另外，6a、6b 只覆盖去程段；末段的异常属于交接失败处理（重试、悬停等待、放弃），不归 6a、6b。

因此流程图的正确画法是：追踪与兜底画成横贯全程的两条带，第 6、7 步只标各自的控制目标。若把追踪画成第 6 步里的一个框，会让人误以为会面阶段不再追踪。

## 6 横切一：实时追踪

从起飞到归巢全程生效，不占步骤：

- 船舶侧：M1 采集 AIS → M2 状态估计与滚动预测；
- 无人机侧：M1 接入遥测 → M4 飞行语义级清洗 → 清洗结果写入共享数据源 → M2、M3、M5 按需取用（遥测只接入一次）。

## 7 横切二：兜底保障

兜底不是第 9 步，而是横切在线的监控机制，从起飞到归巢全程生效，与实时追踪并列为两条横切线。**检测归 M4，决策归 M2**。**例外**：临时禁飞、空域管制突现、多机空域冲突三类**空域类检测**归 M3 功能 15，只作事实事件上报、不做改航决策（见 `81` 附录「跨组裁决落地」B-4、B-5）。

| 触发条件 | 系统动作 |
|---|---|
| 电量告急 | 提前返航 ／ 申请迫停（优先近处机巢，须判定准入；无可借机位时选应急迫降点）。**不转派接力**——货物在这架机上，另一架机无从获得它 |
| 风速突变超阈值 | 降速改航 ／ 放弃本次会面，原机带货返航或迫停；货物回收后再决定是否重派（见 §8） |
| 船舶大幅变向或减速 | 重算会面点；若已不可达则进入第 6b 步意图变更流程 |
| 船位信号丢失 | 降级为沿航道外推；超时未恢复则盘旋等待或返航 |
| 通信中断 | 按最后已知指令执行 ＋ 自主返航 |
| 无人机失联或灭失 | 按最后已知位置与时间外推搜寻；确认灭失则货物随之灭失，订单标记**异常终止**——此时不存在改派，见 §8 |
| 临时禁飞、空域管制突现 | 实时改航绕行 |
| 多机空域冲突 | 派单时先查资源占用（机、巢位、会面窗口），航迹算出后再按航迹级查一次；冲突优先错峰挪起飞时刻或绕行，都不行才回退换候选（仅派单阶段、起飞前；飞行中禁换机） |

## 8 货物回收后重派闭环

重派看似是调度问题，实际上首先是一个**物理约束**：货物是外部加入的有限对象，同一时刻只能处在一个载体上。因此「让另一架机去送同一票货」要成立，必须先把货物从当前载体转移到别处——而唯一可行的转移途径，是**当前这架机成功降落到机巢**。

分界线不是「起飞前、起飞后」，而是「**货物是否已随载体离开机巢**」。飞机在巢内时（含已装机尚未起飞）可以直接换机——卸货重装即可；一旦离巢，货物就绑死在这架机上，此后没有任何办法把它交给另一架在空中或另一处的飞机。

| 原机的落点 | 货物去向 | 能否重派 |
|---|---|---|
| 返航至原巢、迫停于他巢 | 随机落巢，货物被系统回收，状态转为可用 | **能**，且是唯一的重派入口 |
| 迫降于应急迫降点（野外） | 落在系统设施之外 | 不能直接重派，须人工回收后再入队 |
| 无人机失联或灭失 | 货物随之灭失 | 不能，订单**异常终止** |

闭环路径：**原机落巢 → 货物回收 → 订单重入队（状态回到待调度）→ 重新走第 2、3、4 步**。

它与 §9 的数据回流是两条不同的回路：后者回流的是能耗、偏差等用于校准模型的数据，前者回流的是**订单本身**。

重派时的两条约束：

1. **起飞起点受货物所在位置限制**：能直接送这票货的，只有货物所在那个巢的可用机；若要由别巢的机来送，须先把货物转运过去——本期不实现。这意味着**货物位置是重派剪枝的必要输入**，流程中必须持续跟踪，而不只是记一笔账。
2. **只有落进机巢才成立闭环**：应急迫降点在野外，货物落那里不构成回收，重派链路到此断开，须转人工。

## 9 数据回流闭环

每次任务回收三项实际数据，用于校准系统模型，使系统越用越准。

| 回收的实际数据 | 回流校准什么 |
|---|---|
| 实际能耗 | 能耗模型的动态权重 |
| 实际会面偏差 | 调度策略偏好与纠偏阈值 |
| 轨迹预测误差 | 预测模型参数 |

配合带扰动注入 ＋ 对照组的仿真验证框架，这是无实物条件下唯一的有效性证明手段。

## 10 边界声明

1. **接力交接（空中换机）、货物转运（卸至他巢后再送）、下游同品库存补送**——本期均不实现。因此凡涉及「换一架机继续送」的处置，一律表述为「**货物回收后重派**」，不得写成「改派、接力、由下游接手」。
2. **飞行中不存在改派出口**：第 6b 步的出口只有「原机继续追」与「放弃本次会面」两个。
3. 本文只讲步骤与判据，不讲算法与型号；具体计算方式各归其模块文档。
