## 1 目标

### 1.1 定性目标

主视图是答辩的第一印象，目标是「让评委不用听讲解，30 秒就能看出这是真实赣江航道上的多机巢低空物流系统，而且系统在预测、在动态会面」。

三件事必须在画面上「看得见」：

1. **预测式调度**——货船预测轨迹（虚线）＋ 置信椭圆随预测刷新收敛；
2. **动态会面**——会面点十字准星随预测刷新漂移，锁定后高亮；
3. **多机巢与空域约束**——两岸机巢、机队、三座桥梁（含净空约束）、航道都在真实底图上可见。

### 1.2 1.0 范围与边界

- 只做 **2D 主视图（中央地图）**。
- **作业区：赣江南昌段，朝阳大桥—八一大桥之间（约 5.78 km，依据 73-赣江场景说明）**。
- 含：天地图卫星影像底图、场景要素图层、三个卖点动效、数据驱动机制、默认视野自动定位、离线底图兜底预留。
- 不含（后续版本）：3D 会面剖面小窗（2.0）、整屏 3D（3.0，视需要）；配色／主题等视觉与其他页面 UI 另案处理。

### 1.3 验收标准

1. 底图为天地图影像 ＋ 影像注记，稳定加载，无空白／纯色；
2. **加载即自动定位到作业区（赣江南昌段 · 朝阳大桥—八一大桥），无需手动缩放**，视野覆盖全部作业要素；
3. 货船／无人机／机巢／会面点与真实赣江江面、真实桥梁对齐（GCJ-02 转换正确，无可见偏移）；
4. **数据驱动**：无数据时不出任何占位图标，有数据才出现（动态帧与静态台账同理）；
5. 机巢、机队、三座桥梁、航道等场景要素上屏，且不堆叠、可辨认；
6. 预测轨迹为虚线＋半透明置信椭圆，椭圆随预测刷新收敛；会面点随预测刷新漂移、锁定后高亮；
7. 断外网时仍可演示（离线瓦片兜底）。

## 2 设计原则（定死的基准）

### 2.1 真实底图

- 主视图底图固定为**天地图影像底图（`img`）＋ 影像注记（`cia`）**，均为球面墨卡托 `_w` 版本；key 已申请（浏览器端）。
- 保留**矢量底图（`vec`）＋ 矢量注记（`cva`）** 作为可一键切换的备选（答辩讲细节用）。
- **注记配对不可混用**：影像配 `cia`，矢量配 `cva`。
- 呈现真实地理／真实航道／真实桥梁，不做纯示意底图。

### 2.2 数据驱动，只画实际有的

所有要素按来源分两类，**后端没给就不画**：

| 类别 | 要素 | 出现条件 |
|---|---|---|
| 动态要素 | 货船、无人机、会面点、告警 | WebSocket／SSE 实际下发对应帧时才出现 |
| 静态台账 | 机巢、桥梁、航道、禁飞区 | 接口实际返回对应记录时才出现 |

不做硬编码占位数据；演示需要的样例数据单独走「演示数据源」，与真实链路分开。

### 2.3 坐标口径

- 对内（存储／算法）保持 **WGS-84**；
- 对外（前端上屏）统一转 **GCJ-02** 贴天地图；
- 转换只发生在前端渲染层，一个工具函数，转换后需核对货船／无人机／机巢与真实江面无偏移。
- 注意：73 文档中的桥梁坐标为「公开地图示意坐标、可能为 GCJ-02」，须按统一基准转换后再用。

### 2.4 可读性

- 要素沿真实地理铺开，同一位置不叠图标；
- 告警用「环／闪烁」表达，不额外叠一个点；
- 保留图例。

### 2.5 密钥与配置管理

- 天地图 key 放前端环境变量（`VITE_TIANDITU_KEY`），**不进代码库、不入文档正文**；
- 文档仅记录「已申请浏览器端 key」；离线瓦片授权单独评估。

### 2.6 默认视野

- 主视图加载即**自动定位到作业区**（`setView(center, zoom)` 或 `fitBounds(bounds)`），不要求用户手动缩放；
- 作业区边界固定（赣江南昌段 · 朝阳—八一），视野留边距，全部要素一屏可见；
- 容器尺寸变化（窗口缩放／初次渲染未就绪）时，重新 `invalidateSize` + `fitBounds`，避免落到全局视野。

### 2.7 场景范围与要素（依据 73-赣江场景说明）

| 项 | 内容 |
|---|---|
| 服务航段 | 赣江南昌段，朝阳大桥—八一大桥（约 5.78 km 直线） |
| 桥梁 | 朝阳大桥 28.646/115.852、南昌大桥 28.663/115.859、八一大桥 28.692/115.879（示意坐标，可能 GCJ-02） |
| 机巢 | 两岸各一个，共 2 个（坐标待配置，演示用仿真布点） |
| 无人机 | 2–3 架，能力有差异 |
| 主故事 | 货船向上游航行 → 药品补给订单 → 风速突变 → 原机放弃会面返航 → 货物回收 → 订单重入队 |
| 关键约束 | 桥梁净空、机型抗风上限、全域气象熔断、回收后才能重派 |

## 3 当前缺点

| # | 缺点 | 证据 |
|---|---|---|
| 1 | 无真实底图 | MapView 无 tileLayer，原为 CSS 网格；OSM 瓦片国内加载失败（预览暴露） |
| 2 | 无真实地物图层 | 机巢、桥梁、航道、禁飞区等场景要素全部缺失 |
| 3 | 机巢／机队接口已存在但前端未接 | `/api/nests`、`/api/drones` 在 client.js 中 0 次调用 |
| 4 | 禁飞区／迫降点「有实体、无接口」 | `airspace_restriction`、`emergency_landing_point` 有 Entity／Mapper，无 Controller |
| 5 | 预测轨迹画成实线，与设计不符 | shipLayer 无 dashArray；设计 36 §3 要求虚线 |
| 6 | 会面点无漂移动效 | meetingLayer 只画静态十字准星，无历史点迹 |
| 7 | 无人机缺「兜底盘旋」阶段 | droneTrackLayer 仅去程／末段交接／返程三色 |
| 8 | 单实例渲染，承载不了多机巢并发 | ship／drone／rendezvous 均为单值 store，仅渲染 orders[0] |
| 9 | 坐标基准未统一 | WaterwayGeometry 注释已标注「可能为 GCJ-02，须统一基准」；73 桥梁坐标同为示意 |
| 10 | 无离线底图兜底 | 现场断外网时地图一片空白 |
| 11 | 要素为硬编码演示数据，非数据驱动 | 预览为写死坐标，图标不随实际数据出现／消失 |
| 12 | 同位置图标堆叠、可读性差 | 预览中船标与告警点、会面点与盘旋圈叠加，辨认不清 |
| 13 | 主视图无默认视野定义 | 预览默认落到大陆级视野、需手动放大；无固定作业区边界 |

## 4 变动

### 4.1 底图：无 → 天地图影像＋影像注记（可切矢量）

- 接入 `img`（影像底图）＋ `cia`（影像注记）两层瓦片，均为球面墨卡托 `_w`；key 走 `VITE_TIANDITU_KEY`；
- 保留 `vec`＋`cva` 矢量组合作为可一键切换的备选；
- 注记配对修正：影像配 `cia`、矢量配 `cva`，不可混用；
- 预留离线瓦片兜底方案（天地图离线缓存有条款限制，另定授权或备用底图）。

### 4.2 坐标：未统一 → 对外 GCJ-02、对内 WGS-84

- 前端新增 WGS-84 → GCJ-02 转换工具函数，仅渲染层调用；
- 转换后核对货船／无人机／机巢与真实江面、真实桥梁无偏移。

### 4.3 数据驱动：硬编码 → 只画实际有的

- 动态要素由帧驱动、静态台账由接口驱动，无数据不画、不摆占位；
- 演示样例数据独立成「演示数据源」，与真实链路分离，不混入业务图层。

### 4.4 场景图层：只有 4 类 → 场景要素齐全

- 保留：货船、无人机、会面点、告警；
- 新增：两岸机巢（2）、三座桥梁（朝阳／南昌／八一）、赣江航道、禁飞区（如场景需要）；
- 图层清单与样式对齐 36 §2 与 73 §3。

### 4.5 数据接入：接口空转 → 接通

- 前端接通现有 `/api/nests`、`/api/drones`（机巢、机队上屏）；
- 后端补 `/api/airspace`、`/api/landing` 两个只读接口（禁飞区、迫降点）；路径走 ApiPath 常量；
- 定死 `airspace_restriction.scope` 的序列化契约（GeoJSON 等）；
- 机巢坐标按 73 要求「统一坐标系下配置并记录来源」。

### 4.6 动效：静态 → 三个卖点动效

- 预测轨迹：实线 → 虚线＋流动＋置信椭圆收敛；
- 会面点：静态 → 漂移点迹＋锁定高亮；
- 告警：风速突变红色脉冲环＋弹出提示框（与事件流联动）。

### 4.7 默认视野：无 → 自动定位到作业区

- 固定作业区边界（赣江南昌段 · 朝阳—八一）；
- 加载即 `setView`／`fitBounds` 自动定位，留边距、一屏可见全部要素；
- 容器尺寸变化时重新 `invalidateSize` + `fitBounds`，避免初始尺寸未就绪时落到全局视野。

### 4.8 版本路径（不在 1.0 内，仅列后续）

- 2.0：主视图右下加 3D 会面剖面小窗（桥净空／高度／低空走廊）；
- 3.0：视需要评估整屏 3D（可一键切回 2D）。
