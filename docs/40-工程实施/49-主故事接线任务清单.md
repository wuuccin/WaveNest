### 4.3 逐人任务

#### 4.3.1 张睿哲 M2 调度

> C0 是今日最长路径，最先做。

- **C0 首次派发编排**：`DispatchTrigger` 止于 `TaskQueueService.startDispatch`（「调度中」）；主代码里没有把「选机、会面、派发」串起来的生产调用方。唯一含该串法的是 `RescheduleService.reschedule()`（`requeue` → `CandidateSelector.selectBest` → `RendezvousCoordinator.solveFor` → `startDispatch` → `dispatch` → 回填会面点）。
- **做法**：把 `RescheduleService` 里「选机、会面、派发、回填会面点」抽成共用段，由组批之后调用（事件驱动或由 `DispatchTrigger` 续接）。首次派发不走 `requeue`，因为 `requeue` 会清空 `droneId`/`meetTime` 并写「重入队」留痕，语义不符。
- **判据**：下单后订单自然走到「已派发」，`drone_id`、`meet_time`、`meet_lon`、`meet_lat` 均有值，`task_log` 无「重入队」记录。

#### 4.3.2 卢肄文 M2

- **现状**：选机段只选不判。`RescheduleService` 只调 `CandidateSelector.selectBest`（装配 `DroneView`，不判可行性），真正吃风的 `CandidateService.judge(..., worstWindMs, ...)` 与 `FeasibilityJudge` 无生产调用方；`WeatherSnapshotStore.worstWindMs()` 目前只被 `WeatherGateTrigger` 消费。所以「风速一大就刷掉 A 型机」只在单测里成立。
- **做法**：在 C0 搭好的选机段里补上判定，流程为生成、`CandidateService.judge`、择优；现场风取 `store.worstWindMsOrDefault(now, fallback)`。`fallback` 必须显式定死并写进注释：无新鲜风况时不得给 0 m/s（0 会被下游当成「无风、可飞」，是危险方向的默认值），建议取保守值或直接判「数据不足」不放行。
- **判据**：注入 11 m/s 后 M30T（抗风 10.0）被淘汰、M400（12.0）保留，且该判定发生在真实派发链上，不只在单测里。

#### 4.3.3 罗才辉 M3

- **现状**：`RendezvousCoordinator.representativeWind()` 走 `WeatherSnapshotAdapter` 读 `weather` 表，而全库无 `weather` 表写入方（M1 只发 MQ），故 `latest()` 恒返回空，回落 `sys_param`（缺省 0 m/s），会面点运行时不随风变化。
- **做法**：让 `WeatherSnapshotAdapter` 改读 `WeatherSnapshotStore.nearest(lon, lat, nowMs)`（返回 `Optional<WeatherData>`，空即回落；该方法的注释本就是留给会面链的，按位置取风也符合 `22` §7.2 U-05 甲案）。保留「无数据回落 `sys_param`」的兜底，气象异常不得中断调度主链。
- **与 B4 的关系**：本项收口 10-20 B4 的取数来源；端口形状与无数据回落 `sys_param` 的口径沿用 B4，不再改求解器。
- **判据**：注入顺风、逆风两档，会面点与起飞时刻发生方向相反的变化；6a 参数敏感性回归仍绿。

#### 4.3.4 彭紫情 前端与实时推送

- **现状**：`WsPushEndpoint.publish(type, data)` 已就位，但无任何生产调用方（P0-C：`/ws` 握手成功、无业务帧）；前端 `realtime/` 目录已建但无帧可渲。
- **做法**：后端在业务事件点发帧（订单状态变化、船位快照、机位与派发结果），`wl-app.push` 只做转发、不做业务判断；前端按帧类型渲染地图标记与调度台。
- **判据**：起服务后从下单到派发全程有帧，地图出现船舶与无人机标记，状态随派发变化。
- **依赖**：帧类型与宋冰鑫的 C5 告警帧一并定好，两人先对一次。

#### 4.3.5 杨添爻 M1

- **现状**：后端 Controller 只有 3 个（`TurnInjectController`、`WeatherInjectController`、`OrderController`），`/api/drones`、`/api/nests` 均 404（P0-B 前半）。
- **做法**：补无人机台账与机巢台账查询端点。路径复用契约常量 `ApiPath.DRONES` / `ApiPath.NESTS`，不要另写路径字面量；返回值带上 `wind_limit_ms`、`cruise_speed_ms` 两列，便于监控台直接核对 B1 的抗风分档成效。
- **判据**：两个端点返回非空列表，含这两列且与 `003_seed_drone_nest.sql` 一致。

#### 4.3.6 宋冰鑫 M4 检测

- **现状**：检测内核（`DetectionOrchestrator`）与 `AlertRecorder`、`AlertEventPublisher` 均在，但 M4 侧没有任何 `@RabbitListener`。`TelemetryService.accept()` 的注释明写「由 M4 的遥测消费入口调用」，而该入口尚未建；`DetectionOrchestrator` 目前只在测试里被 new。所以告警既没落地也没推帧。
- **做法**：补 M4 的遥测消费入口（`@RabbitListener` 收契约主题 `TopicName.DATA_UAV_TELEMETRY`），驱动 `TelemetryService.accept` → `DetectionOrchestrator` → 告警入 `AlertRecorder` 并推帧。触发点与张的 C0 对齐，帧类型与彭的 C3 对齐。
- **判据**：注入偏航、低电量样本后产生告警记录，并按与彭约定好的帧类型发出（前端呈现由 C3 承接）。
