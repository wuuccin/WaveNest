## 2 中间件（统一用 Docker Compose 起）

**全组统一用 Docker Compose 起中间件**——同一份 `deploy/docker-compose.yml`、同一条 `docker compose up -d`，保证版本、端口、库表结构在所有人机器上完全一致。**这是硬性要求，全员都装 Docker。**

> **前置条件：Windows 上跑 Docker Desktop 需要 WSL2（推荐）或 Hyper-V。** 这是装 Docker 之前的必经一步，**先确认 WSL2 可用再装 Docker**，否则 Docker 会起不来（报 `WSL 2 installation is incomplete` 或 `backend exited before becoming ready`）。
>
> 检查与开启（管理员 PowerShell）：
> ```powershell
> wsl --status          # 看默认版本是否 2；无输出或报错说明未装
> wsl --install         # 一键安装 WSL2（含内核），装完须重启
> ```
> 若机器不支持 WSL2 虚拟化，改用「Hyper-V 后端」（Docker Desktop 安装时选），但 WSL2 后端更省资源、更稳。**这一步是本机前置，与仓库无关，不写进任何仓库文件。**

| 项 | 版本 | 默认端口 | 用途 |
|---|---|---|---|
| MySQL | 8.0+ | 3306 | 14 张表；建库 utf8mb4 |
| Redis | 7.x | 6379 | 实时状态缓存 |
| RabbitMQ | 3.12+（含 management） | 5672／15672 | 模块间消息；管理台 <http://localhost:15672> |
| Mosquitto | 2.x | 1883 | MQTT broker（遥测／指令链路） |

> **`deploy/docker-compose.yml` 是必须入库的交付物**，也是唯一认可的启动方式——它把版本、端口、库表结构一次性钉死，避免「各人直装版本不一」这个联调期最大的坑。
>
> **中间件验收**：`docker compose up -d` 后四件套就绪——MySQL `SELECT VERSION()` 应 8.0+；RabbitMQ 管理台 <http://localhost:15672> 可登录且为 3.12+；Redis `PING` 返回 `PONG` 且为 7.x；Mosquitto 演示期可不起。

## 3 数据库连接参数

**开发期每人连自己本机那套，不是共用一个远程库。** 各人 `docker compose up -d` 起本机四件套，代码默认连 `127.0.0.1`，互不干扰；**14 张表由各人自己建**——张睿哲把 `deploy/sql/001_init.sql` 交进仓库后，每个人 `pull` 下来在本地库执行一遍（或让它随 compose 首次启动自动执行）。联调／演示需要共库时，用 `MYSQL_HOST` 等环境变量或本机 `application-local.yml` 指过去，**不改仓库默认配置**。

连接参数由 compose 固定，无需各人手动对齐：

| 参数 | 值 | 说明 |
|---|---|---|
| 库名 | `wavenest` | compose 自动创建 |
| 账号／口令 | `root`／`wavenest` | 见 `deploy/docker-compose.yml` |
| 字符集 | 库／表 `utf8mb4` | compose 已设 `--character-set-server=utf8mb4` |
| 时区 | `+08:00` | compose 已设 `--default-time-zone=+08:00` |

**★ JDBC 连接串里的两个固定坑（不要改回去）**：

1. **`characterEncoding=utf8`，不能写 `utf8mb4`**。`characterEncoding` 要的是 **Java 字符集名**，不是 MySQL 字符集名；Connector/J 8.x 会把 `utf8` 自动映射到服务端 `utf8mb4`。写 `utf8mb4` 会直接抛 `Unsupported character encoding 'utf8mb4'`（库都连不上，不是乱码那么轻）。
2. **必须带 `useSSL=false&allowPublicKeyRetrieval=true`**。MySQL 8 默认 `caching_sha2_password`，非 SSL 连接首次认证须允许取公钥，否则报 `Public Key Retrieval is not allowed`。

> 仓库 `application.yml` 已按上面两条写好（`backend/wl-app/src/main/resources/application.yml`），**照着用即可，不要「顺手改回 utf8mb4」**。

## 4 开发工具要求

IDE、接口调试等具体工具**自选，不作统一要求**。硬性要求只有三条：

1. Node **20.19+ ／ 22.12+** 与 Git 版本需对齐（**JDK 版本不限，17 起即可**；构建一致性由根构建脚本锁 Java 目标版本保证）；前端**一律用 pnpm**，版本由 `packageManager` 字段锁定。
2. 后端代码使用 Lombok 注解（依赖在根构建脚本登记，注解处理由构建链自动完成，与具体 IDE 无关）；
3. 构建必须可在命令行独立完成（`./gradlew build`，不依赖任何 IDE 内置功能）；**必须使用 Gradle Wrapper**，全员版本由 `gradle/wrapper/` 锁定。

> **Gradle 分发必须走国内镜像（否则首次构建会卡在下载上）**：`services.gradle.org` 会 **307 跳转到 `github.com` 下载分发包，国内网络常连不通**（实测超时）。建仓库时把 `gradle/wrapper/gradle-wrapper.properties` 的 `distributionUrl` 改为镜像地址（已验证可用）：
> ```
> distributionUrl=https\://mirrors.cloud.tencent.com/gradle/gradle-9.7.1-bin.zip
> ```
> 依赖仓库同理建议配 `maven.aliyun.com/repository/public`（`repo1.maven.org` 亦可，作备选）。

## 5 环境自检命令

```
java -version      # 17.x 或 21.x 均可
./gradlew -v       # Gradle 9.7.1（由 Wrapper 锁定）
node -v            # 20.19+ 或 22.12+（Vite 8 要求）
pnpm -v            # 12.x（由 corepack 提供，版本钉在 package.json）
git --version
wsl --status       # Windows：默认版本应为 2（Docker Desktop 的前置）
docker compose version   # 必须：全员用 compose 起中间件
```

> **中间件统一用 `docker compose up -d` 起**（见 §2）。起完做同一组自检——MySQL `SELECT VERSION()` 为 8.0+、RabbitMQ 管理台 3.12+ 可登、Redis `PING` 返回 `PONG` 且为 7.x。

## 6 国内网络与镜像源

> **国内网络必配（实测）**：`registry.npmjs.org` 常连接超时，`registry.npmmirror.com` 正常。装依赖前先设源——`npm config set registry https://registry.npmmirror.com`（写入 `~/.npmrc`，npm 与 pnpm 共用）；若用 corepack 取包管理器，另需环境变量 `COREPACK_NPM_REGISTRY=https://registry.npmmirror.com`。
