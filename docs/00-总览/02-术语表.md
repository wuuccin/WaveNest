## 3 状态词口径

同一状态在历史文档里出现过多种叫法，下表给出唯一写法。**完整状态集、流转条件、写入方见 23-状态机定义**。

| 统一用 | 弃用（历史叫法） | 上下文 |
|---|---|---|
| 待调度 | 待派单、待派发 | 订单已进入派单队列 |
| 调度中 | 派单中、已分配 | 第 2–5 步求解中 |
| 已派发 | 待派发、已完成派单 | 起飞时刻已回填，任务下达 |
| 已受理待唤醒 | 挂起、等待中 | 等船（未驶入服务航段）或等货（货物未备好） |
| 去程中 | 执行中、飞行中 | 对应第 6 步 |
| 末段交接中 | 会面中、交接中 | 对应第 7 步 |
| 返航中 | 返回中、归巢中 | 对应第 8 步 |
| 已完成 | 完成、投送完成 | 交接成功 |
| 已拒绝 | 拒单（口语）、无解 | 业务边界或运力无解 |
| 失败 | 迫降失败 | 迫降野外，转人工回收 |
| 异常终止 | 终止 | 货物灭失 |

禁用说明（这三条必须为 0，除本文的弃用列与 `51-变更记录` 的变更条目）：`待派发`、`待派单`、`已分配`。

## 4 三个调度动作的命名

「派单」一词历史上被用于三个不同动作，必须分开表述：

| 环节 | 动作 | 含义 | 产物 |
|---|---|---|---|
| 第 1 步 | **受理** | 对外承诺承接该订单 | 订单入台账 |
| 第 1 步出口 | **触发调度**（立即 ／ 延后） | 订单进入调度输入，启动求解 | 状态＝待调度，执行第 2→3→4 步 |
| 第 4 步出口 | **任务下达** | 把确定结果交执行侧 | 机型 ＋ 机巢 ＋ 起飞时刻下发 M4 |

约定：「派单」只用于第 1 步出口的「触发调度」；第 4 步一律写「任务下达」，不写「派单」。

## 5 单位与坐标归一

1. **归一由 M6 在落库、入缓存时统一完成**。M1 保持源原始单位与坐标系交付，只做「还原」，不做归一。
2. 基准坐标系：`CGCS2000 / WGS84`；下游一律从 M6 取标准值，不再各自持有并转换原始坐标（避免 GCJ02／BD09 偏移带来的不一致）。
3. 已明确的归一结果：

| 量 | 标准单位 | 出处 |
|---|---|---|
| 经纬度 | 基准坐标系下的十进制度 | 37 的 `ship_ais`、`flight_point` |
| 航速 | m/s | 37 的 `ship_ais` |
| 航向 | 度 | 37 的 `ship_ais` |
| 高度、距离 | 米 | 34 的 Haversine、点到线段距离 |
| 电量 | 百分比 | 34、37 |
| 时刻 | 绝对时间戳 | 占位时间窗 `[t₁, t₁+d]`、起飞时刻 |

4. 未定项：经纬度保留小数位、时间戳精度与时区表述尚未定稿，列入 `53-开放问题`，批 3 重建 `37` 时一并拍定。

## 6 对外表述映射（去算法化）

流程图与申报书一律使用左侧表述；右侧的算法名词仅在被追问技术细节时才展开。

| 对外表述 | 对应的技术细节 |
|---|---|
| 结合航道约束的状态估计与去噪 | 沿航道一维滤波，信号缺失时降级外推 |
| 判断是否具备相遇条件 | 相对运动（拦截）关系求解 |
| 每收到新状态即重新估算一次 | 滚动时域重规划 |
| 按综合代价择优 | 代价函数或拍卖式分配机制 |
| 生成可飞航迹 | 具体寻路算法（不作为创新点） |
| 占住这架机、这个巢位、这个会面窗口、这个归巢时隙 | 资源级占用台账与冲突顺延策略 |
| 错峰挪起飞时刻 | 航迹级时隙冲突消解（不作为创新点） |
| 错峰后回写占位并二次校验 | 时刻一变，会面窗口与归巢时隙占位须同步回写并复校 |
