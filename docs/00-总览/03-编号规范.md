规则：

1. 编号为两位数字 ＋ 半角连字符，例：`21-主流程设计.md`。
2. **模块文档编号公式**：M1→`30`；M2→`31`；M3→`32`、`33`；M4→`34`；M5→`35`、`36`；M6→`37`、`38`。模块文档的文件名必须紧接编号写出 `M<k>-`，例：`35-M5-终端交互.md`。
3. 同目录内编号唯一、递增。新增文档取本段下一个空号；段内允许留空号。**默认不重排**；仅当本段编号序与本项目的主要检索序（组名字母序、主流程步序一类）不一致**且已造成普遍误读**时，方可在该段做**一次性全段对齐**——须同时出改序映射表记入 `51-变更记录`、同步全库引用（格式见 §4）、并过复核清单（文件名／一级标题／元信息「文档编号」三者一致，无空内联代码，无裸编号）。重排后该段**冻结**，此后新增只取空号。
   「已发出的引用失效」的代价范围**只算仓库内**（2026-09-29 定）：库内引用可穷举核对，故重排代价有限；已移出仓库的材料不在约束范围内。
   已按本条重排的一次：`60-算法方案` 段七组方案于 2026-09-29 按组名字母序对齐为 `60`–`66`（映射见 `51` §12 第 11 条）。
4. 编号只体现归属，不体现版本。版本写在文首元信息表与文末版本历史里。
5. 归档件不入编号序列，统一命名 `_原稿/_<原文件名>.md`。
6. **图集目录**：一套图超过单张篇幅时，以 `<编号>-<图类型>/` 建**图集目录**（例 `91-时序图/`）。图集目录占段内**一个**编号；目录内文件命名 `<图集编号>-<序号>-<分段名>.md`（例 `91-3-接单预测.md`），一级标题写 `# <图集编号>-<序号> <分段名>`，编号按 `<图集编号>-<序号>` 计，序号在图集内唯一；目录内文件的图类型词由目录名承载，文件名不重复写。
   **导览页与目录同名**：`91-时序图/91-时序图.md`，标题 `# 91 时序图`，承载图集索引、参与者代号与覆盖范围声明。
   已按本条处理：`91-时序图/`（导览页 ＋ `91-1`–`91-9` 九张图）、`92-状态图/`（导览页 ＋ `92-1`–`92-4` 四张图）、`93-泳道图/`（导览页 ＋ `93-1`–`93-4` 四张图）；原先临时占用的 `95`–`99` 五个编号已释放，仍可作他用。
7. **段整体迁移**：某段的空号不足以容纳新增文档时，该段**整体迁到新段**——新段号取「大于全库当前最大编号的最小整十数」，段内文件编号同步平移。迁移须同时：出迁移映射表记入 `51-变更记录`、改目录名与文件名及其一级标题与元信息「文档编号」、同步全库**现行引用**（格式见 §4）、并过 §1 规则 3 的复核清单。
   **历史叙述不随迁移改写**：各文档文末版本历史表、`51` 各批次的记述里写的是**当时的编号**，保留原号以免失真；读者按 §4 引用时一律用现行编号。`_原稿/` 归档件名同样不改。

## 2 文件命名规则

格式：

```
<两位编号>-<主体名>.md                       通用
<两位编号>-M<k>-<主体名>.md                  模块文档
<图集编号>-<序号>-<分段名>.md                 图集目录内（见 §1 规则 6）
_<任意名>.md                                 元文档、归档件（不入编号序列）
```

硬性约束：

1. 分隔符一律用半角连字符 `-`，**不使用下划线**。
2. **目录名、文件名、文档一级标题不得出现 `与`、`和`两个字符**（连词禁令，落地规则见 §5）。
3. 模块号只写 `M1`–`M6`。禁止 `模块一`、`模块6` 等写法出现在文件名与任何级别的标题里。
4. 类型词只用下列白名单：索引 / 总述 / 术语 / 规范 / 定义 / 分析 / 说明 / 设计 / 记录 / 清单 / 口径 / 剧本 / 方案 / 红线 / 待定项 / 用例图 / 时序图 / 状态图 / 泳道图 / 交互概览图。
   黑名单（一律不得出现在文件名与标题里）：完善版、功能总结、功能完善、修改说明、修订说明、待确认、初版、定稿。
5. 文件名不出现日期、不出现作者、不出现 `v2` 一类版本语义。
6. 文件名主体与文首一级标题**完全一致**（只差编号与扩展名）。模块文档的例外：文件名里的半角连字符在标题里换成空格，即 `30-M1-数据采集.md` 的标题写作 `# 30 M1 数据采集`。

## 3 标题与元信息

1. 一级标题写作 `# <编号> <主体名>`，例：`# 21 主流程设计`。模块文档写作 `# <编号> M<k> <模块名>`，例：`# 30 M1 数据采集`、`# 38 M6 缓存`。
2. 章节号一律用阿拉伯数字并与层级对应：`## 1`、`## 2`；`### 1.1`、`### 1.2`。禁止 `一、`、`（一）` 一类中文序号。
3. 每份文档（图表类除外）文首必须有元信息表：

```markdown
| 项 | 内容 |
|---|---|
| 文档编号 | 21 |
| 版本 | v0.1 |
| 状态 | 草案 / 评审中 / 定稿 |
| 责任人 | — |
| 最后更新 | 2026-09-21 |
| 适用范围 | 覆盖什么、不覆盖什么 |
| 上游依据 | 01 §… ／ 11 §… |
| 下游引用 | 24 §… ／ 31 §… |
```

4. 每份文档文末必须有「版本历史」表：版本、日期、责任人、变更摘要、详细对照（指向 `51-变更记录`）。
5. 表格表头必须有文字，不得出现 `| | |` 空列；正文不得使用转义星号 `\*\*` 表示加粗。

## 4 跨文档引用格式

1. 引用一律写 `文档号 §章节号`，例：`见 24 §3`、`见 37 §2`。
2. **禁止裸文件名引用**。形如「详见《路由、部署与现场演示》一章」「见选机.pdf」的写法一律改写为文档号引用。
3. 被引用章节被拆分或改名时，引用方必须同步改指；改指动作记入 `51-变更记录`。
4. 同一结论只在一处定义，其余位置写引用。单一权威处：

| 主题 | 权威文档 |
|---|---|
| 表结构、缓存键 | `37-M6-数据库`、`38-M6-缓存` |
| 系统参数的初始建议值 | `37-M6-数据库` §5.14.1 |
| 状态机与状态枚举 | `23-状态机定义` |
| 接口、消息主题、模块间调用契约 | `22-接口契约` |
| 需求条目与追溯矩阵 | `11-需求规格说明` |
| 剪枝口径 | `24-选机链设计` |
| 术语与状态词口径 | `02-术语表` |

## 5 连词禁令的落地规则

1. 目录名、文件名、文档一级标题里不得出现 `与`、`和`（正文叙述不受此限）。
2. 一个命名里出现连词，说明它承载两个主题，此时**拆成两份文档**，各自占一个编号；不采用同义替换的方式规避。
3. 唯一例外：连词连接的是同一主题的两种说法时**归并为一个名称**，不拆。已按此处理的七处：选机与任务分配、选机链与剪枝 → `24-选机链设计`；返航与归巢、返航与归巢资源判定 → `25-返航设计`；问题与决策记录 → `50-决议记录`；文档索引与阅读指引 → `00-文档索引`；并发与需求暴增下的三项集中维护措施 → `26-并发控制设计`。
4. 已按第 2 条拆分的三处模块名：`动态会面与路径规划` → `32-M3-动态会面` ＋ `33-M3-路径规划`；`终端交互与可视化` → `35-M5-终端交互` ＋ `36-M5-可视化`；`数据库与缓存` → `37-M6-数据库` ＋ `38-M6-缓存`。模块本身的口径不变，正文里仍可写作「模块三」「模块五」「模块六」。
5. 校验命令（命中必须为 0）：

```powershell
Get-ChildItem 'docs' -Recurse | Where-Object { $_.Name -match '[与和]' }
Select-String -Path 'docs\*\*.md' -Pattern '^#\s.*[与和]'
```
