## 1 研究范围

### 1.1 两项功能

| 全局序号 | 功能 | 模块 | 需求条目 | 主流程步骤 | 落点 | 回答什么问题 |
|---|---|---|---|---|---|---|
| 1 | 订单接入与基本校验 | M2 | `M2-01` | 第 1 步 | `31` §3.1 | 这一单我们做不做；不能立刻派时算等船还是等货，什么时刻把它唤醒 |
| 2 | 船舶状态估计与轨迹预测管理 | M2 | `M2-02` | 第 0 步（常驻）、第 2 步（精算） | `31` §3.2 | 船此刻在哪、多快、朝哪走；未来会到哪、误差多大；「沿航道行驶」这个前提还成不成立 |

对应关系（引 `03` §6.4）：第 0 步 → 功能 2（常驻层，与订单无关、滚动刷新）；第 1 步 → 功能 1（与功能 12 同属该步，三个出口为触发调度、延后触发调度、拒单）；第 2 步 → 功能 2（精算预测，只服务本单）。

### 1.2 明确边界（不做什么）

1. **不改设计口径**。系统服务航段按航道里程算、常驻预测覆盖外扩于服务航段、预测与精算是一套实现两种触发、会面点是组合级产物、数据不足时暂缓而不使用过期数据派机——由 `21`、`24`、`31` 定，本文只给做法。
2. **不做决策**。追得上与回得来（功能 4）、择优与占位（功能 5／6）、是否返航（功能 10）归 M2 其余功能块；本组只出「船会怎么走」与「这个结论可不可信」。
3. **不求解会面点**。会面点取决于机型速度、机巢起点、风况修正与船的预测轨迹，属组合级产物（`24` §3.1、`32` §4.1）；本组只交付预测轨迹，不产生对所有无人机都相同的会面点（`31` §3.2 说明）。
4. **不做无人机侧的状态处理**。无人机是自有设备、遥测是直报状态，不需要像 AIS 那样做估计（`31` §2 分工要点 2）；遥测的格式级校验归 M1，飞行语义级清洗归 M4（`30` §4.2、`20` §4）。
5. **不做坐标与单位归一**。归一由 M6 在落库、入缓存时统一完成，M1 保持源原始单位交付（`37` §3 规则 7、`02` §5）。
6. **不直接落库、不建表**。结果经 M2 交由 M6 落 `ship_ais` 与 Redis（`22` §5 常驻层行、`38` §2）；新增台账的诉求见 §5 待定项 1、7。
7. **不含派单闸门的触发逻辑**。熔断与人工冻结的触发与解除归功能 12（`31` §3.12）；功能 1 只**读**闸门状态，不判气象红线。
8. **不含机型级匹配**。功能 1 只判「货物是否超过全部机型的最大载重」这一业务上界；逐机型与逐组合的筛选归功能 3、功能 4（`31` §3.1、`24` §2.2）。
9. **不碰本期不实现项**：接力交接、货物转运、多级改投、空中排队等待、连续时空风场插值、逐航段风况修正（`21` §10、`24` §9、`33` §7 已定首版不做）。

### 1.3 与相邻功能的分界

| 相邻功能 | 分界 |
|---|---|
| 功能 3、功能 4（C 组） | 本组出预测轨迹与可信状态；能否追上、能否回来由 C 组与 M2 判（`24` §3）。预测**不判可行性** |

| `M4-03` 数据校验过滤（F 组） | F 组清洗**飞行器遥测**的飞行语义级野值；本组估计**船舶**状态。清洗三级分层见 `30` §4.2、`20` §4 |
| `M3-06` 去程段追踪与纠偏（E 组）、功能 9（E 组） | `33` §3.5 规定纠偏循环的第一层动作就是「先重估预测」，因此本组必须提供一个**可高频调用的重估入口**；但 `6a`／`6b` 的分支与处置归 M3／M2。为避免「船侧偏差」两处各判一套，本文把前提监测拆成**事实层／统计层／确认层**并写明归属（§3.2.8）：**事实层与归一化偏差量归本组，精细确认与分档归功能 17**；`33` §3.5 要求的「复用一套判定，不设计两套」由此落实为**量在 A 组、判在纠偏侧** |

| `M3-08` 会面偏差回流（G 组） | G 组交回会面偏差样本；「轨迹预测误差 → 预测模型参数」这一支由本组承接（`32` §3.6、`21` §9、`22` §5 数据回流行） |
| `M4` 偏差比对 | 预测轨迹随任务方案下发 M4，用于其偏差比对（`34` §2、`34` §3.1 功能点 2.1.2；`22` §5 第 5 步任务下达） |

## 2 输入与输出

### 2.1 上游数据的来源、表示方式与粒度

| 数据 | 来源 | 表示方式与粒度 | 使用处 |
|---|---|---|---|
| AIS 船位对象 `AisMessage` | M1 经 MQ 主题 `data.ais`（`22` §1.2、§2） | `mmsi`、`shipName`、`lon`、`lat`、`sog`、`cog`、`ts`；**保持源原始单位与坐标系**；逐报文 | 步骤 A |
| 接入链路健康 `ConnectorHealth` | M1 暴露（`30` §3.5、`22` §2） | 在线／断流／延迟／最后收数时间 | 功能 1 数据有效性、步骤 A 降级 |
| 航道中心线台账 | 待建（见 §5 待定项 1） | 折线节点 ＋ 累计里程 ＋ 分汊点 ＋ 受限水域 ＋ 航段限速 | 步骤 B–E |
| 系统服务航段 | 运营配置（`21` 第 1 步、`02` §2） | 航道里程区间 `[sStart, sEnd]` | 功能 1 空间闸门、`T_max` |
| 气象 `WeatherData` | M1 经 `data.weather` | `lon`、`lat`、`windSpeedMs`、`windDirDeg`、`gustMs`、`ts` | 可选：速度前瞻修正 |
| 水文 `HydroData` | M1 经 `data.hydro` | `lon`、`lat`、`waterLevelM`、`flowMs`、`ts` | 可选（消费方未定，`37` §8 未决 5） |
| 订单 | M5 下单经 `22` §5 第 1 步行；字段含选船、货物类型、重量、紧急程度（`35` §3.1） | 单订单 | 功能 1 |
| 货物状态 | M6 `goods`（`37` §5.3、`23` §6） | 未就绪／已就绪／已装机／已交付／已回收／灭失 | 功能 1 状态闸门 |
| 机型与无人机档案 | M6 `drone`、`nest`（`37` §5.1、§5.2） | `maxPayloadKg`、续航、归属巢、当前所在 | 功能 1 载重上界、`etaMin` 下界 |
| 闸门状态 | 功能 12（`31` §3.12） | 正常／熔断中 | 功能 1 时间闸门（只读） |
| 阈值与参数 | M6 `sys_param`（`37` §5.14） | 键值对，不硬编码 | 全部 |

粒度上的三条硬要求：

1. **时间一律用绝对时间戳，且取报文打点时间 `ts` 而非接收时间**。链路延迟与多基站转发时间差不进入估计与预测（`02` §5 时刻口径）。
2. **AIS 点列必须带 `mmsi`，重复报文按 `mmsi ＋ ts` 去重**。M1 只做基本去重（`30` §4.2），同一报文可能经多基站重复到达，本组须区分「同一目标的两条」与「两个目标」。
3. **归一职责在 M6**。落到本组的结果（状态估计、常驻预测快照）由 M2 交 M6 统一归一；M1 只做「还原」、不做归一（`30` §4.4），本组也不自行转换坐标系（`37` §3 规则 7、`38` §3 规则 4）。

> 一处输入口径待对齐：`22` §5 常驻层写「M1 → M2、M3、M4、M5、M6 传递解析后的原始态势」，而 `37` §3 规则 7 与 `02` §5 规则 2 写「下游一律从本模块取标准值」。本文按**直取 `data.ais` 做实时估计**（低延迟）实现，并把写回 M6 归一后的结果作为对外标准值；两者的统一见 §5 待定项 2。

| `snapshotVersion` | string | 本次判定所用的常驻快照版本，供功能 11 追溯 |

**（3）WebSocket `ship_traj` 载荷**（`22` §4、`36` §4 要求前端能画置信椭圆，故必须传方差或标准差）

```json
{ "type": "ship_traj",
  "data": { "shipMMSI": "...", "version": "PV...", "t0": 0,
            "points": [[lon, lat, t], ...],
            "cov": [[sigmaAlong, sigmaCross], ...],
            "courseDeg": 0, "validitySec": 0,
            "premise": { "status": "VALID", "reason": null } } }
```

前端按 `a = 2·sigmaAlong`（沿航迹方向）、`b = 2·sigmaCross`（法向）画旋转椭圆，旋转角取 `courseDeg`（`36` §3 的「长短轴来自预测方差」）。

### 2.4 调用契约上的六条硬约束

1. **一套实现、两种触发**。常驻预测（全量、滚动刷新）与精算预测（单船、接单按需）必须是一套实现，禁止两套代码；差别只在广度与深度，不在精度高低（`20` §2 硬约束 2、`21` §3 坑 1、`31` §3.2 说明）。实现上体现为**同一个 `predict(shipState, centerline, params)` 函数**被两个调度入口调用，见 §3.2.11。
2. **快照必须带版本号**。同一轮调度所有候选共用同一版本，版本不一致即**拒绝求解**（`32` §3.1 判定 3、§4.2、§6 硬约束 3；`61` §2.1 硬要求 1 据此要求会面求解的输入对象携带版本号）。
3. **常驻层是长期驻留进程**，不因订单启停（`31` §6 硬约束 1）；覆盖范围必须**外扩于系统服务航段**（`20` §2 硬约束 1、`21` §3 坑 2）。
4. **参数一律读 `sys_param`**，不硬编码（`11` 的 `NF-8`、`37` §5.14）。
5. **只出预测与前提状态，不出可行性结论**（`31` §3.2 说明、`24` §3.2、`27` §3）。
6. **按船缓存结果复用**，避免多单重复计算（`26` §5 第 2、3 步行）；并发下同一调度周期共用一份态势快照（`26` §5 常驻层行）。

### 2.6 不确定度表达形式与下游用法

本节给出本组对外交付不确定度的**形式约定**与**下游可直接使用的算法**，作为跨组接口的会签依据。下游（M3 的去程纠偏、M2 的返航复核）在做「偏差显著性」判定时，只需要本组三个量：`σ_along`、`σ_cross`、`courseDeg`。

**（1）给出的是「标准差标量对 ＋ 主轴方位」，不是经纬度 2×2 矩阵**

| 形式 | 是否提供 | 说明 |
|---|---|---|
| 沿航道／法向标准差 `σ_along(t)`、`σ_cross(t)` | **提供**（`points[i].sigmaAlong`／`sigmaCross`） | 与物理分解一致：纵向决定会面**时刻**，横向决定会面**位置** |
| 主轴方位 `courseDeg` | **提供** | 重建 2×2 协方差所需 |
| 经纬度系 2×2 协方差矩阵 | 不直接提供 | 曲线坐标下的耦合塞进经纬度矩阵会丢掉「沿航道—法向」的语义；需要矩阵时按下式重建 |
| 置信椭圆长短轴 | 由前端换算 | `a = 2·σ_along`、`b = 2·σ_cross`，旋转角取 `courseDeg`（`36` §3 要求长短轴来自预测方差） |

**重建公式**（供 E 组 NIS 使用）：

```text
Cov = R(ψ) · diag(σ_along², σ_cross²) · R(ψ)ᵀ ,   ψ = courseDeg
```

**（2）NIS 的可执行算法**：实际船位用同一套曲线坐标投影到同一参考线，得新息 `ν = (Δs, Δe)`，于是

```text
z     = ( Δs / σ_along , Δe / σ_cross )
NIS₂  = z₁² + z₂²   ~  χ²(2)      门限：95% → 5.99，99% → 9.21
```

四路特征各自归一化后即可进同一尺度，避免把不同量纲的量直接放进同一条累积判据：

| 下游特征 | 归一化口径 |
|---|---|
| 位置（XTE／船位偏差） | `zCross = xteM / σ_cross`，`zAlong = abs(Δs) / σ_along` |
| 改向（滑窗平均航向差） | `zCog = abs(ΔCOG) / sigmaCogDeg`（`sigmaCogDeg` 取 `psiThrDeg` 量级，随 σ 缩放） |
| 减速（速度缺口比 ρ） | `zRho = ρ` 本身已无量纲，按其阈值归一 |
| 停车／锚泊 | 不进连续量，按 `navPhase` 走**确定性事实**分支 |

`zSeries`（§2.3）随快照给出近 `confirmWindow` 点的序列，下游的累积判据可直接在其上累积，**不必自己重做投影**——投影需要参考线与窗口化搜索，重做一份会引入版本不一致（`32` §3.1 判定 3 的同类风险）。

**（3）下游必须注意的一条保守性告警**

本组给出的带**不是滤波器的预报协方差，而是含模型误差项的保守包络**（§3.2.7 第 5 步的 `α_along·τ`、`α_cross·τ`）。后果是：`NIS₂` 会系统性偏小，若直接拿 χ² 分位数当门限，**实际虚警率将低于名义值、检测会变迟钝**。两条处置，任选其一：

- 先用 NEES 一致性检验（仿真有真值）标出标定因子 `c`，用 `NIS₂ / c` 与门限比较；
- 或直接放弃 χ² 的理论含义，走 σ 缩放：门限取 `k · σ_along`／`k · σ_cross`，`k` 由目标虚警率标定。

**（4）与下游阈值自适应机制的边界**

- 下游若采用在线共形推断（ACI）之类机制自适应**判定阈值带**，其作用对象是判定门限，**不校准预测模型本身**；
- 本组 §3.2.10 的校准**只调预测模型参数**（速度系数、`α` 增长系数、有效期、前提阈值），且只出建议、经 M2 决策侧确认后写 `sys_param`。
- 两者作用对象不同、互不侵入：**阈值带的在线自适应归下游判定侧，预测模型参数的标定归 A 组。**

**（5）风况不由本组生产**

跨组接口中常把「实时风况、风速风向、突变预警」划到本组，按权威口径应当是：

| 数据 | 实际来源 |
|---|---|
| 风速、风向、阵风 | M1 接入、M6 归一（`22` §1.2 的 `data.weather` 消费方为 M2／M3／M5；`37` §5.7 `weather` 表） |
| 气象超限、风速突变**预警** | 属告警，写 `alert`（`37` §5.12 的告警类型含气象超限；`21` §7 兜底的触发与决策归 M2） |
| 「某位置某时刻风」查询 | M6 `weather`（`38` §2 气象实时） |

本组**只在做预测时可选消费风况**（用于速度前瞻修正，§3.2.7 第 2 步），既不生产风况，也不单独输出风况不确定度。下游若要做「机会约束」式的风况裕度，输入应取 `weather` 的观测与预报误差统计，**不要挂在 A 组的预测上**——否则会形成一处无人生产的接口。

## 3 算法设计

### 3.0 两项功能的选型总览

| 序号 | 选用做法 | 一句话理由 |
|---|---|---|
| 1 订单接入与基本校验 | 分级短路的**规则判定表** ＋ 三道闸门（空间／状态／时间） | 业务边界判定而非偏好排序；判据成本递增、命中即短路，与 `24` §2.2「静态先剪、便宜先算」同一取向；出口四类与 `31` §3.1 对应 |
| 2 船舶状态估计与轨迹预测管理 | **沿航道的一维卡尔曼滤波** ＋ **曲线坐标下的纵向定速外推与横向 OU 过程** ＋ **滚动时域刷新** | 内河船沿航道行驶是强先验，一维滤波参数少、外推稳定、可解释；纵向误差决定会面**时刻**、横向误差决定会面**位置**，正好对应下游两项不同的用途 |

### 3.1 功能 1 订单接入与基本校验（`M2-01`）

#### 3.1.1 选型与理由

采用**分级短路的规则判定表**，出口四类：受理并触发调度、延后触发调度、拒绝、转人工。

- 不用打分模型：本功能回答「做不做」，排序与权重是功能 8 的职责；`24` §5.1 已定「订单优先级不进入候选比较」，同一取向要求这里也不引入偏好分值。
- 不用学习模型：`NF-7` 定为无实物条件下靠仿真＋数据回流证明有效性，训练样本只能来自仿真生成器自身；`NF-7` 与功能 11 要求可追溯，规则表每一行都能回指一条需求与一个参数。
- 不用一次性硬拒：`21` §2 第 1 步与 `31` §3.1 定了三个出口，「延后触发调度」是必须的。
- 不做全量评估：每条判据成本不同（字段校验 < 查档案 < 查常驻预测快照），按成本递增排列并短路，否则一次数据缺失会掩盖真正的拒单理由。

#### 3.1.2 判定流水线（伪代码）

```text
AdmissionResult admit(OrderRequest r, long now):

  // ① 信息完整性
  if (r.mmsi == null || r.cargoType == null || r.goodsWeightKg <= 0
      || r.deadline == null || r.priority == null)
        return MANUAL(INCOMPLETE);

  // ② 幂等与重复
  if (orderRepo.exists(r.orderId))            return orderRepo.firstResult(r.orderId);
  if (duplicateChecker.hit(r, now))           return REJECT(DUPLICATE);

  // ③ 时效性
  double etaMin = minDurationEstimator.lowerBound(r, now);   // 见 §3.1.3
  if (now >= r.deadline)                      return REJECT(EXPIRED);
  if (r.deadline - now < etaMin)              return REJECT(TIME_INFEASIBLE);

  // ④ 货物合法性
  if (!cargoWhitelist.contains(r.cargoType))  return REJECT(CARGO_TYPE);
  if (r.goodsWeightKg > maxPayloadAllTypes() * (1 - maxPayloadMargin))
                                              return REJECT(OVERLOAD);

  // ⑤ 数据有效性
  if (!mmsiValidator.isValid(r.mmsi))         return REJECT(MMSI_INVALID);
  ShipState st = stateStore.get(r.mmsi);
  if (st == null || now - st.ts > ttlAisMs || !connectorHealth.alive())
        return DEFER(DATA_STALE, wakeAt = now + suspendRetrySec, wakeEvent = DATA_RESTORED);

  // ⑥ 空间闸门
  PredictionSnapshot snap = snapshotProvider.getOrCompute(r.mmsi, now);  // 过旧则现算
  if (!inServiceSegment(st.s)) {
      Long tEnter = segmentEntrySolver.firstEntry(snap, serviceStart, serviceEnd, vSign(st));
      long latest = Math.min(r.deadline - (long) etaMin, snap.t0 + horizonSec * 1000L);
      if (tEnter == null || tEnter > latest)  return REJECT(OUT_OF_SERVICE);
      return DEFER(SHIP_OUT_OF_SEGMENT,
                   wakeAt = tEnter - wakeMarginSec * 1000L, wakeEvent = SHIP_ENTERED);
  }

  // ⑦ 状态闸门
  if (goodsRepo.status(r.goodsId) != READY)
        return DEFER(GOODS_NOT_READY, wakeEvent = GOODS_READY);

  // ⑧ 时间闸门
  if (gate.status() == CUTOFF)
        return DEFER(GATE_CUTOFF, wakeEvent = GATE_RESUME);

  return ACCEPT_TRIGGER_SCHEDULE;
```

#### 3.1.3 各判据的可执行定义

| 判据 | 可执行定义 |
|---|---|
| 重复单 | 同一 `mmsi` ＋ 同一 `cargoType` ＋ 重量差 ≤ `weightTolKg`，且下单时间落在 `dupWindowSec` 内的既有非终止态订单，判为重复 |
| `etaMin`（最短任务时长下界） | `etaMin = t_handover_min + 2 · min_{t ∈ snap.points} min_{j ∈ nests} dist(ship(t), nest_j) / v_max_cruise`。**它是下界**：预测时域内的最近距离不超过真实会面点到最近巢的距离，故右侧 ≤ 真实飞行时间 ≤ 真实任务时长。复杂度 O(N·M)，`N` 为点列长度、`M` 为机巢数（典型 180 × 5 = 900 次距离计算，可忽略） |
| 系统服务航段 | 由运营配置给出航道里程区间 `[sStart, sEnd]`（`21` 第 1 步、`02` §2；`37` 的 14 张表内无此台账，见 §5 待定项 1）；判据是**估计弧长 `s` 是否落在区间内**（按航道里程算，不是直线距离，也不是机巢能力范围） |
| 驶入时刻 | 在 `snap.points` 上取首个使 `s` 穿越边界的点（顺流判 `s ≥ sStart`，逆流判 `s ≤ sEnd`），在相邻两点间线性插值得 `tEnter`；因 `v > 0` 使 `s(t)` 单调，单次扫描 O(N) 且无需二分 |
| 载重上界 | `maxPayloadAllTypes() = max over drone 档案的 maxPayloadKg`（`37` §5.2）；`maxPayloadMargin` 为裕度 |
| 数据有效性 | 三个条件同时检查：估计结果存在、`now − state.ts ≤ ttlAisMs`、`ConnectorHealth` 未断流（`30` §3.5） |
| 幂等 | 以 `orderId` 为唯一键，Redis `SETNX order:adm:{orderId}` 抢占；命中则返回首次结论，不重算 |

#### 3.1.4 出口与原因码

| 出口 | 状态落点（`23` §3） | 原因码 | 唤醒／后续 |
|---|---|---|---|
| 受理并触发调度 | `待调度` | — | 由功能 8 组批进入第 2 步 |
| 延后·等船 | `已受理待唤醒` | `SHIP_OUT_OF_SEGMENT` | 按 `tEnter − wakeMargin` 定时唤醒 |
| 延后·等货 | `已受理待唤醒` | `GOODS_NOT_READY` | 货物就绪事件唤醒（`23` §8） |
| 延后·熔断 | `已受理待唤醒` | `GATE_CUTOFF` | 闸门解除后恢复（`31` §3.12） |
| 延后·数据不足 | `已受理待唤醒`（落点待定，见 §5 待定项 5） | `DATA_STALE` | 按 `suspendRetrySec` 重判；超 `maxSuspendSec` 转人工 |
| 拒绝 | `已拒绝` | `DUPLICATE`／`EXPIRED`／`TIME_INFEASIBLE`／`CARGO_TYPE`／`OVERLOAD`／`MMSI_INVALID`／`OUT_OF_SERVICE` | 记录原因供 M5 展示 |
| 转人工 | `待受理`（不流转，见 §5 待定项 5） | `INCOMPLETE` | 调度员补录 |

> 状态词一律按 `23` §3、`23` §9 与 `02` §3 的写法；原因码是本文拟制的**内部枚举**，落库编码由 M6 定（`37` §5.4 的「失败或终止原因」字段）。

#### 3.1.5 关键判据与并发

- **受理不等于立刻派得出去**：没有可用运力时同样进等待队列，属资源原因，不是拒单（`31` §3.1 说明）。
- **拒单只来自业务边界与运力彻底无解两种情形**（`31` §3.1）；本功能只能给出前一种，后一种在功能 4／功能 5 的出口（`24` §7）。
- **熔断期间不拒单**（`31` §3.12 说明）。
- **进调度的订单均已满足「货已备好」**，故功能 4 求解会面点时不再考虑装货等待（`21` §2、`31` §3.1 说明）——这是本功能给下游的隐式承诺，必须在状态闸门这一步严格守住。
- **并发**：接单处是订单洪峰入口，按 `26` §5 第 1 步「订单队列 ＋ 削峰；超容量排队或超时降级」处理；判定本身无共享写，仅在写 `order_task` 与 `task_log` 时进入事务（`23` §8）。
- **复杂度**：除 `etaMin` 与驶入求解为 O(N·M)／O(N) 外均为 O(1)；实测目标见 §4.2。

### 3.2 功能 2 船舶状态估计与轨迹预测管理（`M2-02`）

#### 3.2.1 选型与理由

三层结构：**沿航道的一维状态估计**、**前提监测**、**曲线坐标下的纵向与横向分离预测**，配滚动时域刷新与版本号。对外表述按 `02` §6 的既定映射：「结合航道约束的状态估计与去噪」——沿航道一维滤波，信号缺失时降级外推。

- 不用二维运动学外推（经纬度平面上跑匀速或匀转弯模型）：没有航道先验，长时域必然漂出航道；而下游对预测的使用方式是**在时间上求根**（`32` §3.1 在 `[当前时刻, T_max]` 上取最小正根），误差会直接变成会面点与会面时刻的误差——`21` §3 的表把它记为「直接错——会面点就错了」。二维运动学保留为**短时域的退化情形**与对照基线。
- 不用数据驱动序列模型：`NF-7` 无实物，训练数据只能来自仿真生成器自身，模型学到的是生成器的偏置，答辩无法自证；且与 `NF-8` 参数化、功能 11 可解释复盘相悖。列为对照项。
- **不把「数据过期」与「预测不可信」混为一谈**：`21` 第 0 步与 `31` §3.2 说明明确「状态估计与预测是两件事」。前者要挂起接单，后者要回上游重跑，两者的判据与出口完全不同，必须分层。
- **前提判定做成单一共用服务**：`33` §3.5 要求纠偏循环与兜底表的「船舶大幅变向或减速」**复用一套判定，不设计两套**，因此本文的前提监测是一个被两处调用的组件（§2.5 的 `PremiseMonitor`），而不是两段逻辑。

#### 3.2.2 数据模型

**（1）航道中心线台账**（承接 `21` 第 2 步与 `32` §6 的「航道拓扑约束」；承载方见 §5 待定项 1）

```text
WaterwayCenterline {
  centerlineId, version,
  nodes     : [ { nodeId, lon, lat, s } ],           // s 为自起点累计里程（m，Haversine 累加）
  segments  : [ { segId, fromNode, toNode, lenM, courseDeg, speedLimitMs } ],
  junctions : [ { junctionId, sAtJunction,
                  branches: [ { branchId, firstNodeId, courseDeg } ] } ],
  restrictedAreas : [ { areaId, type: 锚地|港区, polygon: [(lon,lat)] } ],
  serviceSegment  : { sStart, sEnd }                 // 系统服务航段
}
```

**（2）逐船状态对象**（常驻层内存态，`26` §6 的「P0 最小实现：内存中的一张表 ＋ 单线程」）

```text
TrackState {
  mmsi, lastTs,
  s, vs, e, deDt,                // 沿航道里程、沿航道速度、横向偏移、横向速度
  P,                             // 2x2 协方差（s, vs）
  varE,                          // 横向方差
  quality,                       // OK | EXTRAPOLATED | INSUFFICIENT
  gapSec,                        // 累计连续缺失时长

  premise,                       // PremiseState
  pending[],                     // 待确认的可疑点

}
```

#### 3.2.3 步骤 A：AIS 清洗与去重

**去重**：滑动窗口 `dupAisWindowSec`，键 `(mmsi, floor(ts))`。实现用逐船有界 LRU（Redis `SETNX ais:seen:{mmsi}:{ts}` 作跨实例兜底），窗口过期即释放。

**跳点剔除**（对相邻有效点 `k−1 → k`，`Δt = ts_k − ts_{k−1}`）：

```text
d         = haversine(p_{k-1}, p_k)
vImplied  = d / Δt
suspicious = (vImplied > vGateMs)                                  // ① 位移过快
          || (|angleDiff(cog_k, cog_{k-1})| > dcogGateDeg && vImplied < vTurnMinMs)  // ② 低速大转向
          || (|sog_k − vImplied| > epsSogMs)                       // ③ 速度不自洽
```

可疑点进 `pending` 而**不立即丢弃**：

- 若 `pending` 内相邻点互相自洽（相邻残差 < `epsPairM`）且长度 ≥ `confirmCount` → 判为**真实机动**，整段接受，清空 `pending`；
- 若 `pending` 长度 > `pendingMax` 仍不自洽 → 整段判为**野值**丢弃。

这一设计是必需的：`21` §5.1 把「减速、加速、避让、换道」列为正常的量变，单点速度门限会把真实的急减速误剔。

**丢包外推**：若 `Δt > gapFactor × ΔtNominalSec`，进入 gap：用 §3.2.5 的预测步补位，标 `quality = EXTRAPOLATED`；`gapSec` 累计，超过 `gapMaxSec` 置 `quality = INSUFFICIENT`（功能 1 的数据有效性据此暂缓）。

**时间对齐**：按 `resampleStepSec` 重采样为等间隔序列，乱序报文先按键排序。

#### 3.2.4 步骤 B：曲线坐标投影

**局部平面近似**：以船舶所在段起点 `(lon0, lat0)` 为原点做等距圆柱投影

```text
x = (lon − lon0) · cos(lat0) · R · π / 180
y = (lat − lat0) · R · π / 180            // R = 6371008.8 m
```

短距离（≤ 数 km）下与 Haversine 的差异可忽略，且使点到线段投影退化为平面几何。

**点到线段**（线段 `A→B`，点 `P`）：

```text
t = clamp( dot(AP, AB) / |AB|² , 0, 1 )
Q = A + t · AB
d = |P − Q|
e = sign( AB.x·AP.y − AB.y·AP.x ) · d      // 左正右负，以航道走向为基准
s = seg.sStart + t · seg.lenM
```

**窗口化搜索**（关键，防止在分汊点跳到并行分支）：以上一时刻的 `s_prev` 为基准，只在

```text
[s_prev − dsWinM, s_prev + dsWinM],  dsWinM = vMaxCraftMs · Δt + dsWinMarginM
```

覆盖到的线段上搜索；首点做全量搜索。这样同时在性能上把 O(全部线段) 降到 O(W)（`W` ≈ 8–20 段）。

**退化路径（参考线台账未落地时的保底方案）**。项目**没有航道中心线图层**：`37` 的 14 张表里只有 `airspace_restriction`（禁飞区、限飞区、限高、航道管制）与 `emergency_landing_point`，没有中心线或拓扑。本组的三级退化如下，**第二级不依赖任何新增台账，因此方案在台账未落地时仍可实现**：

| 级别 | 参考线来源 | 保留的能力 | 失去的能力 | 依赖 |
|---|---|---|---|---|
| 首选 | 航道中心线台账（§3.2.2） | 全部：`(s, e)` 分解、纵横向分离、分汊分支、受限水域语义 | — | 需新增台账（§5 待定项 1） |
| **退化 1（保底）** | **本船上一版预测轨迹**作为参考折线 | 纵横向分离、`σ_along`／`σ_cross` 分解、`s(t)` 单调推进（预测轨迹自身即时间参数化折线） | 航道语义、分汊分支语义、受限水域语义 | **零新增依赖** |
| 退化 2 | 无参考线，二维运动学外推 | 仅短时域位置预测 | 上述全部，且长时域漂移 | 零 |

退化 1 的代价是「横向偏移」变成「相对上一版预测的横向偏移」，语义从「偏离航道」变为「偏离自己的预测」，因此 P3／P4 两类判据在该级别下不可用、`e` 的物理上界（航道半宽）也失效，`σ_cross` 只能靠 `alphaCrossMs` 增长而不做截断。这一点必须写进会签单：**若台账不落地，本组与纠偏侧都会退化为「相对各自参考线的偏差」，两侧的参考线与偏差量口径必须统一，否则同一场景会得出不同结论**（与 `20` §5「两边各算一套余量会给出相反结论」同类风险）。建议本组与 M3 侧联名向 M6 提新增「航道中心线台账」。

#### 3.2.5 步骤 C：沿航道一维卡尔曼滤波

状态 `x = [s, v_s]ᵀ`，观测 `z = s̃`（由 §3.2.4 投影得到）。

**预测**

```text
F = [[1, Δt], [0, 1]]
Q = q · [[Δt³/3, Δt²/2], [Δt²/2, Δt]]        // 连续白噪声加速度模型，q 为加速度功率谱密度
x⁻ = F x ,  P⁻ = F P Fᵀ + Q
```

**更新**

```text
H = [1, 0] ,  S = H P⁻ Hᵀ + r_s ,  K = P⁻ Hᵀ / S
x  = x⁻ + K (z − H x⁻)
P  = (I − K H) P⁻
```

**观测噪声** `r_s`：AIS 位置误差 `σ_pos` 投影到航道方向后被放大 `1/cos θ`（`θ` 为航迹与航道夹角），故

```text
r_s = (σ_pos / cos θ_clamped)² ,   θ_clamped = min(θ, θ_maxDeg)
```

角度接近垂直时该观测对纵向几乎无信息，用 `θ_maxDeg` 截断避免除零（此时纵向主要由模型预测推进）。

**初始化**：`s = 投影值`，`v_s = sog · cos(angleDiff(cog, waterwayCourse))`，`P = diag(σ_pos², (2 m/s)²)`。

**约束**：`e ∈ [−W/2, W/2]`（`W` 为航道宽度）；`v_s` 限幅到 `[0, vMaxCraftMs]`，但**限幅前**先判方向——若滤波给出的 `v_s < 0`，说明船已掉头或投影跳到了对向航道，置前提为 `INVALID(REVERSED)` 而不再外推。

#### 3.2.6 步骤 D：横向 OU 模型与机动检测

横向偏移用均值回复过程（Ornstein–Uhlenbeck）建模，离散形式

```text
e_{k+1} = φ · e_k + sqrt(1 − φ²) · σ_e · w ,   φ = exp(−Δt / τ_e) ,  w ~ N(0,1)
```

- `τ_e` 为回复时间常数（船回到航道中心线的典型时间尺度）；
- `σ_e` 为稳态标准差，取值应覆盖单侧航道内的正常横向摆动；
- 稳态方差 `Var(e) = σ_e²`，因此带宽度有天然的物理上界。

**换道机动检测**：连续 `lcCount` 个采样满足 `|Δe| > lcStepM` 且同号，判为换道机动（`21` §5.1 的「换道」属量变，前提仍成立）。机动期间：

- 横向预测改为「当前横向速度线性外推到目标车道中心」，`e_pred(τ) = e_0 + deDt · min(τ, τ_lc)`；
- `σ_cross` 取 `lcInflate` 倍放大，覆盖外推不确定性；
- 机动结束（`|deDt|` 回落至阈值以下）后回到 OU 预测。

首版提供开关 `lcModelEnabled`，关闭时仅做 `σ_cross` 膨胀，不做位置偏移，避免过拟合。

#### 3.2.7 步骤 E：多步预测与不确定性带

对 `τ = Δt, 2Δt, …, T_horizon` 逐步执行：

```text
1) 递推协方差：P⁻(τ) = F P⁻(τ−Δt) Fᵀ + Q          // 只用预测步，无观测
2) 速度前瞻：若 v_s > speedLimit(s(τ−Δt))
        v(τ) = v_lim + (v_s − v_lim) · exp(−τ / τ_v)     // 一阶衰减到航段限速
   否则 v(τ) = v_s
3) 沿程推进：s(τ) = s(τ−Δt) + v(τ) · Δt
4) 横向：e_pred(τ) = e_0 · exp(−τ / τ_e)            // 或机动模型，见 §3.2.6
   Var_e(τ) = σ_e² · (1 − exp(−2τ / τ_e))
5) 不确定度合成：
   σ_along(τ) = sqrt(P⁻_ss(τ)) + α_along · τ
   σ_cross(τ) = sqrt(Var_e(τ)) + α_cross · τ
   σ_cross(τ) = min(σ_cross(τ), laneHalfWidthM)
6) 反投影：在 s(τ) 所在线段上按比例插值得基准点，再沿该段法向偏移 e_pred(τ)
   得 (lon, lat)，cog 取该段 courseDeg
```

- 第 5 步的两项 `α · τ` 是**模型误差项**，覆盖限速、避让、加速等未建模机动；没有它，滤波协方差会给出过于乐观的带宽度。
- `σ_along` 与 `σ_cross` 必须分开输出：`32` §3.1 在时间上求根，纵向误差直接决定会面**时刻**；`36` §2、§3 画置信椭圆，横向误差决定会面**位置**（`22` §4 的 `cov` 字段）。

#### 3.2.8 步骤 F：有效期与前提监测

**有效期**（`31` §3.2 输出「预测有效期与可信状态」）：

```text
validitySec = min { τ ∈ 步列 : σ_along(τ) > lTolM 或 σ_cross(τ) > wTolM }
若不存在这样的 τ，则 validitySec = horizonSec
```

**前提监测：三层拆解与归属**。`31` §3.2 要求本组输出「前提是否仍成立」。这里有一个必须避开的坑：**「持续成立」不能只靠双阈值迟滞**——迟滞管的是输出端复位，并不保证「持续成立才触发」，单帧尖峰照样会触发；真正防误触发的是累积逻辑（累积和检验、M-of-N 这类）。据此把前提监测拆成三层，并一次把归属写清：

| 层 | 内容 | 归属 | 理由 |
|---|---|---|---|
| **事实层** | 数据质量 `quality`；确定性事实：`navPhase ∈ {在航, 减速, 停车, 锚泊}`、进入锚地／港区、`v_s` 反向 | **本组** | 只需本组的状态估计与地理围栏即可判定，是确定性事实，不需要统计确认 |
| **统计层** | 归一化偏差序列 `zSeries` ＋ **保守粗标记**（M-of-N，如 3/5），供功能 9 的「重新获取预测」门槛（`31` §3.9） | **本组出量**，粗标记用 M-of-N | M-of-N 可解释性最强、检测概率可解析、响应快，适合做不追求最优的粗门槛 |
| **确认层** | 累积和检验精细确认、`6a`／`6b` 分档、阶段状态机、与纠偏截止时刻的比对 | **E 组功能 17** | `33` §3.5 的三层判定顺序是「先重估预测 → 再按需重算会面点 → 最后比阈值」，**阈值比较与指令下发都在纠偏侧**；且「检测延迟是否还来得及纠」也只有纠偏侧知道（`21` §5.1 要求该判定必须持续成立，因为回上游重跑的代价很大） |

即：**本组只做「事实 ＋ 归一化偏差量 ＋ 粗标记」，不做精细确认与分档**；纠偏侧要更灵敏的主判据时直接消费 `zSeries`（窗长 `confirmWindow`），不必自己重做投影——投影依赖参考线与窗口化搜索，重做一份会引入版本不一致。归一化口径见 §2.6 第（2）项。

**事实层判据表**（P2 加「窗口内位移小于一船长」第三重条件，以区分过闸／待闸的临时减速）：

| 判据 | 进入条件 | 退出条件 | 输出 |
|---|---|---|---|
| P0 掉头或逆向 | 滤波 `v_s < 0` | `v_s` 回到正值持续 `tPsiSec` | `INVALID(REVERSED)` |
| P1 偏航（**粗标记**） | `abs(dCogDeg) > psiThrDeg` 在最近 `mOfN` 个上报周期内成立 ≥ M 次 | 未达标持续 `tPsiSec` | `SUSPECT(DEVIATED)`，并置 `zSeries` |
| P2 持续趋零 | `v_s < vStopMs` **且** 窗口内位移 < 一船长 **且** 持续 `tStopSec` | 回升至 `vStopMs + vHysMs` 以上 | `INVALID(STOPPED)`／`navPhase = 停车` |
| P3 分汊歧义 | 落在 `[s_bp − bpInM, s_bp + bpOutM]` 内且 `branchAmbiguous` 持续 `tBpSec` | 出邻域或分支锁定 | `INVALID(BRANCH_AMBIGUOUS)` |
| P4 受限水域 | 估计位置落入 `restrictedAreas` 多边形（射线法）且持续 `tRaSec` | 离开多边形 | `NOT_APPLICABLE(RESTRICTED_AREA)` |

判断优先级 `P4 > P3 > P0 > P2 > P1`（P1 是疑似，排在确定性事实之后）；`NOT_APPLICABLE` 表示**预测在此情形下不适用**（船已进锚地／港区，本单不可能按原方案完成），与 `INVALID`（可重算）在语义上分开，供 M2 区别处置。P0 不做驻留计时——方向反转本身已是确定性事实。

**`navPhase` 四态与转移**（条件为「速度阈值 ＋ 持续时间 ＋ 地理语义」三重）：

```text
在航 ──v_s < vStopMs 且持续 tStopSec，位移 < 一船长──▶ 停车
在航 ──v_s 下降但未达停车条件，且 ρ > rhoTh ──────────▶ 减速
停车 ──位置落入锚地／港区多边形且持续 tRaSec ──────────▶ 锚泊
减速 ──v_s 回升至 vStopMs + vHysMs 以上──────────────▶ 在航
停车 ──v_s 回升且位移恢复──────────────────────────▶ 在航
```

两点纪律：**减速用速度缺口比 ρ 判，不用绝对速度**，以免把内河过闸／待闸／交汇避让的临时减速误判为停车；进入「停车」态即作为最高优先级事件置入 `premise`——船停了，本次会面必然失败。

**AIS 航行状态位的使用口径**：对**船**而言，AIS 自带的 navigational status 字段由船员人工录入，**不可靠，只能投票不能判决**。因此即使后续补入该字段（见 §5 待定项 9），本组也只把它当作 `navPhase` 判定的一票，不作终判——与 `22` §2 当前字段缺失时用 `sog` ＋ 位移驻留间接判定是同一套逻辑。

**分汊分支判定**：

```text
对每个分支 b：Δψ_b = |angleDiff(cog, branch_b.courseDeg)|
b* = argmin Δψ_b
branchAmbiguous = (Δψ_{b2} − Δψ_{b*}) < dpsiMarginDeg     // 第二优与最优过于接近
分支概率：w_b ∝ exp( −Δψ_b² / (2 · σ_ψ²) )，归一化
当 s > s_bp + bpOutM 时锁定 branchId 并清除 ambiguous（滞后锁定）
```

歧义期间向下游只给**单一** `P(t)`（取最大权分支，`32` §3.1 的求根需要一个确定的轨迹），并把 `1 − w_max` 作为风险项交付，**不混进 `σ_cross`**——那会让带宽虚高，同时污染 C 组剪枝的保守方向。

#### 3.2.9 步骤 G：快照打包、版本号、缓存与推送

**版本号**

```text
version = "PV" + hex( sha1( shipMMSI | t0 | paramVersion | centerlineVersion | predictorVersion ) )[0:12]
```

`paramVersion` 取 `sys_param` 的变更版本戳（见 §5 待定项 3），`centerlineVersion` 取航道中心线台账版本。同一轮调度所有候选共用同一版本；M3 侧校验不一致即拒绝求解（`32` §3.1、§6 硬约束 3）。

**缓存键与 TTL**（`38` §6 未决 2「键命名规范」与未决 3「TTL」在本组范围内的建议值）

| 键 | 内容 | TTL |
|---|---|---|
| `ship:state:{mmsi}` | 最新 `TrackState` | `3 × residentIntervalSec` |
| `ship:pred:{mmsi}` | `PredictionSnapshot` | `max(3 × residentIntervalSec, validitySec)` |
| `ship:pred:hist:{mmsi}` | 最近 `calDepth` 个快照的抽稀点列，供校准比对 | `calDepth × residentIntervalSec` |
| `ship:active` | 在航船集合（`ttlAliveSec` 内有 AIS 的 mmsi） | 滚动刷新 |
| `order:adm:{orderId}` | 接单幂等标记 | `dupWindowSec` |

**推送**：本组产出的 `ship_traj` 消息（§2.3）经 M2 的 WebSocket 通道推 M5（`22` §4、`36` §4）；「会面点随预测刷新而动」的画面效果（`36` §2 的设计取向）依赖这条链路持续推送。

#### 3.2.10 步骤 H：预测误差回流校准

**样本采集**：常驻层每轮刷新时，取最近 `calDepth` 个历史快照在**当前时刻**的预测值（在 `points` 上线性插值），与当前估计值比较：

```text
errAlong = s_est − s_pred(now)      // 纵向误差，m
errCross = e_est − e_pred(now)      // 横向误差，m
预测时域段 = floor( (now − t0) / calTimeBucketSec )
船速段     = 按 v_s 落入 [0, 1.5) / [1.5, 3.5) / [3.5, ∞) m/s 三档
```

按 `(预测时域段 × 船速段)` 分层存入环形缓冲（容量 `calWindowN`）。

**统计与建议**（要求层内样本数 ≥ `calMinSamples` 才产出建议）：

| 观察 | 建议 | 限幅 |
|---|---|---|
| `abs(μ_along) > kBias · σ_along(τ̄)` 连续 `calPersistM` 个周期 | 沿航道速度加偏置 `−μ_along / τ̄` | `±maxVBiasMs` |
| `p95_cross > kBand · σ_cross(τ̄)` | 放大 `α_cross` | 单次调整 ≤ `maxAdjustRatio` |
| `p95_cross < kTight · σ_cross(τ̄)`（带宽过保守，浪费可行集） | 缩小 `α_cross` | 单次调整 ≤ `maxAdjustRatio` |
| `p95_along > kBand · σ_along(τ̄)` | 放大 `α_along` | 单次调整 ≤ `maxAdjustRatio` |

**落法**：只产出 `CalibrationSuggestion` 列表（经功能 11 记录、由 `36` §2 的预测误差曲线展示），经 M2 决策侧确认后写 `sys_param`；**不自动写回**，避免单次偏差引起阈值抖动（`NF-8`、`37` §5.14）。G 组功能 19 回流的会面偏差样本作为辅助样本并入同一校准队列（`32` §3.6）。

#### 3.2.11 常驻层调度与高频重估入口

**（1）常驻轮**

```text
每 residentIntervalSec：
  for mmsi in activeShipRegistry:
      state = trackStates.get(mmsi)
      if 收到新 AIS:   state = cleanAndUpdate(state) ; snap = predict(state)
      else:            state = kalmanPredictOnly(state) ; state.quality = EXTRAPOLATED
                       snap = predict(state)            // 仍产出快照，供接单与纠偏
      snapshotStore.put(mmsi, snap) ; shipTrajPublisher.publish(snap)
```

**（2）接单按需精算**：取 `ship:pred:{mmsi}`；若 `now − t0 > staleSec` 或版本已被更新，则**同步调用同一个 `predict()`** 现算一次（`21` §3 触发列：「快照过旧或缺失则现算一次」）。

**（3）纠偏高频重估入口**：`33` §3.5 规定纠偏循环「每收到一次新状态」就先重估预测。若每次都全量重算，多机并发时会形成请求风暴（`26` §4）。因此：

- 入口 `reestimate(mmsi)` 与常驻轮**共用同一个 `predict()`**（兑现「一套实现、两种触发」）；
- 加**最小重算间隔 `minRecalcSec`**（`26` §5 第 6 步「节流合并」；`26` §6 的「每架机设最小重算间隔（最简节流）」）：间隔不足时直接返回现有快照并递增命中计数，不重算；
- 按船缓存快照供**多单复用**（`26` §5 第 2、3 步行明确「按船…缓存结果复用」），同一调度周期内共用同一版本（`26` §5 常驻层行「统一态势快照」）。

**（4）并发与吞吐**：P0 按 `26` §6 的最小实现——单进程内存态、每 `mmsi` 一个状态对象、无跨船共享写，不引入分布式锁与消息队列（`26` §6 已明示这两者属后续阶段）。
