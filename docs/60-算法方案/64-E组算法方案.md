## 1 组定位与主流程边界

> 本篇只落"输入与输出"与"边界"，回答 E 组在主流程里是哪几步、接哪组的数据、传给哪组。算法设计见第二～四篇。

### 1.1 总览

| 功能     | 功能名         | 所属模块          | 主流程位置           | 一句话职责              |
| ------ | ----------- | ------------- | --------------- | ------------------ |
| **17** | 去程段追踪与纠偏    | 模块三 动态会面与路径规划 | 第 6 步 去程段       | 判偏航 / 意图变更，出纠偏量    |
| **9**  | 飞行过程中的重新调度  | 模块二 调度引擎      | 第 6 步 6b ＋ 全飞行段 | 变化判定 ＋ 分级响应，出重调度请求 |
| **10** | 返航复核与归巢资源判定 | 模块二 调度引擎      | 第 8 步 返航        | 三级降级判定，出落点结论       |

**三者衔接**：功能17 **发现变化** → 功能9 **分级响应** → 功能10 **返航降级**。

**E 组整体定位**：全程只出"判定与结论"，航迹生成、占位、采集、检测、预测、执行均归对应组。

### 1.2 功能17 · 去程段追踪与纠偏 — 输入输出与边界

#### 1.2.1 输入

| 数据项            | 来源                | 内容                      | 表示方式与粒度                         |
| -------------- | ----------------- | ----------------------- | ------------------------------- |
| 实时状态流 · 无人机侧   | 模块四（经 F 组清洗与状态估计） | 位置、速度、航向、剩余电量、飞行模式、健康状态 | 带时间戳的状态帧；电量给百分比与剩余飞行分钟**双口径**   |
| 实时状态流 · 船舶侧    | A 组态势与预测          | 船位、航速航向；及其**预测航迹**      | 状态帧 ＋ 预测序列（带时间窗）；覆盖范围须外扩于系统服务航段 |
| 无人机规划去程航迹与精算基线 | B 组航迹生成 / 第 5 步精算 | 航点序列、起飞时刻、预计会面时刻        | 航迹对象 ＋ 时刻字段；航点到点级，时刻到秒级         |
| 实时风况           | A 组               | 风速、风向、突变预警              | 标量／矢量 ＋ 预测序列；按预测步长              |

> 风况不是判定基准，而是**偏航的成因与补偿量**——解释"为什么会歪"，不用来判"歪没歪"。

#### 1.2.2 输出

| 输出                         | 去向                                        | 内容                              | 表示方式          |
| -------------------------- | ----------------------------------------- | ------------------------------- | ------------- |
| **6a 出口**：会面点重算请求 ＋ 离散指令类型 | 重算请求→**B 组**（调 32 服务重算该机会面点）；指令→**模块四**执行 | 当前状态快照 ＋ 指令类型；**不是自己算航向/速度修正量** | 请求对象 ＋ 指令对象   |
| 意图变更持续监测信号                 | 6b 判据 / **功能9**                           | 船侧偏差是否持续成立                      | 判定信号（含持续成立标志） |
| **6b 出口**：处置结论             | **功能9**（继续追）／**功能10**（放弃本次会面）             | 继续追 或 放弃本次会面                    | 判定结论          |

> **6a / 6b 定义（全文档统一，勿写错）**：**6a**＝会面前提仍成立，就地重算这一架机的会面点（调 32 服务）＋ 下发离散指令，**E 组不自算航向/速度修正量**；**6b**＝会面前提失效（放弃本次会面），作为高优先级事件交功能9 判档。二者是功能17 的两个出口，不是两个算法。

#### 1.2.3 边界（明确不做什么）

- 不做航迹生成与重规划——归 B 组；
- 不做会面点规划与会面交接动作——归 B / C 组；
- 不做底层异常检测（失联／低电量／故障）——归 F / G 组，本功能仅消费告警事件；
- 不做长周期态势预测——归 A 组，本功能消费其快照；
- 不做飞控执行——归模块四；
- **不在飞行中改派／换机**——项目明令禁止。

### 1.5 跨功能共用口径（易混点，勿写错）

| 易混点            | 正确口径                                                      |
| -------------- | --------------------------------------------------------- |
| "偏航" vs "意图变更" | 机侧：实际位置 vs 规划航迹 → **偏航**；船侧：实际船位 vs 预测航迹 → **意图变更**（不是偏航） |
| 意图变更的出口        | 只有「继续追」／「放弃本次会面」两个口，**不存在"停／换机交给其他无人机"**                  |
| 返航降级顺序         | 回原巢 → 迫停他巢 → 迫降野外。**按序降级，迫降是最后一级，不可跳级**                   |
| 返航目标           | **唯一化＝原巢**。"偏离大／别处更近"不是改投理由                               |
| 货与机的关系         | **货机同行，落巢即回收**，卸货点＝落点；不存在"卸 A 巢 ＋ 空机回原巢"                  |
| 重派出发点          | ＝**回收巢**（回原巢从原巢派；迫停留他巢则从他巢派）                              |
| 实时状态流          | 沿用既定术语，**分机侧（模块四/F）与船侧（A 组）标注**                           |

### 1.7 E 组内部接口契约与已决事项

> 本章是 E 组**自己能定且已定**的部分：组内两个交接口的字段契约，以及阈值、迟滞、通信条件等组内自决项。跨组接口见第五篇第3章。

#### 1.7.1 组内链路与触发来源（口径澄清）

- 功能17 的 **6b 是"触发事件"不是最终结论**——它进入功能9 判档；
- **功能10 的唯一入口＝功能9 的"终止"档**，用触发来源字段记录最初由谁触发（功能17 意图变更 / F·G 告警 / 电量包线破限 / 失联超时 / 空域或气象）；
- 一次任务**至多产生一次终止事件**，此后不再重复触发；功能10 降级链"占位即锁定"兜底。

#### 1.7.2 功能17 → 功能9：意图变更事件（6b）

| 字段                                | 必填 | 说明                                    |
| --------------------------------- | -- | ------------------------------------- |
| event_id                         | 是  | 事件唯一序号，跨功能可追溯，用于去重与回放              |
| source＝功能17                       | 是  | 事件来源标识                               |
| event_type（改向/减速/停车/驶入分汊/偏出走廊）   | 是  | 判据类型，决定功能9 走哪个分支                     |
| 前提失效标志 ＋ 已持续时长                   | 是  | 6b 是否成立及持续时间，供功能9 判档                 |
| 偏差量化（XTE / 改向角 / 速度缺口比 ρ）        | 是  | 按 event_type 给对应量，供幅度分档              |
| 发现时刻 / 首次超阈时刻                    | 是  | 供检测延时统计与时序回放                         |
| 船标识、会面点标识、规划会面时刻                  | 是  | 供功能9 评估影响范围                          |
| 机侧快照（位置、剩余电量）                    | 是  | 供功能9 判能量底线（是否还够返航）                   |
| 不确定带 / cov                       | 否  | 有则用于幅度归一化                            |

#### 1.7.3 功能9 → 功能10：归巢判定触发事件（终止档）

| 字段                                      | 必填 | 说明                          |
| --------------------------------------- | -- | --------------------------- |
| event_id（承接上游事件号）                       | 是  | 贯穿 17→9→10，日志可回放            |
| trigger_source                          | 是  | 枚举：功能17 意图变更 / F·G 告警 / 电量包线破限 / 失联超时 / 空域或气象 |
| 档位＝终止                                   | 是  | 功能10 入口的唯一档位                |
| 任务标识（任务ID、订单ID）                         | 是  | 关联订单与后续重派闭环                 |
| 机标识 ＋ 状态快照（位置、高度、剩余电量双口径、飞行模式、健康状态、时间戳）  | 是  | 第一级可行性判定输入                  |

## 2 功能17：去程段追踪与纠偏

**术语口径（先统一，避免后面对不上）**：

| 说法              | 含义                                                    | 归属                       |
| --------------- | ----------------------------------------------------- | ------------------------ |
| 偏航距离            | 无人机实际位置 vs 自己的规划航迹                                    | 机侧，**M4 已算好，E 只消费**      |
| 船位偏差 / 横向偏差 XTE | 船舶实际船位 vs 预测航迹                                        | 船侧，**E 自己定义并判**          |
| 会面              | 本项目用语                                                 | 不用「会遇」（避碰领域词）            |
| 前提是否成立          | 33-M3 §3.5 的判定对象                                      | 船侧偏差判的是"前提成不成立"，不是"船变没变" |
| **6a**（出口一）     | 前提仍成立 → 重算这一架机的会面点（调 32 服务）＋ 下发离散指令，**E 不自算航向/速度修正量** | 功能17 输出，定义见第一篇 2.2       |
| **6b**（出口二）     | 前提失效 → 放弃本次会面，作为高优先级事件交功能9 判档                         | 功能17 输出                  |

**适配度标记**：★★★ 主线｜★★ 辅助/叠加/兜底｜△ 消费别组结论、不自研

### 2.1 问题定位（方法层）

功能17 不是"算一个偏航量"，而是：**拿机侧＋船侧两路状态，每个上报周期滚动重估一次"这次会面还能不能达成"，判定走「常规纠偏」还是「意图变更」，并给出对应动作**。

落到方法层，是一条四层流水线：

```
第一层 特征层：把船的"变"量化成可比较的偏差量
        ↓
第二层 归一化层：把偏差除以预测自身的不确定带 → 无量纲 z(t)
        ↓
第三层 确认层：要求"持续成立"才确认（防误触发，防抖）
        ↓
第四层 决策层：滚动重估，输出本周期动作（不动作 / 发起重算会面点 / 放弃会面）
```

### 2.2 第一层：船侧偏差特征（怎么判"船真的变了"）

#### 2.2.1 偏航距走廊判据 XTE / XTL ★★★

**原背景**：ECDIS 电子海图航线监控（IMO 强制功能），给计划航线每航段设走廊宽度 XTL，船位实时偏航距 XTE 越限即报警。

**本项目怎么用**：把**上游预测航迹**当"计划航线"，每周期算船位到预测航迹的**垂直距离（带左/右符号）**，作船侧主偏差量。直行段收紧、分汊口与港区段放宽。

**优点**：物理意义清晰、实现极简（点到线段距离）、带符号可判改向意图、内河约束强时比纯统计有效。

**缺点 / 局限**：① 原本依赖航道中心线 GIS，项目**无此图层**（现有台账只有 `airspace_restriction` 与 `emergency_landing_point`），退化版为"到预测航迹距离"，**失去航道语义**；② 弯道段须切分段折线；③ 顶流压载会误报，须与 ΔCOG 交叉判。

**适配程度**：★★★，**采用"到预测航迹"的退化版**；后续拿到电子航道图可升级。

#### 2.2.2 规则化运动学特征体系 ★★★

**原背景**：海事监管 AIS 异常行为识别，运动学异常完全可由 SOG、COG、ROT 与加速度刻画，无训练数据。

**本项目怎么用**：为三类意图变更各设判据，对齐 `33-M3` §3.5 那三条：

| 意图变更类型    | 特征与判据（定性）                                 |
| --------- | ----------------------------------------- |
| 改向        | 滑窗内累计航向偏量 Θ(t) 超阈值，**且窗口内各帧同号**（滤除钟摆式抖动）  |
| 减速        | 速度缺口比 ρ =（预测航速 − 实际航速）/ 预测航速 超阈值，且持续若干帧   |
| 停车 / 锚泊靠泊 | SOG 低于近零阈值 **且** 窗口内位移小于一船长 **且** 连续成立若干帧 |
| 驶入分汊      | ΔCOG 指向汊道 **且** XTE 朝汊道侧单调增大              |

**优点**：零训练数据、每条可物理语言解释、与项目既定判据同源。

**缺点 / 局限**：单特征必误判（须多特征交叉）；阈值全部标定，冷启动值靠第二层 SCP/ACI；**ROT 不在接口字段**（`22-接口契约` 的 `AisMessage` 无 ROT，只能由 COG 差分派生或向 A 组要）；**低速时 COG 不可信**（须冻结 COG 判据、改由位移矢量反算航迹向）。

**适配程度**：★★★，**与项目判据同源，是分支判据主体**。

#### 2.2.3 航行状态状态机（在航 / 减速 / 停车 / 锚泊）★★★

**原背景**：从 AIS 轨迹自动识别锚泊、靠泊事件（锚地利用率统计等）。

**本项目怎么用**：维护四态状态机，转移条件用「SOG 阈值 + 持续时间 + 地理语义」三重条件。**一旦进入"停车"态即触发最高优先级重估**（船停了会面必然失败）。

**优点**：把决定性事件单独处理、优先级清晰、是答辩最好讲的结构。

**缺点 / 局限**：依赖锚地/港区边界数据（与 2.1 GIS 缺口同源）；AIS 自带的 navigational status 字段人工录入不可靠，只能投票不能判决；内河"过闸/待闸/交汇避让临时减速"会被误判——对策是用**减速率 ρ 而非绝对速度**，交给第三层防抖自然滤除。

**适配程度**：★★★。

#### 2.2.4 地理语义围栏（分汊点 / 锚地 / 港区）★★

**原背景**：内河汇合水域交通模式挖掘，区域判断对内河航道"有实质前景与效用"。

**本项目怎么用**：分汊点上游设预告楔形区，船位进入且 COG 指向非预期汊道（或 XTE 持续朝汊道侧增大）即判"改道意图"；锚地/港区多边形作 2.3 状态机第三重条件。

**优点**：内河相对远海独有增量、实现成本低（点在多边形内+射线法）。

**缺点 / 局限**：**需电子航道图图层，项目目前没有**；拿不到就退回纯运动学判据。

**适配程度**：★★（数据到位则升 ★★★）。**先按无 GIS 设计保底方案**。

#### 2.2.5 滑窗平均航向差（预测—实测一致性）★★★

**原背景**：雷达航迹与 AIS 航迹的**目标关联**——用两源平均航向差量化一致性。

**本项目怎么用**：把"预测航迹"视作虚拟源，算实测 COG 与预测航迹切向的**滑窗平均航向差**，作"改向"平滑特征（需做角度环绕处理）。

**优点**：比单帧 ΔCOG 抗噪、天然连续量，正好喂给第二层归一化。

**缺点 / 局限**：角度环绕有小坑；低速时同样冻结。

**适配程度**：★★★，**比单帧 ΔCOG 更适合作 CUSUM 输入**。

### 2.3 第二层：归一化（让阈值随预测质量自动缩放）

**这一层是题眼**：比较的不该是"偏差大不大"，而是"**偏差相对于预测自身的不确定度大不大**"。门限应是**预测不确定带的倍数**，而非绝对米数/度数。

#### 2.3.1 归一化新息平方 NIS + 卡方门限 ★★★（有条件）

**原背景**：卡尔曼跟踪量测验证、关联门控。ν 经新息协方差 S 归一化，NIS = νᵀS⁻¹ν 服从 χ² 分布，门限查卡方分位数表（2 维：95%→5.99，99%→9.21）。

**本项目怎么用**：ν = 实际船位 − 预测船位；S = 新息协方差；NIS 超卡方门限即"偏差超出不确定带"。

**为什么自动缩放**：同样物理偏差 ν，预测越不准（S 越大）→ NIS 越小 → 越不报警。

**优点**：门限自带误报率含义、实现即 2×2 矩阵求逆、输出无量纲连续量正好喂第三层。

**缺点 / 局限（三条硬伤）**：① **强依赖 A 组 `cov` 形式**（矩阵/区间/半径/没有，须问卢肄文）；② NIS 只覆盖位置，ΔCOG/ρ/XTE 量纲不同不能直接进同一 CUSUM（须各特征单独归一化或多变量马氏）；③ 上游不确定带"不诚实"会虚警，需先用 3.4 NEES 标定。

**适配程度**：★★★，**前提是 A 组给协方差**——目前最需立刻确认。

#### 2.3.2 σ 缩放动态阈值（k × 区间半宽）★★

**原背景**：时序预测异常检测标准做法。

**本项目怎么用**：上游给分位数区间则取阈值 = k × 不确定带半宽（横/纵向分开），k 由目标虚警率定。

**优点**：NIS 的标量退化版，实现最简单。**缺点**：失方向相关性，门限无卡方漂亮理论含义。

**适配程度**：★★，**3.1 拿不到协方差时的保底**。

#### 2.3.3 自适应共形推断 ACI + 分裂共形冷启动 ★★★

**原背景**：共形预测给任意黑箱生成覆盖率有保证的区间；SCP（Vovk et al., 2005）用校准集残差经验分位数；ACI（Gibbs & Candès, 2021, NeurIPS）允许分布漂移、在线递推更新带宽。

**本项目怎么用**：冷启动（SCP）跑若干"船正常航行"回合收集残差定初始阈值；在线（ACI）用历史"预测−实测"残差维护自适应不确定带，盖不住真值则调宽。

**优点**：完全无训练/无分布假设、几十行代码、允许分布漂移、正好回答"阈值第一版从哪来"；与项目既定"实际会面偏差与轨迹预测误差回流校准"机制天然吻合。

**缺点 / 局限**：覆盖率是长期意义、短期带宽可能偏窄/偏宽；学习率 γ 可调（可用 AgACI 免调）。

**边界**：**只校准判定阈值带，不校准预测模型本身**——文档须写死，否则会被当成侵入 A 组（卢肄文）的活。

**适配程度**：★★★，**作 3.1 兜底 + 长期在线校准**。

#### 2.3.4 NEES 一致性检验（仿真内自校准）★★

**原背景**：滤波器一致性检验——验证估计器报告的协方差是否与实际误差一致。

**本项目怎么用**：仿真有真值，检查上游不确定带是否诚实；NEES 偏大说明偏窄，先给协方差乘标定因子。

**优点**：低成本且天然是实验章节。**缺点**：只在仿真有效；措辞写"一致性标定"，**别写"检验 A 组预测准不准"**。

**适配程度**：★★（工具/实验用）。

#### 2.3.5 协方差匹配（朴素 EWMA 方差估计）★

**原背景**：自适应滤波用实测新息反推噪声协方差。

**本项目怎么用**：对残差做 EWMA 方差估计，阈值 = k × σ̂。

**优点**：直觉好讲。**缺点**：无可证覆盖率保证。

**适配程度**：★，**作 ACI 对照基线**。

### 2.4 第三层：确认与防抖（"持续成立"才生效）

#### 2.4.1 累积和检验 CUSUM ★★★（主判据）

**原背景**：统计过程控制经典（Page, 1954），最快变化检测，最小化检测延迟，ARL0 可查表定标。

**本项目怎么用**：对归一化偏差做单边 CUSUM：S(t) = max(0, S(t−1) + z(t) − k)，S 超门限 h 才确认。

**优点**：①"持续成立"内生保证（单帧尖峰被 max(0,·) 截断）；②"误触发代价高"有量化旋钮（ARL0 由 k,h 查表定标）；③对幅度敏感。

**缺点**：要求输入是归一化连续量；k,h 需查表标定；"持续"隐式、不直观；突变+噪声需复位策略。

**适配程度**：★★★。**硬约束**：检测延迟（1σ 偏移约 10–12 样本 × 上报周期）必须小于"最后可修正时刻"前剩余时间，否则测出也来不及纠。

#### 2.4.2 M-of-N 滑窗确认逻辑 ★★★（硬基线 + 对照实验）

**原背景**：雷达航迹起始抑制假航迹——N 周期至少 M 次关联成功。

**本项目怎么用**：判据在最近 N 周期至少 M 次成立才触发（如 3/5）。

**优点**：可解释性最强、检测概率可解析、极简响应快。

**缺点**：对偏移幅度无感、M/N 无理论最优化。

**适配程度**：★★★，**作硬基线，并把"M-of-N vs CUSUM 检测延迟—虚警率对比"做成论文实验章节**。

#### 2.4.3 双阈值迟滞 + on/off 延时 ★★（叠加层，不可单独用）

**原背景**：工业报警管理（ISA-18.2 / EEMUA 191）消除抖动报警。

**本项目怎么用**：每判据配"触发阈值 > 解除阈值"双门限 + 触发/解除延时。

**优点**：消灭乒乓、复位干净、成本近零；对第四层很重要（会面点修正指令不能来回抖）。

**关键认知**：**迟滞管的是"输出端复位"，不保证"持续成立才触发"**，单帧尖峰照样触发。真正防误触发的是 CUSUM/M-of-N 累积逻辑，**迟滞只能叠加，不能单独用**。

**适配程度**：★★（叠加在 4.1/4.2 之上）。

#### 2.4.4 其余做法定位

| 方法       | 原背景                            | 优点                 | 缺点            | 适配度                            |
| -------- | ------------------------------ | ------------------ | ------------- | ------------------------------ |
| **EWMA** | 与 CUSUM 并列经典控制图（Roberts, 1959） | 适合渐进漂移（减速类 SOG 缓降） | 对突变不如 CUSUM   | ★★ 与 CUSUM 并行：突变 CUSUM、渐进 EWMA |
| **SPRT** | 序贯假设检验（Wald, 1945）             | α/β 显式可控           | 需参数化 H1 偏移量 δ | ★ 备选/论文等价叙述                    |

**三层叠加效果**：CUSUM 挡瞬时尖峰 → M-of-N 兜底 → 迟滞防乒乓，**单帧抖动触发在结构上不可能发生**。

### 2.5 第四层：滚动重估框架与动作生成

#### 2.5.1 滚动时域控制骨架（RHC / MPC）★★★

**原背景**：模型预测控制，每周期基于最新状态求解有限时域优化，只执行第一步，下周期用新测量重解。

**本项目怎么用**：每上报周期 → 更新状态 → 重估可行性 → 重解"继续/修正/中止" → **只下发本周期指令**。

**优点**：与"在线决策"定义对应，框架复杂度低（内部可简化为规则，不必真跑 QP）。**缺点**：本身非创新点。

**适配程度**：★★★，**创新点在骨架里嵌的 A/B/C 三层**。

#### 2.5.2 收缩时域 + 「最后可修正时刻」★★★（亮点）

**原背景**：直升机着舰类"终端时刻确定、终端状态非平衡点"问题，机动时间指定后退化成逐周期缩短的 QP（SHMPC）。

**本项目怎么用**：会面时刻由船程与机程共同确定后，剩余时域每周期自然缩短；越接近会面点，重估重点从"要不要修正"转向"还够不够时间/能量修正"。核心概念：**存在最后可修正时刻**——过了它即使发现船变了也只能中止。

**优点**：给纠偏截止时间干净形式化；**反过来约束第三层**（CUSUM 检测延迟须小于剩余可修正时间）。

**适配程度**：★★★（概念采纳，不求求解器）。

#### 2.5.3 双层架构：可行性评估层 + 执行层 ★★★

**原背景**：移动目标拦截系统把"目标状态估计/预测"与"滚动规划执行"解耦。

**本项目怎么用**：**E 组就是上层**，周期输出 go/no-go 与修正请求；下层（B 组航迹寻路）只消费上层输出。

**优点**：接口干净、职责分明，正好对应项目分组叙事。

**适配程度**：★★★。

#### 2.5.4 任务阶段状态机 FSM ★★★

**原背景**：无人机平台降落中把任务分为导航/跟随/降落等阶段切换策略。

**本项目怎么用**：去程段显式建模为 `巡航追踪 → 疑似偏差（确认中）→ 确认变更/重定会面点 → 接近段（冻结大修正，只允许微调）→ 中止返航`；状态转移条件即 A/B/C 三层输出，4.3 迟滞保证状态不乒乓。

**优点**：答辩最直观的系统图；阶段化天然解决"接近会面点时不该再做大改"。

**适配程度**：★★★。

#### 2.5.5 需拆开归属的两块（不能整套放进功能17）

| 方法             | 拆分归属                                | 适配度        |

**即：功能17 只输出"船是否变了 + 建议发起重算会面点"，不自己把 go/no-go 做全套。**

### 2.7 算法融合：这条流水线怎么真的跑起来

#### 2.7.1 层间接口：每层只传一个量

| 工序     | 干什么         | 输入            | 输出             |
| ------ | ----------- | ------------- | -------------- |
| L1 特征  | 把"变"量化成可比偏差 | 船侧/机侧状态流、预测航迹 | 各特征偏差 x(t)     |
| L2 归一化 | 偏差除以预测不确定带  | x(t)、上游 cov   | 无量纲 z(t)       |
| L3 确认  | 持续成立才作数（防抖） | z(t)          | 每条特征确认布尔       |
| L4 合成  | 多证据收敛成一个结论  | 各确认布尔         | 前提成立/失效 + 变更类型 |
| L5 阶段  | 给出时序上下文     | 结论 + 任务进度     | 允许动作集          |
| L6 动作  | 出本周期出口      | 阶段 + 结论       | 不动作 / 6a / 6b  |

**能串起来靠三个统一**：L2 统一尺度、L3 统一时间、L4 统一结论。**L2 是枢纽**——没有它下游只看 z(t)，与上游量纲彻底解耦；上游数据形式一变只换 L2 实现。

#### 2.7.2 两个关键结构

**① 机侧偏航走旁路，不参与意图判定。** 机侧偏航距离（M4 已给）不进 L2 船侧归一化、不进 L4 意图合成，直接进决策层触发 6a（重算会面点请求）。旁路不等于不做防抖——下发 6a 指令前同样要过超阈门槛与迟滞。

**② 多特征用「分路 OR」，不用「合成一个标量」。** 三路船侧判据各自归一化、各自累积确认，**任一确认即判前提失效**。合成会丢失变更类型（类型决定下游处置），分路可逐条标定、单独定位误报。

#### 2.7.3 算法的四种角色（不是全部上线）

| 角色           | 成员                                        | 说明                 |
| ------------ | ----------------------------------------- | ------------------ |
| **主线**       | XTE + 运动学特征/状态机(+围栏) → NIS → CUSUM（每特征一路） | 真正跑的一条链            |
| **叠加层**      | 迟滞双门限                                     | 只做输出端复位            |
| **基线/可退化替身** | M-of-N                                    | CUSUM 标定过大时顶替；论文对比 |
| **对照实验**     | EWMA、GLR                                  | 论文做检测延迟—虚警率对比      |
| **降级兜底**     | σ 缩放、ACI + SCP                            | 仅上游不给协方差时顶上        |

**结论**：降级只换 L2 一个盒子，其余层不动。"去问卢肄文 cov 给不给矩阵"只影响 L2，不推翻整条链。

#### 2.7.4 一个上报周期的执行顺序

1. 收到新状态帧 → 更新滑动窗口；
2. L1：算各特征偏差 x(t)；
3. L2：除以对应不确定带 → z(t)；
4. L3：各特征累积确认——未过门限则本周期结束，回第 1 步；
5. L4：合成"前提成立/失效 + 变更类型"；
6. L5：推进阶段，判断是否已过最后可修正时刻；
7. L6：出本周期动作，**只下发这一步**；
8. 进入下一周期（滚动时域）。

#### 2.7.5 接回项目流程的三条硬约束

1. **判据 → 前提的映射必须显式写死**：船沿预测正常行驶＝前提成立→6a；改向/停车/驶入分汊＝前提失效→6b。
2. **6a 动作形式按 `33-M3` §3.5 口径**：是"只重算这一架机的会面点（调 32 服务）＋下发离散指令"，**不是自己算航向/速度修正量**。
3. **检测延迟必须小于剩余可修正时间**：CUSUM 确认延迟须落在最后可修正时刻之前。

### 2.8 必须处理的缺口

1. **A 组 `cov` 的具体形式**（协方差矩阵/区间半宽/半径/无）——决定走 C1（NIS 卡方）、C3（σ 缩放）还是 C4（ACI 在线共形）。**最优先去问卢肄文。**
2. **ROT 不在接口字段**——由 COG 序列差分派生或向 A 组要。
3. **航道中心线 GIS 缺失**——XTE 退化为"到预测航迹距离"；地理围栏暂不可用，先按无 GIS 设计保底。
4. **多特征量纲不统一**——NIS 只覆盖位置，ΔCOG/ρ/XTE 不能直接进同一 CUSUM，须各特征单独归一化或多变量马氏。
5. **判据 → "前提是否成立"的映射（本文已补齐）**——船沿预测正常=前提仍成立→6a；改向/停车/驶入分汊=前提失效→6b。已写进 7.5 硬约束 1。
6. **6a 的动作形式已按 `33` §3.5 统一**——是"重算会面点请求（调 32 服务）+ 选择指令类型"，非自己算修正量；第一篇 2.2 输出表述已同步改为此口径，全文档不再出现"自算航向/速度修正量"。

### 2.10 验证方式与评估指标

> 功能17 本质是在线变化点检测，验证以"检测速度 vs 虚警率"权衡为核心，全部指标在仿真回放中统计。**本章即功能17 的专用验证方案**；通用手段（回放、蒙卡、消融、WCET 等）见第五篇第1章 D1–D8。

**核心指标**：

- **ARL₀ / ARL₁**：ARL₀＝无变化时到虚警的平均周期数（越大越好）；ARL₁＝变化发生后到检出的平均周期数（越小越好），绘制权衡曲线。
- **EDD**（期望检测延迟）：真值变化时刻到判出时刻的上报周期数，统计均值/中位数/90 分位数。
- **虚警率 / 漏报率 / ROC-DET 曲线**：不同信噪比下绘制，评估稳健性。
- **不同信噪比下的性能退化曲线**：控制注入事件幅度，观察 EDD 与虚警率随幅度变化。

**场景构造与数据来源**：

- **数据来源**：以**合成轨迹（船舶运动学模型生成）为主**——项目暂无内河 AIS 历史数据集；若获取长江/珠江 AIS 历史数据，作可选交叉验证增强，**不阻塞**验证进度。
- **注入方式**：在选定航段不同位置人工注入三类事件——改向（5°/15°/30° 参考区间）、减速（10%/30%/50% 参考区间）、停车（速度趋零），每事件有精确真值时刻，控制幅度与注入位置。
- **规模建议**：3–5 个典型航段（直线/弯道/交汇区）× 三类事件 × 多幅度 × 每组合 ≥30 随机时刻，生成 ≥270 测试场景（建议值，按仿真资源与方差收敛判据标定，非定死）。

**方法组合**：A1（ARL₀/ARL₁）+ A2（EDD）+ A3（ROC/DET）+ A4（合成/AIS 回放注入）+ A5（信噪比分层）+ D1（回放）+ D4（消融：去掉迟滞层看虚警率变化）+ D6（WCET：验证每上报周期内完成判定）。

**为什么适合**：功能17 本质在线变化点检测，ARL/EDD 是标准评估指标；回放注入能构建带真值标注测试集；消融实验直接证明每层贡献。

## 3 功能9：飞行过程中的重新调度

**术语口径（先统一）**：

| 说法    | 含义                     | 归属                       |
| ----- | ---------------------- | ------------------------ |
| 变化    | 与计划不符的事件总称：变更类＋异常类＋环境类 | E 消费，不生产                 |
| 触发门槛  | 这条变化"够不够格"被考虑          | 功能9 自研                   |
| 触发节制  | 够格之后，"多久允许触发一次"        | 功能9 自研                   |
| 四档响应  | **继续 / 调整 / 重调度 / 终止** | 功能9 自研，口径已由项目定死          |
| 重调度请求 | 给上游"保留什么、放开什么"约束消息     | 功能9 只**生成请求**，求解归 C/D 组  |
| 终止    | 本次任务作废                 | 功能9 只判"是否中止"，**落点归功能10** |

**适配度标记**：★★★ 主线｜★★ 辅助/叠加/兜底｜△ 消费别组结论

### 3.1 问题定位（方法层）

功能9 不是"把异常转发给上游"，而是：**飞行中出现变化时，判定这条变化该走哪一档响应，并在确认为重调度时，给上游一个说清"保留什么、放开什么"的请求。**

落到方法层，是一条四层流水线：

```
第一层 事件层：把各类变化与告警统一成事件，排优先级、做抑制与合并
        ↓
第二层 触发层：先过门槛（够不够格），再过节制（允不允许现在触发）
        ↓
第三层 档位层：判四档之一（继续 / 调整 / 重调度 / 终止），含互锁与守卫
        ↓
第四层 请求层：界定影响范围，做硬软约束分层，生成重调度请求消息
```

### 3.2 第一层：事件层（变化的接入与排序）

#### 3.2.1 事件优先级、抑制与合并 ★★★

**原背景**：工业报警管理"报警风暴"问题——多告警同时涌来须排优先级、抑制次要、合并同源（ISA-18.2）。

**本项目怎么用**：把上游各类事件（功能17 意图变更、F/G 告警、A 组风况突变、D 组时隙变化）统一成事件对象，按**安全类 > 任务类 > 效率类**排序；同源事件时间窗内合并；低优先级在高优先级处理期间被抑制。

**优点**：解决"多个变化同时到达怎么办"，纯规则零成本，有标准可引。

**缺点 / 局限**：优先级要有依据（按"是否威胁飞行安全"二分再按影响面排序）；抑制有代价，需超时兜底。

**适配程度**：★★★。

#### 3.2.2 触发审计与可解释日志 ★★

**原背景**：安全关键系统决策可追溯性——记录"为什么触发/没触发"。

**本项目怎么用**：每个周期把"收到什么事件→过没过门槛→过没过节制→判了哪一档→为什么"落成结构化日志。

**优点**：天然是演示与论文实验素材，成本极小，答辩被追问时直接调日志。

**适配程度**：★★（**强烈建议保留**，性价比最高非算法件）。

#### 3.2.3 事件来源清单（必须写进输入部分）

功能9 消费的事件来自四处，**自己不做任何检测**：

| 来源          | 事件                 | 归属              |
| ----------- | ------------------ | --------------- |
| 功能17（E 组自己） | 意图变更确认 / 放弃本次会面    | 自产自用            |
| F 组 / G 组   | 数据偏差超限、失联、低电量、故障告警 | 消费，**检测算法不归 E** |
| A 组         | 风况突变预警             | 消费              |
| D 组         | 会面窗口 / 归巢时隙变化      | 消费              |

### 3.3 第二层：触发层（两条正交的线）

> **这一层最重要认知**：触发机制分属**两条正交的线**——门槛（够不够格）与节制（多久允许一次）。**必须先过门槛，再过节制，都通过才真的触发。**

#### 3.3.1 门槛线：死区 + 分层带 ★★★

**原背景**：控制与工业报警抑制微小波动——偏差落死区内不动作；配进入≠退出双门限（Schmitt trigger 思想）。

**本项目怎么用**：对每个连续型变化量（会面窗口偏差、风况变化幅度、电量消耗偏离度）设**进入/退出双门限**，形成"死区—警戒—超限"分层带，只有进入"超限"带才够格。

**优点**：最实用——绝大多数"变化"是正常波动，死区直接滤掉；纯规则可解释零算力；与功能17 迟滞同一思想（但不在同一层）。

**缺点 / 局限**：死区宽度要标定；过宽漏报、过窄形同虚设，权衡要写进论文。

**适配程度**：★★★。

> **边界**：A3「多指标触发函数—决策表」只输出"触发标志 + 触发原因"；映射到四档响应属第三层活，不进触发层。

#### 3.3.2 门槛线：事件等级直通 ★★★

**原背景**：告警分级响应——失联/灭失/严重故障性质上无需比较幅度、直接响应，走旁路直通。

**本项目怎么用**：上游告警自带等级时，**高等级事件旁路直通**第三层，不经死区；低等级才走死区。

**优点**：结构上保证"安全类事件不会被死区吞掉"。

**缺点**：依赖上游给的等级粒度（**缺口：项目里告警等级是否分级、分几级，未定死**）。

**适配程度**：★★★。

#### 3.3.3 节制线：最小触发间隔 + 冷却期 ★★★

**原背景**：事件触发控制避免 Zeno 行为（无限次触发）——两次触发强制最小间隔；离散事件系统称 dwell time。

**本项目怎么用**：连续两次重调度设**最小触发间隔**；一次重调度完成后进**冷却期**，冷却期内新变化只记录不触发（除非安全类直通事件）。

**优点**：直接控制触发频率，防止"反复要求上游重跑"——飞行中重调度最大工程风险。

**缺点 / 局限**：间隔太长延误真实需求、太短失去意义；**冷却期与安全类直通必须互斥**，否则吞掉紧急事件。

**适配程度**：★★★。

#### 3.3.4 节制线：事件触发式重规划（总框架）★★★

**原背景**：事件触发控制——只在"事件使原计划误差超限"时才重算（Åström & Bernhardsson, 2002, CDC；Tabuada, 2007, *IEEE TAC*；Heemels et al., 2012, CDC）。

**本项目怎么用**：作为第二层**总框架**：默认不重算，只有收到事件且过了 3.1/3.2 门槛、又过了 3.3 节制，才进第三层判档。

**优点**：给这一层有学术名字的框架，与"机载算力有限、下游重跑代价高"约束对应。

**适配程度**：★★★。

#### 3.3.5 自触发 / 预测触发 ★★（可选）

**原背景**：自触发控制——不只判断"现在要不要算"，还预测下次必须检查时刻（Anta & Tabuada, 2010, *IEEE TAC*）。

**本项目怎么用**：用 A 组预测推算"会面窗口预计何时超限"，提前触发；否则推后下次检查。

**优点**：比被动等事件更省。**缺点**：中复杂度且强依赖上游预测质量。

**适配程度**：★★（可选增强，第一版不上；论文作"未来工作"）。

### 3.4 第三层：档位层（四分档判定）

#### 3.4.1 四档的含义与出口（项目既定口径，先钉死）

| 档位      | 含义          | 出口去向                             |
| ------- | ----------- | -------------------------------- |
| **继续**  | 影响不大，照原计划飞  | 回原计划，继续监测                        |
| **调整**  | 小改，不回上游     | 传导到去程或返航环节（去程＝功能17 的 6a；返航＝功能10） |
| **重调度** | 原计划作废，回上游重跑 | 交 C 组两关剪枝 + D 组择优占位              |
| **终止**  | 本次任务作废      | **交功能10 定落点**（E 自己不判落哪）          |

> **红线**：终止 ≠ 换机/改派。终止后链路是「原机带货返航或迫停 → 落巢回收 → 第五章重派闭环」，飞行中不存在转派接力。

#### 3.4.2 决策表 / 规则表 ★★★

**原背景**：业务规则可审查表达——"什么条件组合→什么结论"写成可人工审阅的表（Forgy, 1982, *AI*，Rete 算法）。

**本项目怎么用**：把"变化类型 × 幅度 × 飞行阶段 × 剩余资源"映射到四档，写成决策表。低算力下**直接查表**。

**优点**：可解释可审查、改规则不用改代码、复杂度低。

**缺点 / 局限**：条件维度多会组合爆炸→对策是**先按飞行阶段分表**；遗漏组合必须有默认出口（默认＝"继续 + 加强监测"）。

**适配程度**：★★★，**四档判定主体实现**。

#### 3.4.3 状态图 / 有限状态机 ★★★

**原背景**：复杂系统模式管理（Harel, 1987, Statecharts）。

**本项目怎么用**：主状态 = 巡航去程 / 会面 / 返航；每主状态挂子状态 = 正常/调整中/重调度等待/终止。转移条件＝第二层触发标志 + 第四层返回结论。

**优点**：答辩最直观系统图；天然解决"同一事件不同飞行阶段应有不同档位"；与功能17 阶段 FSM 同一套语言。

**缺点**：状态多了防爆炸→主状态严格限三个。

**适配程度**：★★★，**核心骨架；决策表挂在状态转移上**。

#### 3.4.4 模式互锁与守卫条件 ★★★

**原背景**：航空与工业控制防模式混淆——守卫条件禁止不该发生的模式切换。

**本项目怎么用**：显式列出禁止项——重调度进行中禁止再次触发；返航中禁止发起新会面；电量低于安全裕度禁止进入"调整"档（只能继续或终止）；冷却期内除安全类外一律不触发。

**优点**：**把 3.3 节制与 4.2 决策表连起来的胶水**，防逻辑自相矛盾，成本极低。

**适配程度**：★★★。

#### 3.4.5 优雅降级 ★★（叙事框架）

**原背景**：系统能力下降时保持核心功能，按预定顺序逐档降级。

**本项目怎么用**：把四档包装成降级链：**全自主会面 → 调整会面 → 重调度 → 中止返航**，每档是前一档不可行时的退路。

**优点**：给四档有层次叙事。

**适配程度**：★★（**论文叙事框架**，与决策表并存）。

#### 3.4.6 中止判据（终止档专属判据）

**边界写死**：以下判据只回答"**本次任务是否作废**"，**不回答"回哪个巢、迫停还是迫降"**——后者是功能10 活。

| 方法                      | 原背景                                                               | 本项目怎么用                        | 适配度                       |
| ----------------------- | ----------------------------------------------------------------- | ----------------------------- | ------------------------- |
| **C1 Go/No-Go 阈值判据**    | 任务前/中继续与否决策                                                       | 实时算继续收益与风险，低于阈值则终止            | ★★★                       |
| **C3 剩余资源 × 任务成功概率折中**  | 可靠性工程任务中止策略（Levitin, Xing & Dai, 2018, *IEEE Trans. Reliability*） | 电量须覆盖返航+备降裕度；预计会面后剩余低于安全裕度则终止 | ★★★                       |
| **C4 能量/安全包线**          | 无人机 RTH 与迫降工程安全边界                                                 | 在线检查能量包线，被突破即终止               | ★★★（只判包线破没破）              |
| **C5 多级告警响应矩阵**         | 工业报警分级响应（ISA-18.2）                                                | 告警等级 × 飞行阶段 → 动作，落进 4.2 决策表   | ★★★                       |
| **C2 风险–收益权衡**          | 决策分析效用理论（Keeney & Raiffa, 1976）                                   | 货物价值/紧迫性 vs 风险，规则化效用函数        | ★ 与 C1 重叠，可选              |
| **C6 MDP 最优停止 + 离线阈值表** | 随机环境最优中止（Puterman, 1994）                                          | 离线算阈值表、在线查表                   | ★ 论文对照/备选（复杂度中–高，与极简原则不符） |

> **边界**：空间围栏类触发判定留在第二层 3.2；落点与返航相关判定全部归功能10，不进本层。

#### 3.4.7 自主等级（需改写后才能用）★

**原背景**：人机权限分配（Sheridan & Verplank, 1978；Parasuraman et al., 2000）。

**本项目怎么用**：把"确认"落实为"**由上游调度引擎受理**"——继续档与调整档机载自主执行；重调度档提交上游受理并等待返回；终止档自主执行但强制记审计日志。

**适配程度**：★★。

#### 3.4.8 应急检查单 ★★

**原背景**：航空应急程序标准化（FAA/NASA UAS contingency management）。

**本项目怎么用**：高等级告警处置做成固定检查单（失联→保持航向并计时→超时转终止；低电量→立即终止并交功能10）。

**优点**：安全类处置不经复杂判定，最可靠好解释。

**适配程度**：★★（高等级告警旁路专用）。

### 3.5 第四层：请求层（重调度请求生成）

#### 3.5.1 硬 / 软约束分层 ★★★（本层核心）

**原背景**：约束满足问题区分"不可违反"与"可权衡"，软约束排优先级（Wilson & Borning, 1993；Bistarelli et al., 1997）。

**本项目怎么用**：回上游重跑前，把原计划约束分层——

- **硬约束（不可放开）**：飞行安全、禁飞区与空域限制、返航电量底线、机巢能力、会面物理可行性
- **软约束（可放开，按优先级序）**：原时间窗、能耗最优、路径长度、其他任务时隙占用

**优点**：这才是"重调度请求生成"真正答案——请求内容即"硬约束保留清单 + 软约束可放开清单（带优先级）"；复杂度低可解释满分；防"重跑时把不该动的也改了"。

**缺点 / 局限**：软约束优先级序需定；硬约束须穷举且被上游认可——**跨组接口，汇总时与 C/D 组对齐**。

**适配程度**：★★★。

#### 3.5.2 约束松弛 / 部分约束满足 ★★

**原背景**：过约束问题按优先级放松（Freuder & Wallace, 1992）。

**本项目怎么用**：原计划不可行时，按 5.1 优先级序**逐条**放开软约束直到上游可解；每放开一条记审计日志。

**优点**：把"放开"变有序可追溯动作。

**缺点**：松弛过度导致上游解无意义→须给松弛设上限（最多放开 N 条，硬约束永不放开）；中复杂度。

**适配程度**：★★（5.1 分层基础上叠加）。

#### 3.5.3 最小冲突集（MUS / QuickXplain）★

**原背景**：解释"为何约束集不可满足"——找导致冲突最小子集（Junker, 2004, AAAI）。

**本项目怎么用**：重跑仍无解时，告诉上游"**必须改哪几条**"。

**优点**：失败原因说清楚，论文与演示素材。

**缺点**：中复杂度且需访问上游求解过程——求解不归 E 组。

**适配程度**：★（可选增强，上游愿提供冲突信息则可用）。

#### 3.5.4 影响集 / 依赖图 ★★★

**原背景**：真值维护系统维护推理依赖关系（Doyle, 1979；Dechter, 2003）。

**本项目怎么用**：把变化事件映射到受影响计划片段（会面时间/等待点/航段/时隙），据此判定**局部还是全局重跑**。

**优点**：直接回答"这次重算多大范围"，是 5.6 输入。

**缺点**：需维护计划依赖图，粒度要和其他组对齐。

**适配程度**：★★★（范围界定判据来源）。

#### 3.5.5 增量 vs 全局重跑适用条件 ★★★

**原背景**：判断何时增量修补、何时从头重算。

**本项目怎么用**：同时满足"变化局部/硬约束未冲突/时间裕度足/依赖图局部/上游预测置信度够高"→判**局部**；否则**全局**。

**优点**：把"重算多大范围"变可审查规则判定。

**缺点**：五条每一条都要能计算（尤其"上游预测置信度"依赖 A 组）。

**适配程度**：★★★。

#### 3.5.6 重调度请求模板 ★★★

**原背景**：上下游接口标准化——固定结构消息而非临时拼参数。

**本项目怎么用**：请求固定含：任务 ID、当前状态快照、触发原因、**保持约束清单（硬）**、**可松弛约束清单（软，带优先级）**、影响范围（局部/全局）、上下文、时间戳。

**优点**：**功能9 输出的标准形态**，直接定义接口。

**缺点**：需与上游（C/D 组）就字段一致。

**适配程度**：★★★。

> **边界**：E 组只**界定**改动范围并输出"局部重规划请求"；修补算法归下游执行。

### 3.7 算法融合：这条链怎么真的跑起来

#### 3.7.1 层间接口：每层只传一个量

| 工序    | 干什么            | 输入                  | 输出                 |
| ----- | -------------- | ------------------- | ------------------ |
| L1 事件 | 统一事件、排序、抑制合并   | 各类变化与告警             | 本周期待处理事件（有序）       |
| L2 触发 | 先过门槛、再过节制      | 事件+连续偏差量+时间戳        | 触发标志 + 触发原因        |
| L3 档位 | 判四档之一          | 触发标志+飞行阶段+剩余资源      | 档位结论（继续/调整/重调度/终止） |
| L4 请求 | 界定范围、分层约束、生成消息 | 档位结论（仅"重调度"档）+原计划约束 | 重调度请求消息            |

**能串起来靠两个分离**：L2 内部把**门槛**与**节制**分两条线（正交，不能混）；L3 把**档位判定**与**落点判定**彻底分开（落点归功能10）。

#### 3.7.2 三个关键结构

**① 门槛与节制串联，不是并联。** 顺序固定：事件→门槛（够不够格）→节制（允不允许现在）→才触发。

**② 安全类事件必须有旁路。** 高等级告警跳过死区与冷却期直达 L3，这条守卫显式写进 L2。

**③ 只有"重调度"档进 L4。** 继续档原地返回；调整档传导到去程（功能17 的 6a）或返航环节；终止档交功能10。

#### 3.7.3 与功能17 的接缝

```
功能17（去程段）判出"意图变更确认 / 放弃本次会面"
        ↓  作为高优先级事件上报
功能9 的 L1 接入 → L2 门槛与节制裁决 → L3 判四档
```

**分工边界**：功能17 负责"发现变化"（船侧判据），功能9 负责"变化之后怎么办"（分级响应）。功能17 的 6a 是"调整"档在去程段就地执行实例；功能17 的 6b（放弃会面）作为事件进功能9，由功能9 判档后交功能10。

#### 3.7.4 一个周期的执行顺序

1. 收到本周期事件与状态 → L1 排序、合并、抑制；
2. L2 过门槛：连续量比死区双门限，高等级事件走旁路直通；未过→本周期结束；
3. L2 过节制：检查最小间隔与冷却期（安全类除外）；未过→只记录，本周期结束；
4. L3 结合飞行阶段与剩余资源查决策表判档；守卫条件校验（互锁）；
5. 继续→回监测；调整→传导对应环节；终止→交功能10；
6. 重调度→L4：算影响集→定局部/全局→硬软约束分层（必要时有序松弛）→按模板生成请求；
7. 提交上游（C 组剪枝 + D 组占位），进冷却期；
8. 全程写审计日志，进下一周期。

#### 3.7.5 接回项目流程的三条硬约束

1. **四档出口去向按 4.1 表写死**——尤其"终止 → 功能10"；
2. **终止 ≠ 换机/改派**——终止后"原机带货返航/迫停 → 落巢回收 → 第五章重派闭环"；
3. **L2 迟滞与功能17 迟滞不在同一层**——功能17 是信号层防抖（判据别来回判），功能9 是决策层防抖（别反复要求上游重跑），思想同源但层级不同，文档分开写。

**验证方式与评估指标**

> 功能9 是规则/状态机决策系统，验证以"分支覆盖 + 触发频率稳定 + 闭环收敛"为核心。**本节即功能9 的专用验证方案**；通用手段见第五篇第1章 D1–D8。

- **状态机覆盖**：转移覆盖率、转移对覆盖率（Chow W-方法），遍历"继续→调整→重调度→终止"全部状态与转移；MCDC 覆盖率验证复合条件判定充分性（如"电量低 AND 风况差"中单条件翻转是否改变决策）。
- **触发频率与稳定性**：单位飞行时长触发次数、平均触发间隔、间隔方差、最大连续触发次数；注入阈值附近波动序列查是否 Zeno 式抖动（迟滞+最小间隔守卫效果）。
- **场景矩阵穷举**：将"事件类型 × 飞行阶段"（若上游告警分级则补第三维"事件等级"）组合成决策表逐条核对。⚠ **维度退化**：若上游无等级字段，则"事件等级"一维不成立，高等级直通退化为 3.2 的旁路（所有事件都走死区门槛），**矩阵降为两维**（事件类型 × 飞行阶段），此情形下"等级"相关单元格不参与穷举。
- **闭环稳定性**：与上下游仿真串联，观察重调度次数是否收敛、有无"重调度→新计划→又触发"循环。
- **可审查性**：每条决策是否留完整日志（输入条件/规则触发/输出档位），能否从日志重放决策轨迹。
- **对抗性/边界注入 + 消融**：注入高频事件序列测频率控制；去掉事件优先级抑制看触发频率变化。
- **端到端**：与功能17（意图变更）、功能10（终止档）串联，看完整链路能否闭环。

**场景构造建议**：决策表穷举（事件类型×等级×阶段全部有意义组合）+ 抖动测试（阈值附近来回波动序列）+ 闭环串联（与上下游仿真联跑）。数据来源为仿真生成的场景矩阵与边界序列。

## 4 功能10：返航复核与归巢资源判定

**术语口径（先统一）**：

| 说法     | 含义                          | 归属                   |
| ------ | --------------------------- | -------------------- |
| 返航复核   | 进入返航时，按实时电量＋风况＋时隙占用重新核算该落到哪 | 功能10 自研（决策层）         |
| 落点结论   | 回原巢 / 迫停他巢 / 迫降野外           | 功能10 输出              |
| **迫停** | 借用**有设施的其他机巢**机位（需按时隙准入）    | 功能10 判**准入**，D 组占位   |
| **迫降** | 野外**无设施**场地                 | 功能10 判**落点**，B 组生成航迹 |
| 备降     | 民航用词（备降机场）——本项目统一用迫停/迫降     | 禁用                   |
| 原巢唯一化  | 默认回原巢；"别处更近"**不是**改投理由      | 项目既定原则               |
| 不可跳级   | 回原巢 → 迫停他巢 → 迫降野外，顺序强制      | 项目既定原则               |
| 返程电量基线 | 上游精算给出的返程所需电量               | 消费，不自算               |
| 归巢时隙占用 | 各机巢/迫停点时隙占用状态               | 消费 D 组，不自分配          |

**适配度标记**：★★★ 主线｜★★ 辅助/叠加/兜底｜△ 消费别组结论

### 4.1 问题定位（方法层）

功能10 不是"算一条回家的航线"，而是：**在准备返航的此刻，拿实时电量＋实时风况＋时隙占用，判定该落到哪一级，并给出落点结论。**

落到方法层，是四个部分——**先判第一级，不可行才往下走，绝不跳级**：

```
第一层 可行性层：判「原巢回不回得去」            ← 每周期必跑
        ↓ 不可行
第三层 准入层：判「他巢此刻能不能进」            ← 只在第一级不可行时跑
        ↓ 给出「可借 / 无位可借」
第二层 降级层：定最终级别（不可跳级、占位即锁定）  ← 吃上面两个结论
        ↓ 无位可借
第四层 迫降点层：台账候选 + 否决筛除 + 可达性      ← 只在无位可借时跑
```

> **层号与执行顺序**：层号按第二～五节编号（可行性＝第一层、降级＝第二层、准入＝第三层、迫降＝第四层）。**执行顺序是 1 → 3 → 2 → 4**——降级层必须拿到准入层"可借/无位可借"结论才能定级，不能先跳级再判。

### 4.2 第一层：返航可行性判定（第一级「回原巢」）

#### 4.2.1 储备能量政策 A1 ★★★（第一级核心判据）

**原背景**：民航燃油规划要求飞机从航路任意点都能安全飞抵目的地并保留最终储备（EASA：活塞 45 min、涡轮 30 min）。

**本项目怎么用**：上游返程电量基线加储备裕度，形成核心不等式——**实时电量 ≥ 返程基线 ＋ 储备裕度**则第一级可行。储备裕度是 `sys_param` 参数，由回流数据标定。

**优点**：有规章可引、语义强、结构极简（一个不等式＋一个参数）、与功能17"超阈值才动"同语言。

**缺点 / 局限**：储备裕度无可直接搬用的权威数据，靠仿真标定；只用点估计时对突变风况不敏感（这正是 2.3 要补的）。
  
**适配程度**：★★★。

#### 4.2.2 低电量绝对阈值 A5 ★★★（兜底）

**原背景**：无人机 RTH 低电量阈值（工程实践普遍做法）。

**本项目怎么用**：作为第一级**兜底规则**，与 2.1 **取更保守者**。实时电量低于绝对安全阈值时无论基线算什么都直接判第一级不可行。

**优点**：防"基线算错"、纯比较零成本、两条取保守者＝简单冗余保护。

**缺点 / 局限**：绝对阈值与机型/负载强相关；设太保守频繁降级虚警，太松失兜底意义。

**适配程度**：★★★。**必须与 2.1 并存，不可只留一条。**

#### 4.2.3 不确定性处理：A3 机会约束 / A4 鲁棒裕度 / 固定 k（同一件事的三档）

> **这一条单独记**：A1、A3、A4 看着是三个方法，**其实是同一件事的三个档**——第一级裕度怎么按上游不确定性表达形式降级。与功能17"L2 按 `cov` 形式降级"**同构**，两份文档同一套叙事。

**① A3 机会约束可达性（有分布时用）★★★**：风况不确定性建模为分布，要求"**返航可达概率 ≥ 1−α**"。顺风自动收紧、逆风自动放宽。缺点：强依赖上游给风况分布；α=0.01–0.05 不能直接搬，须重新标定。

**② A4 鲁棒裕度 / 最坏情况裕度（只有范围时用）★★★**：A3 低算力替代，用最坏情况风算返程能耗上界再加固定裕度。缺点：风况剧烈时可能过度保守、过早降级。

**③ 固定裕度系数 k（都没有时用）★★★（兜底）**：上游只给返程基线点估计则设固定系数放大基线，最低可行档。

> **降级规则（写进文档照抄）**：有分布→**A3 机会约束**；只有范围→**A4 鲁棒裕度**；都没有→**固定系数 k**——与功能17 的 `cov` 三档降级同一缺口、同一写法。

**适配程度**：★★★（三档并存，按可获取性自动降级）。

#### 4.2.4 返航能量包线查找表 A6 ★★

**原背景**：飞行器性能包线——把能量与距离安全边界画成线。

**本项目怎么用**：把 2.1–2.3 判据**统一表达为"能量—距离—风况"包线**，离线生成查找表，在线只查表。

**优点**：在线算力极低、参数变更离线重算一次、答辩可视化素材。

**缺点 / 局限**：离线生成中复杂度（扫参数空间）；包线离线冻结，上游能耗模型改了要重生成（版本耦合）。

**适配程度**：★★（建议作 2.1–2.3 统一实现外壳，标定工作量评估）。

#### 4.2.5 能量状态标签 A7 ★★（必须改写后才能用）

**原背景**：民航剩余燃油仅够飞抵最近机场时声明"MINIMUM FUEL"，低于最终储备声明"MAYDAY FUEL"。

**⚠ 冲突（必须改）**：这是**向 ATC 的无线电声明**——**本项目无 ATC，全自动链路**，须改写为机内状态标签。

**改写后可用**：保留分级词汇，但落成**内部状态标签**：第一级可行但裕度小于预警线→「最小能量状态」（黄色，加密复检）；第一级不可行→「能量紧急」（红色，立即降级判定）。

**适配程度**：★★（改写后用）。

#### 4.2.6 周期性复检（保留不可返回点的规章内核） ★★★

**⚠ 概念取舍**：不可返回点（PNR）含义是"过了该点继续前进比返回更优"，而本项目**返航目标唯一化＝原巢**，不存在"继续前进 vs 返回"二选一——**概念不成立，只保留内核**。

**保留的规章内核 ★★★**：A2 引用的条款里真正用得上的要求——**沿航路按检查点周期性复检剩余能量**。这正是"**返航复核**"定义：**按固定时间间隔（每周期）重算第一级可行性**。

**适配程度**：★★★（保留内核）。

> 条款 **UAM.OP.VCA.195**（属 **EASA Regulation (EU) 2024/1111**）：VTOL/vertiport 能量方案，含最终储备保护、MINIMUM FUEL/MAYDAY FUEL、沿航路检查点。

### 4.3 第二层：降级层（三级降级链与切换守卫）

#### 4.3.1 降级链 / 应急计划序列 B1 ★★★（结构骨架）

**原背景**：系统能力逐步丧失时按预定义序列降级（UAS 从标称飞行计划逐级切应急计划）。

**本项目怎么用**：三级降级整体框架：第一级→第二级由 2.x 可行性判据驱动；第二级→第三级由第三层准入判定（全不可用）驱动。**顺序强制、不可跳级。**

**优点**："不可跳级"天然由降级链保证；状态机低复杂度；与功能9"四档降级"同族（答辩叙事可统一）。

**适配程度**：★★★。

> 文献：**SESAR #0350「Vertiport disruption and emergency management」**。

#### 4.3.2 单向不可逆降级 B4 ★★★（占位即锁定）

**原背景**：安全关键系统降级后不允许"乐观回切"（功能安全与航空应急管理）。

**本项目怎么用**：**本层主守卫**——第三级（迫降）一旦激活不可回第二/第一级；第二级（迫停他巢）**一旦占位落定即锁定**，不再回切。

**为什么用"占位即锁定"**：本项目一旦向他巢申请并占用时隙，等于向另一资源方承诺使用；若允许风况改善后回切，会造成占位冲突（与 D 组占位并发打架）。**占位即锁定**比"允许回切+防抖"更简单安全。

**优点**：逻辑简单状态少、避免与 D 组占位冲突（跨模块正确性）、符合简单可解释原则。

**缺点**：牺牲极少数"风况突然大幅改善"最优性——那是过度优化，项目明确不要。

**适配程度**：★★★。

#### 4.3.3 迟滞切换 B2 ★★（只保留一处用途）

**原背景**：防模式在阈值附近反复切换（Schmitt 触发思想）。

**本项目怎么用**：**只用在第一级裕度边界防横跳**——第一级判定吃"实时电量 vs 返程基线＋裕度"，返程基线随风况变，不等式在边界上会抖，配进入/退出双门限有实际必要。

**⚠ 只用于一处**：迟滞只用于第一级裕度边界；按 3.2 第二级占位即锁定，不存在回切，不需回切防抖。

**适配程度**：★★（只用于第一级裕度边界）。

#### 4.3.4 最小驻留时间 B3 ★（并入或删）

**原背景**：切换系统稳定性理论——刚进某模式强制停留。

**本项目怎么用**：第三级迫降点选定后、下发前留短确认窗（更像"下发前确认"）。

**适配程度**：★（并入 3.2 锁定逻辑后删除，不单列）。

#### 4.3.5 分级响应矩阵 B5 ★★★（由三维改两维）

**⚠ 用两维**：**风况已进返程电量基线**（2.1 不等式里 `E_return` 本身是风况相关精算结果）——风况再单列一维＝重复计数、判定过保守。

**本项目怎么用（两维）**：**「第一级可行性」× 「借位可用性」→ 输出三级**

| 第一级可行 | 有他巢可借 | 落点结论         |
| ----- | ----- | ------------ |
| 是     | —     | **第一级 回原巢**  |
| 否     | 是     | **第二级 迫停他巢** |
| 否     | 否     | **第三级 迫降野外** |

**优点**：两维就够，表小可审查、答辩一眼懂；决策矩阵是落点结论标准输出形态。

**适配程度**：★★★，**落点判定主体实现**。

#### 4.3.6 优雅降级 B6 ★★（叙事框架）

**原背景**：系统能力下降时保持核心功能，逐步舍弃次要功能。

**本项目怎么用**：作 3.1 理论支撑——"安全着陆"底线不降，逐步舍弃：精确会面时间窗 → 他巢精确机位 → 迫降点精确性。

**缺点**：概念性不改变实现。

**适配程度**：★★（论文叙事框架）。

### 4.4 第三层：借位（他巢）准入判定（第二级）

> **关键前置**：他巢**距离各不相同**，必须先判"**这个他巢回不回得去**"，不可达直接从候选集剔除——**这是可行性筛除，不是择优**，不违反原巢唯一化。

#### 4.4.1 可达性筛除（C3 扩展到本层）★★★（最大方法缺口）

**原背景**：判断已知着陆点是否在飞行器可达范围（UAS 应急着陆；Springer 2013 迫降点可达性分析）。

**本项目怎么用**：准入判定**之前**，先对**候选他巢逐个做可达性筛除**——用实时电量与到该他巢返程能耗比较（口径与 2.1 一致），**不可达者直接剔除**，不进时隙检查。与 5.2 可达性**同一方法，两处共用**。

**为什么第二级也要判**：他巢远近不同，第二级若默认"他巢一定能到"，不筛除会出现"判了准入但飞不到"的假可行。

**优点**：补逻辑漏洞、不引入择优、与第三级共用方法口径一致。

**缺点**：需"到他巢返程能耗估计"——上游是否按目标点给能耗，待确认。

**适配程度**：★★★。

#### 4.4.2 容量约束检查 D2 ★★★

**原背景**：判断 vertiport 给定时刻机位容量是否饱和。

**本项目怎么用**：时隙检查**之前**粗筛——某他巢总机位数已被全部占用，无需逐时隙检查即判不可用。

**优点**：先粗后细省无意义时隙比较、低成本。

**缺点**：依赖他巢总机位数与当前占用数——是否由系统掌握、待确认。

**适配程度**：★★★。

#### 4.4.3 时隙可行性检查 D1 ★★★（第二级核心判据）

**原背景**：vertiport 容量管理与时隙分配——判断某时间窗是否存在可用进场/离场/服务时隙。

**本项目怎么用**：**第二级"迫停他巢"核心判据**。检查他巢在**预计到达时刻附近**是否存在空闲机位时隙（口径与 D 组占位并发对齐）。

**优点**：直接回答"这个机位此刻能不能进"；低复杂度（时间区间比较）。

**缺点 / 局限**：**只判准入、不判分配**——分配落子归 D 组；依赖上游给"带时间区间的占用状态"。

**适配程度**：★★★。

#### 4.4.4 时隙重叠判定 D5 ★★★

**原背景**：判断两时间区间是否冲突（调度可行性检查）。

**本项目怎么用**：4.3 具体实现——给定预计到达时刻与占用时长，检查 `[到达, 到达+时长]` 是否与已占用区间任一重叠。

**优点**：4.3 算法内核，排序+扫描极低复杂度。

**缺点**：**占用时长要估准**——估短挤占后续任务，估长误拒。

**适配程度**：★★★。

#### 4.4.5 借位准入完备性检查 D3 ★★★

**原背景**：系统验证与穷举检查——确保"确实无位可借"判断不遗漏候选。

**本项目怎么用**：**放行到第三级前的前置守卫**——必须确认**所有候选他巢**都被检查且均不可用（可达性×容量×时隙全失败），才输出"无位可借"。

**优点**："无位可借"结论必须可审计；列表遍历低成本；答辩可展示"候选表逐项打叉"。

**缺点 / 局限**：**候选列表不完备则完备性无法保证**→"候选集完备性由上游保证"写进接口约定；**跨组接口，与 D 组、M6 对齐**。

**适配程度**：★★★。

### 4.5 第四层：迫降点筛选（第三级，仅"回不去且借不到位"时）

> **本层形态**：项目 M6 台账已有 `emergency_landing_point`（迫降点台账）与 `airspace_restriction`（禁飞区），迫降点**从台账候选集里按否决条件筛除 + 可达性判定得出**——不是从零生成候选，不是实时地形识别。

#### 4.5.1 迫降点否决性条件 C1 ★★★（台账候选集 + 一票否决）

**原背景**：应急着陆时快速排除不可用场地（UAS 应急着陆）。

**本项目怎么用**：第三级激活后，对**台账候选迫降点**逐项过**否决性条件**（一票否决，不参与打分）。内河必需否决项：

- **坡度**：超阈值直接否决（两岸堤岸坡度）
- **地表类型**：水面/湿地/密集建筑区否决
- **障碍物密度**：高压线塔、通信塔、密集建筑区否决
- **人群密度**：人员活动区否决
- **沟通/通信条件**：无通信覆盖区否决（**可降级为风险标记**，见备注）

**优点**：与台账设计一致（直接用现成候选集）；"一票否决"比"多准则打分"简单可解释；可岸端预计算，机载只查表。

**缺点 / 局限**：**需台账带上述属性字段**（坡度/地表类型/人群/通信）——当前是否具备待确认；缺失则退化为"距航道距离+水面/陆地二值"粗筛。

**备注**：通信条件若无实时覆盖图，**从"否决条件"降级为"风险标记"**（允许选择但标高风险），否则可能把唯一可用点否决、导致无点可选。

**适配程度**：★★★。

#### 4.5.2 迫降点可达性分析 C3 ★★★

**原背景**：判断已知应急着陆点是否在可达范围（Springer 2013）。

**本项目怎么用**：第三级里，**只在可达的迫降点中选**。可达性由上游返程能耗估计驱动（与 2.1、4.1 同口径），E 组**只做"可达/不可达"判断，不做路径规划**。

**适配程度**：★★★。

#### 4.5.3 水面迫降 —— 由"适宜性评估"改为"否决条件" ★★★

**⚠ 定性**：**多旋翼 UAV 水面迫降≈损失机体**——不是"适宜性有高低"，而是"**直接否决**"。

**本项目怎么用**：**并入 5.1 否决条件**——"水面/湿地"作为地表类型否决项之一。

**适配程度**：★★★（并入 5.1，作否决项）。

#### 4.5.4 民航备降机场判据迁移 C2 ★★（仅迁否决维度）

> 术语说明：本项目统一用"**迫停/迫降**"，民航"备降"仅作否决维度来源。
>
> **原背景**：民航备降机场适航性评估（着陆距离、天气 minima、场道条件）。
>
> **本项目怎么用**：**只迁移否决性判据**（物理参数与气象条件满足"能不能用"），**不迁移择优逻辑**（多备降场打分优选）。
>
> **优点**：给否决条件一套有规章依据的维度来源。
>
> **缺点**：源判据含择优打分逻辑，须剥离后只保留否决维度。
>
> **文献**：EASA **CAT.OP.MPA.192** — 标题＝*Selection of aerodromes and operating sites*。
>
> **适配程度**：★★。

### 4.7 算法融合：这条链怎么真的跑起来

#### 4.7.1 层间接口：每层只传一个量

| 工序     | 干什么         | 输入                        | 输出                 |
| ------ | ----------- | ------------------------- | ------------------ |
| L1 可行性 | 判"原巢回不回得去"  | 实时电量+返程基线+风况+参数           | **第一级可行性（可行/不可行）** |
| L3 准入  | 判"他巢此刻能不能进" | 候选他巢+能耗估计+时隙占用（仅第一级不可行时跑） | **借位可用性（可借/无位可借）** |
| L2 降级  | 按顺序定最终级别+守卫 | 第一级可行性(L1)+借位可用性(L3)      | **最终降级级别**         |
| L4 迫降  | 台账筛除+可达性    | 迫降点台账+能耗估计（仅无位可借时跑）       | **落点结论（迫降点 ID）**   |

> **执行顺序 L1 → L3 → L2 →（必要时）L4**：先算第一级可行性，不可行才查他巢，拿到"可借/无位可借"后由 L2 定级，只有"无位可借"才进 L4。L2 虽是"降级层"但必须等 L3 结论才能定级，不能先跳级。

**能串起来靠两个分离**：L1 把**能量判定**与**风况处理**合成一个不等式（风况进基线，不单列）；L2 把**级别推进**与**准入判定**彻底分开（推进是结构，准入是判据）。

#### 4.7.2 三个关键结构

**① 三级是"顺序推进 + 占位锁定"，不是"三选一打分"。** 一旦向他巢占位即锁定，简单且安全。

**② 可达性贯穿第二、三级，不是只用在迫降。** 他巢远近不同必须先筛可达。可达性是二值筛除（可行性），不是排序（择优）——区别要写明，否则被误读成"在多巢中择优"。

**③ 风况只出现一次。** 风况通过影响返程电量基线进入判定，不再单独成维。B5 从三维改两维依据在此；某处又让风况单独调阈值＝重复计数。

#### 4.7.3 三级出口去向表（功能10 输出标准形态）

| 级别      | 落点结论                | 去向                                  |
| ------- | ------------------- | ----------------------------------- |
| **第一级** | 回原巢                 | → B 组生成返航航迹并精算返程电量 → 模块四下发执行        |
| **第二级** | 迫停他巢（含他巢 ID + 准入结论） | → **D 组占归巢时隙** → B 组生成航迹并精算 → 模块四下发 |
| **第三级** | 迫降野外（含迫降点 ID）       | → B 组生成航迹 → 模块四下发（**无占位环节**）        |

> **一句话**：**E 组只出"落点结论"，B 组画航线与精算电量、D 组占时隙、模块四执行。**

#### 4.7.4 与功能17 / 功能9 的接缝

```
功能17 判出「放弃本次会面」（6b）  ┐
                                    ├─→ 都通向功能10 返航复核
功能9 判出「终止」档               ┘
                                        ↓
                         功能10 判三级落点 → 出结论
```

**分工边界**：功能17 负责去程段"发现变化"（含放弃会面处置结论）；功能9 负责全飞行段"变化后怎么办"（四档分级）；功能10 只负责"**落到哪**"。**「放弃会面」与「终止」是进入功能10 的两个触发入口**，功能10 输出落点结论给 B/D 组与模块四。

> **注意**：功能9 判"任务是否中止"，功能10 判"中止后落哪"——**两个判定前后相连但不是同一个**，不能混写。

#### 4.7.5 边界（明确不做什么）

- 不做返航/去程航迹生成——归 B 组；
- 不做返程电量精算——归第5步精算/B 组，E 只消费基线；
- 不做归巢时隙分配落子——归 D 组，E 只判"能不能进"；
- 不做原始数据采集与状态估计——归模块一/F 组；
- 不做异常检测与告警算法——归 F/G 组；
- 不做长周期态势/气象预测——归 A 组；
- 不做飞行中改派/换机；
- 不做底层飞控执行——E 只出结论，执行归模块四。

#### 4.7.6 一个周期的执行顺序

1. 进入返航（或复检周期到）→ L1 算第一级可行性（周期复检）；
2. 第一级可行→输出「回原巢」，结束；不可行→进 L2；
3. L2 按降级链进第二级（第一级边界先过迟滞双门限防横跳）——级别待 L3 结论确认；
4. L3 对候选他巢：可达性筛除 → 容量粗筛 → 时隙可行性（重叠判定）→ 逐个判定；
5. 有可借→输出「迫停他巢（含 ID 与准入结论）」→**占位即锁定**；转 7.3；
6. 全部不可用→**完备性检查**确认"无位可借"→进 L4；
7. L4 对台账候选迫降点：过否决性条件（含水面否决）→可达性判定→输出「迫降野外（含点 ID）」；
8. 出结论→交 B 组生成航迹并精算→交 D 组占位（若二级）→交模块四下发。

#### 4.7.7 接回项目流程的三条硬约束

1. **三级不可跳级、占位即锁定**——不能出现"回切"或"多巢择优"；
2. **风况只经返程基线进入判定**——不得单独成维或单独调阈值；
3. **可达性是"筛除"不是"择优"**——措辞必须写清，否则会被读成"改投次近巢"，与"原巢唯一化"冲突。

### 4.8 缺口、参数名目与验证方式

#### 4.8.1 必须处理的缺口

1. **上游是否按"目标点"给返程能耗估计**——4.1 可达性筛除与 5.2 迫降点可达性都依赖；若上游只给"回原巢"基线、不给"到他巢/到迫降点"能耗，第二、三级无法做可达性筛除，需与第5步精算/B 组确认口径。
2. **风况不确定性表达形式**（分布？范围？点估计？）——决定 2.3 走 A3、A4 还是固定 k，与功能17 的 `cov` 同一缺口。
3. **他巢的机位数、占用状态、时隙数据结构**——4.2/4.3 依赖，是否由系统掌握、是否带时间区间，需与 D 组确认。
4. **候选他巢列表的完备性由谁保证**——4.5"无位可借"结论须建立在候选集完备之上，接口约定与 D 组写清。

#### 4.8.3 验证方式与评估指标

> 功能10 是可行性判定 + 降级链决策，验证以"误判代价不对称 + 降级链结构属性 + 完备性"为核心。**本节即功能10 的专用验证方案**；通用手段见第五篇第1章 D1–D8。

- **第一级判定 + 误判方向代价（C1）**：构造"够回/差一点/明显不够"三类能量场景，统计判定正确率，并分别统计"该回却判不回"（漏判）与"回不去却判能回"（虚判）的发生率与严重程度——两类代价不对称，需分别标注。
- **三级降级正确性**：构造典型场景（原巢够回/原巢不够但有机位/连机位都无）逐条回放，核对是否落在正确级别。
- **降级链结构属性（C2）**：注入"刚降级后风况突然改善"，检查是否**仍不回切**（第三级→第二级、第二级→第一级应为 0 次）、是否**不跳级**（第一级→第三级应为 0 次）。
- **准入判定**：构造时隙重叠/容量饱和/不可达三类他巢，核对是否被正确剔除（可达性筛除先于时隙检查）。
- **完备性（C3）**：设定 N 个候选他巢随机使部分不可用，检查"无位可借"结论生成时是否遍历全部候选、有无遗漏。
- **裕度保守度折中（C4）**：对固定/鲁棒/机会约束三种策略扫描不同裕度，绘制"裕度—虚警率"与"裕度—漏报率"曲线。
- **蒙特卡洛整体仿真（C5 + D2）**：随机化风况、电量、他巢占用，跑足够多次（建议 5000–10000 次，经验值按方差收敛判据调整），统计各级成功率、误判率、平均停留时间；D6（WCET）验证每周期判定满足实时性。
- **端到端**：与功能17（放弃会面）、功能9（终止档）串联，看完整链路能否闭环。
- **标准对标（D8）**：将分级决策验证映射到 MH/T 2017—2025 的"自主决策"测试科目，作国内标准对标。

#### 4.8.4 组内已决事项

## 5 附录：通用验证方法论、推荐组合与跨功能待确认项

> 各功能的专用验证方案已内置在其篇章内（功能17 第10章、功能9 第8章、功能10 第8.3 节）；本篇给出三功能共用的通用验证方法、推荐验证组合总览，并汇总跨功能待确认项，便于评审与汇总时对齐。

### 5.1 通用仿真验证方法论（三类功能共用）

#### 5.1.D1 仿真回放（Replay）

三类功能共用基础手段：功能17 用 AIS 轨迹回放驱动变化点检测；功能9 用场景序列回放驱动分级决策；功能10 用飞行状态序列回放驱动降级链。可采用"离线评估 → 仿真压测 → 数字孪生回放"三阶段路径。

#### 5.1.D2 蒙特卡洛批量仿真（Monte Carlo）

随机化初始条件、环境参数、事件时序批量运行，统计通过率/误判率/触发频率分布。收敛判据：均值标准误小于预设阈值（如相对值 <1%）即停止采样。功能10 整体验证建议 5000–10000 次迭代（经验值，按方差收敛判据动态调整）。

#### 5.1.D3 对抗性测试 / 最坏情况注入（Adversarial Testing）

功能17 注入"边界幅度"意图变更；功能9 注入高频事件序列；功能10 注入"电量刚好在判定阈值附近"场景。目的：发现边界条件下的失效模式。

#### 5.1.D4 消融实验（Ablation Study）

去掉某层/模块观察性能下降，证明该层贡献：功能17 去掉迟滞层看虚警率变化；功能9 去掉事件优先级抑制看触发频率变化；功能10 去掉完备性检查看"无位可借"判断准确率变化。是申报书论证创新点的有力证据。

#### 5.1.D5 敏感性分析（Sensitivity Analysis）

对阈值参数（检测阈值、迟滞带宽、裕度系数）做 ±10% 扰动，观察输出（EDD、触发频率、误判率）变化幅度。某参数小扰动导致输出剧变→该参数需更精确标定。

#### 5.1.D6 最坏情况执行时间 WCET（Worst-Case Execution Time）

测量每决策周期算法最坏执行时间，验证满足上报周期硬约束（如功能17 须每上报周期内完成判定）。可通过注入大量事件走最慢路径测量，或借助 aiT 等静态分析工具/实测统计。

#### 5.1.D7 航空 V\&V 标准框架（ARP4754A + DO-178C）

作为验证方案顶层框架引用。将功能9/10 验证活动映射到 DO-178C 目标层级、功能17 统计验证映射到 ARP4754A 系统级验证。**本项目为挑战杯科创项目，不必完全按适航标准执行**，但可引用框架提升可信度。

#### 5.1.D8 无人系统自主性验证标准（MH/T 2017—2025 系列）★ 国内标准对标亮点

国内无人驾驶航空器系统**分布式操作**与**自动化等级**测试权威依据，比引用国外适航标准更贴合"多机巢分布式调度"国情场景。测试框架覆盖：① 测试对象与环境定义；② 仿真测试系统（HIL/SIL）要求；③ **测试科目**（感知、决策、控制、协同等）与**指标要求**；④ 测试结果评估与报告规范。其中"自主决策"科目可直接承载功能9 四档分级验证，"协同/感知"科目可承载功能17 船侧意图变更检测验证，是"国内标准对标"最直接抓手。

### 5.2 三功能推荐验证组合总览

> **编号体系说明**：本表的 **A/B/C 系列**为各功能**专用验证条目**编号，**D 系列**指本附录第1章的**通用验证方法**编号；与第二～四篇正文中的**功能方法代号**（如 A1 运动学规则、A2 XTE 走廊、B1 CUSUM、C1 NIS 卡方）**分属两套体系，勿混淆**。

**功能17（去程追踪与纠偏）**：指标 ARL₀/ARL₁、EDD、虚警/漏报率、ROC-DET、信噪比退化曲线；场景 = 3–5 航段 × 三类事件 × 多幅度 × ≥30 随机时刻（≥270 场景，建议值）；数据 = 合成轨迹为主、真实 AIS 可选增强；方法 = A1(ARL₀/ARL₁) + A2(EDD) + A3(ROC/DET) + A4(回放注入) + A5(信噪比分层) + D1(仿真回放) + D4(消融) + D6(WCET)。

**功能9（飞行中重新调度）**：指标 转移/转移对/MCDC 覆盖率、触发频率与稳定性、闭环收敛、场景矩阵通过率；场景 = 决策表穷举 + 抖动测试 + 闭环串联；数据 = 仿真场景矩阵与边界序列；方法 = B1(状态机覆盖) + B2(触发频率稳定) + B3(场景矩阵穷举) + B4(闭环稳定性) + B6(对抗注入与消融) + D2(蒙特卡洛) + D3(对抗性测试) + D4(消融)。

**功能10（返航复核与归巢资源判定）**：指标 各级判定正确率、误判方向代价矩阵、降级链不可逆/不跳级违规次数、完备性遗漏数、裕度折中曲线、蒙卡统计量；场景 = 正常/边界/降级/完备性四类；数据 = 仿真随机化生成；方法 = C1(第一级判定与误判代价) + C2(降级链结构属性) + C3(完备性) + C4(裕度保守度) + C5(蒙特卡洛) + D2(蒙特卡洛) + D6(WCET) + D8(MH/T 标准对标)。

> 三类功能最终都需"端到端串联"验证：功能17（放弃会面）→ 功能9（终止档）→ 功能10（三级落点）一条完整链路能否闭环。
