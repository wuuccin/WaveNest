## 1 功能 3 候选机型、机巢和无人机生成（★）

### 1.1 研究范围

| 项 | 内容 |
|---|---|
| 序号 | 3 |
| 功能名 | 候选机型、机巢和无人机生成 |
| 所属模块 | 模块二 调度引擎 |
| 回答的问题 | 给定一笔待调度任务，应该**用哪一类机型、从哪个机巢、调哪一架具体无人机**去执行？展开全部可行的"机型 × 机巢 × 无人机实例"候选组合，供下游 D 组（候选方案综合择优）评测。 |

### 1.2 输入与输出

**输入（来源与粒度）**

| 输入 | 来源 | 表示方式与粒度 |
|---|---|---|
| 任务需求 | A 组·订单接入与基本校验（输出） | 结构化订单：取/送点坐标、时间窗、载荷重量与体积、优先级；单笔任务一级 |
| 机巢清单 | 机巢注册表（静态配置 + 实时状态） | 机巢 ID、位置、可驻留机型列表、当前状态（沿用项目状态词）、挂载无人机列表；机巢一级 |
| 无人机机队清单 | 机队状态服务（实时） | 无人机 ID、所属机巢、机型、当前状态（空闲/占用等既定状态）、当前电量、载荷能力；实例一级 |
| 机型能力包线 | 静态配置 | 各机型的巡航/最大速度、最大续航、最大载荷、抗风等级、起降条件；机型一级 |
| 船舶预测轨迹 | A 组·船舶状态估计与轨迹预测管理（输出，可选粗筛） | 未来 T 秒预测轨迹及不确定度；用于地理可达性初判 |

**输出（给谁）**

- 候选组合列表 → 给 **功能 4（本组可行性判断）** 与 **D 组·候选方案综合择优**。
- 每条候选 = `(机型, 机巢, 无人机实例, 初步可达标志)`。
- 初步可达标志：仅基于静态/半动态约束的粗判（如地理半径内），**不**代表最终可行。

**边界（明确不做什么）**

- 不做最终能耗与电量整环验算（属功能 4，本组）。
- 不计算具体可飞航迹（属 B 组·可飞航迹生成）。
- 不做多候选间的占位与并发仲裁（属 D 组·资源占用与并发冲突管理）。
- 不决定最终航线与起飞时刻（属 D 组·航线确认与起飞时刻确定）。

### 1.3 算法设计

**核心思路**：先按静态能力预筛、再展开受限笛卡尔积，避免"全量机型×机巢×实例"组合爆炸；静态约束离线预计算并缓存，动态状态在每次展开时实时判定；实例"空闲"作为展开前的硬前置条件做早剪枝。

**候选组合展开方式（步骤）**

1. **机型筛选（静态）**：依据任务载荷、时间窗松紧、抗风要求，对照机型能力包线，过滤出候选机型集 `M`。
2. **机巢筛选（静态 + 半动态）**：过滤"可驻留机型 ∈ M"且"地理上处于可达半径内"的机巢，得候选机巢集 `N`。
3. **实例筛选（动态）**：在 `N` 内，过滤出当前状态为"空闲"的无人机实例，得候选实例集 `U`。
4. **组合展开**：对 `(m∈M, n∈N_m, u∈U_n)` 做受限笛卡尔积，生成候选组合列表。

**静态剪枝与动态剪枝的分工**

- **静态剪枝（离线 / 低频缓存）**：机型能力包线、机巢–机型兼容、机巢地理可达半径、任务–机型硬性约束（载荷 / 抗风 / 续航）。不随运行时状态变化，预计算后缓存复用。
- **动态剪枝（运行时实时判定）**：实例当前状态（空闲 / 占用 / 故障 / 充电中等既定状态）、机巢实时占用、当前风况是否超出机型抗风等级。随调度时刻变化，每次展开实时判定。

**实例是否空闲在展开阶段就过滤掉**：**是**。采用"先筛实例空闲、再展开组合"的早剪枝策略——把"实例空闲"作为展开前置硬条件，而非展开后再剔除。这样避免生成大量以"忙"实例为成员的候选，直接压低下游计算量。是否纳入"充电中但预计在任务窗口前可就绪"的实例，列为待定项（见第 5 节）。

**参数与阈值（只列名目与含义，不写死取值）**

| 参数名 | 含义 |
|---|---|
| `payload_match` | 机型最大载荷 ≥ 任务载荷 的匹配判据 |
| `windclass_match` | 机型抗风等级 ≥ 任务区最不利风级 的匹配判据 |
| `range_match` | 机型最大续航 ≥ 任务粗估航程 × 安全系数 的匹配判据 |
| `R_nest` | 机巢地理可达半径：机巢到任务端点的可达距离阈值（直线 / 规划航迹，待定） |
| `idle_whitelist` | 进入候选的实例状态白名单，默认仅"空闲"；可配置是否含"充电中且预计可调度" |
| `cap_combo` | 单任务最大候选组合数上限；超出时按距离 / 优先级截断 |
| `TTL_static` | 机型 / 机巢静态约束缓存的失效刷新周期 |

### 1.4 验证方式

| 维度 | 内容 |
|---|---|
| 数据 / 场景 | 典型订单集（覆盖不同载荷、距离、时间窗）+ 机队快照（空闲 / 占用 / 故障混合状态） |
| 指标 | 候选集**召回率**（是否覆盖全部真实可行组合）；候选集**规模**（平均 / 最大候选数）；**展开时延**；静态剪枝命中率；动态剪枝命中率；**漏生成率**（应生成却未生成的真实可行组合占比） |

### 1.5 待定项

- "空闲"判定口径：充电中但预计在任务窗口前可就绪的实例是否纳入？需与 **D 组·航线确认与起飞时刻确定** 对齐。
- 机巢地理可达半径 `R_nest` 用直线距离还是规划航迹？粒度需与 **B 组·可飞航迹生成** 对齐。
- 组合爆炸时的截断策略（按距离？按优先级？）需与 **D 组·候选方案综合择优** 的择优口径一致。
- 静态缓存命中但实例实时状态已变（如已转"占用"）时的处理与一致性保障。

## 2 功能 4 候选组合可行性判断（★★）

### 2.1 研究范围

| 项 | 内容 |
|---|---|
| 序号 | 4 |
| 功能名 | 候选组合可行性判断 |
| 所属模块 | 模块二 调度引擎 |
| 回答的问题 | 功能 3 产出的某个候选组合到底**飞不飞得成**？通过"两关"判据筛掉不可行组合：第一关**追得上**（能否在会面点按时交汇），第二关**回得来**（整环电量是否够）。 |

### 2.2 输入与输出

**输入（来源与粒度）**

| 输入 | 来源 | 表示方式与粒度 |
|---|---|---|
| 候选组合列表 | 功能 3（本组生成，输出） | `(机型, 机巢, 无人机实例, 初步可达标志)`；候选一级 |
| 会面点求解结果 | B 组·会面点求解（输出） | 会面点坐标、会面时刻窗口 `[t_arr_min, t_arr_max]`、双方到达时间；会面一级 |
| 会面点重算事件（飞行中） | E 组功能 17（去程段追踪与纠偏）6a 分支 | 飞行中重算产出的**新会面点 / 会面窗**，作为更新输入再次触发本功能复判（见第 3 节"重触发口径"） |
| 船舶预测轨迹 | A 组·船舶状态估计与轨迹预测管理（输出） | 未来 T 秒预测轨迹及不确定度带 |
| 机型能耗模型 | 静态配置 | 速度–功耗曲线、悬停功耗、风速→功耗修正系数；机型一级 |
| 风场（实时 / 预报） | 环境数据服务 | 任务区风矢量序列（时空网格），含最不利风况取值 |
| 机巢位置与无人机当前电量 | 机巢注册表 / 机队状态服务 | 机巢坐标、实例电量（SOC） |

**输出（给谁）**

- 每个候选的可行性结论 → 给 **D 组·候选方案综合择优**（仅可行候选进入择优）。
- 结论 = `通过` / `不通过` + **不通过原因码**（`追不上` / `回不来` / `其他`）+ 关键中间量（所需电量、可用电量、最迟起飞时刻）。

**边界（明确不做什么）**

- 不计算具体可飞航迹（属 B 组·可飞航迹生成）。
- 不做多候选间的占位与并发仲裁（属 D 组·资源占用与并发冲突管理）。
- 不做综合择优打分（属 D 组·候选方案综合择优）。
- 不做飞行中实时重规划（属 E 组功能 9·飞行过程中的重新调度）。
- **不做飞行中返航落点决策（原巢 / 借他巢 / 迫降），属 E 组功能 10·返航复核与归巢资源判定**；本功能在派单阶段只判"回原巢"，判"回不来" = 该候选直接不通过、不落任何巢。

### 2.3 算法设计

**核心思路**：两关顺序执行，**先"追得上"后"回得来"**，任一关不过即剪枝，不再进入下一关，降低计算量。两关均依赖上游：第一关依赖 **B 组·会面点求解**，第二关依赖**航迹能耗与电量整环验算**。

**重触发口径（跨组接口）**：飞行中若 E 组功能 17（去程段追踪与纠偏）的 6a 分支**重算会面点**，则以新会面点 / 会面窗对该在飞候选**重新触发本功能判断（复判）**——第一关以新会面点 / 会面窗复判时间可行性；第二关因去程 / 回程航迹长度随会面点变化，需重算整环能耗。复判仍按"回原巢"口径，输出格式与原因码不变；派单阶段的批量判断与飞行中的单候选复判**共用同一套两关判据**。

#### 第一关｜追得上（依赖会面点）

- **判定目标**：无人机从机巢 `n` 出发，能否在会面时刻窗 `[t_arr_min, t_arr_max]` 内到达会面点 `P`。
- **步骤**：
  1. 取 B 组·会面点求解给出的会面点 `P` 与到达时间窗，结合机型速度包线，估算去程飞行时间 `t_fly_out`（含风修正）。
  2. 反推**最迟起飞时刻** `t_launch_max = t_arr_max − t_fly_out − launch_buffer`。
  3. 判定：`t_launch_max ≥ 当前时刻` ⇒ **追得上**；否则 **追不上**。
  4. 若即便立即起飞也晚于 `t_arr_max`（会面窗本身不可达），标记 `追不上-会面窗不可达`。
- **依赖说明**：本关只做**时间可行性**，不重算会面点；派单阶段的会面点与会面窗由 B 组·会面点求解先产出，飞行中的会面点更新由 E 组功能 17（6a 分支）推送并触发复判（见"重触发口径"）。

#### 第二关｜回得来（依赖航迹能耗与电量整环验算）

- **判定目标**：对"去程（机巢→会面点）+ 会面停留 + 回程（会面点→机巢）"整环做能耗与电量验算，确保落回**原机巢**时电量 ≥ 安全余量。**派单阶段只判"回原巢"，不判备降落点。**
- **步骤**：
  1. 去程能耗 `E_out` = 机型能耗模型 × 去程航迹长度 × 最不利风修正。
  2. 回程能耗 `E_back` = 机型能耗模型 × 回程航迹长度 × 最不利风修正（回程常逆风，更耗能）。
  3. 会面停留能耗 `E_hold` = 悬停 / 盘旋功耗 × 预计停留时长（含会面窗等待上限）。
  4. 整环需电 `E_total = E_out + E_hold + E_back`。
  5. 可用电量 `E_avail = 当前电量 − soc_margin`。
  6. 判定：`E_total ≤ E_avail` ⇒ **回得来**；否则 **回不来**（该候选直接不通过，不落任何巢）。

#### 最不利风况的取值方式

- 采用**沿整环逐段取该段最不利风分量（逆风分量最大）**的方式，而非全程取单一最大风。逐段取对能耗最不利的风方向与量级，使能耗估算**偏保守但不至于过度悲观**。
- 风值来源：实时 / 短期预报风场在对应时空网格的取值，可叠加配置的安全系数 `wind_safety`。
- **不取**"历史极端风"（过于保守、误杀可行组合），也**不取**"无风基准"（过于乐观、漏杀不可行组合）。

**参数与阈值（只列名目与含义，不写死取值）**

| 参数名 | 含义 |
|---|---|
| `hold_max` | 会面点盘旋等待的最长时长上限 |
| `launch_buffer` | 反推最迟起飞时刻时的安全缓冲 |
| `soc_margin` | 落巢时须保留的最低电量（比例 / 绝对值） |
| `wind_seg` | 最不利风分段粒度（与风场网格分辨率匹配，待定） |
| `wind_safety` | 风况安全系数，叠加于分段最不利风取值 |
| `cruise_power` | 巡航功耗（机型能耗模型条目） |
| `hover_power` | 悬停 / 盘旋功耗 |
| `wind_factor` | 风速 → 功耗修正系数 |
| `reason_code` | 不通过原因码枚举：`追不上` / `回不来` / `其他` |

### 2.4 验证方式

| 维度 | 内容 |
|---|---|
| 数据 / 场景 | ① **合成网格扫描**：可控变量（会面窗宽度、风况、初始电量、机巢距离）做参数网格，验证两关在各边界下的通过 / 剪枝行为正确；② **轨迹回放**：用 A 组·船舶状态估计与轨迹预测管理的船舶轨迹 + B 组·会面点求解的会面点回放若干历史任务，统计剪枝结果；③ **重触发复判场景**：模拟飞行中会面点重算（E 组功能 17 触发），验证复判链路正确触发且口径一致 |
| 指标 | 两关判据**准确率**（与精算仿真对比的误杀率 / 漏放率）；**剪枝召回**（真实不可行组合被剪掉的比例）；**误杀率**（可行组合被错杀比例，过严的最不利风会推高此项）；单候选判断时延；`wind_safety` 敏感性（其对误杀 / 漏放的影响曲线） |

### 2.5 待定项

- **口径澄清（原"跨机巢备降"表述有歧义，已按项目口径更正，非开放问题）**：派单阶段只判"回原巢"，判"回不来" = 该候选直接不通过、不落任何巢；飞行中返航落点决策（原巢 / 借他巢 / 迫降）属 **E 组功能 10（返航复核与归巢资源判定）**，不在本功能范围。
- B 组·会面点求解输出的"会面窗"若带不确定性（来自船舶轨迹不确定度），本关如何吸收？取窗上限做保守判，还是传递概率？需与 **B 组·会面点求解** 对齐接口。
- 最不利风分段粒度 `wind_seg` 与风场网格分辨率如何匹配？需与气象数据源对齐。
- 电量安全余量 `soc_margin` 是否随任务关键级 / 夜间 / 海况动态调整？需与 **G 组·低电量预警** 口径一致。
- 各组功能编号对照表：建议在总报告统一附一张"各组功能编号对照表"；本方案中他组功能暂以"组名 + 功能名"指代（E 组已按其报告既定编号功能 9 / 10 / 17 引用）。
- 算法方法出处：功能 3 / 4 为工程规则推导，未引用外部文献；若项目要求每个功能附算法文献出处，需补充确认（当前按"规则合理即可"口径执行）。

## 3 组间接口与依赖小结

| 本组功能 | 主要上游 | 主要下游 |
|---|---|---|
| 功能 3 候选生成 | A 组·订单接入与基本校验、A 组·船舶状态估计与轨迹预测管理（粗筛）、机巢 / 机队状态、机型能力包线 | 功能 4（本组）、D 组·候选方案综合择优 |
