# 天地图个人密钥使用指南

WaveNest 主地图使用天地图卫星影像 `img_w` 和影像注记 `cia_w`，也可在地图右上角切换到矢量底图。天地图密钥有个人配额，因此每位开发成员都要申请并使用自己的浏览器端密钥；仓库不会提供或保存公共密钥。

## 一、申请自己的密钥

1. 打开[天地图官网](https://www.tianditu.gov.cn/)并登录。
2. 从官网进入“开发资源”，再进入“服务中心控制台”。不要使用已经失效的 `console.tianditu.gov.cn` 旧地址。
3. 在左侧打开“开发管理 → 应用管理”，选择“创建新应用”。
4. 推荐填写：
   - 应用名称：`WaveNest无人机调度演示`
   - 行业类别：物流、无人机、交通（按页面可选项填写即可）
   - 应用类型：**浏览器端**
   - 域名白名单：本机开发填写 `127.0.0.1`
5. 提交后，在应用详情中复制生成的 Key。

域名白名单只接受域名或 IP，不能填写 `http://127.0.0.1:5173`，也不能包含协议或端口。如果平台仍不接受本机 IP，可暂时留空用于本地联调；正式部署时必须改成实际域名白名单。

## 二、配置到自己的电脑

在仓库根目录执行复制操作，或手工复制文件：

```powershell
Copy-Item frontend/.env.example frontend/.env.local
```

然后打开 `frontend/.env.local`，将个人 Key 填在等号后：

```env
VITE_TIANDITU_KEY=在这里填写自己的Key
```

不要给 Key 加中文引号，不要把其他文字写在同一行。`.env.local` 已被 Git 忽略，不会随正常提交进入仓库。

## 三、重新启动并验证

环境文件只在前端启动时读取。保存后需要停止并重新启动前端：

```powershell
pnpm --dir frontend run dev
```

访问 `http://127.0.0.1:5173/`，检查：

1. 地图不再显示“卫星底图待配置”；
2. 右下角显示天地图来源信息；
3. 主图能够看到南昌赣江段的卫星影像和道路/地名注记；
4. 地图右上角可以在“卫星影像”和“矢量底图”间切换。

业务坐标与天地图球面墨卡托瓦片统一使用 CGCS2000 / WGS-84，前端直接按系统坐标上图，不再施加 GCJ-02 偏移。开发取点工具输出的也是可用于系统录入的 CGCS2000 / WGS-84 坐标。

开发环境需要在网址后加 `?debug=1` 才会显示“开发取点”面板，例如 `http://127.0.0.1:5173/?debug=1`；普通演示网址不会显示，生产构建也始终隐藏。点击地图即可显示并复制系统经纬度，点击船舶、无人机或机巢图标可查看要素 ID 和系统坐标。

## 四、常见问题

| 现象 | 处理办法 |
| --- | --- |
| 显示“卫星底图待配置” | 检查文件名是否为 `frontend/.env.local`，变量名是否为 `VITE_TIANDITU_KEY`，然后重启前端。 |
| 显示“天地图瓦片加载失败” | 检查 Key 是否复制完整、应用类型是否为浏览器端、白名单是否填成 `127.0.0.1`，并检查网络。 |
| 白名单提示格式错误 | 只填 `127.0.0.1`，不要填 `http://`、`https://` 或 `:5173`。 |
| 地图正常但订单/机巢为空 | 这是后端 `8080` 服务或数据问题，与天地图 Key 无关。 |
| 换电脑或其他组员运行 | 每台电脑分别创建 `.env.local` 并填写使用者自己的 Key。 |

## 五、安全要求

- 不要把真实 Key 写入 `.env.example`、源码、截图、群消息或提交记录。
- 提交前运行 `git status`，确认 `frontend/.env.local` 没有出现在待提交文件中。
- Key 意外泄露时，应立即在天地图应用管理中重置或删除旧 Key。

没有配置密钥时，系统仍保持赣江南昌段初始视野并提示缺少配置，但不会用虚构底图冒充真实影像。机巢图标只根据后端 `GET /api/nests` 返回的有效坐标绘制。
